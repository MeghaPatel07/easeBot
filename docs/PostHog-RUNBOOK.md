# PostHog Runbook — Easebot

Operational playbook for running PostHog on the free tier. Paired with
`docs/PostHog-EVENTS.md` (taxonomy) and `docs/PostHog-SPRINT-REPORT.md`
(implementation record).

---

## 0. Quick facts

| Fact | Value |
|---|---|
| Hosting | PostHog Cloud (US) — free tier |
| Monthly caps | 1M events / 5K replays / 1M flag requests |
| Proxy path (FE → BE) | `/ingest/*` → `POSTHOG_HOST` |
| Kill switches | `VITE_POSTHOG_ENABLED=false`, `POSTHOG_ENABLED=false` |
| Consent gate | `localStorage.ph_consent` set by `AnalyticsConsent.tsx` |
| Auth carrier for BE | `x-ph-distinct-id` header + authed `req.user.uid` |

## 1. Turning it on (prod go-live)

1. Create a project at app.posthog.com → copy the public `phc_...` key.
2. FE env (Vercel/static host): set `VITE_POSTHOG_KEY`, `VITE_POSTHOG_HOST=/ingest`, `VITE_POSTHOG_ENABLED=true`.
3. BE env: set `POSTHOG_PROJECT_KEY`, `POSTHOG_HOST=https://us.i.posthog.com`, `POSTHOG_ENABLED=true`.
4. Redeploy both. Open the app in a fresh browser → consent banner → Accept.
5. In PostHog → Live events, confirm a `pageview` + `login_completed` lands.

## 2. Turning it off (incident)

Flip either env var to `false` and redeploy. All `track()`/`capture()` calls
become no-ops immediately — no data is buffered or leaks. Safe for outages,
cost overrun, or privacy concerns.

## 3. Usage watchdog (cost control)

PostHog project → Data management → Billing shows live usage. Set alerts:

| Metric | Threshold | Action |
|---|---|---|
| Events | 70% of 1M | Tune sampling — reduce replay rate, check for hot events |
| Replays | 70% of 5K | Drop sample rate 10% → 3% in `lib/analytics.ts` `startReplay` |
| Flags  | 70% of 1M | Bump bootstrap TTL, move misused flags to env config |

### Escape hatches (least painful first)
1. Lower replay sample (`0.1` → `0.03`) in `analytics.ts`.
2. Disable `capture_pageview` on non-funnel routes.
3. Send dev/staging to a **separate** PostHog project with its own free quota.
4. Self-host — 1 day of work, unlimited forever.

## 4. Daily ops

### Check funnel health
PostHog → Insights → Funnels → "Signup to Paid".  
Steps: `signup_started` → `signup_completed` → `first_message_sent` → `paywall_shown` → `checkout_started` → `payment_succeeded`.

Drops >15% step-to-step = investigate. Look at matching session replays for
that cohort.

### Check replay health
PostHog → Session replay → filter by `plan_tier = free`, last 24h. Watch 3–5
random sessions. Confirm no PII (chat content, wedding date, names, emails, card numbers) visible.

If PII leaks: add `data-ph-mask` to the offending element, ship a hotfix,
delete affected replays via PostHog UI.

### Check cost trend
Org settings → Usage. Trendline should stay <80% of caps. If not, follow §3.

## 5. Feature flags

Flags live in PostHog → Feature flags. Conventions:

- Kill switches: prefix `kill_` (e.g. `kill_image_gen`)
- Experiments: prefix `exp_` (e.g. `exp_paywall_copy_v2`)
- Rollouts: prefix `rollout_` (e.g. `rollout_pricing_v2`)

Read from FE: `useFeatureFlag('rollout_pricing_v2')`.  
Read from BE: `await isFeatureEnabled('kill_image_gen', uid)`.

Always pair a flag with a `capture('$feature_flag_called', ...)` — PostHog does
this automatically when you read the flag, so experimentation dashboards work
out of the box.

## 6. Identity model

- **Anonymous**: distinct_id generated by posthog-js, stored in cookie.
- **Logged-in**: `identify(uid)` in `AuthContext` on auth change. Same uid on BE.
- **Guest → signup conversion**: `identify(uid)` auto-merges anonymous history
  into the new identified profile via PostHog's implicit aliasing. No manual
  `alias()` call needed in most cases — the first `identify()` after an
  anonymous session does the merge.
- **Logout**: `reset()` in `AuthContext.handleSignOut` — issues a fresh
  anonymous distinct_id so next user on the same browser doesn't merge.

## 7. Known limitations / follow-ups

- `tool_invoked` events are not yet instrumented per-tool — add to each tool
  handler in `chatController.ts` when tool-level analytics matter.
- `otp_verified` not yet instrumented — add in `authController.handleVerifyOtp`.
- `payment_abandoned` relies on client-side timeout; if user closes tab, fires
  on next session. Consider a server-side 30-min `pending` sweep if accuracy
  matters.
- Session replay on mobile Safari has rare input-mask gaps in WebKit — keep
  an eye on replays from iOS devices during QA.

## 8. Incident playbook — "analytics looks wrong"

1. Is the kill-switch on? Check env. If on, data loss is expected.
2. Check ad-blocker — test in Firefox + uBlock Origin. Events should still
   flow via `/ingest/*` (that's the whole point of the reverse proxy).
3. Check browser console for `posthog` errors.
4. Check BE logs for `[posthog]` warnings.
5. Check PostHog status page: status.posthog.com.
6. If stale identity: reproduce the issue, open PostHog → Persons → find the
   distinct_id from `posthog.get_distinct_id()` in the browser console.

## 9. GTM readiness checklist

- [ ] Real PostHog keys in prod env (FE + BE)
- [ ] Consent banner live, tested in multiple geos
- [ ] Reverse proxy `/ingest/*` returns 200 (spot-check)
- [ ] Funnel step-through shows >0% for every step (smoke test)
- [ ] Replay of a real checkout session shows no PII
- [ ] Webhook idempotency verified — simulate a PayU retry, confirm exactly
      one `payment_succeeded`
- [ ] Usage watchdog alert configured at 70% cap
- [ ] This runbook linked from team wiki / README
