## Steps to reproduce
1. Open two tabs.
2. Tab A — toggle dark → light (top-bar ThemeToggle).
3. Tab B — observe.

## Expected
Tab B re-applies the same theme. Pages match.

## Actual
- ThemeContext writes localStorage (line 112), persists to backend (line 118) but does NOT add a `window.addEventListener('storage', …)`.
- The boot script in index.html only fires once on initial document load — it can't react to a storage event.
- Tab B keeps the old theme until user reloads.

## Impact
P2 — cosmetic but jarring; user toggling theme expects parity across tabs (matches OS dark-mode UX).

## Fix direction
Add a storage event listener in ThemeContext that listens for `STORAGE_KEY === 'easebot-theme'` and re-applies theme.

## Evidence
- src/contexts/ThemeContext.tsx:43-50 (writes only, no read on storage event)
