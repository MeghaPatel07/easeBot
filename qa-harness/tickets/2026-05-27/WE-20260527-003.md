## Description

Hitting `/checkout?plan=pro&billing=monthly` while signed out silently 302s/replaces to `/pricing` with no message. Users (and external "upgrade" CTAs in the pricing rollout) cannot deep-link into checkout without being told they need to sign in first.

## Steps to reproduce

1. Open incognito at `http://localhost:8081/checkout?plan=pro&billing=monthly`.
2. Observe the address bar.

## Expected

If guest, either render the checkout page with an inline "Sign in to continue" gate, or redirect to `/login?returnTo=/checkout?plan=pro&billing=monthly` so the user is brought back after auth.

## Actual

URL silently becomes `/pricing`. Plan/billing query params are lost. No toast, no explanation.

## Evidence

- Screenshot: `qa-harness/evidence/WE-20260527-003/screenshots/checkout-redirect.png`

## Notes

Breaks the documented PayU upgrade journey — any "Upgrade" button that links straight to `/checkout` will dead-end at /pricing for the 95% of users not already signed in.
