## Description

Most of the documented "side pane" features (`planner`, `budget`, `timeline`, `reminders`, `notifications`, `gallery`, `saved-items`, `shopping`, `notes`, `progress`, `collaborate`) are routed only under `/:userId/<feature>`. Guests have no userId, so they cannot reach these routes. The harness brief asks to verify:
- Checklist CRUD (max 5 for free tier)
- Settings + tone + voice (covered separately via /?settings=account)
- Liked messages persistence
- Gallery view
- Budget dashboard + line items
- Timeline / Reminders / Notifications panel
- Shared chat link
- Free vs Premium gating

Without an authenticated session (and a non-destructive test account), these cannot be exercised by the QA harness. I tried `/login` → "Continue With Email" → was asked for an email; without test credentials I cannot proceed without risking creating a real user record.

Filing as a *coverage gap* ticket so triage can either:
1. Provide a test account credential pair, or
2. Add a "guest preview" mode for these features (read-only with demo data), or
3. Add Playwright auth fixtures the QA harness can reuse.
