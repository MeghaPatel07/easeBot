# WE-20260527-308 — Sourcemaps disabled in build → no production stack traces possible

**Severity:** P2
**Status:** triaged
**Assigned:** fix-performance
**Area:** Performance observability
**File:** `Wedding-Ease-Viva-Chat/vite.config.ts:37`
**Discovered:** 2026-05-27

## Symptom
```ts
// vite.config.ts
build: {
  sourcemap: false,
}
```

Without sourcemaps:
- PostHog session replay + error tracking shows minified frames.
- Web Vitals attribution (which DOM node was the LCP element, which task was the longest) is unreadable.
- Performance regressions in CI are hard to diff because flamegraphs are unintelligible.

## Suggested fix
Use `sourcemap: 'hidden'` so the `.map` files exist for upload to PostHog/Sentry but aren't referenced from production JS. The maps stay private but error symbolication works.

```ts
build: {
  sourcemap: 'hidden',
}
```

PostHog supports uploading sourcemaps via `posthog-cli sourcemap upload`. Wire that into the build pipeline.
