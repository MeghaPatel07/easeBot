## Description

Sending an invalid `audioBase64` value triggers an ffmpeg conversion failure whose stderr is included verbatim in the 500 response. The leaked string discloses:

- The macOS temp-folder structure: `/var/folders/gd/p3q5gbvd1cl4gn1p8j1t9c4r0000gn/T/`
- A monotonically-incrementing temp filename (`viva-input-1779875900921.webm`) → reveals a millisecond timestamp / process state
- Confirms ffmpeg is in use server-side (specific binary name + exit-code phrasing)

This is a CWE-209 Information Exposure Through Error Message. An attacker can probe with shaped inputs to enumerate the server's filesystem layout.

## Steps to reproduce

1. `curl -X POST http://localhost:3001/api/transcribe -H "Content-Type: application/json" -d '{"audioBase64":"not-base64-garbage!!"}'`

## Expected

`500 { "error": "Audio could not be processed", "code": "TRANSCRIBE_FAILED" }`. Log the ffmpeg stderr server-side only.

## Actual

```json
{"error":"Audio conversion failed: ffmpeg exited with code 1: /var/folders/gd/p3q5gbvd1cl4gn1p8j1t9c4r0000gn/T/viva-input-1779875900921.webm: Invalid data found when processing input\n"}
HTTP=500
```
