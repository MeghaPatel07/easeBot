## Symptom
`grep -rn "from 'lucide-react'"` returns **126 named-import statements** across the app. The largest single import is in `pages/Index.tsx`:
```ts
import {
  Sparkles, Heart, MessageSquare, Calendar, Lightbulb, Globe,
  Lock, ArrowLeft, CheckSquare, Bookmark, Image, ShoppingCart,
  DollarSign, ThumbsUp, Keyboard, BarChart3, Clock, Bell, Users,
  FileText, X, Copy, Check, Link, Share2, MessageSquareHeart, RotateCcw,
} from 'lucide-react';
```

`lucide-react` does support tree-shaking out of the box, but only when the bundler can statically resolve each named export. With 126 named imports spread across the app and inside conditionals, tree-shaking is fragile.

In the build output, individual lucide icons ARE getting split into tiny chunks (`check-CGuyPQef.js`, `arrow-left-CJEr09OQ.js`, etc) — so tree-shaking IS working for some. But the main vendor bundle still includes most of them.

## Suggested fix
1. Audit the actual icon set used. The Vercel React best-practices skill recommends migrating to `lucide-react/icons/X` direct imports for explicit code-splitting:
   ```ts
   import Sparkles from 'lucide-react/dist/esm/icons/sparkles';
   ```
   This guarantees each icon is its own chunk.
2. Or: pull the small set of frequently-used icons into a local `src/icons.ts` barrel and use one canonical entry point.
3. Confirm `componentTagger` (development-only Lovable plugin) isn't inadvertently rewriting these imports in prod.

## Suggested verification
Total `lucide-react` payload in production bundle should be < 30 kB gzipped after fix.
