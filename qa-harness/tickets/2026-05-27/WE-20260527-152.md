## Steps to reproduce
1. Open ProfileMenu (TokenPoolBar visible).
2. Send a message in chat.
3. Watch the "Monthly tokens" + "Today" bars.

## Expected
After backend returns each chat response (which knows the token cost), the meter updates within ~1s.

## Actual
- `useUsageStats` polls every 60s with `staleTime: 30_000`. No invalidate after a chat message completes.
- The meter sits stale; user sends 5–10 messages without the bar moving.
- A 402 ("quota_exceeded") arrives only when the user hits the hard cap — too late for the meter to be useful as feedback.

## Impact
P1 — pricing PRD §5 promises 75% / 90% / 100% banners. Those don't fire predictably because the snapshot is stale at the moment of warning.

## Fix direction
After every successful chat response, the chat hook should `queryClient.invalidateQueries(['account','usage'])` (or backend can return updated counts inline and the hook setQueryData them).

## Evidence
- src/hooks/useUsageStats.ts:7-8 (refetchInterval 60s, staleTime 30s)
- src/hooks/useChat.ts (no invalidate of 'account','usage' after send)
