## Description

The `useChat` send-message catch block handles `AbortError` and `quota_exceeded`. EVERY other failure mode renders as:

> "Something went wrong. Please try again."

This conflates:
- Network drop (`navigator.onLine === false`)
- DNS/timeout (`TypeError: Failed to fetch`)
- 429 chat-burst-limit (backend has a specific code: `chat_burst_limit`)
- 500 internal error
- 502 / Azure upstream
- 401 / expired token

Users get no useful guidance, can't tell whether to wait, retry, sign in, or upgrade. Support gets vague tickets ("the chat doesn't work").

Also, there's no `navigator.onLine` listener anywhere in the codebase — confirmed by `grep`. The app cannot detect or surface offline state.

## Steps to reproduce

1. Open chat. Disconnect Wi-Fi.
2. Send a message.

## Expected

- Detect `!navigator.onLine` BEFORE attempting fetch — show "You're offline. We'll send when you're back."
- On 429: show "Slow down — try again in a few seconds."
- On 5xx: show "Our servers had a hiccup — retry?"
- On 401: redirect to re-auth.
- Queue the user message and offer a "Retry" button on each failure.

## Actual

Generic "Something went wrong" for every non-quota failure.
