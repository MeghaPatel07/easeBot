## Description

`ChatRequestSchema` requires `message: z.string().min(1).max(10000)`. The controller at line 653 checks `if (!message && !audioBase64 && !imageBase64)` and returns 400 — indicating audio-only or image-only submissions should be supported. But the schema's `min(1)` causes zod to reject the request long before the controller check fires.

Verified: `curl -d '{"audioBase64":"..."}'` returns `"message is required"` from the validator, not the controller's friendlier "message, audioBase64, or imageBase64 is required" error.

Effect: voice-only and image-only flows from the frontend break unless the frontend always populates a dummy message. The intended controller branch at line 653 is dead code.

## Steps to reproduce

```bash
curl -X POST http://localhost:3001/api/chat -H "Content-Type: application/json" -d '{"audioBase64":"validBase64Here"}'
# → 400 "message: Required" (zod), NOT "message, audioBase64, or imageBase64 is required" (controller)
```

## Expected

Schema-level `.refine()` that asserts at least one of `message`, `audioBase64`, `imageBase64` is present:

```ts
}).refine(d => d.message || d.audioBase64 || d.imageBase64, {
  message: 'message, audioBase64, or imageBase64 required'
})
```

## Actual

`message` is unconditionally required. Audio-only/image-only paths blocked at validation.
