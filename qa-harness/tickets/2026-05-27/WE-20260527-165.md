## Steps to reproduce
1. Open same chat in Tab A and Tab B.
2. Tab A — switch mode from "chat" → "image".
3. Tab B — observe input placeholder / send button icon.

## Expected
Tab B reflects the same mode (or at minimum doesn't show conflicting state when a message is sent and arrives via Firestore listener).

## Actual
- Mode is local React state in chat header components. No Firestore field, no broadcast.
- When Tab A sends an image-mode message, Tab B receives the message via `subscribeToMessages` (chatService.ts:164) — but Tab B's UI still thinks it's in "chat" mode, so a follow-up send in Tab B fires a chat-mode request even though the conversation is image-mode.

## Impact
P2 — multi-tab UX inconsistency; not the primary use case but real for power users.

## Fix direction
Either: persist mode per-thread to Firestore (thread.mode) and pick up via subscribeToThreads; or store mode in a BroadcastChannel that other tabs listen to.

## Evidence
- Active mode is local prop `selectedMode` (ChatHeader.tsx:29, src/pages/Index.tsx)
- No mode persistence in chatService.ts thread schema
