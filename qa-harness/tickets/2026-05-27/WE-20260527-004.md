## Description

Opening the Settings modal logs:

```
`DialogContent` requires a `DialogTitle` for the component to be accessible for screen reader users.
Warning: Missing `Description` or `aria-describedby={undefined}` for {DialogContent}.
```

The top-level `SettingsShell.tsx:267` sets `aria-labelledby="settings-shell-title"`, so it is **not** the offender. Some nested dialog (likely a sub-modal triggered when the Settings shell opens, or the AnalyticsConsent overlay) is missing a `DialogTitle`. The Radix runtime warning fires every time the modal renders.

## Steps to reproduce

1. `http://localhost:8081/` → dismiss consent.
2. Click "Settings" in left sidebar (or `?settings=account` URL).
3. Open DevTools console.

## Expected

No Radix accessibility warnings. Every DialogContent gets a `DialogTitle` (use `VisuallyHidden` if visually undesired).

## Actual

The two warnings above print on every modal render. Screen readers won't announce the dialog purpose.

`grep -rn "DialogContent" Wedding-Ease-Viva-Chat/src/components` then check each for a sibling `DialogTitle`. Probable suspects: `FeedbackDialog.tsx`, `InvitePartner.tsx`, an inner step inside `SettingsShell`.
