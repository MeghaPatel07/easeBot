## Description

Enumerating every `button[aria-label]` on `/` returns:
```
["Send Feedback","Beta program info","Response language","Switch to dark mode","Reset occasion and mode","Attach","Attach"]
```
No entry for Send/Submit. The send button (the up-arrow icon at the right of the composer) ships without `aria-label`, so screen-reader users hear only the SVG title (if any).

## Steps to reproduce

1. `http://localhost:8081/`.
2. In console: `[...document.querySelectorAll('button')].map(b => b.getAttribute('aria-label') || b.innerText.trim()).filter(Boolean)`.

## Expected

Send icon button has `aria-label="Send message"` (or similar) and a programmatic disabled state when input is empty.

## Actual

No aria-label. Filling the textarea with text does NOT change any aria-labelled "send" button (because none exists with that label).

## Evidence

- `qa-deep2.mjs`: `SEND_STATE_BEFORE: []` and `SEND_STATE_AFTER: []` (filtered for any aria-label containing "send" or "submit" — both empty).

## Notes

Same icon button should also be `type="submit"` so Enter-in-textarea works in screen-reader virtual-cursor mode.
