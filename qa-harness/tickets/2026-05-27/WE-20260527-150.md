## Resolution (2026-05-27)

Closed by the WE-20260527-170 umbrella fix — `AuthContext.profile` now subscribes via `onSnapshot(doc(db,'users',uid))`, so display-name (and every other profile field) fans out to sidebar, chat header, NotesView, InvitePartner, useChat, useTokenPool the instant the Firestore write lands. ProfileMenu (which reads from `useAccount`) was already correct; this PR closes the gap on the `useAuth()` side.

## Steps to reproduce
1. Sign in.
2. Open Settings → Account tab.
3. Change Display Name (e.g., "Krish" → "Krishna").
4. Click Save. Toast "Profile updated" appears.
5. Without reloading, look at:
   - Sidebar bottom (ChatSidebar.tsx line 502 — initials + name)
   - Profile menu dropdown (ProfileMenu.tsx line 177)
   - InvitePartner / NotesView (pages/Index.tsx lines 1349-1350 — passes `profile.name` as a prop)
   - ProfileIcon avatar fallback (chat/ChatHeader.tsx line 89)

## Expected
All surfaces show "Krishna" within 1s.

## Actual
- ProfileMenu shows "Krishna" (because it uses `useAccount()` which TanStack-invalidates).
- Sidebar/InvitePartner/NotesView/ProfileIcon still show "Krish" until full reload.

## Root cause (likely)
`AuthContext` (src/contexts/AuthContext.tsx line 87-145) loads `profile` ONCE via `getDoc(doc(db,'users',uid))` inside `onAuthStateChanged`. There is NO `onSnapshot` listener on the user doc. Every other consumer reads `profile` from `useAuth()` (not `useAccount`), so the stale snapshot wins everywhere except ProfileMenu.

Settings save path:
- `AccountTab` calls `updateProfile` from `useAccount()`.
- `useAccount.profileMutation.onSuccess` calls `qc.invalidateQueries(['account','me'])`.
- BUT it never refreshes `AuthContext.profile` state.

## Impact
P0 — primary identity field. Mirrors Krish's canonical "I changed my name and it didn't update" example precisely.

## Fix direction (NOT for QA — for fix-state-data)
Attach an `onSnapshot(doc(db,'users',uid))` in `AuthContext` so `profile` is realtime — OR remove `profile` from `AuthContext` and have all consumers go through `useAccount()` only.

## Evidence
- src/contexts/AuthContext.tsx:87-145 (one-shot getDoc, no listener)
- src/hooks/useAccount.ts:86,91 (only invalidates TanStack cache, not AuthContext)
- src/components/chat/ChatSidebar.tsx:502, src/pages/Index.tsx:1349-1350, src/components/chat/ChatHeader.tsx:89 (consumers of stale AuthContext.profile)
