## Description

The home page's `<img>` tag scan shows the same `Wedding%20ease.png` rendered twice (`imgs=2` in poll). That likely means mobile + desktop versions of the hero logo are both mounted in the DOM with one hidden via CSS, similar to the duplicate attach button case (WE-20260527-008). For an image asset that's the same in both viewports, only one render is needed; the other is wasted bandwidth and an extra DOM node.

## Steps to reproduce

1. `http://localhost:8081/`.
2. Console: `[...document.querySelectorAll('img')].filter(i => /Wedding/.test(i.src)).length` → returns `2`.

## Expected

Single `<img>` with responsive size attributes.

## Actual

Two `<img>` elements; one hidden via Tailwind responsive utilities.

## Evidence

- `qa-img.mjs` polled image list shows `imgs=2` repeatedly.

## Notes

Fixes are pattern-consistent with WE-20260527-008 (attach button duplicate).
