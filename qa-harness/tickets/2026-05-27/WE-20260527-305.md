# WE-20260527-305 — Index.tsx has 43 useState + 20+ useEffects on `messages` → re-render cascade risk

**Severity:** P2
**Status:** triaged
**Assigned:** fix-performance
**Area:** Performance / React anti-patterns
**File:** `Wedding-Ease-Viva-Chat/src/pages/Index.tsx`
**Discovered:** 2026-05-27

## Symptom (static analysis — runtime profiler not yet captured)
`pages/Index.tsx` declares **43 `useState` calls** and **20+ `useEffect` hooks** in a single 1668-LOC component. Several effects fan out off `messages` / `threads`:

```
Line 310:  }, [messages, pendingScrollToId]);     // fires every streaming token
Line 332:  }, [searchQuery, user, threads]);
Line 847:  }, [user, messages]);                  // fires every streaming token
Line 856:  }, [user, messages]);                  // fires every streaming token
```

In `hooks/useChat.ts` line 535-537, the streaming loop updates `messages` on every `event.v` token:
```ts
streamedText += event.v
setMessages(prev => prev.map(m => m.id === aiMsgId ? { ...m, text: streamedText } : m))
```
Each `setMessages` triggers re-render of all 43 `useState` consumers in Index plus every effect with `messages` in its dep array.

There is **zero `React.memo`** on any of ChatMessages, ChatSidebar, ChatHeader, ChatInput (grep `React.memo|memo(` returns 0 hits in `components/chat/`).

## Why this is P2 not P1
TBT in Lighthouse was 0 ms — meaning total blocking time across the static page-load trace is fine. The risk is at runtime during streaming chat (which Lighthouse doesn't measure) and on lower-end mobile. INP wasn't measurable here because no interactions were simulated. Recommend re-running with field-data PostHog Web Vitals (already imported) or DevTools recorder before downgrading.

## Suggested fix (when fix-frontend picks this up)
1. Split `pages/Index.tsx` into route-shell + per-view containers. The 43 `useState` declarations are doing the job of feature-area reducers.
2. Wrap `ChatMessages`, `ChatSidebar`, `ChatHeader`, `ChatInput` in `React.memo` and pass stable callbacks (most callbacks are already declared inline without `useCallback`).
3. Move streaming text into `useReducer` or a dedicated store so token updates don't bubble to unrelated effects. The `useEffect(..., [user, messages])` at lines 847 + 856 should be split — the user-dep code shouldn't re-run on every token.
4. Hoist `MODE_CONFIG`, `SUPPORTED_LANGUAGES` (imported, fine) and any static JSX (welcome-card icons) out of the component body.

## Suggested verification
Open React DevTools Profiler, record a 5-message chat session, measure render count of `<Index>`. Target: < 100 renders per message. Without memo, this is likely > 500.
