## Description

Both `<input type="file" accept="image/*">` elements in `ChatMessages.tsx` (around lines 291 and 317) feed `FileReader.readAsDataURL(file)` without any `file.size` guard. The Vibe Composer uses `MAX_FILE_BYTES = 8MB` and Notes uses `MAX_PASTE_IMAGE_SIZE = 10MB`, so the cap is well-known in the codebase — but the chat-input attach path is missing it.

Effect on a 50MB image:
- ~70MB base64 string allocated synchronously in the main thread.
- Browser tab freezes for several seconds.
- POST body to /api/chat is ~70MB. Backend's `express.json({ limit: '20mb' })` rejects at 413, but the user has already paid the freeze cost AND data has been sent over the wire.
- Worse on mobile: triggers tab kill on iOS Safari.

## Steps to reproduce

1. Open chat. Click image-attach.
2. Pick a >20MB image.
3. Observe: tab freezes ~3-5s; eventually backend returns 413; user sees a network error toast.

## Expected

Match the existing pattern — define a chat-image MAX (e.g. 8MB) and reject before `readAsDataURL`:

```ts
if (file.size > MAX_CHAT_IMAGE_BYTES) {
  toast.error('Image too large — max 8MB.')
  return
}
```

## Actual

No size check. Tab freezes; large uploads sent over wire.
