## Description

Clicking the Settings button pushes `?settings=account` onto the URL. Closing the modal (Esc / outside-click) probably does not clean the query param (untested live but visible in the URL after `qa-settings.mjs`). The user's back button then takes them back into Settings instead of away from the page.

## Steps to reproduce

1. `http://localhost:8081/`, dismiss consent.
2. Click Settings.
3. URL becomes `/?settings=account`.
4. Press Escape to close the modal.
5. Inspect URL — does the query param go away? Press Back — does it open Settings again?

## Expected

`replaceState`-based open and a `replaceState` cleanup on close. Settings should not pollute history.

## Actual

Param persists; back button behaviour likely intercepts the user.

## Evidence

- URL captured in `qa-settings.mjs`: `SETTINGS_URL: http://localhost:8081/?settings=account`.

## Notes

Confirm via a live click-close-back test.
