## Steps to reproduce
1. Sign in.
2. Theme toggle → dark.
3. Open Settings → Appearance tab.

## Expected
Settings page shows "Dark" selected.

## Actual
- ThemeContext line 118 calls `patchAccountPreferences(merged)` directly bypassing `useAccount.updatePreferences` (which would invalidate).
- TanStack cache for `['account','me']` is NOT invalidated.
- If user opens Settings page within 30s staleTime, the visible select shows the old value (until manual reload or 30s passes + a refetch fires).

## Impact
P2 — only inconsistent with the Settings page's own visible state. Theme itself does apply correctly because that side-channels via local state.

## Fix direction
Replace `patchAccountPreferences(merged).catch(...)` with the `useAccount.updatePreferences(merged)` mutation — already invalidates correctly.

## Evidence
- src/contexts/ThemeContext.tsx:117-118, 129-130 (bypasses useAccount mutation; no invalidate)
- src/hooks/useAccount.ts:90-91 (proper path that invalidates)
