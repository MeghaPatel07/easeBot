# WE-20260527-303 — Render-blocking Google Fonts cost 1.16 s on every cold load

**Severity:** P2
**Status:** triaged
**Assigned:** fix-performance
**Area:** Performance / Critical render path
**File:** `Wedding-Ease-Viva-Chat/index.html` (head)
**Discovered:** 2026-05-27

## Symptom
Lighthouse render-blocking-resources audit on production build:

| Resource | Wasted ms |
|---|---|
| `fonts.googleapis.com/css2?family=Inter+Noto+Serif...` | **970 ms** |
| `fonts.googleapis.com/css2?family=Material+Symbols+Outlined...` | **191 ms** |
| local CSS bundle (`index-*.css`, 28.5 kB gzip) | 459 ms |

Two synchronous Google Fonts `<link rel="stylesheet">` tags block the parser before the React tree mounts. The Material Symbols variable-axis font is especially heavy.

## Suggested fix
1. Move Google Fonts to async load via the standard trick:
   ```html
   <link rel="preload" as="style" href="https://fonts.googleapis.com/css2?family=Inter:wght@300..700&display=swap"
         onload="this.onload=null;this.rel='stylesheet'">
   ```
   plus `<noscript>` fallback. The existing `&display=swap` is already in the URL so FOIT is avoided.
2. Drop the Material Symbols stylesheet from the head entirely — load it only inside the settings/icon-picker code path (it's only used by a handful of admin screens, not the chat itself). Use a separate `<link>` injected from inside the lazy-loaded settings chunk.
3. Add `<link rel="preload" as="font" type="font/woff2" crossorigin href="<inter-400 url>">` for the one font weight that's used above the fold.
4. Consider self-hosting Inter — eliminates the cross-origin connection (preconnect alone doesn't help when the stylesheet itself blocks).
