## Description

Sending a successful chat decrements the counter from 10 → 9. Sending an image-generation request that fails (see WE-20260527-002) keeps the message counter at 9, suggesting the counter decrements regardless of outcome. If the SSE stream errors out before the assistant's first token, the user still loses one of their 10 free messages — a poor UX for a feature that's already broken.

## Steps to reproduce

1. Open guest at `http://localhost:8081/`. Counter shows `10 messages remaining`.
2. Send `Generate an image of pastel mandap with white roses`.
3. Wait until error appears (~110 s).
4. Note counter is now `9` (image gen never actually delivered).

## Expected

Counter is only debited on successful response (or refunded on stream error). Confirm via the dev-console events that the debit is reverted when the SSE stream emits an `e` (error) frame.

## Actual

Counter is decremented at request-send time and never restored.

## Evidence

- `qa-flow.mjs` log shows successful messages decrementing 10→9→8→7.
- `qa-img.mjs` after image-gen error: body still shows "9 messages remaining" (one debit) for an effectively-zero-value response.

## Notes

This is also relevant for pricing rollout token-meter accuracy — same logic likely applies to tokens for failed image generations.
