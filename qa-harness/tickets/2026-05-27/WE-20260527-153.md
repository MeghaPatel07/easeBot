## Steps to reproduce
1. In Settings → AI Behavior, switch voice preset (e.g., "Aria" → "Roger").
2. Click Save.
3. Without reloading, request TTS playback on an assistant message in Chat.

## Expected
New voice plays.

## Actual
- AiBehaviorTab line 191 calls `savePersonalization(user.uid, { voiceId })` — writes Firestore directly via `updateDoc`.
- AuthContext does NOT subscribe to user doc with `onSnapshot`. So `profile.voiceId` stays old.
- useChat.ts line 506 reads `profile.voiceId` from AuthContext when building TTS request.
- Result: TTS uses old voice until full reload.

Note: `setLocalVoiceId` is also called (AiBehaviorTab line 189) to localStorage; that side-channel partially saves the user, but the canonical `profile.voiceId` in React state is stale. Anywhere reading from `profile.voiceId` (not localStorage) will be wrong.

## Impact
P1 — directly violates the "I changed it, why isn't it different?" UX bar.

## Fix direction
Same root fix as WE-20260527-150: AuthContext should listen to the user doc.

## Evidence
- src/services/settingsService.ts:5-11 (direct Firestore write)
- src/pages/settings/tabs/AiBehaviorTab.tsx:189-191
- src/hooks/useChat.ts:506 (consumer of stale value)
- src/contexts/AuthContext.tsx:87-145 (no listener)

## Note (2026-05-27)
Likely closed by WE-20260527-170 PR — verify after merge. `AuthContext.profile` is now subscribed via `onSnapshot`, so direct Firestore writes from `savePersonalization(user.uid, { voiceId })` will fan out to `profile.voiceId` immediately and `useChat.ts:506` will read the fresh value.
