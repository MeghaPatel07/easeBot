## Description

On desktop, the chat input has no microphone / voice-record affordance reachable via accessible queries. Aria enumeration on `/` returns no `aria-label` containing `mic`, `voice`, `record`, or `dictate`. On mobile (screenshot `WE-20260527-005`), a mic icon is visible in the input — so voice IS implemented but only renders on small viewports. Per PRD-TTS-Pipeline §1, voice input via the Speech SDK is a documented core feature; restricting it to mobile contradicts the spec.

## Steps to reproduce

1. Desktop `http://localhost:8081/`.
2. Inspect the chat composer. No mic icon to the right of the textarea.
3. Mobile (375 px) same page — mic IS visible.

## Expected

Voice/mic button visible on both desktop and mobile (and accessible: `aria-label="Start voice input"`).

## Actual

Desktop hides it entirely; only "Attach" buttons exist (and those are also hidden — WE-20260527-007).

## Evidence

- Aria enumeration in `qa-deep2.mjs`.
- Mobile screenshot `qa-harness/evidence/WE-20260527-005/screenshots/mobile-home.png` shows mic.

## Notes

The PRD describes user voice input as Microsoft Speech SDK / Azure Cognitive Services (STT). Desktop users currently can't use it.
