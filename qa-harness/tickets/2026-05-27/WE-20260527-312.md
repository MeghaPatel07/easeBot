# WE-20260527-312 — Cannot measure INP / runtime perf — no `INP` instrumentation in PostHog client

**Severity:** P3
**Status:** triaged
**Assigned:** fix-performance
**Area:** Performance observability
**File:** `Wedding-Ease-Viva-Chat/src/lib/analytics.ts`
**Discovered:** 2026-05-27

## Symptom
The frontend integrates PostHog (`posthog-js` is a dep, `src/lib/analytics.ts` wraps it) but there is **no Web Vitals reporting code path** — no `onINP`, `onLCP`, `onCLS` from `web-vitals` package; no `posthog.capture('$web_vitals')`.

Result: there is no field data on INP, LCP, CLS from real users. Lighthouse Lab data is single-shot and synthetic — Lab LCP was 9.9 s but we don't know what real users on real networks see.

## Suggested fix
1. Add `web-vitals` package: `npm i web-vitals`
2. In `src/main.tsx` after `createRoot`, register listeners:
   ```ts
   import { onLCP, onINP, onCLS, onFCP, onTTFB } from 'web-vitals';
   import { track } from '@/lib/analytics';
   [onLCP, onINP, onCLS, onFCP, onTTFB].forEach(fn => fn(m => track('web_vital', { name: m.name, value: m.value, id: m.id, rating: m.rating })));
   ```
3. Add `web_vital` to the `EventName` union in `analytics.ts`.
4. In PostHog: create a dashboard with p75 LCP/INP/CLS over time per route.

## Why this blocks runtime perf QA
Until INP is being captured, performance-QA tickets about chat-streaming UX, scroll jank, and interaction lag are based on static analysis only.
