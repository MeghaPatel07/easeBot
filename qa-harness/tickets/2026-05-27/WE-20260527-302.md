# WE-20260527-302 — NoteEditor (513 kB / 158 kB gzip) bundles TipTap eagerly into the main graph

**Severity:** P2
**Status:** triaged
**Assigned:** fix-performance
**Area:** Performance / Bundle splitting
**File:** `Wedding-Ease-Viva-Chat/src/components/notes/NotesView.tsx:29`
**Discovered:** 2026-05-27

## Symptom
`dist/assets/NoteEditor-D1BRRvzy.js` is 513.09 kB raw (157.90 kB gzipped). Lighthouse flags **141 kB of unused JS** inside it on a route where notes aren't open.

## Root cause
`src/components/notes/NotesView.tsx` line 29 statically imports `NoteEditor`:
```ts
import NoteEditor from '@/components/notes/NoteEditor';
```
NoteEditor in turn loads ~15 TipTap extensions (table, task-list, color, highlight, image, link, character-count, etc — see `package.json` dependencies). TipTap is one of the heaviest deps in this app.

NotesView is one of the sidebar tabs — used only when the user clicks "Notes" — but because Index.tsx statically imports NotesView and NotesView statically imports NoteEditor, this all lands in the boot graph regardless.

It IS in its own chunk (513 kB) only because the Vite analyzer sees it referenced from a route file; if WE-20260527-301 lands and Index becomes lazy, the question is whether this should be lazy from inside NotesView too.

## Suggested fix
Wrap the editor render inside NotesView with React.lazy + Suspense so opening the Notes tab without an active note doesn't download TipTap:

```ts
const NoteEditor = lazy(() => import('@/components/notes/NoteEditor'));
// ...
<Suspense fallback={<EditorSkeleton />}>
  {activeNoteId && <NoteEditor ... />}
</Suspense>
```

Also confirm `@tiptap/pm/state` and other peer plugins aren't being double-bundled.
