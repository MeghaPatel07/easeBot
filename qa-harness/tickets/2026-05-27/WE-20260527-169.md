## Steps to reproduce
1. Go offline (or simulate network failure).
2. Toggle theme.
3. Go back online.
4. Reload page.

## Expected
Theme applies locally + server. Or graceful failure with retry.

## Actual
- ThemeContext line 118 / 130 swallows error: `patchAccountPreferences(merged).catch(() => { /* noop */ })`.
- Server NEVER persists; localStorage holds the new value; reload from another browser shows old value because backend wasn't updated.
- No retry. No reconciliation.

## Impact
P3 — minor; only manifests on network failure during pref save.

## Fix direction
Replace `.catch(noop)` with a toast or background retry; or wire through `useAccount.updatePreferences` which propagates the error.

## Evidence
- src/contexts/ThemeContext.tsx:118,130 (silent noop)

NOT closed by WE-20260527-170. The umbrella state-sync fix addresses AuthContext.profile staleness, but this ticket is orthogonal — the bug is the `.catch(() => {})` in ThemeContext silently swallowing backend errors. Needs its own toast / retry / reconciliation fix.
