# WE-20260527-306 — Chat images (gallery + inline) have no `loading="lazy"` / no width-height

**Severity:** P3
**Status:** triaged
**Assigned:** fix-performance
**Area:** Performance / Image strategy
**File:** `Wedding-Ease-Viva-Chat/src/components/chat/ChatMessages.tsx`, `GalleryView.tsx`
**Discovered:** 2026-05-27

## Symptom
- `ChatMessages.tsx` has 7+ `<img>` tags rendered per message (avatar, attached image, generated images, product thumbnails) — zero `loading="lazy"` attribute (grep returns 0 hits).
- `GalleryView.tsx` has only 1 `loading=` attribute across the entire file despite being designed to render dozens of images.
- No `width`/`height` attributes on the inline images — CLS hazard once images are remote.

## Why this matters
- Gallery flows render 30-50 generated images. Without `loading="lazy"`, the browser fetches them all on mount, even those below the fold — wasting bandwidth and decode time.
- On a 50-message chat history (cold start), every message's images decode immediately, blocking the main thread.
- Lighthouse on `/test-user/gallery` showed LCP 8.5s, partly attributable to eager-loading every gallery image.

## Suggested fix
1. Add `loading="lazy"` and `decoding="async"` to every gallery + inline chat image. The avatar on the assistant bubble should stay eager.
2. Add `width` and `height` attributes (or aspect-ratio CSS) to every image to lock layout.
3. For gallery cards, consider a `<picture>` with AVIF + WebP sources if the storage backend can serve them.
