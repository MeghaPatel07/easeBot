## Steps to reproduce
1. Settings → Personalization → edit "About me" textarea + Response Style. Save.
2. Without reloading, send a chat message.

## Expected
Backend receives new "about" + responseStyle as system prompt context.

## Actual
- PersonalizationTab line 136 calls `useAccount.updateProfile(...)` → invalidates `['account','me']` (useAccount.ts:86).
- However, useChat (and most consumers downstream of `useAuth`) read `profile.about`, `profile.responseStyle` from AuthContext — NOT from useAccount.
- Send pipeline serializes the stale `profile.about` to the backend; new instructions ignored until refresh.

## Impact
P1 — the entire personalization feature appears broken from the user's perspective.

## Fix direction
Either:
(a) AuthContext.onSnapshot;
(b) Refactor useChat/send pipeline to read profile from useAccount() (the source of truth that does get invalidated).

## Evidence
- src/pages/settings/tabs/PersonalizationTab.tsx:101,136,183
- src/hooks/useAccount.ts:86 (invalidates only useAccount cache)
- src/contexts/AuthContext.tsx (no listener)

## Note (2026-05-27)
Likely closed by WE-20260527-170 PR — verify after merge. `useAccount.updateProfile` writes to Firestore (via backend) → the new AuthContext snapshot listener fans `profile.about` / `profile.responseStyle` out to `useChat`. Send pipeline serializes fresh values.
