## Description

The current behaviour matches the "Current State" described in PRD-BugsFixes section 1.5: a user whose email isn't on the collaborator list (or who hits a bad share id while signed out) sees only:
> Note not found
> This note doesn't exist or the link may be invalid.

PRD calls for a "Request Access" page instead, distinguishing "not found" from "you don't have access."

Filing as a tracker for this functional gap, not a duplicate — PRD-BugsFixes describes the future fix, but the live behaviour I observed is worth recording as a separate QA item for the harness sheet so triage can correlate.

## Steps to reproduce

1. `http://localhost:8081/shared/note/nonexistent`.

## Expected

When the user is signed in but lacks access, show "Request Access" UI with current user email shown and a Request button (PRD 1.5).

## Actual

Generic "Note not found" string.
