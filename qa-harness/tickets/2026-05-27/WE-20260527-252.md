## Description

Every `<label>` in SignIn/SignUp modals is rendered as a styled `<label class="text-xs text-foreground/50 ml-1">…</label>` followed by an `<Input>` with NO `htmlFor`/`id` linkage. Screen readers therefore do not announce the field's label when the input receives focus. Examples: Email (594), Password (873), Phone (974), Verification Code (996), New password (694), Confirm password (758).

## Steps to reproduce

1. Open the SignIn modal
2. Tab from one input to the next with VoiceOver running

## Expected

VoiceOver announces each input as e.g. "Email, edit text" / "Password, secure edit text".

## Actual

VoiceOver announces "edit text" with no field name — user cannot tell which field they are filling.

## Notes

Fix: add stable `id` to each `<Input>` and matching `htmlFor` to the `<label>`. This propagates to:
- `SettingsModal.tsx:204` (Nickname label)
- Any other form using the same pattern.
