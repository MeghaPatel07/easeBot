## Description

The chat is the central interaction of the product. Assistant messages stream in via `TypewriterMarkdown` but the message container has NO `aria-live`, no `role="log"`, no `role="region"`. Screen-reader users hear nothing when the model replies — they have no signal that a response has arrived or completed. They must manually navigate back to find new content.

`ChatInput` only sets `aria-live="polite"` on the recording timer (line 322). Nothing announces the actual conversational reply.

## Steps to reproduce

1. Start VoiceOver
2. Send a message via the chat
3. Wait for assistant response

## Expected

The assistant's reply is announced (or at minimum, a polite live-region update such as "Assistant: ..." or a status indicator that a new message arrived). The message-list container should be a live region (`role="log" aria-live="polite" aria-relevant="additions"`).

## Actual

VoiceOver remains silent. The user has no way to know a reply arrived without re-navigating the document.

## Notes

This is the single biggest blocker for SR users on the platform. Suggested fix: wrap the assistant-message rendering with `<div role="log" aria-live="polite" aria-atomic="false">`. Avoid `assertive` — would interrupt mid-sentence. Suppress `aria-live` during streaming (announce only final settled text) to avoid character-by-character spam from the typewriter effect.
