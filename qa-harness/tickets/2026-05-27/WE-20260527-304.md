# WE-20260527-304 — Hero logo PNG is 303 kB at 1520×735 — should be ~30 kB AVIF

**Severity:** P2
**Status:** triaged
**Assigned:** fix-performance
**Area:** Performance / Asset optimization
**File:** `Wedding-Ease-Viva-Chat/src/assets/images/logo.png` → bundled as `dist/assets/logo-j_ScG-E3.png`
**Discovered:** 2026-05-27

## Symptom
- File: PNG, 1520 × 735, 8-bit/RGBA, non-interlaced — **302,917 bytes**.
- Used at `src/pages/Index.tsx:1529` for the empty-state hero (`className="h-20 sm:h-30"` — rendered at ~120 px tall = max ~250 px wide).
- Lighthouse network audit ranks this as the **3rd-largest payload (303 kB) on every cold load**, behind only the two JS bundles.
- A second logo (`easebot-D6BiD7YY.png`, 224 kB) and the `images/typo.png` favicon (63 kB!) are similarly oversized.

## Why this matters
- LCP candidate on `/` empty state — if it loses to a JS-rendered text node, it's still ~300 kB on the critical path.
- Decoding 1520-wide PNG on mid-tier mobile costs 50-150 ms of main-thread time.

## Suggested fix
1. Re-export logo as AVIF (or WebP fallback) at the actual rendered max width — `360×174` covers retina. Use `<picture>`:
   ```tsx
   <picture>
     <source srcSet="/logo.avif" type="image/avif" />
     <source srcSet="/logo.webp" type="image/webp" />
     <img src="/logo.png" width={360} height={174} alt="TheWeddingBot" ... />
   </picture>
   ```
2. Always include explicit `width` and `height` to prevent CLS.
3. Move icon `typo.png` (63 kB!) to a `<32 kB` AVIF or — better — an inline SVG.
4. `easebot-D6BiD7YY.png` (the avatar in ChatMessages) is loaded per AI message — should be a 64×64 WebP, ~3 kB.

Expected savings: ~500 kB off the first paint + faster LCP by ~1.5 s on Slow 4G.
