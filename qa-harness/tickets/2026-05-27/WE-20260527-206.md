## Description

The partner-name `<Input>` lacks `maxLength`. Pasting a 10MB string accepts the value, renders the input as a giant scroller, and on Save sends the full string to the backend PATCH /api/account/profile. Custom-instructions textareas elsewhere in the same file correctly use `maxLength={CUSTOM_INSTRUCTIONS_MAX}` (lines 398, 422) so the missing limit on partnerName is a regression / inconsistency.

## Steps to reproduce

1. Open Settings → Personalization.
2. Paste a 50,000-character string into Partner name.
3. Field accepts it. Save attempts to submit.

## Expected

Cap partnerName client-side at e.g. 80 chars with `maxLength={80}`. Same for any "nickname" / first-name fields. Display a small character counter.

## Actual

No client-side cap. Backend may also lack one (unverified due to strict auth on PATCH endpoint).

- `qa-harness/evidence/WE-20260527-206/personalization-tab.snippet`

## Notes

Audit all `<Input>` usages in the settings tab tree for missing maxLength.
