## Symptom
Lighthouse mobile audit (simulated throttling) on production build (`npm run build` + `vite preview`):

| Page | LCP | FCP | TBT | CLS | TTI | Perf score |
|---|---|---|---|---|---|---|
| `/` | **9.9s** | 6.6s | 0ms | 0 | 9.9s | 0.59 |
| `/test-user/gallery` | **8.5s** | 6.6s | 0ms | 0 | 8.5s | 0.60 |
| `/test-user/budget` | **10.0s** | 6.6s | 0ms | 0 | 10.1s | 0.59 |
| `/chat/seed-thread-50msgs` | **10.2s** | 6.6s | 0ms | 0 | — | 0.59 |

Targets (per QA brief): LCP < 2.5s good, > 4s ticket. **Every primary route is > 8s — 2x the ticket threshold.**

TBT/CLS are fine — the issue is purely load weight + render-blocking head.

## Cause (drilled in via Lighthouse JSON)
1. Static `import` of the Index orchestrator pulls 1.32MB of JS into a single chunk before first paint (`dist/assets/Index-BI9zObHt.js`, 355KB gzipped).
2. Render-blocking head: two Google Fonts stylesheets (Inter + Material Symbols variable) cost ~1.16s combined wasted ms; local CSS bundle (28.5KB gzipped) adds 459ms.
3. `logo-j_ScG-E3.png` is 303KB raw PNG (1520×735) — used as hero on `/` chat empty state. Should be ~30KB WebP/AVIF.

## Suggested fixes (for fix-performance / fix-frontend)
1. Split `pages/Index.tsx` (1668 LOC, 1.32MB chunk) — see WE-20260527-301.
2. Convert hero logo PNG to AVIF or WebP + add `width`/`height` + responsive `srcset`.
3. Defer Material Symbols font; load only when settings opens.
4. Use `<link rel="preload" as="font" crossorigin>` for the Inter subset.
