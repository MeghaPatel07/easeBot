## Description

`curl -I http://localhost:8081/` returns no `Content-Security-Policy`, `X-Frame-Options`, `X-Content-Type-Options`, `Referrer-Policy`, or `Strict-Transport-Security` headers. The backend has Helmet configured (CSP intentionally off so SSE works), but the frontend dev server is bare. If `firebase.json` hosting config also lacks these headers, production inherits the same gap.

This compounds risk if any rendering bug were ever introduced (XSS, clickjacking via iframe embed).

## Steps to reproduce

1. `curl -I http://localhost:8081/`
2. Observe only `Content-Type`, `Cache-Control`, `Etag`. No security headers.

## Expected

Production hosting should set CSP (with the SSE-friendly directives the backend already documents), X-Frame-Options: DENY (or frame-ancestors via CSP), X-Content-Type-Options: nosniff, Referrer-Policy: strict-origin-when-cross-origin.

## Actual

```
HTTP/1.1 200 OK
Access-Control-Allow-Origin: *
Content-Type: text/html
Cache-Control: no-cache
```
