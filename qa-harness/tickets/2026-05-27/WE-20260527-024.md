## Description

Routes only support the abbreviated paths:
- `/privacy` (works) → 200 Privacy Policy renders
- `/terms` (works) → 200 Terms renders
- `/privacy-policy` (404) → NotFound
- `/terms-of-service` (404) → NotFound
- `/images` (404) → NotFound (canonical needs userId: `/:userId/images`)
- `/settings` (404) → NotFound (settings are query-string driven: `/?settings=account`)
- `/checkout` (200 but silently routes to `/pricing` — see WE-20260527-003)

External and search-engine traffic typically uses the long forms (especially `/privacy-policy` and `/terms-of-service`). SEO and shareability suffer.

## Steps to reproduce

1. Visit each URL in a fresh tab and observe outcome (or run `qa-pages.mjs`).

## Expected

Common aliases redirect (HTTP 301/302 or client-side `<Navigate>`) to their canonical route. `/settings` either renders a wrapper that opens the settings modal, or redirects to `/?settings=account`. `/images` redirects to `/:userId/images` if signed in or `/login?returnTo=/images` if not.

## Actual

All those URLs hit the catch-all `<Route path="*" element={<NotFound />} />` and dead-end.

## Evidence

- `qa-pages.mjs` route probe output.

## Notes

Add `<Route path="/privacy-policy" element={<Navigate replace to="/privacy" />} />` and equivalents. Trivial fix, high SEO/UX value.
