## Description

The inputSanitizer trims whitespace BEFORE the Zod validator runs. So a user who pastes `"   "` (three spaces) gets a 400 "String must contain at least 1 character(s)" error. The error is technically true post-trim but misleading from the user's POV — they typed three characters and got told they typed none. Frontend should disable the Send button when the message is whitespace-only.

## Steps to reproduce

1. Type `   ` (three spaces) into the chat input.
2. Click Send.

## Expected

Send button disabled while message trims to empty. No network call made.

## Actual

Network call made; 400 returned; error toast (likely) confusing.

## Evidence

- `qa-harness/evidence/WE-20260527-207/curl.log`

## Notes

Frontend `ChatInput.tsx` should apply `disabled={message.trim().length === 0}` (verify it doesn't already — confirmed via empty + whitespace returning identical 400 from backend, suggesting client-side gate is missing).
