## Steps to reproduce
1. Open dashboard.
2. Backend admin tool / Firestore console — bump user's plan tier (free → pro).
3. Wait. Watch ProfileMenu's plan pill.

## Expected
Pill flips within seconds.

## Actual
- `useAccount.staleTime: 30_000` — TanStack will not refetch for up to 30 seconds even if a window-focus event happens within stale window.
- If user is staring at the same window, the next refetch happens on:
  - Window focus blur/refocus, OR
  - 30+ seconds pass and a consumer reads the query, OR
  - Some mutation triggers invalidate.

## Impact
P2 — only manifests when backend changes data without a frontend-initiated mutation (e.g., subscription renewal cron, manual admin edit, expired trial flip).

## Fix direction
Either reduce staleTime to ~0 and rely on `refetchInterval`, or add an `onSnapshot` on the user doc that calls `qc.invalidateQueries(['account','me'])` when Firestore changes.

## Evidence
- src/hooks/useAccount.ts:81 (staleTime: 30_000)

## Note (2026-05-27)
Partially addressed by WE-20260527-170 PR. The new AuthContext snapshot fans out plan-tier changes immediately to every `useAuth()` consumer. The 30s `useAccount` staleTime still affects components that ONLY read from `useAccount` (mostly ProfileMenu's plan pill). Optional follow-up: have the AuthContext snapshot also call `qc.invalidateQueries(['account','me'])` on each change. Verify after merge whether the residual ProfileMenu lag is acceptable.
