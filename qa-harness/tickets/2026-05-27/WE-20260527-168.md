## Steps to reproduce
1. Open Thread A.
2. Open the same chat in Tab B (or sidebar > 3-dot > delete in same tab).
3. Delete thread A in Tab A.
4. Tab B (or current view) — Firestore listener removes the thread from sidebar.

## Expected
Active thread header / chat area clears or redirects.

## Actual
- `subscribeToThreads` (chatService.ts:108) DOES use onSnapshot — good.
- useChat.deleteThread (line 1023) calls `deleteThreadDoc` then needs to clear `activeThreadId` if it matches. Quick read of Index.tsx line 596 suggests deletion happens but no explicit guard that activeThreadId is reset.
- Subscriber removes the thread from `threads`, but if `activeThreadId` still points to it, the message subscription continues against a deleted thread, surfaces fail silently, header keeps the title.

Verification needed during live QA.

## Impact
P2 — quality issue, not data corruption.

## Fix direction
In useChat.deleteThread, if `threadId === activeThreadIdRef.current`, also `setActiveThreadId(null)` + clear messages.

## Evidence
- src/hooks/useChat.ts:1023-1024
- src/services/chatService.ts:71 (delete writes)
