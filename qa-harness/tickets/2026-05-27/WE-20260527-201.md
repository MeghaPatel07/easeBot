## Description

`requireAuth` catches `verifyIdToken` failures and returns 401 with `{ error, detail: err.message }`. The `detail` field is the raw Firebase Admin SDK exception, which advertises the SDK family, the firebase.google.com docs URL, and a verbose hint string. This lets an attacker confirm Firebase Auth is in use and shapes brute-force attacks against the auth endpoints.

The errorHandler middleware is bypassed because the route returns directly.

## Steps to reproduce

1. `curl -s -X POST http://localhost:3001/api/chat -H "Authorization: Bearer fake-token-xxx" -H "Content-Type: application/json" -d '{"message":"hi"}'`

## Expected

`401 { "error": "Invalid or expired token" }` only. No `detail` field; no SDK strings; no third-party docs URLs.

## Actual

```json
{"error":"Invalid or expired token","detail":"Decoding Firebase ID token failed. Make sure you passed the entire string JWT which represents an ID token. See https://firebase.google.com/docs/auth/admin/verify-id-tokens for details on how to retrieve an ID token."}
```

## Evidence

- `qa-harness/evidence/WE-20260527-201/curl.log`

## Notes

Drop the `detail` field, OR gate it behind `process.env.NODE_ENV !== 'production'`.
