## Steps to reproduce
1. ChatHeader → click globe → switch language EN → HI.
2. Without reload, click mic / use voice input.

## Expected
STT uses new language.

## Actual
- `updatePreferredLanguage` (authService:44 import) writes Firestore via the legacy authService path.
- AuthContext does not subscribe — `profile.preferredLanguage` stays stale.
- STT call site (anywhere reading `profile.preferredLanguage`) sends old language code.

Note: chat header itself uses a local prop `preferredLang` so the UI label updates instantly. The bug is one layer down — the *backend* call site that reads from AuthContext.

## Impact
P2 — slightly less visible than name (UI shows correct label) but voice transcription quality silently degrades.

## Fix direction
Same root cause; AuthContext onSnapshot.

## Evidence
- src/services/authService.ts (updatePreferredLanguage path)
- src/contexts/AuthContext.tsx (no listener)

## Note (2026-05-27)
Likely closed by WE-20260527-170 PR — verify after merge. `profile.preferredLanguage` is now reactive in AuthContext, so the STT call site reads the freshly-written language code without F5.
