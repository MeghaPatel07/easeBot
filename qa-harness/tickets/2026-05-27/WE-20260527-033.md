## Description

Toggling dark mode via the header button flips `<html class="dark">`. The toggle works at the document-class level (verified). However, per `sysytemprompt.md` (theme refactor spec), every UI element should use tokens with no hardcoded colors. Live: the chat input's placeholder, border, and the action-card glass effect look correct in light but the contrast in dark mode appears washed out (the `glass-action-card` shadow + alpha-mixed text are hard to read).

A full dark-mode visual sweep is needed — this ticket flags it as a category, not a single bug.

## Steps to reproduce

1. `http://localhost:8081/`, dismiss consent.
2. Click "Switch to dark mode" in the header (top-right).
3. Compare textarea border, send button, action cards, message bubbles, occasion chips.

## Expected

Per sysytemprompt.md success criteria: "Theme toggle works instantly with no flicker. Zero hardcoded colors. Complete token coverage. No visual inconsistencies."

## Actual

Dark mode is wired; visual polish has gaps (light-only tokens leaking into dark mode is a regression risk).
