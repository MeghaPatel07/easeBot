## Description

Guest banner shows: `Guest Mode — 10 messages remaining · 3 images remaining`. The pricing page (`/pricing`) describes Free as "300K tokens / month (50K daily) … Voice, vision & image generation" — i.e. a token-based limit, NOT a hard cap of 3 images. Backend `quotaMiddleware.ts` debits images as `vision` (2,000 tokens each) and never enforces a count of 3. The "3 images remaining" copy is misleading at minimum and may not be a real, enforced limit.

## Steps to reproduce

1. `http://localhost:8081/` guest.
2. Read the guest banner: shows "3 images remaining".
3. Visit `/pricing` → Free row has no "3 images" line.

## Expected

UI copy that reflects what is actually enforced. Either honour a hard 3-image guest cap (visible in code + tests) or show a token estimate instead.

## Actual

Frontend hardcodes "3 images remaining" with no clear source-of-truth in the backend quota config (`tokenMeter.ts`, `quotaMiddleware.ts`).

## Evidence

- Body text grep: "3 images remaining" in all guest-mode body dumps (`qa-explore.mjs`, `qa-chat2.mjs`, etc.).
- `/pricing` body in `qa-pages.mjs` shows no per-image limit for Free.

## Notes

Consistency issue. Cross-team: pricing rollout owners should reconcile.
