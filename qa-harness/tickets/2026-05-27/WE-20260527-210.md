## Description

POSTing `{"text":"<script>alert(1)</script>","voice":"default"}` returns a 200 WAV. The endpoint accepts arbitrary text including HTML/script tags and forwards to Azure Speech without stripping tags or applying any allowlist. Two issues:

1. **Quota burn**: an attacker can submit megabyte-long SSML or HTML to consume Azure Speech minutes (paid resource).
2. **SSML injection** (if Azure Speech parses SSML): an attacker can embed `<voice>`, `<break>`, `<lexicon>` tags to alter voice, fetch external lexicon files, or chain operations the application didn't intend.

Combined with guest pass-through (ticket 204) this is a free TTS API for anyone.

## Steps to reproduce

1. `curl -X POST http://localhost:3001/api/tts -H "Content-Type: application/json" -d '{"text":"<script>alert(1)</script><speak><voice name=\"en-US-AriaNeural\">test</voice></speak>","voice":"default"}'`

## Expected

Strip all HTML tags client- and server-side. Reject inputs that contain `<` after stripping. Reject SSML root tags unless the request explicitly opts into SSML mode. Cap text length to ~2000 chars.

## Actual

WAV returned (200) — server accepted and synthesized.

## Notes

Likely fix: a `sanitizeText(text)` helper in the TTS controller plus a max-length zod schema.
