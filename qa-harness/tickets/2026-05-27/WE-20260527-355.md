## Description
The `toneSettings` body field accepts a `concise` value 0–100, intended to steer response length. Comparing two requests with identical message but concise=0 vs concise=100 yields almost identical output length: 795 chars vs 851 chars (concise=100 actually being slightly LONGER). The slider has no functional effect on output verbosity.

## Steps to reproduce
1. `curl -X POST http://localhost:3001/api/chat -d '{"message":"What are the key things to plan for a 6-month-out wedding?","toneSettings":{"concise":0}}'` → response ~795 chars.
2. Same with `"concise":100` → response ~851 chars.

## Expected
concise=100 → noticeably shorter output (target: ≤ 30% of concise=0 length, or hard-cap to 2-3 short sentences).

## Actual
concise=100 produces essentially the same response as concise=0; structure (numbered list, subsections) unchanged.

## Notes
Either the personalization suffix being injected by `buildPersonalizationSuffix` is too gentle ("be a bit more concise…") or it's not being injected at all when only one slider is set. Verify (a) the suffix is non-empty when concise=100 is the only value, (b) the suffix is positioned where the LLM actually weights it, and (c) consider a hard max_tokens cap that scales with the slider (e.g. concise=100 → max_tokens=150).
