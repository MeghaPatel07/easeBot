## Description

Inspecting all `<button aria-label="Attach">` elements on the desktop home page finds two buttons but Playwright reports both with `isVisible() === false`. The vision input flow (PRD-TTS-Pipeline / chatupdates.md / image upload + tasting prompts) cannot be triggered without an attach affordance.

## Steps to reproduce

1. Desktop viewport (≥1024px) → `http://localhost:8081/`.
2. Dismiss consent.
3. Inspect `button[aria-label="Attach"]` — `getComputedStyle(btn).display` is `none` or `visibility:hidden`.

## Expected

Attach button visible to all users on desktop (free guests can still upload one image per the documented vision flow; quota enforced server-side).

## Actual

The button is in the DOM (×2 instances — themselves a bug, see WE-20260527-008) but neither is rendered to the user. Effectively the only way to upload an image is mobile.

## Evidence

- Playwright probe in `qa-flow.mjs` printed `Attach btn visible: false`.
- Aria-label enumeration in `qa-deep2.mjs` lists "Attach" twice in `aria-label`-only enumeration but the buttons themselves aren't clickable.

## Notes

Possibly the file-input `<input ref={fileInputRef} type="file" … className="hidden" />` is being counted (it is at `Index.tsx:1592`) but the trigger button is also being hidden via responsive utility classes. Audit `ChatInput.tsx` for `hidden sm:flex` mistakes.
