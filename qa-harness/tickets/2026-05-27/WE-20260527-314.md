# WE-20260527-314 — `chatService.ts` chunk is 161 kB / 49 kB gzip — Firestore SDK eagerly bundled into chat path

**Severity:** P2
**Status:** triaged
**Assigned:** fix-performance
**Area:** Performance / Bundle splitting
**File:** `Wedding-Ease-Viva-Chat/src/services/chatService.ts`
**Discovered:** 2026-05-27

## Symptom
`dist/assets/chatService-2FdnCHng.js` ships at 161.73 kB raw / **49.13 kB gzip**. Lighthouse flags ~40 kB of it as unused on the gallery route (where chat isn't open).

This file imports Firestore SDK methods directly:
```ts
addDoc, collection, doc, updateDoc, getDocs, deleteDoc, Promise.allSettled(...)
```

Even though chat is the primary surface, several routes (gallery, budget, timeline) don't actively need the chatService module until the user types — yet it's loaded on cold start.

## Suggested fix
1. Confirm chatService is only used inside the `useChat` hook chain. If so, lazy-load `useChat` via dynamic import behind a feature flag on cold start of non-chat pages.
2. Bigger win: switch the Firestore SDK to the **modular tree-shakeable** API. Verify each import like `import { addDoc, collection } from 'firebase/firestore'` is from the modular path (not `firebase/firestore/lite` or full SDK).
3. Consider Firestore's `lite` SDK for read-only routes — saves ~100 kB but loses realtime.
