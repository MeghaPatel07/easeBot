## Description

`requireAuth` calls `next()` without setting `req.user` when no Authorization header is present. The chat router uses this middleware so guest POST `/api/chat` succeeds (HTTP 200, full Azure OpenAI completion returned) with NO bearer token at all. Combined with the public-CORS config (`origin: '*'`), any web origin or `curl` can spend Azure quota for free and harvest model output.

The chat-burst limiter is keyed by a fingerprint (UA + accept-language + IP) which an attacker trivially rotates.

## Steps to reproduce

1. `curl -s -X POST http://localhost:3001/api/chat -H "Content-Type: application/json" -d '{"message":"hi"}'` (no Authorization header)
2. Observe HTTP 200 + full LLM response.

## Expected

Either (a) reject anonymous requests with 401, OR (b) impose a hard per-fingerprint daily cap and short-circuit to a canned response if the user is unverified.

## Actual

Guest gets full Azure-quality completions, only constrained by 10/10s burst limiter.

## Notes

The auth.ts comment explicitly says this is "preserved behavior" for notes/chat. If guest mode is intentional, tier it: guest users → cached / heavily-rate-limited / smaller model. Otherwise tighten to require auth.
