## Description

The SSE route comment claims `Last-Event-ID support (log for future replay)` and the route accepts the header. But the handler does nothing with it beyond a console.log:

```ts
if (lastEventId) {
  console.log(`[chat:sse] Client reconnecting with Last-Event-ID: ${lastEventId}`)
}
```

A client that disconnects and reconnects with `Last-Event-ID: 42` does NOT receive a replay from event 43+; instead a fresh stream starts from id 1. The numeric "id" injected by the route wrapper at line 49 is per-stream, not globally unique — so a Last-Event-ID across streams is meaningless anyway.

This is non-functional reconnection support presented as functional. If a downstream load balancer or proxy reconnects an EventSource, the client will receive the whole conversation a second time.

## Steps to reproduce

```bash
curl -N -X POST http://localhost:3001/api/chat/stream -H "Last-Event-ID: 999" -d '{"message":"hi"}'
# → fresh stream from id: 1, no acknowledgment of LEI
```

## Expected

Either:
- Implement actual replay: cache the last N events per requestId, and on Last-Event-ID, replay events with id > LEI.
- OR remove the misleading code comment + log to avoid implying functionality that isn't there.

## Actual

Logged-only; misleading.
