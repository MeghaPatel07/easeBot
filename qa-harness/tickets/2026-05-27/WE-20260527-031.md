## Description

Per PRD: shared chats have a 7-day expiry. Visiting `/share/nonexistent` shows:
> This shared conversation has expired or does not exist.

The OR makes the message useless. A 404-from-Firestore is conflated with "expired", which has very different remediation: "expired" → ask the original sharer for a fresh link; "missing" → check the URL. Also no display of when it expired if expiry IS the reason.

## Steps to reproduce

1. `http://localhost:8081/share/abcd12345` (any random string).

## Expected

Distinguish errors via the API response:
- 404 → "This link is invalid. Check the URL or ask the sender for a new link."
- 410/expired → "This shared chat expired on Apr 1, 2026. Ask the sender for a refresh."

## Actual

Single ambiguous string.
