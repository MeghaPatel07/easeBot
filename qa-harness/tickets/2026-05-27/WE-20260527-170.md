## Root architectural issue (umbrella ticket for WE-20260527-150..169)

The codebase has TWO independent caches of the user profile:
1. `useAuth().profile` — `AuthContext` state, written by one-shot `getDoc` at sign-in. Never refreshed. Read by ChatSidebar, NotesView, InvitePartner, ChatHeader.ProfileIcon, useChat.
2. `useAccount().profile` — TanStack Query `['account','me']`, 30s staleTime, invalidates on settings mutations. Read by ProfileMenu, Settings tabs.

Every mutation only refreshes ONE of these. The other stays stale until a full reload.

## Pattern signature
- "It updates in some places but not others without reload."
- This is exactly Krish's canonical complaint.

## Fix direction (architecture-level)
Pick ONE source of truth. Recommended:
1. Add `onSnapshot(doc(db,'users',uid))` in `AuthContext` so AuthContext.profile is realtime (and matches useAccount values since both observe the same Firestore doc).
2. Have `useAccount` read its `profile` from AuthContext (or from the snapshot) rather than its own getAccountMe round-trip.
3. Single mutation path: `useAccount.updateProfile` → backend write → Firestore push → both caches see it immediately.

## Impact
P0 — meta-ticket. Closing this likely closes WE-20260527-150, 153, 154, 158, 159, 160, 161, 166, 169 simultaneously.
