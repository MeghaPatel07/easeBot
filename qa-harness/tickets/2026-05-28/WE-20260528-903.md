## Description

The spec implies share links have a 7-day TTL. Reality:

```ts
// src/services/notesService.ts:394
export async function enablePublicLink(noteId: string, permission: string): Promise<string> {
  const shareId = crypto.randomUUID()
  await updateDoc(noteRef(noteId), {
    publicAccess: { enabled: true, permission, shareId },
    publicShareId: shareId,
    updatedAt: serverTimestamp(),
  })
  return shareId
}
```

No `expiresAt`, no `ttl`, no scheduled cleanup. The shareId is written to the live note document, so any subsequent edit to the original note is immediately visible to anyone with the share URL. There is no snapshot.

```ts
// src/services/notesService.ts:412
export async function getNoteByShareId(shareId: string): Promise<any> {
  const q = query(notesCol(), where('publicShareId', '==', shareId))
  const snap = await getDocs(q)
  if (snap.empty) throw new Error('Shared note not found')
  return snap.docs[0].data()    // ← raw live doc, no TTL check, no field stripping
}
```

Two problems:

1. **No TTL.** A shareId enabled in 2024 still resolves in 2026 unless the owner explicitly hits `DELETE /api/notes/:noteId/public-link`. Public exposure window is unbounded.
2. **Live-document leak.** Edits to the original note (including comments, collaborators array, internal annotations) are reflected in the public share. The expectation per spec is "updating original thread doesn't update share" — currently the opposite.

## Steps to reproduce

```bash
# Need valid auth + an existing noteId for this to be reproducible end-to-end,
# but the source code is determinative:
grep -n "expir\|ttl\|7\s*\*" easebot-backend/src/services/notesService.ts
# → no matches
```

Manually:
1. POST `/api/notes/:noteId/public-link` → record `shareId`.
2. GET `/api/notes/shared/:shareId` → returns full note.
3. PATCH the original `/api/notes/:noteId` (e.g. change content).
4. GET `/api/notes/shared/:shareId` again → updated content immediately visible.

## Expected

- `enablePublicLink` should write `publicAccess.expiresAt = now + 7d` (or whatever the product spec dictates).
- `getNoteByShareId` should check `expiresAt > now` and return 410 Gone when expired.
- Public reads should strip collaborator emails, comments array, and any private metadata fields. Either snapshot the public content at share time, or filter on read.
- Add a scheduled cleanup (or just rely on the read-time check) so stale share docs get pruned.

## Actual

- Share URLs are permanent.
- Public reads see the full mutable note document — every later edit is exposed; collaborator emails and comment threads are returned verbatim.
