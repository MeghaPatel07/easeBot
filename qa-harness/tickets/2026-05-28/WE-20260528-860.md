## Description

`src/components/ui/sonner.tsx`:
```tsx
const Toaster = ({ ...props }: ToasterProps) => {
  const { theme = "system" } = useTheme()
  return (
    <Sonner
      theme="dark"               // ← HARD-CODED, ignores `theme` variable above
      ...
```

The component reads the theme via `useTheme()` but then passes a literal `"dark"` to the underlying `<Sonner>`. The hook return value is unused — likely a copy-paste from a shadcn snippet where the correct line is `theme={theme as ToasterProps["theme"]}`.

Effect: In light mode every sonner toast is dark — looks out-of-place against the warm cream background palette. This is most visible on /chat where the chat surface is light and a sonner toast pops up dark.

## Steps to reproduce

1. Switch to light mode (Sprint 2 tickets covered the dark-mode tokens; default is light).
2. Trigger any sonner toast (or fire one via DevTools: `import { toast } from 'sonner'; toast('Hello')`).
3. Observe dark toast on light background.

## Expected

```tsx
theme={theme as ToasterProps["theme"]}
```

## Actual

Toasts always dark.

## Evidence

- sonner.tsx:8-13 (cited above).
