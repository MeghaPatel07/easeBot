# WE-20260528-1501 — Backend cold-start: 9 synchronous module imports before port binds, p95 ≥3-5s

**Severity:** P2
**Status:** triaged
**Assigned:** fix-performance
**Area:** Performance / Backend cold-start
**Discovered:** 2026-05-28

## Symptom
`server.ts` performs all credential validation, PostHog init, and ESM module graph resolution **before** `server.listen()` binds. Health checks fail during cold-start, breaking Cloud-Run autoscale (502 until ready).

## Measured (static analysis — backend was not restarted)
Synchronous startup work (from `server.ts` + `app.ts`):
1. `dotenv/config` — disk read of `.env` (~5-20ms)
2. `validatePaymentConfig()` — sync env validation, fails fast
3. `initPostHog()` — `new PostHog(KEY, ...)` blocks (~50-150ms first call w/ DNS)
4. Module-level `firebaseAdmin.ts`: `initializeApp({ credential: applicationDefault() })` — **synchronous metadata-server probe in GCP, ~200-800ms cold**
5. `firebase.ts` (web SDK) — pulled in transitively via `imageStorage.ts`
6. Routers + middleware — `helmet`, `cors`, ~30 ESM imports

Then after `listen()` callback fires:
- `startReminderScheduler()`, `startGuestCleanupCron()`, `startSubscriptionScheduler()` — three setInterval loops + a Firestore probe each.

## Why this matters
- Health endpoint `/api/health` cannot answer until the listen callback runs → autoscale tags the container "unhealthy" for ~3-5s on cold.
- Three schedulers immediately query Firestore on boot — competes with the first user request.

## Root cause
`firebaseAdmin.ts` line 65: `export const adminApp: App = buildApp()` — **module-level side effect.** Any import of `firebaseAdmin` in another module forces eager init. Same for `firebase.ts` web SDK (transitively imported by `imageStorage`).

## Suggested fix
1. Make `adminApp` a lazy getter: `let _adminApp: App | null = null; export function getAdminApp() { return _adminApp ??= buildApp() }`.
2. Defer `startReminderScheduler` + `startGuestCleanupCron` + `startSubscriptionScheduler` by 5s after `listen()` so first request is not blocked.
3. Add `/api/health` short-circuit before any middleware that may hit Firebase.
