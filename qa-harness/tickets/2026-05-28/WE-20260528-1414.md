## Description

```ts
export const translatorCircuitBreaker = new CircuitBreaker({
  name: 'AzureTranslator',
  failureThreshold: 3,
  windowMs: 60_000,
  cooldownMs: 30_000,
})
```

Three failures in 60 seconds OPEN the breaker for 30 seconds. During OPEN, `translateText` returns the original text with `"[Translation temporarily unavailable]"` appended, and `detectLanguage` defaults to English. So EVERY non-English user who chats during this 30s window gets:
- An untranslated input → LLM still receives the raw text but with English-only system prompt instructions.
- A reply in English regardless of the user's chosen language.

A single attacker who can intermittently slow or fail the Translator request (e.g. via WE-20260528-1413 oversize payload, or just sending malformed text) trips the breaker for ALL multilingual users for 30s windows. Easy DoS of i18n.

The translator failureThreshold of 3 (vs llm/image's 5) is too aggressive — translator is not expensive enough to defend with such a tight breaker.

## Expected

- Raise translator failureThreshold to 10/60s.
- During breaker OPEN, fail gracefully per-user (return raw text + a flag in the response) instead of system-wide unavailability.
- Distinguish 4xx Azure errors (client bug) from 5xx (Azure outage) — only the latter should count toward breaker failures.
