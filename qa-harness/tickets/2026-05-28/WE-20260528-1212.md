## Description

`useChat.ts:497`:

```ts
const history = user ? undefined : messagesRef.current.map(...)
```

History is only built for guests. For signed-in users, the backend reads from Firestore. But `userPersonalization` (lines 504-508) is built from `profile?.nickname`:

```ts
const userPersonalization: UserPersonalization | undefined = profile ? {
  nickname: profile.nickname, ...
} : undefined
```

Two issues:

1. **`profile` comes from AuthContext**, which is the same `getDoc`-once-snapshot architecture root-caused in Cluster #1 (S1 -152, PR #32 not landed). Until PR #32 lands, nickname changes done after first AuthContext load do NOT reach `userPersonalization` until full page reload.

2. **`UserPersonalization` is `undefined` (not `{}`)** for guests. Backend `buildPersonalizationSuffix(undefined)` correctly returns `''`. Once a guest signs up mid-thread, the AuthContext resolves a `profile` and the next message includes nickname. But the **summarized history** from before signup (sent on the next call due to history.length>10) is built from `messagesRef.current` where the assistant had no nickname context. The summary therefore references the user as "user" or generic terms, then the recent live messages reference them by nickname. Disjointed UX.

## Steps to reproduce

1. Open chat as guest. Send 10+ messages. Sign up (mid-thread allowed per chatupdates.md).
2. Send the 11th message. Backend summarizes turns 1-6 from the no-nickname history, then appends recent turns with nickname.
3. Assistant reply mixes generic + nickname tones inconsistently.

## Expected

(a) AuthContext.profile updates via onSnapshot (per PR #32). (b) On guest→user conversion, sendMessage re-emits a `personalization_updated` marker that the backend can use to re-summarize prior history with name context, OR (c) The backend's summarizer respects current personalization when summarizing.

## Actual

Stale profile data + summary-without-nickname + live-with-nickname.
