## Description

The string "Something went wrong. Please try again." appears in 6+ places as the default error. It identifies *that* an error happened but suggests no specific action. For users with cognitive impairment OR for any user under stress, "try again" without diagnosis = a loop trap. WCAG 3.3.3 requires error messages provide *specific* guidance.

Worst case: `services/authService.ts:79` is the **default fallback** for unmapped auth codes — any new Firebase Auth error code immediately becomes "Something went wrong" with no debug info, no retry guidance, no support link.

## Steps to reproduce

1. Trigger a network error during signup (DevTools → Offline)
2. Observe generic message — no "Check your connection?" hint, no support link

## Expected

Each error path should:
- Identify the cause in user language ("We could not reach our server — check your internet")
- Suggest specific next action ("Try again in a moment, or visit /help if this keeps happening")
- Link to support / FAQ / status page
- Include an error code (short, copyable) so support tickets are diagnosable

## Actual

5/6 occurrences are identical, undifferentiated, action-less.
