## Description

Long assistant messages (often 1000+ words for planning summaries) render as a single tall bubble. When printed (Cmd+P) on Letter paper, the bubble starts mid-page and continues onto the next page mid-paragraph — with the previous page's footer cutting through a sentence. Even when -864's `@media print` lands, without explicit `break-inside: avoid-page` rules per bubble, the printer splits awkwardly.

## Steps to reproduce

1. Open a `/share/:token` with a long (>1500-word) assistant message.
2. Cmd+P.
3. Observe bubble spans page break with no header repetition; sentence mid-cut.

## Expected

```css
@media print {
  .message-bubble { break-inside: avoid; orphans: 3; widows: 3; }
  .message-bubble[data-long="true"] { break-inside: auto; } /* only allow break on very long bubbles */
}
```

For very long bubbles, repeat sender + timestamp at top of continuation page (CSS `position: running` — limited browser support; alternative is JS-driven pagination in a print-specific component).

## Actual

Random splits.

## Evidence

- SharedChat.tsx / SharedNote.tsx don't set print-specific break properties.
- Companion to -864.

## Notes

Lower priority than -864 (which adds the stylesheet at all). Apply both together.
