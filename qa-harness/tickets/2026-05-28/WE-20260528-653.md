## Description

When the assistant invokes a tool (save_checklist, create_reminder, save_budget, generate_image), the visual indicator is the same generic "thinking" pill. There is no per-tool affordance ("Creating your checklist…" / "Saving 12 budget items…") to either visual or AT users. SR users have zero signal that durable side-effects are happening — they think the assistant is still composing prose.

Sonner toasts ARE fired on tool_error (line 607) but NOT on tool_start or tool_result success. The user experience is: silence → suddenly a saved checklist appears in the sidebar.

## Steps to reproduce

1. Enable VoiceOver
2. Switch to Planner mode
3. "Build me a 6-month wedding checklist"
4. Wait — no announcement that a checklist is being created, only generic typing indicator

## Expected

Polite live-region announces tool start ("Saving your checklist…") and tool success ("Checklist saved with 24 items"). Errors stay assertive (already wired via toast).

## Actual

Silent until raw assistant prose appears. The fact that an artifact was created is invisible to AT.

## Notes

Backend already emits `tool_start` events on the SSE channel — see useChat.ts:584 where `event.t === 'tool_result'` is handled. Add a `setToolStatus` ref + `<p role="status" aria-live="polite" className="sr-only">` near the message list. Cleanup on tool_result.
