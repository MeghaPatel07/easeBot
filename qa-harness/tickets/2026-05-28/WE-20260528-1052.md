## Description

Checkout form (Full name, Email, Address line, Country, State, City, Postal code, GSTIN) has zero `autocomplete=` attributes. WCAG 2.2 added 3.3.7 Redundant Entry, which is satisfied when previously-entered info is auto-filled or available for re-selection. Since browsers/PMs can auto-fill these fields from stored profile data, the absence of `autocomplete=` is a direct 1.3.5 + 3.3.7 failure.

Also note: `fullName` and `email` already pre-fill from `user.displayName`/`user.email` (good, but partial). Address fields force re-entry every checkout — fails 3.3.7.

## Expected

`autoComplete` on all checkout fields: `name`, `email`, `street-address`, `address-level1` (state), `address-level2` (city), `postal-code`, `country`, `tel`. GSTIN can stay un-autocompleted (custom).

Additionally: persist billing address to user profile after first successful checkout, prefill on subsequent visits — satisfies 3.3.7 spirit.

## Actual

Every checkout retypes the entire address.

## Notes

Most users only buy 1–2 plans, so 3.3.7 impact is lower than e.g. an e-comm site, but the SC is still failed for upgrade/downgrade cycles + topup flow.
