# WE-20260528-1528 — Backend chatController file is 1700+ lines — module hot-path parse cost grows linearly

**Severity:** P3
**Status:** triaged
**Assigned:** fix-performance
**Area:** Performance / Backend module size
**Discovered:** 2026-05-28

## Symptom
`grep -c "phCapture" chatController.ts` finds events at lines 1240, 1670, 1684, 1719. `wc -l chatController.ts` (per the read up to 1719+) confirms >1700 lines.

V8 parses the entire file on first require (Node.js doesn't lazy-parse function bodies until called, but the top-level scope is parsed eagerly).

## Why this matters
- ~50-100ms cold-start parse for this file alone.
- Hurts test iteration time (every Vitest run re-parses).
- High cognitive load makes future fixes risky — already 4 import sites for sharp/Azure across same file.

## Suggested fix
Split `chatController.ts` into:
- `chatController.ts` — Express handlers, orchestration
- `chatImagePipeline.ts` — image-gen branching (Stage 1-6)
- `chatHistoryBuilder.ts` — history slicing, summarization wiring
- `chatStreamHandlers.ts` — SSE response shape

Each becomes lazy-parseable on first use.
