## Description

The Account profile-save flow has multiple distinct failure modes:
1. Client validation (e.g. name <2 chars) — should be caught before mutation, but if not.
2. Backend validation (e.g. phone format).
3. 500 (server crash).
4. 403/401 (auth expired).
5. 429 (rate-limited).

All five appear to surface as the same generic toast (per audit of `toast({})` calls in the file and the underlying mutation hook). User can't tell whether to fix their input vs retry vs sign back in.

## Steps to reproduce

1. Open Settings → Account.
2. Try each failure (invalid phone format / DevTools-offline / expired token).
3. Compare toast strings — they're all the same generic copy.

## Expected

Map error codes to specific user-facing strings (see also -862). For 4xx, mirror the backend's field-level error in the toast. For 5xx, generic + retry. For 401, "Session expired — sign in" + redirect.

## Actual

Single generic message.

## Evidence

- AccountTab.tsx onError handler.

## Notes

Sub-case of -862; filing standalone because Account is a high-traffic surface.
