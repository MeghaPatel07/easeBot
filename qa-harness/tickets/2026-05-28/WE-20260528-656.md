## Description

Clicking a sidebar item (Planner, Liked, Gallery, Reminders, Notes) calls `navigate('/<userId>/...')`. The view swaps inside the existing app shell — no full document reload, no focus movement, no `document.title` update. For SR users, the experience is:

- Focus stays on the just-clicked sidebar button
- VoiceOver does not re-announce "you are now on the Planner page"
- The new view's h2 "Planner" (line 1223) is not auto-focused
- `useCanonical` only sets the `<link rel="canonical">` — the document title remains "TheWeddingBot" everywhere

Net: the user has no idea the page changed unless they manually re-traverse the DOM.

## Steps to reproduce

1. VoiceOver on, at `/`
2. Open sidebar, click "Planner"
3. Observe focus and announcement — nothing changes audibly

## Expected

On route change: (a) move focus to the new view's h1/h2 with `tabIndex={-1}`, (b) update `document.title` to `Planner — TheWeddingBot`, (c) optionally emit a `role="status"` announcement.

## Actual

Focus and title stay put.

## Notes

Add a `RouteAnnouncer` component subscribed to `useLocation()`; on path change, set document.title + dispatch focus to `main h1, main h2`. Consider React's `useId` + `aria-labelledby` on `<main>` so SR users get the section name as the landmark name.
