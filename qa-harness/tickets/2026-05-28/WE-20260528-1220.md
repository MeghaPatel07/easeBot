## Description

```tsx
toast({
  title: 'Could not save',
  description: (err as Error)?.message ?? 'Please try again.',
  variant: 'destructive',
})
```

If `updateProfile` rejects with a backend message like `"Firestore: PERMISSION_DENIED: missing or insufficient permissions"` or `"network error: fetch failed"`, it lands directly in the toast. Stack-trace–adjacent strings can also leak.

Similar pattern in many tabs. Verified at AccountTab.tsx:195.

## Expected

User-facing toast shows a normalized human message. Raw `err.message` is logged to console + posthog `tool_error_shown` with `error_code` but not displayed.

## Actual

Raw err.message → user sees engineering jargon.

## Notes

Fix-frontend. Tiny. Pattern fix: wrap `extractUserSafeMessage(err)` everywhere in settings tabs.
