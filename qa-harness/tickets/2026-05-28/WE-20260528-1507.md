# WE-20260528-1507 — TanStack QueryClient has no global cache config — defaults leak (5min staleTime, Infinity gcTime)

**Severity:** P2
**Status:** triaged
**Assigned:** fix-performance
**Area:** Performance / Memory
**Discovered:** 2026-05-28

## Symptom
`App.tsx:53` is just `const queryClient = new QueryClient()`. No `defaultOptions` set. TanStack v5 defaults:
- `staleTime: 0` (every refetch on mount)
- `gcTime: 5 * 60 * 1000` (5 min)
- `refetchOnWindowFocus: true`

Only `useAccount.ts:81` overrides locally: `staleTime: 30_000`. Everything else uses defaults.

## Cache contents after ~30min normal use (static analysis of useQuery sites)
- account → ~2KB, refetches on every tab focus
- subscription → ~1.5KB, refetches on every tab focus
- thread list → already on Firestore onSnapshot (NOT in TanStack, see -1508)
- payment success polling: keeps fresh subscription polls in flight

## Why this matters
- Every tab focus triggers ~5-10 simultaneous refetches → backend gets hit by /api/account, /api/payment/subscription, etc., even when nothing changed.
- 5min gcTime means evicted cache is rapid — but per default refetch behavior, the data is re-pulled on next mount.

## Suggested fix
```tsx
const queryClient = new QueryClient({
  defaultOptions: {
    queries: {
      staleTime: 30_000,
      gcTime: 5 * 60_000,
      refetchOnWindowFocus: false,  // we have onSnapshot for live data
      retry: 1,
    }
  }
})
```
