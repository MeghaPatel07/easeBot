## Description

Sprint 3 task #1 asks for "Login flow end-to-end — POST /api/auth/login with valid creds, capture session cookie". That endpoint **does not exist**:

```ts
// easebot-backend/src/routes/auth.ts:10-16
router.post('/forgot-password/send-otp',       handleSendOtp)
router.post('/forgot-password/verify-otp',     handleVerifyOtp)
router.post('/forgot-password/reset-password', handleResetPassword)
```

The actual auth model is:

1. Frontend authenticates against Firebase Auth via the Firebase JS SDK (email/password, Google OAuth).
2. Frontend forwards the Firebase ID token as `Authorization: Bearer <jwt>`.
3. Backend `requireAuth` middleware (`src/middleware/auth.ts:21-52`) calls `adminAuth.verifyIdToken(token)`.
4. There is no session cookie. There is no backend-issued JWT. The "session" is the Firebase ID token's 1-hour lifetime, refreshed by the SDK.

This is a defensible architecture (the BE never needs to know the user's password), but the Sprint 3 spec wording implies a self-managed login endpoint that doesn't exist. Two paths forward:

- Update the spec to test the SDK→Bearer flow via a Playwright run instead of curl.
- Or, if there's product appetite, add a thin `/api/auth/login` that wraps Firebase REST `signInWithPassword` so the backend issues + refreshes the token and the FE can drop its Firebase JS SDK dependency. That's a non-trivial scope add.

Test verification of the actual contract:
```bash
curl -isS -X POST http://localhost:3001/api/auth/login -d '{"email":"x","password":"y"}'
# → HTTP/1.1 404 Not Found
curl -isS http://localhost:3001/api/account/me
# → HTTP/1.1 401 Unauthorized, body: {"error":"Authentication required","code":"UNAUTHORIZED"}
curl -isS http://localhost:3001/api/account/me -H 'Authorization: Bearer fake.token.here'
# → HTTP/1.1 401 Unauthorized, body: {"error":"Invalid or expired token","detail":"…"}
```

Bearer-gated routes work correctly. Sessionless login does not exist by design.

## Expected (per current architecture)

Sprint 3 #1 should be rephrased as:
- Drive Firebase Auth client-side via Playwright (signInWithEmailAndPassword), capture the resulting ID token from `firebase.auth().currentUser.getIdToken()`.
- Assert `GET /api/account/me` with `Authorization: Bearer <token>` returns the expected profile.
- Assert that after `await signOut()`, the token still verifies until natural expiry — there is no server-side revocation unless `FIREBASE_CHECK_REVOKED=true` and the user is force-signed-out via `/api/account/sign-out-everywhere`.

## Notes

- Notable subtlety in `requireAuth`: if **no Authorization header** is present, it does `next()` without 401 — this is intentional for the guest pass-through pattern on /api/chat, /api/notes (which then 401 internally in the controller). Strict routes use `requireStrictAuth` which does 401 on absence.
- This is the correct issue to raise to triage: spec lists a non-existent endpoint, not a backend bug per se.
