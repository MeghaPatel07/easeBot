## Description

A successful call to `POST /api/generate-image` returns a JSON object whose `imageUrl` field is an **array of base64-encoded JPEG data**, not a URL:

```
HTTP/1.1 200 OK
Content-Length: 574497
X-Guest-Id: 0630d035-3049-4957-b0e8-4470bbb80650
…
{"imageUrl":["/9j/2wBDAAMDAwMDAwMDAwMEBAQEBAYFBQU…<572KB of base64>…"]}
```

The field name `imageUrl` strongly implies a URL string. Frontend code (or any partner integration) doing `<img src={response.imageUrl}/>` will silently break. Memory and bandwidth cost is also significant — 574KB JSON per image vs ~80 bytes of a CDN URL.

Three discrete contract issues:

1. **Misnamed field.** Either the response field should be `imageBase64` (or `imageData`) when returning inline bytes, or the controller should upload to Firebase Storage and return an actual URL.
2. **Array vs scalar.** It's `imageUrl: string[]` — but the request only generates a single image. Either rename to `imageUrls` (plural), or unwrap to a scalar.
3. **Inline base64 bloat.** Returning 574KB of base64 inside a JSON body is roughly 33% larger than the raw bytes would be. Should be a signed URL.

## Steps to reproduce

```bash
curl -X POST http://localhost:3001/api/generate-image \
  -H 'Content-Type: application/json' \
  -d '{"prompt":"wedding mandap with marigold flowers"}'
# → 200, Content-Length: 574497
# → body: {"imageUrl":["/9j/2wBDAA…"]}
```

## Expected

Either:
- `{ "imageUrls": ["https://storage.googleapis.com/…signed.jpg"] }` — upload + sign + return URL list. or
- `{ "imageBase64": ["data:image/jpeg;base64,/9j/…"] }` — rename field to reflect what it actually contains.

## Actual

`{ "imageUrl": ["<raw base64 jpeg>"] }` — field name lies, type is array but request asks for 1, body is huge.
