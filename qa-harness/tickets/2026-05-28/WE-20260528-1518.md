# WE-20260528-1518 — Frontend track() called inside try/catch swallows perf telemetry — no perf event taxonomy

**Severity:** P3
**Status:** triaged
**Assigned:** fix-performance
**Area:** Performance / Observability
**Discovered:** 2026-05-28

## Symptom
Looking at `analytics.ts:240-248`, the `track()` function silently swallows errors and never captures performance-critical events:

```ts
export function track(event: EventName, props: Record<string, unknown> = {}): void {
  if (!ENABLED || !ready) return
  try { posthog.capture(event, props) } catch { /* swallow */ }
}
```

Missing events in the EventName union (`analytics.ts:7-160`):
- `lcp_measured`, `inp_measured`, `cls_measured` — Core Web Vitals
- `chat_stream_first_byte_ms` — time from request to first SSE chunk
- `chat_stream_total_ms` — already covered backend-side as `stream_completed.latency_ms`
- `route_change_duration_ms` — soft-nav timings
- `image_render_ms` — gallery image decode time

## Why this matters
- Sprint 1 -312 explicitly noted no INP instrumentation. Field data for the perf regressions reported in -1102, -108, -1103 is still not being collected.
- Without RUM data, fix-frontend will tune the wrong thing.

## Suggested fix
1. Add a `web-vitals` library hookup that captures LCP/INP/CLS/TTFB/FCP and forwards to `track('web_vitals_*', ...)`.
2. Add those event names to the EventName union so TypeScript enforces taxonomy.
3. In `useChat.ts`, capture `chat_stream_first_byte_ms` between `fetch(...)` start and the first `read()` resolution.
