# WE-20260528-1513 — GalleryView grid renders all images eagerly — `loading="lazy"` defers fetch but not DOM creation

**Severity:** P3
**Status:** triaged
**Assigned:** fix-frontend
**Area:** Performance / Gallery rendering
**Discovered:** 2026-05-28

## Symptom
`GalleryView.tsx:144-170` renders `images.map((img, idx) => (<button>...<img loading="lazy"/>...</button>))`. The browser's `loading="lazy"` attribute defers the network fetch until the img scrolls near the viewport, BUT every `<button>` + `<img>` element is created in the DOM immediately.

For a user with 200+ generated images:
- 200 button elements + 200 img elements + 200 hover overlay divs (4 per item) = ~1000 nodes
- Initial render cost: ~30-80ms layout + paint
- No `width`/`height` attrs on `<img>` → CLS as images load asynchronously

## Why this matters
- Heavy users (50+ images) see lag opening the gallery tab
- Each image lacks intrinsic size → cumulative layout shift on scroll
- No IntersectionObserver-based pagination — all 200 items mount even when only 12 are in viewport

## Suggested fix
1. Add `width={300} height={300}` (or aspect-ratio CSS) to reserve box.
2. Virtualize with `react-window` / `react-virtuoso` for grids > 50 items.
3. Paginate the Firestore query to 50 images at a time; "Load more" button.
