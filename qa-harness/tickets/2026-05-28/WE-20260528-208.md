## Description

`GET /api/admin/users` (a path that does not exist) returns Express's default HTML body:

```
<!DOCTYPE html>
<html lang="en">
<head><meta charset="utf-8"><title>Error</title></head>
<body><pre>Cannot GET /api/admin/users</pre></body>
</html>
```

Content-Type is `text/html`. Every other route in this API responds with JSON. The frontend `functionsService` / `useChat` error handling code path assumes JSON and would throw on `.json()` parse, surfacing a misleading "network error" rather than a graceful 404.

Worse: a typo on a route (e.g. `/api/chat ` with a trailing space, or `/api/chats` plural) would produce an HTML body instead of a structured 404.

## Steps to reproduce

```bash
curl -s -i http://localhost:3001/api/admin/users
# HTTP/1.1 404 Not Found
# Content-Type: text/html
# (HTML body)
```

## Expected

Add a catch-all 404 handler at the end of `/api/*`:

```ts
app.use('/api/*', (_req, res) => {
  res.status(404).json({ error: 'Not found', code: 'NOT_FOUND' });
});
```

## Actual

Express default HTML 404.
