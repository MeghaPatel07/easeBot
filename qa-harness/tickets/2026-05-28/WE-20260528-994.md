## Steps to reproduce
1. Open a thread with ~50 messages (long enough to trigger background summarization).
2. Send a new message just as the summarization tool-call returns.

## Expected
Both operations resolve cleanly; new message preserved.

## Actual
- `messagesRef.current` and `setMessages` updated via stream while the summarizer's `setMessages(serverHistory)` overwrites with the summarized history, in-flight user message lost.

## Suggested owner
fix-state-data
