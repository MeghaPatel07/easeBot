## Description

After tapping "Save Changes" in SettingsModal, the button briefly changes to a green `Check + "Saved"` then auto-closes the modal 900ms later (line 153). SR users:

- Hear no confirmation that the save succeeded
- The modal disappearing without explanation is disorienting — focus jumps back to the body
- On error path (line 156: `setSaveState('idle')`), the button just reverts — no error toast, no announcement, no recovery prompt

## Steps to reproduce

1. SR on
2. Open Settings → change Nickname → Save
3. Listen — silence, then the modal closes itself

## Expected

Render an `sr-only` `<p role="status" aria-live="polite">Settings saved</p>` when `saveState === 'saved'`. On error, swap to `role="alert"` with "Settings could not be saved — please try again." Restore focus to the trigger (gear icon) after auto-close.

## Actual

No SR feedback; focus orphaned post-close.

## Notes

The 900ms auto-close + silent failure path is also a cognitive-a11y issue (no time to read confirmation). Consider an explicit "Done" affordance rather than auto-close.
