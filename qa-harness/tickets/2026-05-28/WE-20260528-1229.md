## Description

`first_message_sent` event fires inside `handleSendMessage` (line 427-435) gated by `sessionStorage.getItem('ph_first_msg_at')`. Quick-prompt cards (handleQuickPrompt at 925-931) call `setInputText(action)` and do NOT send — see -1209. Until the user clicks the send button manually, the `first_message_sent` activation marker is **never** written.

If -1209 is fixed (auto-send on card click), `first_message_sent` will fire because `handleSendMessage` is called. So this ticket is contingent on -1209.

If -1209 is NOT fixed and the user types their own message instead, `first_message_sent` fires from the manual send path — which means activation is correctly counted, BUT the source attribution `mode: mode ?? 'auto'` won't include `'via_quick_prompt'` — so the activation rate from quick-prompt CTAs is invisible.

## Expected

Either fix -1209 OR add `source: 'quick_prompt' | 'composer'` to the `first_message_sent` payload.

## Actual

Activation source attribution missing.
