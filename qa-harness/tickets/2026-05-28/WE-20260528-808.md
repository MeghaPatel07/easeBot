## Description

Sprint 3 brief adversarial item #6: "set tone slider to 50, change another setting, navigate away, come back — does the slider snap back or stay at 50?"

The local `toneSettings` state is reset from `profile?.toneSettings` whenever the `[open, profile]` dependency changes:

```tsx
// SettingsModal.tsx:94-106
useEffect(() => {
  if (open) {
    setNickname(profile?.nickname ?? '')
    setVoiceId(profile?.voiceId ?? '')
    setToneSettings(profile?.toneSettings ?? DEFAULT_TONE)   // ← clobbers in-flight edits
    setSaveState('idle')
    setActiveTab('identity')
  }
}, [open, profile])
```

Three failure modes:

### Mode A — Mid-edit profile refetch (silent data loss)
User opens Settings → drags "Warm" slider from 33 → 50 → does NOT click Save yet. Meanwhile:
- `PaymentSuccess.tsx:46` runs `queryClient.refetchQueries({ queryKey: ['account', 'me'] })`,
- OR `useAccount()` polls,
- OR another tab writes to `users/{uid}` via the SDK direct path (per WE-20260528-105),
- OR Firebase `onAuthStateChanged` fires for token refresh,
the AuthContext profile updates → this useEffect re-runs → slider RESETS to 33. **User's edit is silently discarded.**

### Mode B — Modal-close-without-save (no warning)
Open, move slider, close (overlay click). Reopen. Slider is back to saved value. Expected, but there is no "Discard unsaved changes?" prompt to give the user a chance to save.

### Mode C — AI Behavior tab (sister page) has same pattern via useMemo
```tsx
// AiBehaviorTab.tsx:105-106
() => profile?.toneSettings ?? DEFAULT_TONE,
[profile?.toneSettings],
```
The `useMemo` re-derives on every `profile.toneSettings` change. Same snap-back risk.

There is no `isDirty` flag anywhere in either component. There is no `beforeunload` warning. The user has zero signal that their slider changes were thrown away.

## Steps to reproduce

Live repro:
1. Sign in. Open Settings → AI Personality tab.
2. Drag "Warm" slider from 33 → 50. Do NOT click Save.
3. In a second tab, open Settings → Account, change anything that triggers a profile update (e.g. nickname). Save.
4. Return to tab 1 — AuthContext profile mutates from the Firestore listener (or on the next refetch). The Warm slider snaps back to 33.

Code-level repro (deterministic):
- Open the modal in React DevTools.
- Note `state.toneSettings.warm = 33`.
- In console: `window.dispatchEvent(new Event('focus'))` to trigger any refetchOnWindowFocus that AuthContext uses.
- After profile updates: slider state is 33.

## Expected

ONE of:
- (a) Add `isDirty` flag. Skip the reset useEffect when `isDirty === true`. Show toast "Settings updated remotely — reload to see latest" if profile mutates mid-edit.
- (b) Only run the reset useEffect on `[open]` not on `[open, profile]` — accept staleness for the modal session.
- (c) Hold local edits in a ref that survives profile mutation; merge profile-on-server-side with local-on-client only on Save.

Plus a `Discard unsaved changes?` prompt on overlay click when dirty.

## Actual

Slider value is rewritten from profile on every profile change while modal is open. No prompt on close.
