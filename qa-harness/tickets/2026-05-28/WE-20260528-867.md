## Description

Directional lucide icons (Send, ChevronLeft, ChevronRight, ArrowLeft, ArrowRight) don't auto-flip based on parent `dir`. They're SVGs with fixed paths. Verified by audit:

| Icon | File | Should mirror in RTL? |
|---|---|---|
| `Send` | ChatInput.tsx:2 | Yes — paper-plane idiom points toward where text "ends" |
| `ChevronLeft` / `ChevronRight` | GalleryView.tsx:3,221,231 | Yes — prev/next gallery nav |
| `ArrowLeft` | SettingsShell.tsx:31, used as "back to nav list" on mobile settings | Yes — back arrows mirror |
| `ChevronDown.rotate-180` | ChatInput.tsx:191,427 (mode dropdown) | No — vertical, unaffected |
| `ChevronRight` (in BudgetDashboard expand-row) | BudgetDashboard.tsx:2,203 | Yes — disclosure indicator follows reading direction |

There's no system-wide solution — the fix is to apply `rtl:-scale-x-100` (Tailwind) to each directional icon at use-site, OR wrap them in a `<DirectionalIcon>` helper that flips automatically when `dir="rtl"` is detected.

## Steps to reproduce

1. `document.documentElement.dir = 'rtl'` in DevTools.
2. Open /chat → look at Send button → still points up-right (should be up-left in RTL).
3. Open gallery lightbox → prev/next chevrons still left=prev, right=next (RTL users expect the opposite).
4. Open Settings on mobile → back-arrow still points left (should point right in RTL).

## Expected

Either:
- Add `rtl:-scale-x-100` class at each directional-icon use-site, OR
- Build `<DirectionalIcon name="Send" />` that consumes a direction context and renders the mirrored variant.

## Actual

Directional icons hard-coded LTR.
