## Description

src/hooks/useChat.ts triggers setMessages(prev => prev.map(m => ...)) inside the streaming chunk handler on every SSE/stream chunk received (lines 536, 542, 547, 556, 568, 577, 624). Each call:
1. Creates a new array
2. Iterates all N messages
3. Triggers ChatMessages re-render (which is NOT memoized — see 310)

For a typical 200-word response streaming in 30 chunks with 50 prior messages, this is 30 × O(50) = 1500 object allocations and 30 full ChatMessages renders. INP during streaming will be > 200ms easily.

This is also a memory pressure source — old message objects are GC'd repeatedly.

## Steps to reproduce

1. View src/hooks/useChat.ts grep 'setMessages'
2. Send a long message, observe streaming with React DevTools Profiler open

## Expected

Streaming updates target only the in-flight message via a ref or via a per-message store (Zustand atom/Jotai), not the full array map.

## Actual

Every chunk triggers an O(N) map + array spread + full ChatMessages re-render.

## Notes

Recommend: extract per-message text into a ref + force update only that message component, OR adopt a normalized message store keyed by id.
