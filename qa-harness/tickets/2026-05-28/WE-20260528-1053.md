## Description

The waveform progress bar has `role="slider"` + ARIA value props but ZERO keyboard handlers — no `onKeyDown`, no `tabIndex`, no arrow-key support. Only `onClick={handleSeek}` (mouse-only, derives ratio from clientX). This is a textbook 2.5.7 failure: seeking the audio is achievable only via a click/drag pointer gesture; keyboard / switch / voice-control users cannot scrub.

Also fails 4.1.2 — role="slider" advertises a contract (arrow keys, Home/End, PageUp/Down expected) that the component does not honor. Screen readers will instruct the user to "use arrow keys" and the user will get nothing.

## Steps to reproduce

1. Open Settings → Voice preview, OR play a TTS chat message.
2. Tab focus toward the progress bar.
3. The bar IS NOT in the tab order at all (no tabIndex) — focus skips it.
4. Even if focused via DOM injection, arrow keys do nothing.

## Expected

- `tabIndex={0}` so keyboard users can focus
- `onKeyDown` handler: Left/Right = ±5s, Home = 0, End = duration, PgUp/Down = ±10s
- Pointer alternative for drag: 2.5.7 requires that any dragging gesture have a non-drag equivalent (the click-to-seek covers this for pointer users, but key users need arrow alternatives)

## Actual

Cannot operate the slider via keyboard at all.

## Notes

Replace bespoke bar with Radix `<Slider>` (already used elsewhere via `src/components/ui/slider.tsx`) — it's keyboard-correct out of the box.
