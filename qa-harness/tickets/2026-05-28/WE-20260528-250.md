## Description

This is the "backend down" scenario the task brief calls out. Verified flow when backend is unreachable:

1. Frontend SPA loads normally (frontend is static).
2. Chat page mounts. NO call to `/api/health` is made on mount; no banner appears.
3. User types a message; only on Send does the failure surface — as a generic toast.

Combined with WE-20260528-228 (silent stream hang), the worst UX is: send → toast says "failed" → user retries → fails again → no clear "backend is offline" signal → user assumes their internet is broken.

## Steps to reproduce

1. `lsof -ti :3001 | xargs kill` — kill backend.
2. Reload frontend at localhost:8081.
3. Observe: no banner. Type and send → toast. Try voice → toast. No system-wide signal.

## Expected

- On mount, fire one `GET /api/health`. If it fails, show a sticky banner "Service unavailable — we'll reconnect automatically" and disable Send.
- Retry `/api/health` every 30s. When it succeeds, clear the banner and emit a "service restored" toast.

## Actual

No banner. Per-action failures only.

- Manual repro.
