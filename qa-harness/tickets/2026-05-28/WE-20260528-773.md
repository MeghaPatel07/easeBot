## Description
exchangeRateService.ts exists, hits exchangerate-api.com v6 with cached real-time rates, but its file-level docstring explicitly says: "Single consumer: paymentController". The LLM has NO tool exposing this service. So when a user asks "what's $25k in INR" or "convert my $150 pp budget to rupees", the model invents an exchange rate (likely from training-cutoff, so 6-12 months stale; can be off by 5-15%).

Practical impact: a couple budgeting in INR sees a USD-to-INR conversion from the AI that's off by ₹50k on a ₹2L budget. They make planning decisions on bad data.

## Steps to reproduce
1. `curl -X POST http://localhost:3001/api/chat/stream -d '{"message":"convert 25000 USD to INR for my budget"}'`
2. LLM responds with a rate (might say 83, 82.5, 84.2 — varies by run).
3. Compare to `exchangeRateService.getLockedRate('USD', 'INR')` — that's the truth.

## Expected
- Define a new `convert_currency` tool: parameters `{amount, from, to}`, calls `getLockedRate(from, to)` and returns the result.
- Update all 4 prompts: "For ANY currency conversion, you MUST call `convert_currency`. Never quote an exchange rate from memory."
- Same for the inverse direction (INR → USD).

## Actual
LLM makes up rates. Already-built service sits unused for chat.
