## Steps to reproduce
1. `grep -rn "onIdTokenChanged" Wedding-Ease-Viva-Chat/src` returns 0.
2. Sign in. After ~55min, Firebase SDK rotates the ID token in the background.
3. Any service that cached the previous token in a module-level variable still sends the stale token on next API call.

## Expected
`onIdTokenChanged` subscriber updates a shared token ref; HTTP layer reads from the ref on each request.

## Actual
- AuthContext only uses `onAuthStateChanged`, which fires on sign-in/sign-out but NOT on token refresh.
- Services that need the token call `auth.currentUser.getIdToken()` (not `getIdToken(true)`) per call. SDK returns cached token if not yet 5min from expiry; auto-refreshes only if expired. Race window exists during the 5-minute pre-expiry window.
