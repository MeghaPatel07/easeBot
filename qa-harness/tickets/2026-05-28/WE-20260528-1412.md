## Description

`summarizeConversation` receives an array `{role, content}` where `content` is always a string. The summarizer system prompt is:

> "Summarize this wedding planning conversation, preserving key decisions, dates, budgets, preferences, and action items. Be concise."

It does NOT instruct the model to preserve image URLs or tool-call markers. Consequence: when summarization eventually fires (after the fix in WE-20260528-1411), any older `[Image generated successfully ... image_urls=["https://storage.googleapis.com/..."]]` lines are summarized away. The follow-up turn cannot reference "the mandap image we generated 12 turns ago" because the URL is gone.

Sprint-4 brief item 1 specifically asks: *"Does summarizer preserve image reference + tool results? Send 200 turns."* Today: no. The summary system prompt doesn't even mention images / URLs.

## Expected

Update `SUMMARIZER_SYSTEM_PROMPT` to include:

> "Always preserve EXACT image URLs (https://...) and the image they describe. Always preserve any structured data the assistant generated (checklist IDs, note IDs, reminder dates). Do NOT paraphrase URLs."

Better: store image URLs as a separate `summaryImageRefs: string[]` field on the thread doc, surface them back in the system prompt suffix, so the LLM can reference them without relying on the summarizer to preserve them.
