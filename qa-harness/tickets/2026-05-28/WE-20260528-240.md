## Description

```ts
useEffect(() => {
  const el = textareaRef.current;
  if (!el) return;
  el.style.height = 'auto';
  const sh = el.scrollHeight;    ← FORCED LAYOUT
  el.style.height = `${Math.min(sh, maxHeight)}px`;
  setIsOverflowing(sh > collapsedMax);
}, [inputText, maxHeight, collapsedMax]);
```

Reading `scrollHeight` after writing `height = 'auto'` forces a synchronous layout. This pattern runs on every keystroke (inputText dependency). Modern browsers can absorb a single forced layout per frame; multiple inputs typing-fast on a complex page can hit jank.

Additionally, `setIsOverflowing` triggers another React render → another paint. The `useEffect` doesn't `requestAnimationFrame`-batch.

## Steps to reproduce

1. Open Chrome devtools → Performance.
2. Open chat. Hit Record.
3. Hold a key in the composer for 1 second.
4. Stop. Inspect: per-frame "Recalculate Style" and "Layout" entries.

## Expected

Wrap in `requestAnimationFrame`:

```ts
useEffect(() => {
  const el = textareaRef.current;
  if (!el) return;
  const id = requestAnimationFrame(() => {
    el.style.height = 'auto';
    const sh = el.scrollHeight;
    el.style.height = `${Math.min(sh, maxHeight)}px`;
    setIsOverflowing(prev => prev !== (sh > collapsedMax) ? (sh > collapsedMax) : prev);
  });
  return () => cancelAnimationFrame(id);
}, [inputText, maxHeight, collapsedMax]);
```

## Actual

Synchronous layout per keystroke.
