# WE-20260528-1121 — `userPrefsCache` is the ONLY LRU cache wired — pattern works, audit for replication

**Severity:** P3 (positive finding + recommendation)
**Status:** observed
**Assigned:** fix-performance
**Area:** Performance / Architecture pattern
**File:** `easebot-backend/src/lib/userPrefsCache.ts`
**Discovered:** 2026-05-28

## Observation
`easebot-backend/src/lib/userPrefsCache.ts` uses `lru-cache` (already a backend dependency) with:
- TTL eviction
- Per-cache miss/hit events emitted to PostHog (`stt.pref_cache`)
- A `__clearCacheForTests()` escape hatch
- Firestore-backed reload on miss

This is exactly the pattern we recommend for tickets -1104 (translation), -1105 (TTS), -1106 (summarizer). The wheel does not need to be reinvented.

## Suggested fix
Create `easebot-backend/src/lib/cacheFactory.ts` exporting:
```ts
export function createPosthogObservedCache<K, V>(name: string, opts: LRUOptions): LRUCache<K, V> {
  const cache = new LRUCache<K, V>(opts)
  // Wrap get/set to emit `cache.${name}.hit` / `.miss` to PostHog
  return cache
}
```
Use this for the 3 missing caches identified this sprint.

## Why P3
Not a bug — but turning the existing pattern into a reusable factory reduces the friction to fixing -1104/-1105/-1106.
