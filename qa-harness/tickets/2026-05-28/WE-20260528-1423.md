## Description

After the LLM call completes, `processOutbound(text, responseLanguage)` synthesizes TTS audio if the request originated from voice. The charge for that TTS happens inside Azure TTS (real money) but the chat reconcile path (`chargeTokens({kind:'chat'})`) does not include the TTS cost. Each call's tokens are debited independently:
- `chargeTokens({kind:'chat'})` — Azure GPT input+output tokens.
- TTS internally either succeeds silently or fails silently. There IS a tokenMeter `kind:'tts'`, but it's only invoked from `/api/tts` route directly, not from the chat pipeline's outbound stage.

Consequence: voice-driven chat consumes TTS minutes the user is not metered for. The token meter undercounts cost, which is fine for the user but means the cost projection in the dashboard is wrong.

Cross-check by inspecting `outbound.ts` and `tts.ts` to confirm.

## Expected

After successful `processOutbound`, `chargeTokens({kind:'tts', characters: finalText.length})` for the responseLanguage. If TTS fails, no charge.
