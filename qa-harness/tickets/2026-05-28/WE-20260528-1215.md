## Description

`register({ active_mode: selectedMode })` fires on every mode change. The FE `selectedMode` is one of `'auto' | 'planner' | 'stylist' | 'knowledge'`. The backend mode enum is `'planner' | 'styler' | 'knowledge'` (note typo `styler` vs FE `stylist`).

Result: PostHog cohorts built on `active_mode = 'stylist'` will match FE-tracked users but NOT backend-tracked (the BE never emits `stylist` because it sees the requested mode silently dropped and routes to `assistant` by default — see -1214). The dashboard authoring team will define cohorts like "active_mode in (stylist, styler)" defensively, or worse, miss the cohort entirely.

Same drift for `mode_selected` event at line 149.

## Steps to reproduce

1. Open `/chat`. Switch mode to Stylist. PostHog Live event view → see `$set.active_mode = 'stylist'`.
2. Send a message. Backend log (or `d` SSE event) shows `mode = 'assistant'` (modeRouter default) because BE never received `stylist`.

## Expected

Single source of truth for mode names. Either FE migrates to `styler`, or BE migrates to `stylist`. Then `active_mode` super-prop matches BE-emitted mode-tagged events.

## Actual

Two enums diverge silently. Cohorts will not unify.

## Notes

Closes naturally with -1214. Documentation: docs/PostHog-EVENTS.md should declare `active_mode` allowed values explicitly.
