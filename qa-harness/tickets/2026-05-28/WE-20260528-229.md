## Description

Chat messages render via plain `.map(...)` over the messages array — no virtualization (`react-window`, `@tanstack/react-virtual`, etc.) in the imports. Each message renders a TypewriterMarkdown + ReactMarkdown + custom override components (img, table, li). At a few hundred messages this becomes a multi-megabyte DOM.

The frontend reads (`getChatHistory`) is unbounded for the active thread. A power user (e.g. an internal QA who has been smashing the demo for weeks) on a long thread will see scroll-jank, slow input typing (because React re-renders the whole list on every keystroke), and eventually browser memory pressure.

## Steps to reproduce

1. Open a thread with 500+ messages (or seed via Firestore admin).
2. Open chat. Try to type a new message.
3. Observe input lag.

## Expected

Virtualize the messages list (e.g. `@tanstack/react-virtual`). Render only the visible viewport + small buffer. Lazy-load older messages on scroll-up.

## Actual

Plain `.map`. Full DOM.
