## Description

```ts
imageData: z.string().optional(),
imageMimeType: z.string().optional(),
```

No validation of:
- That `imageData` is base64 (no regex check; no `decode` attempt at the boundary).
- That `imageMimeType` is in an `image/*` allowlist (`image/jpeg`, `image/png`, `image/webp`).
- That decoded byte length is below a per-image cap (the only cap is the 20MB body limit, shared with the rest of the payload).

This means a caller can submit any base64 (or even non-base64) blob with `imageMimeType: 'image/svg+xml'` or `application/exe` and the pipeline will pass it downstream to the image service. SVG-with-script payloads are a classic XSS surface for any future "render attached image" path.

## Steps to reproduce

```bash
curl -s -X POST http://localhost:3001/api/chat -H "Content-Type: application/json" \
  -d '{"message":"check this image","imageData":"PHN2ZyB4bWxucz0iaHR0cDovL3d3dy53My5vcmcvMjAwMC9zdmciPjxzY3JpcHQ+YWxlcnQoMSk8L3NjcmlwdD48L3N2Zz4=","imageMimeType":"image/svg+xml"}'
# Schema accepts it; downstream handler decides what to do.
```

## Expected

```ts
imageMimeType: z.enum(['image/jpeg','image/png','image/webp']).optional(),
imageData: z.string().regex(/^[A-Za-z0-9+/=]+$/).max(8 * 1024 * 1024).optional(),  // ~6MB raw
```

## Actual

Free-form string + free-form MIME accepted.
