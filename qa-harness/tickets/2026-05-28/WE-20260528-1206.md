## Description

`GeolocationService.setCurrencyOverride` writes to `localStorage[eb_currency_override]`. Reads via `getUserCurrency` always check override first (correctly — override beats cache). Single-tab reload behavior is **correct** (I was wrong in earlier draft).

The actual bug is **cross-tab**:

- Tab A on `/pricing` overrides USD → EUR.
- Tab B on `/pricing` is open simultaneously. Tab B still shows USD because Pricing.tsx only calls `getUserCurrency()` inside a one-time `useEffect` mount (line 258).
- No `window.addEventListener('storage', ...)` watcher exists in Pricing.tsx (or in geolocationService) to react to the override change.

Tab B will re-read the override on next mount, but until then the user sees a stale currency. If Tab B navigates to `/checkout` from a tier card, it carries the **stale** currency in route state.

This is a sibling of the cross-tab cluster (S2 -570, S3 -989). Filing as net-new because the audit asked specifically about the override path, and the prior tickets do not name `Pricing.tsx`.

## Steps to reproduce

1. Open two tabs on `/pricing`. Both show INR (or whatever).
2. In tab A, override to EUR.
3. Tab B still shows INR.
4. In tab B, click any tier → land on `/checkout` → priced in INR.

## Expected

Pricing.tsx subscribes to `storage` events for `eb_currency_override` and re-runs the geolocation resolution on change. Cross-tab consistency.

## Actual

No storage listener. Tab B stuck on last-resolved value.

## Notes

Fix-state-data. Two-line fix in Pricing.tsx: `useEffect(() => { const h = (e) => { if (e.key === 'eb_currency_override') setCurrency(...) }; window.addEventListener('storage', h); return () => removeEventListener(...) }, [])`. Pairs with S3 -971 BroadcastChannel scaffold.
