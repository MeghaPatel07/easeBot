## Description

When the backend (`http://localhost:3001`) is down or unreachable:
- Send returns a network error → useChat surfaces a toast.
- Voice transcribe → another toast.
- Auto-save on note edit → silent fail (toast may be debounced).

There's no global "backend offline" banner that proactively warns the user before they invest in typing a long message that's going to fail. There's no retry queue — once the user gets a "send failed" toast, they have to manually retry every individual action.

## Steps to reproduce

1. Kill backend: `lsof -ti :3001 | xargs kill`.
2. Open chat at localhost:8081. UI loads (no banner).
3. Type a message and Send → "Failed to send" toast.
4. Try voice → "Failed to start" toast.
5. Bring backend back up — no auto-retry of the queued message.

## Expected

- Health probe on app boot + every 30s while idle; show a sticky banner "Service unavailable — reconnecting…" when probe fails.
- Queue the user's unsent messages; auto-replay on reconnect.

## Actual

Per-action toasts only. No queue. No banner.

## Evidence

- Manual repro flow; no existing health-poll in `src/services/`.
