## Description

Message bubbles cap with `max-w-[calc(100%-2rem)] sm:max-w-sm md:max-w-lg lg:max-w-xl` but never apply `break-words`, `overflow-wrap-anywhere`, or `whitespace-pre-wrap` to the bubble container or the rendered text node. Confirmed by `grep -n 'break-words\|break-all\|overflow-wrap' src/components/chat/ChatMessages.tsx` → zero hits.

That means:
- An assistant reply that includes a long URL (Google Maps share-link is often 700+ chars) or a hex code without spaces (`0xDEADBEEF...`) overflows the bubble.
- On mobile (375px viewport, bubble cap = 343px) the overflow extends past the right edge → horizontal page scroll appears.
- The same bubble at desktop `max-w-xl` (576px) overflows the chat column into the sidebar gutter.
- LLM responses containing long markdown code fences (`base64` blobs from "decode this for me" requests) are common and reproducible.

## Steps to reproduce

1. Open /chat (any auth state).
2. Paste user message: `https://www.google.com/maps/place/Taj+Mahal/@27.1750151,78.0399665,17z/data=!3m1!4b1!4m6!3m5!1s0x39747121d702ff6d:0xdd2ae4803f767dde!8m2!3d27.1750151!4d78.0421552!16zL20vMGQyenc?entry=ttu` (single token, ~280 chars, no spaces).
3. Observe the bubble extends beyond the viewport on 375×812; horizontal page scroll appears.
4. Try a longer assistant reply (paste a base64 image — `data:image/png;base64,iVBORw...` 5000+ chars) into a fake message via React DevTools.
5. Layout breaks identically.

## Expected

Add to bubble inner text node:
```
className="... break-words [overflow-wrap:anywhere]"
```
Or in `src/index.css`:
```css
.chat-msg-text * { overflow-wrap: anywhere; }
```

For markdown-rendered HTML (`markdownToHtml`), confirm `<pre><code>` blocks scroll internally with `overflow-x-auto` rather than expanding the parent.

## Actual

No wrap directive. Long unbroken strings break responsive layout and cause global horizontal scroll on mobile.

## Evidence

- ChatMessages.tsx:364 — user bubble `max-w-[calc(100%-2rem)] ... text-foreground/90` (no break-words)
- ChatMessages.tsx:424 — assistant bubble outer (no break-words)
- ChatMessages.tsx:961 — image-card variant (no break-words on captions)

Sprint 1 -053 noted "Tablet chat input text wraps" — that's the textarea. This ticket is the **rendered message bubble**, a different surface. Sprint 1 -060 ("share-expired text overflow") is also distinct (share page, not chat).
