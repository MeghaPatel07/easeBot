## Description
The non-stream chat route (`POST /api/chat/`) mounts `validateBody(ChatRequestSchema)`. The streaming route (`POST /api/chat/stream`) does NOT. Result: any unsupported `mode` value (e.g. `"NOTAREALMODE"`, `"Stylist"` mixed-case, `"chat"`, `"image"`) returns HTTP 200 with a normal streaming response instead of a 400 contract error. The schema-comment in routes/chat.ts acknowledges this: "validation is handled by the controller" — but no validation actually runs.

## Steps to reproduce
1. `curl -X POST localhost:3001/api/chat/stream -d '{"message":"Hi","mode":"NOTAREALMODE"}'` → HTTP 200, content streams normally.
2. Schema declares `mode: z.enum(['planner', 'styler', 'knowledge']).optional()` — any other value should 400.

## Expected
HTTP 400 with `{ error: "Invalid request", details: [...] }` for unknown `mode` values.

## Actual
HTTP 200 streaming; mode silently coerced to default.

## Fix sketch
Mount `validateBody(ChatRequestSchema)` before the SSE wrapper in routes/chat.ts:`router.post('/stream', requireAuth, chatBurstRateLimiter, validateBody(ChatRequestSchema), quotaCheck('chat'), ...)`. Verify schema also covers `language`, `toneSettings`.
