# WE-20260528-1115 — `helmet.contentSecurityPolicy: false` disabled wholesale to allow SSE — security/perf tradeoff worth re-examining

**Severity:** P3
**Status:** triaged
**Assigned:** fix-security
**Area:** Performance / Security headers
**File:** `easebot-backend/src/app.ts:42-44`
**Discovered:** 2026-05-28

## Symptom
```ts
// Disable contentSecurityPolicy so SSE / EventSource connections are not blocked
app.use(helmet({ contentSecurityPolicy: false }))
```

The comment is incorrect — CSP does not block SSE responses (SSE is just `text/event-stream` MIME); CSP only governs *client-side* loading of scripts/styles/connect-src. The original author likely meant the browser-side CSP set by the SPA index.html.

By disabling backend CSP entirely on JSON API responses, we lose XSS hardening on any path that ever serves HTML (the `/api/payment/return` POST handler emits HTML for PayU return — confirmed visually in some flows).

## Why "perf"
This is filed as P3 perf-related because if we re-enable CSP we should also add `connect-src 'self' azure-... posthog-... firebase...` — those connect entries can be measured against actual outbound destinations.

## Suggested fix
1. Re-enable CSP with `connect-src` covering Azure (translator + speech + openai), Firebase, PostHog, PayU.
2. Verify SSE on /api/chat/stream still works (it will).
3. Confirm no measurable response-time regression (helmet adds <1ms per request).
