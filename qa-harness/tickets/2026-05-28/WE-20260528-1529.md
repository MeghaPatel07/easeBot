# WE-20260528-1529 — circuitBreaker.onFailure prunes failures array on every check — O(n) per call

**Severity:** P3
**Status:** triaged
**Assigned:** fix-performance
**Area:** Performance / Backend hot path
**Discovered:** 2026-05-28

## Symptom
`circuitBreaker.ts:121-126`:
```ts
private getRecentFailureCount(): number {
  const cutoff = Date.now() - this.windowMs
  this.failures = this.failures.filter(f => f.timestamp >= cutoff)  // O(n) every call
  return this.failures.length
}
```

`onFailure` calls `getRecentFailureCount()` on EVERY failure to check threshold. If the breaker is healthy, `failures` is short and this is fine. But under degraded conditions (e.g. Azure outage), failures accumulate up to threshold=5 fast, then more failures still queue up while the breaker is OPEN.

## Why this matters
- Marginal — failures cap at ~5-10 in practice.
- BUT under pathological conditions (sustained 100s of failures in cooldown period), the filter walk adds up.

## Suggested fix
Use a ring buffer or sliding window with explicit head/tail pointers. Or trigger the prune only when `failures.length > 100` to amortize.

This is a P3 — the current code is correct, just not ideal.
