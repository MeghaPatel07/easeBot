## Description

WE-20260527-251 covers adding `role="log" aria-live="polite"` to the message list. However the **content inside the live region is the TypewriterMarkdown component**, which mutates the DOM character-by-character (12ms cadence). When wrapped in aria-live="polite", VoiceOver/NVDA either:
- Cancel and restart the announcement on every text mutation (rapid speech overlap)
- Or batch-skip the streaming content and announce nothing once it settles

The fix for -251 must be paired with a strategy: render a hidden settled-text mirror in the live region only AFTER `isStreaming === false` (or once the message reaches a "settled chunk" boundary like a sentence). Announce only the final assistant text once.

## Steps to reproduce

1. Open VoiceOver (Cmd+F5)
2. Send "Plan a Goa wedding for 200 guests" — wait for streamed reply
3. Observe announcement behavior — either character-storm or silence

## Expected

A single polite announcement of the assistant's final reply (or one announcement per settled paragraph). No mid-stream interruption.

## Actual

If -251 lands naively (wrap the typewriter in role=log), every keystroke retriggers the announcer. SR users hear garbled fragments. Confirmed via grep: `TypewriterMarkdown` uses `useTypewriter(text, isStreaming, 12, 2)` which is the source.

## Notes

Implementation strategy: keep TypewriterMarkdown as the visual element with `aria-hidden="true"`, render a sibling `<div className="sr-only" role="status" aria-live="polite">{settledText}</div>` that updates only when `isStreaming` flips to false. Alternative: announce on paragraph boundaries via debounced effect.
