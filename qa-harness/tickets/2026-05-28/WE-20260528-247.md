## Description

```ts
router.post('/cancel', requireAuth, (req, res) => {
  const { requestId } = (req.body ?? {})
  if (!requestId || typeof requestId !== 'string') {
    res.status(400).json({ error: 'requestId is required' })
    return
  }
  const outcome = cancelRequest(requestId, req.user?.uid ?? null)
  if (outcome === 'forbidden') {
    res.status(403).json({ error: 'forbidden' })
    return
  }
  res.status(204).end()
})
```

Two issues:
1. `cancelRequest(requestId, req.user?.uid ?? null)` — `req.user` is null for anonymous callers (per WE-20260528-202). The `cancellationRegistry` likely checks owner; with `uid = null`, the behavior is unclear. If it's permissive (matches null-owner-stored requests), anonymous callers can cancel anonymous streams of OTHER anonymous callers.
2. No format check on `requestId` — accepts any string. An attacker can iterate known IDs and try to cancel arbitrary streams. The 403 vs 204 response distinguishes "this requestId exists but isn't yours" from "this requestId doesn't exist" — an info-leak side channel.

- Format check: `requestId: z.string().uuid()`.
- Always return 204 regardless of "exists / yours / not found" to remove the side channel.
- For anonymous callers, require a session token / X-Guest-Id matching the stream's creator fingerprint.
