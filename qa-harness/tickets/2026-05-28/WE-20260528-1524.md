# WE-20260528-1524 — useChat appends to messages on every SSE chunk — 50 setState calls/sec at peak streaming rate

**Severity:** P1
**Status:** triaged
**Assigned:** fix-frontend
**Area:** Performance / React rendering
**Discovered:** 2026-05-28

## Symptom
`useChat.ts` (per the grep showing line 845-891) calls `setMessages(prev => ...)` to push text deltas as they arrive. Azure OpenAI streams ~10-50 tokens/sec depending on response length. Each token can trigger 1-3 chunks.

**Estimated render frequency at peak: 20-50 setMessages/sec.** With ChatMessages NOT memoized (-1509), each setState triggers a full list re-render.

## Why this matters
- For a 50-message thread + a streaming reply, every chunk causes React to walk all 50 message components.
- Markdown rendering inside each message bubble (likely via `react-markdown` or similar) adds 1-3ms per render.
- Cumulative: at 30 chunks/sec × 50 messages × 1ms/render = 1500ms/sec of main-thread work — LONG TASK territory, blocks INP.

## Suggested fix
1. **Coalesce chunks:** batch setMessages to once per `requestAnimationFrame` (~16ms) instead of per chunk. Each batched update flushes accumulated text.
2. **Split state:** store the streaming-in-progress text in a separate ref/state that only the bottom message subscribes to. Other messages don't re-render at all.
3. Wrap each message bubble in `React.memo` keyed by `(id, text, liked)`.
