## Description

```ts
onKeyDown={e => {
  if (e.key === 'Enter' && !e.shiftKey) {
    e.preventDefault();
    handleSend();
  }
}}
```

`handleSend` is invoked on every Enter. There's no `isTyping`/`isPending` guard on the keypress path — `disabled={!hasContent || voiceState === 'recording' || ...}` covers the button click but the Enter keydown calls `handleSend` regardless of `isTyping`.

A user holding the Enter key (long-press, mac key-repeat) fires send N times in a few hundred ms. The chat burst limit kicks in at the 11th, but the first 10 are billed.

## Steps to reproduce

1. Type "hi" in the chat input.
2. Hold Enter for 2 seconds.
3. Observe: 10 user-message bubbles appear; 11th triggers 429 ("chat_burst_limit").
4. Quota counter is decremented 10×.

## Expected

In `onKeyDown`: `if (e.key === 'Enter' && !e.shiftKey && !isTyping && hasContent) { ... }`. Match the button's disabled state.

## Actual

Enter bypasses the button's disabled guard.
