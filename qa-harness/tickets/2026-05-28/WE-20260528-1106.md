# WE-20260528-1106 — No conversation-summary cache — same N-message history re-summarized via LLM each time the rolling window expires

**Severity:** P2
**Status:** triaged
**Assigned:** fix-performance
**Area:** Performance / External-service caching (LLM cost + latency)
**File:** `easebot-backend/src/services/conversationSummarizer.ts`
**Discovered:** 2026-05-28

## Symptom
`summarizeConversation()` is called from `chatController.ts` lines 724 and 1229 — both inside the chat handler hot path when the conversation history exceeds a window size. Grep shows no cache layer.

Two specific re-summarization cases that pay LLM latency every time:
1. User abandons and resumes a session — same message list re-summarized.
2. SSE retry / reconnect path — handler re-enters, re-summarizes.

Azure OpenAI summarization call is typically 800-2500ms and a few hundred tokens of cost.

## Root cause
Stateless service — no `hash(messages) → summary` memoization. Note that `userPrefsCache.ts` already uses LRUCache so the dependency exists.

## Suggested fix
1. Hash the input messages (stable JSON serialization → sha256) and cache the summary in an LRU keyed by `(uid, hash, language)`. TTL 1h is fine — summaries are stable for a given message list.
2. Optionally persist to Firestore at `users/{uid}/summaries/{hash}` so summary survives backend restart (the cache pattern matches `userPrefsCache`'s Firestore-backed LRU).

## Expected impact
On reconnect / abandonment-resume flows: removes a 1-2s LLM call from the request path. Also reduces token bill ~5% in steady state.
