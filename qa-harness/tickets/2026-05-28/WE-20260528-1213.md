## Description

Live probe of `POST /api/tts` with identical body twice in a row at 17:29Z on 2026-05-28.

```
TTS1: 3.022939s size=226244 code=200
TTS2: 1.792193s size=226244 code=200
```

Identical wav payload (226244 bytes both times). TTS2 was 1.23s faster — this is **Azure-side TLS reuse + JIT warmup**, NOT an in-process cache. Verified by reading `ttsController.ts:67-70`:

```ts
res.set('Content-Type', 'audio/wav')
res.set('Content-Length', String(wavBuffer.length))
res.set('Cache-Control', 'no-store')
res.send(wavBuffer)
```

`Cache-Control: no-store` is explicit. `generateSpeech({ text: capped, voiceName, language: ttsLang })` is called every time with no memoization. No `Map<key, Buffer>` cache. No `LRUCache` on this path.

**Conclusion: S2 -403 ("TTS no cache") is still open and accurate on main.** No regression has landed. The "1.7s vs 3.0s" looks cache-like but is network warmup.
