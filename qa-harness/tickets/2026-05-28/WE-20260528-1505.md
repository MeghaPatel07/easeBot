# WE-20260528-1505 — PostHog frontend register() called on every mode change — super-properties balloon

**Severity:** P3
**Status:** triaged
**Assigned:** fix-performance
**Area:** Performance / Analytics overhead
**Discovered:** 2026-05-28

## Symptom
`pages/Index.tsx:151` calls `register({ active_mode: selectedMode })` on every selectedMode change inside a `useEffect`. `register()` writes to `posthog.persistence` (localStorage) which is synchronous.

Each `track()` call then includes the super-properties in its payload. For high-frequency events (`message_sent`, `gallery_image_viewed`, `note_block_widget_used`) the cumulative overhead is:
- ~50-150 bytes of extra payload per event
- One localStorage write per mode toggle (rarely a hot path, but on mobile + Brave with isolation it's ~1-3ms)

## Why this matters
- Mode-switch stress (20× per Sprint 4 brief) generates 20 localStorage writes + 20 super-property merges within seconds.
- On low-end Android Chrome, localStorage I/O can stall the main thread for 5-15ms per write.

## Suggested fix
1. Only call `register()` when `selectedMode` actually changes (use a ref comparator — currently runs on every selectedMode dep change which is fine, but the initial render also fires).
2. Move active_mode to per-event prop instead of super-prop, OR use `posthog.register_once()` for stable session-level props.
