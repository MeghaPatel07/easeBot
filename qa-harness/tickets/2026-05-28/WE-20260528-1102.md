# WE-20260528-1102 — /chat TTI = LCP (6.5s) — page is fully blocked until LCP, not interactive during

**Severity:** P1
**Status:** triaged
**Assigned:** fix-performance
**Area:** Performance / Interactivity
**Discovered:** 2026-05-28

## Symptom
On `/chat` prod (median of 3): LCP = TTI = **6.46s**, FCP 5.62s, TBT 0ms.

TTI being exactly equal to LCP indicates the main thread is idle (TBT=0) but the page is treated as non-interactive until the largest paint completes. Conventional expectation: TTI lands within ~50–200ms of LCP, and ideally users can type / scroll while LCP is still arriving.

## Why this matters
Users on /chat staring at FCP at 5.6s wait another **0.85s** to actually click "send" or type — the input field is mounted but the route is still considered non-interactive. With TBT=0, this is not a long-task problem; it's an LCP-blocking layout (likely the chat composer or empty-state mascot competes with hero image for LCP designation, and React's hydration is finishing in lockstep).

## Root cause hypothesis
The LCP candidate on /chat is likely the empty-state mascot image or first message bubble, AND the chat input area renders below it. With no resource hints (`<link rel="preload">` for the input bundle, no `fetchpriority="high"` on the LCP image), the browser serializes work.

Sprint 1 -312 noted no INP instrumentation — we cannot yet confirm INP vs TTI gap in field data.

## Suggested fix
1. Identify LCP element on /chat (Lighthouse `largest-contentful-paint-element` audit) — confirm whether mascot or chat composer wins.
2. Add `fetchpriority="high"` on the LCP image, `preload` for the critical chat composer chunk.
3. Render chat composer above the LCP-candidate image in the DOM order so it can hydrate first.
4. Add PostHog INP/TTI tracking (block on Sprint 1 -312).
