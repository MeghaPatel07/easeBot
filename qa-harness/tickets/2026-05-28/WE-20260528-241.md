## Description

Sending `{"message":"a"}` is accepted (HTTP 200) and routed through the full LLM pipeline. The reply is the canonical "I'm here to help with weddings" fallback, which costs ~150 output tokens. For an accidental cat-on-keyboard event ("a", "f", " ", "."), each invocation burns quota.

This isn't a bug per se — `min(1)` is the literal schema — but a `min(2)` or a "looks like a real message" heuristic (e.g. at least one vowel + length ≥ 2) would meaningfully reduce billing on misclicks while costing zero accessibility.

## Steps to reproduce

```bash
curl -s -X POST http://localhost:3001/api/chat -H "Content-Type: application/json" -d '{"message":"a"}'
# HTTP 200, ~150 tokens of fallback response, ~$0.0001 cost
```

## Expected

Either `message.min(2)` (paired with a UI hint on the composer to avoid a confusing 400) OR a controller-level early-return that replies with a static "Could you elaborate?" string without invoking the LLM.

## Actual

Single-char passes; LLM invoked.
