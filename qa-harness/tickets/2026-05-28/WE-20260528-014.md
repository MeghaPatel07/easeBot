## Description

`InvitePartner.handleSubmit` does three things:

1. Writes the new collaborator entry into Firestore `users/{uid}/collaboration/main`.
2. Builds `inviteLink = \`${window.location.origin}/invite?from=${userId}\``.
3. Shows toast: `"Invite sent to ${trimmed}. They'll receive an email to join your plan."`

But:
- **No email is actually sent.** There is no `fetch`, no Cloud Function call, no `notify` API. `grep -n "sendInvite\|sendEmail\|fetch\|notify" InvitePartner.tsx` returns nothing.
- **`/invite` is not a registered React-Router route.** `grep '"/invite' Wedding-Ease-Viva-Chat/src/App.tsx` returns nothing. If the user does manage to share the link via the "Copy link" button, the recipient lands on the SPA's `NotFound` page.

So the inviter sees success messaging but nothing happens. The intended recipient never hears about it. The shareable link, if used, dead-ends.

## Steps to reproduce

1. Open InvitePartner UI (Settings → Collaborate, or wherever it's mounted).
2. Enter `someone@example.com`, click "Send invite".
3. Observe toast "Invite sent to someone@example.com. They'll receive an email to join your plan."
4. Check the email inbox of `someone@example.com` — nothing arrives.
5. Click "Copy invite link" → paste somewhere → open it (`http://localhost:8081/invite?from=<uid>`) → React Router renders `NotFound`.

## Expected

Either:
- Wire `handleSubmit` to a backend `/api/collab/invite` endpoint that actually sends an email via the existing email service.
- Register a `/invite` route with a meaningful landing page that handles `?from=<uid>` (e.g. shows "X invited you to plan their wedding — sign in to accept").

Until both ship, the UI should not claim "email sent".

## Actual

Toast lies. Link 404s.
