## Description

Programmatic audit found **35 of 40 (88%)** visible buttons on the landing page at mobile widths fall below the iOS 44×44 / Material 3 48×48 touch-target minimum. Affected affordances include:

| Button | Measured (px) | Spec |
|---|---|---|
| AnalyticsConsent "Decline" | 66 × 28 | < 44 height |
| AnalyticsConsent "Accept" | 65 × 28 | < 44 height |
| Sidebar Settings | 20 × 32 | < 44 both |
| Sidebar Help | 20 × 32 | < 44 both |
| Sidebar "Send Feedback" link | 22 × 54 | < 44 width |
| Sidebar "See Plans And Pricing" | 20 × 80 | < 44 width |
| Header collapse + new-chat | 40 × 32 | < 44 both |

Sprint 1 -263 / -268 / -270 covered specific surfaces (privacy anchor links, ChatInput, sidebar collapse). This ticket is the **landscape-level finding** — most clickable UI on the entire mobile landing is below spec, suggesting a missing token / utility (e.g., `min-h-tap` / `min-w-tap`) in the design system.

## Steps to reproduce

1. Mobile viewport 375×812
2. Run `Array.from(document.querySelectorAll('button')).filter(b => { const r = b.getBoundingClientRect(); return r.width > 1 && (r.width < 44 || r.height < 44); }).length`
3. Returns ≥35

## Expected

Either add an opt-out (`min-h-[44px] min-w-[44px]`) on every interactive surface, OR add a global utility like `[role="button"], button, a[href] { min-height: 44px; min-width: 44px; }` scoped under a `@media (pointer: coarse)` block.

## Actual

Buttons fail Apple HIG Section 4 (Layout → Tap Targets) and Material 3 spec.

## Evidence

- Programmatic measurement output captured in this run (`sprint2-touch.mjs`)

## Notes

Companion to -263/-268/-270. This ticket frames it as a system-wide design-token gap rather than per-component fix. Fail WCAG 2.5.5 (Level AAA) — not strict requirement but commonly required for commercial mobile-first apps.
