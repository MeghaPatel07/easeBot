## Description

The consent banner uses `role="dialog"` with only `aria-label="Analytics consent"`. There is no `aria-describedby` pointing to the explanatory `<p>` ("We use privacy-friendly analytics…"), so screen readers announce the dialog name but not what the user is consenting to. Also missing `aria-modal` (whether or not it actually traps focus — it does not, which is its own concern).

## Steps to reproduce

1. Clear localStorage `ph_consent`, reload.
2. With VoiceOver, navigate into the consent banner.

## Expected

VO announces "Analytics consent, dialog. We use privacy-friendly analytics to improve your planning experience…" before reaching Decline/Accept.

## Actual

VO announces "Analytics consent, dialog" and lands on the Decline button. The user has to manually re-navigate to find the paragraph.

## Notes

Add `id="ph-consent-desc"` to the `<p>`, then `aria-describedby="ph-consent-desc"` on the dialog. Decide whether `aria-modal="true"` and a focus trap are appropriate — banner is non-blocking so probably not.
