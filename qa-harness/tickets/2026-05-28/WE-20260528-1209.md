## Description

The "Help me decide" pill in the desktop empty state (Index.tsx line 1556-1561) has handler:

```tsx
onClick={() => setInputText('Help me decide what I need for my wedding')}
```

It **only sets composer text**. It does not:
- Trigger send (`handleSendMessage`)
- Switch mode (selectedMode stays `auto`)
- Fire a `quick_prompt_clicked` PostHog event (only the 4 quick-prompt cards do — line 927)

So the user clicks "Help me decide" expecting an AI response, gets only text in the composer, has to click send themselves. The walkthroughpoints.md spec says the starting prompt options should "trigger correct mode + first message".

Same problem with the four `actionButtons` (line 1567-1571): they call `handleQuickPrompt` which only `setInputText(action)` (line 925-931). User still has to click send.

## Steps to reproduce

1. Load `/chat` empty state on desktop (>=640px).
2. Click "Help me decide" pill.
3. Composer fills with "Help me decide what I need for my wedding" but nothing sends.
4. Same for "What should I get", "Help me plan", "Show me ideas", "Ask anything".

## Expected

Per walkthrough spec: clicking the card should send the message AND select the appropriate mode (Help me plan → planner; Show me ideas → stylist; Ask anything → knowledge; What should I get → auto/stylist).

## Actual

All cards only stage the text in the composer. No mode switch. Send still requires explicit button click.

## Notes

Fix-frontend. handleQuickPrompt should `setSelectedMode(modeForIntent(text))` and call `handleSendMessage(action)` directly. The card metadata in `buildActionButtons` (line 894-915) has the intent already — extend the type to include `intendedMode` and route accordingly.
