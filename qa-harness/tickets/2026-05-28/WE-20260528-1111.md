# WE-20260528-1111 — Backend memory baseline 30MB; +15MB drift after 1200 reqs of /api/health — no leak, but no GC pressure either

**Severity:** P3 (observability gap, not a defect)
**Status:** triaged
**Assigned:** fix-performance
**Area:** Performance / Observability
**Discovered:** 2026-05-28

## Symptom
Sequence of RSS measurements on the Node backend (PID 68635) on Sprint 3 day:
- Before tests: 30.0 MB (after ~4.4h uptime + light load)
- After 1200 health requests + Sharp benchmarks + Translator probes: 45.6 MB
- Net drift: +15.6 MB

This is **not** a leak — load was bounded to read-only health and no real chat / image flow. But:
1. We cannot establish a real leak slope because we cannot drive authenticated chat load (-1108).
2. There is no memory observability shipping to PostHog or any APM: no periodic `process.memoryUsage()` emission.
3. No `--max-old-space-size` configured: production node will use V8 default heap (~1.5GB on 64-bit) which masks slow leaks for weeks before OOM.

## Suggested fix
1. Emit `process.memoryUsage()` (rss, heapUsed, external) every 60s to PostHog as `backend.mem` event.
2. Set `NODE_OPTIONS=--max-old-space-size=512` in prod for the backend container; tighter ceiling surfaces leaks faster (current observed working set is 30-50MB, so 512MB has 10× headroom).
3. After -1108 unblocks: rerun 1000-request authenticated chat load and re-measure delta over 30 minutes.
