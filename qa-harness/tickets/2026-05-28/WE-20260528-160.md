## Description

`useAccount` uses `staleTime: 30_000` and has no `refetchInterval`, no `refetchOnWindowFocus` (defaults to TanStack's project default — verify in `queryClient.ts` if a global override exists). When Tab A completes an upgrade and PATCHes the plan, Tab B's cached `['account','me']` stays in stale-but-served mode for 30 s; on tab focus the cache returns the OLD value because there's no focus refetch override here, and the global query client may have it disabled. Even worse, server-driven changes (PayU webhook → backend tier change) never invalidate either tab. Compounds WE-20260528-155 (badge stays "Free").

## Steps to reproduce

1. Open same account in Tab A and Tab B.
2. In Tab A, perform an upgrade (or simulate by direct backend tier update).
3. Tab B's ProfileMenu shows the old plan badge.

## Expected

Tab B reflects the new plan within ~1 s of upgrade completion.

## Actual

Tab B keeps old plan for ≥30 s (until staleTime elapses + a query refetch trigger fires).

## Evidence

- Screenshot(s): `qa-harness/evidence/WE-20260528-160/screenshots/`
- Console log: `qa-harness/evidence/WE-20260528-160/console.log`

## Notes

Either drop `staleTime` to 0 here and add `refetchInterval: 15_000`, OR attach a Firestore listener that triggers `qc.invalidateQueries(['account','me'])` whenever the user doc updates (also closes WE-20260528-152 cross-tab).
