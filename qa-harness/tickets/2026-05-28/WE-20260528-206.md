## Description

The backend `ChatRequestSchema` enforces `message.max(10000)`. The frontend `ChatInput` textarea has NO `maxLength` attribute and the parent `onInputChange` has no length guard. A user pasting a long document (e.g. a chat history dump, a long article) types/pastes freely past 10K characters, then hits Send and gets:

```json
{"error":"Validation failed","details":[{"code":"too_big","maximum":10000,...,"message":"String must contain at most 10000 character(s)","path":["message"]}]}
```

This raw Zod error reaches the user as a generic "send failed" toast (per `useChat.ts` error path). No graceful "your message is too long — current 14,231 / max 10,000" UI.

## Steps to reproduce

1. Open chat at localhost:8081.
2. Paste a 15K character block (Lorem Ipsum × ~3).
3. Type a message and hit Send.
4. Observe: silent fail / generic error toast. Console shows the raw Zod 400.

## Expected

- `maxLength={10000}` on the textarea (or a CHAR_CAP constant), and a live "9,800 / 10,000" counter when within 1000 chars of cap.
- Disable Send button + show inline "Message too long — trim 4,231 characters" when over cap.
- Match the backend max as a single shared constant if practical (e.g. via a shared `MAX_CHAT_MESSAGE_CHARS` env-bridged value).

## Actual

No `maxLength`. No counter. Generic toast on submit failure.
