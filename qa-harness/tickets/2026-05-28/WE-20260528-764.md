## Description
Sprint 1 -353 already filed the broader "personalization sliders are ignored" issue for `verbosity`. This is the SAME problem isolated to the `warm` slider specifically: warm=100 emits `"Be warm and nurturing in your responses — use empathetic phrasing and affirm the user's feelings."` while warm=0 emits `"Keep a neutral, composed tone — avoid overly sentimental language."`

But the assistant.ts prompt baseline ALREADY says (line 14-17): "Warm, thoughtful, emotionally present", "No AI feel. No fluff." So a "neutral, composed" suffix from warm=0 conflicts with the baseline-warm prompt — the prompt baseline tends to dominate and warm=0 has near-zero observable effect.

## Steps to reproduce
1. Same prompt with `toneSettings.warm=0` vs `toneSettings.warm=100`.
2. Measure: empathic phrasing count, exclamation count, "I'm sorry to hear that" frequency in stress-trigger inputs.
3. Difference should be detectable; empirically the deltas are within noise.

## Expected
- Strong, hard-overriding instructions: warm=0 → "OVERRIDE the default warmth: respond with a clinical, factual register. No empathy phrases, no 'I'd love to'. Acknowledge briefly then deliver information."
- warm=100 → maintains current.

## Actual
The injected suffixes are too gentle relative to the baseline prompt. Slider does almost nothing observable.

## Notes
This is one slice of the broader slider problem (see -353). All sliders need this treatment. Cheapest fix: when a slider is at an extreme (≤10 or ≥90), prefix the instruction with "OVERRIDE PREVIOUS PERSONALITY: …".
