## Description

There IS a `register({ is_authenticated: true, plan_tier })` call at line 126-129 inside the `onAuthStateChanged` listener — good. But:

- The very first PostHog `pageview` (auto-captured at `init` time) fires BEFORE the auth listener resolves.
- For that first event, super-props don't include `is_authenticated`, so dashboards have to coalesce missing-vs-false.

On logout (line 211): `register({ is_authenticated: false })` is set. But PostHog `reset()` is called on the same path which **clears all super-props**. So the `false` is set on a fresh distinct_id; the prior session's events still have `true`. That's the correct posthog pattern, but the line 211 register is redundant after reset and may not stick. Worth verifying via Live events.

## Notes

Low-impact analytics hygiene. Filed so dashboard authors don't trust `is_authenticated` filter for first-pageview cohort.
