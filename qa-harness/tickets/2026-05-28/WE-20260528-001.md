## Description

`GET /api/speech-token` (mounted via `app.get(\`${prefix}/speech-token\`, getSpeechToken)` in `app.ts` with **no `requireAuth` middleware**) returns a fresh Azure Cognitive Services Speech JWT to any caller — no Firebase token, no Bearer header, no anti-abuse check. The JWT is valid for ~10 min and authorizes Speech-to-Text + Text-to-Speech calls directly against our Azure Speech Services tenant. A script kiddie can poll this endpoint and burn through the Speech Services F0 free tier (or paid tier in prod) by routing arbitrary TTS/STT workloads through our subscription.

The decoded JWT payload leaks:
- `subscription-id: 224b6237a21a47f0ab1953e8dcfd7fe7`
- `azure-resource-id: /subscriptions/0c355664-3033-4fd8-9d00-1904e5f1837b/resourceGroups/OpenAI/providers/Microsoft.CognitiveServices/accounts/EaseBot`
- `region: eastus`, `product-id: SpeechServices.F0`

This is a different surface but the same class of bug as WE-20260527-204 (chat without auth).

## Steps to reproduce

1. `curl -sS http://localhost:3001/api/speech-token` (no Authorization header).
2. Observe HTTP 200 with body `{"token":"eyJhbGciOiJFUzI1NiIs...","region":"eastus"}`.
3. Decode JWT (base64 payload segment) → see Azure subscription IDs in plaintext.
4. Use the token in the Azure Speech SDK with our region/resource — it will authorize until `exp`.

## Expected

- Endpoint requires a Firebase Bearer token (`requireAuth` / `requireStrictAuth`).
- Unauthenticated requests get `401 {error:"Authentication required"}`.
- Authenticated requests get the JWT but rate-limited per-uid to ~30/min.
- Consider a per-uid daily cap on token issuance.

## Actual

- Open to the public internet via the dev host.
- No rate limit specific to this endpoint (only the global `apiRateLimiter`).
- Token payload is itself non-secret to Azure but it gives temporary signed access to our subscription's quota.

## Evidence

- Console log: `qa-harness/evidence/WE-20260528-001/console.log` (decoded JWT, curl trace).

## Notes

This compounds with WE-20260527-204 (chat-route unauth pass-through) — together, an anonymous attacker has free Azure OpenAI + Azure Speech without any auth gate. Recommend rolling the Azure Speech resource key after fix lands.
