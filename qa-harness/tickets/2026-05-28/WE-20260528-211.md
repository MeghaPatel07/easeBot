## Description

When sending an Arabic prompt to `/api/chat`, the response `text` field includes the assistant body followed by:

```
[Translation temporarily unavailable]
```

This literal user-visible string suggests the translation pipeline failed silently and a placeholder was inlined into the final text. It:
1. Leaks internal pipeline state to the user.
2. Will render inside the chat bubble verbatim.
3. Implies a bilingual response was expected (assistant text + translated copy) — but instead users see a confusing bracketed status string.

## Steps to reproduce

```bash
curl -s -X POST http://localhost:3001/api/chat -H "Content-Type: application/json" \
  -d '{"message":"ما هي تقاليد الزفاف العربية؟"}'
```

Inspect the `text` field — ends with `\n\n[Translation temporarily unavailable]`.

## Expected

If translation fails, EITHER omit the placeholder entirely OR return a structured field (`response.translation: null` + a side-band warning) the client can choose to render. Never inline a debug string into chat copy.

## Actual

Literal placeholder text inlined.
