## Description

`profileMutation` and `prefsMutation` invalidate `['account','me']` only `onSuccess`. There is no `onMutate` optimistic write or `setQueryData` patch. Result: between the click of Save and the server's 200, every consumer keeps showing the OLD value (often 600–1500 ms feel like an eternity for "what did my save actually do"). On flaky links this can stretch to multiple seconds.

## Steps to reproduce

1. Open Settings → Account. Edit name to "TEST-OPT".
2. Throttle network to Slow 3G in DevTools. Click Save.
3. Watch the AccountTab card, the ProfileMenu identity row, and the avatar initials.

## Expected

Local state shows "TEST-OPT" instantly (optimistic) with a subtle pending indicator until server confirms.

## Actual

UI shows the previous value until the PATCH returns (~3–8 s on Slow 3G). Optimistic UX is missing.

## Evidence

- Screenshot(s): `qa-harness/evidence/WE-20260528-161/screenshots/`
- Console log: `qa-harness/evidence/WE-20260528-161/console.log`

## Notes

Add `onMutate` that does `qc.setQueryData(['account','me'], old => ({...old, profile: {...old.profile, ...patch}}))` plus `onError` rollback. Lines `useAccount.ts:84-92`.
