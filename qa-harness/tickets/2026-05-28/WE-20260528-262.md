## Description

The chat composer textarea has `outline-none focus:outline-none focus:ring-0 focus-visible:outline-none focus-visible:ring-0`. This explicitly forbids any browser-painted OR app-painted focus indicator. Keyboard users tabbing into the composer have zero visual confirmation that focus has landed.

While the textarea pill container may have its own visible border, that border state does not change between unfocused and focused (verified via DOM inspection); there is no perceptual feedback when keyboard focus enters.

## Steps to reproduce

1. Open `/`, click somewhere else (e.g. the title) to remove focus from composer.
2. Press Tab repeatedly until you would expect to land on the composer.
3. Observe no focus ring or border change.

## Expected

Visible focus state on the wrapping pill (or on the textarea itself) — minimum 2px ring at 3:1 contrast.

## Actual

No visible focus.

## Notes

The likely intent was "don't double-paint a ring inside the pill" but the fix needs to move focus styling to the parent pill via `:has(textarea:focus-visible)` or by adding `focus-within:` styling.
