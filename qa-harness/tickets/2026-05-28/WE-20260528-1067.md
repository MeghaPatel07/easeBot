## Description

Sprint-1 -651 + -251 cover the typewriter-vs-aria-live trap. This ticket adds the COMPLEMENT: even after those fixes, **there's no signal to the SR user that streaming is done**. The settled-text mirror approach assumes the user notices the announcer reading the final message. But for long messages (40+ seconds streaming), the user may have moved on — the announcement when the message settles will be interrupted by the user's next action.

## Expected

When streaming finishes:
1. Settled text rendered into hidden `<div role="status" aria-live="polite">` (per -651 fix)
2. ALSO: append a terse "[message complete]" marker, OR title-case the message origin ("TheWeddingBot replied")
3. If user has navigated away from the message list (focus elsewhere), update the document title briefly ("• TheWeddingBot replied — TheWeddingBot")

## Actual

Stream-complete is implicit; users with low attention or distractibility miss it.

## Notes

Pair with -651. Specifically: at `useChat.ts:518` where the final-message state is set, emit a transient ARIA live update with prefix "Message complete:" then the body — gives SR users an audible "earcon" boundary.
