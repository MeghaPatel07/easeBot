## Description

Generated image URLs come from Firebase Storage signed URLs that expire (default 7 days). Older chats reference expired URLs. Gallery thumbnails reference deleted images (race between cleanup and grid refresh).

Audit: `grep -rn "onError" src/components/GalleryView.tsx src/components/chat/ChatMessages.tsx` → zero hits.

Effect: when an image URL fails to load:
- Browser renders the default broken-image glyph (varies per browser).
- No copy explains what happened ("Image expired" / "Unable to load").
- No retry / refresh path.
- ChatMessages.tsx:366 (attached-image user bubble) — same.
- GalleryView.tsx:156 — same; clicking the broken thumbnail still opens the lightbox, which then has a broken larger image.

## Steps to reproduce

1. Open /gallery, find an older image.
2. DevTools → Network → block the image URL pattern.
3. Reload.
4. Observe broken-image glyph; no error state.

## Expected

```tsx
<img
  src={url}
  onError={(e) => { e.currentTarget.src = '/placeholder.svg'; setHasError(true); }}
  ...
/>
{hasError && <div className="absolute inset-0 flex items-center justify-center text-xs text-foreground/40">Image unavailable</div>}
```

For the lightbox, surface a retry button if image fails.

## Actual

Default browser broken-image glyph; no UX.

## Evidence

- GalleryView.tsx + ChatMessages.tsx audited.

## Notes

`public/placeholder.svg` already exists (the 1200×1200 gray square with broken-image glyph). It's not currently wired as an `onError` fallback anywhere.
