## Description
Occasionally Azure OpenAI returns a completion with empty `content` (it does happen — particularly with safety-filter intermediate states or model-side aborts). The controller streams `t:"c"` chunks then `t:"d"` final frame with `text:""`. The FE renders an empty message bubble — completely blank, no avatar text, no "regenerate" button, no error.

Worse: the empty turn is committed to Firestore message history. Future history fetches see an empty `assistant` message which confuses the LLM ("why is the previous turn empty?").

## Steps to reproduce
1. Force a 0-token completion (mock the Azure response in dev, or trigger a safety-filter intermediate that emits no content).
2. Observe blank bubble + Firestore record.

## Expected
- Controller: detect `text.trim() === ''` post-stream. Emit an SSE `error` frame with code `EMPTY_COMPLETION`. Do NOT persist the empty assistant message.
- FE: on `EMPTY_COMPLETION`, show "Hmm, I didn't catch that — let me try again." with an auto-retry once, then a manual retry button.

## Actual
Empty bubble persists. User has no path forward except sending another message.

## Notes
Pair with -777 (1MB response chaos). Both are LLM-output-quality chaos cases. The fix is similar: a post-stream sanity check in the controller before the final SSE frame.
