## Description

Sonner toasts are great UX but for SR users they have a known quirk: toast.error / toast.success without `important: true` may not always announce reliably, especially on rapid succession. Multiple call-sites in PlannerView (80, 84, 150, 158) fire one-after-another (e.g. user clicks Copy fast → "Failed to copy" can be drowned by next toast).

For destructive/error paths, SR users need a more aggressive announce. `toast.error` should use `important: true` OR the component should fall back to an inline `role="alert"` element.

## Expected

- All `toast.error(...)` calls audited; pass `{ important: true }` to force live-region announcement
- Critical errors (auth, payment) get inline `<div role="alert">` next to the affected field, NOT just a toast

## Actual

Mixed pattern; many error toasts are polite by default → may be missed.
