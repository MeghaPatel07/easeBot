## Description

The Account tab's Nickname `Input` (AccountTab.tsx:531) is rendered with **no `maxLength` attribute, no `.slice(0, N)` in `onChange`, and no length-counter UI**. Compare with the AI-Behavior Personalization tab where `CUSTOM_INSTRUCTIONS_MAX = 1500` is enforced both via `setX(value.slice(0, MAX))` AND `maxLength={MAX}` AND a visible counter (PersonalizationTab.tsx:395-406). The nickname field has none of that.

Saving a 100-char nickname like `"Aaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaa"`:
1. POSTs successfully — backend accepts (Firestore field is unbounded text).
2. Renders in ChatHeader at the top of /chat as a single very long token.
3. ChatHeader uses no `truncate`/`line-clamp` on the nickname slot — the page layout shifts the right-side icons off the viewport (related to but not duplicate of WE-20260528-051).
4. ChatSidebar profile-row line has `truncate` on name but the row also displays the long nickname elsewhere in some flows.
5. Toast notifications that include `"Welcome, ${nickname}!"` (multiple places) push the close-X out of the toast.

## Steps to reproduce

1. Sign in.
2. Open Settings → Account → Nickname.
3. Paste 100 'A's, hit Save.
4. Close Settings, view chat header / sidebar / any toast that uses nickname.
5. Observe layout shifts and clipping.

## Expected

- Add `maxLength={32}` (matching common social-app nickname caps).
- Add `setNickname(e.target.value.slice(0, 32))`.
- Show "X / 32" counter under field.
- All consumers (`ChatHeader`, sidebar profile row, toast templates) wrap nickname with `truncate` + `max-w-[...]`.

## Actual

No cap, no truncation in consumers → horizontal layout breakage.

## Evidence

- AccountTab.tsx:531-537 (Input definition, missing maxLength).
- PersonalizationTab.tsx:395-406 (correct pattern for reference).

## Notes

Related to but distinct from WE-20260528-151 (nickname-change doesn't reach AuthContext) — that's a state-sync bug; this is a length-validation + visual-overflow bug.
