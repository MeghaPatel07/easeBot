## Description

The voice composer replaces the textarea while recording. Only the timer is in a live region (line 320-326: `aria-live="polite"`). State transitions are not announced:

- `voiceState: 'idle' → 'requesting'` (mic permission requested) — silent
- `'requesting' → 'recording'` — silent
- `'recording' → 'transcribing'` — visible "Transcribing…" label exists but no aria-live
- `'transcribing' → final transcript in input` — silent

SR users tap mic → silence → maybe they think it failed → they tap again, cancelling. The visible "Transcribing…" pill (line 315) has no role.

Bonus: the waveform `<div aria-hidden>` (line 281) is correctly hidden, but the surrounding `<div role="group" aria-label>` (line 254) only announces a static label; transitions aren't surfaced.

## Steps to reproduce

1. SR on
2. Tap mic
3. Listen — no signal that recording started

## Expected

Add a sibling `<p role="status" aria-live="polite" className="sr-only">` updated by voiceState:
- `requesting`: "Microphone permission requested"
- `recording`: "Recording, {duration} seconds"
- `transcribing`: "Transcribing your message"
- error: "Transcription failed, please try again" (role=alert)

## Actual

Only the bare timer is in a live region; state transitions silent.

Pair with WE-20260527-260 (sidebar overflow trigger) — both are recording-style controls. The 60-second auto-stop in useVoice.ts:131 should also announce ("Recording stopped automatically after 60 seconds").
