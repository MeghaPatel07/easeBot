# WE-20260528-1521 — analyzeImage instantiates a new AzureOpenAI client per call — no client reuse

**Severity:** P2
**Status:** triaged
**Assigned:** fix-performance
**Area:** Performance / Azure OpenAI
**Discovered:** 2026-05-28

## Symptom
`imageGeneration.ts:515-520` (inside `analyzeImage`) instantiates `new AzureOpenAI({...})` on EVERY call. The `getClient()` in `azureAI.ts:18-33` also does the same — `new AzureOpenAI(...)` returns a fresh instance every call.

Each `new AzureOpenAI(...)` allocates:
- An internal `fetch`-based HTTP client
- A keep-alive agent (or relies on the default global agent)
- JSON schema cache

Without singleton reuse, connection pooling per host is at best per-`fetch`-default (~6 concurrent in Node default).

## Why this matters
- Adds ~30-80ms per AI call for client construction + TLS handshake (no keep-alive across calls).
- Throws off connection coalescing — concurrent calls don't share the H2 multiplexed stream.

## Suggested fix
Convert `getClient()` to a memoized singleton:
```ts
let _client: AzureOpenAI | null = null
export function getClient(): AzureOpenAI {
  if (_client) return _client
  // ... env validation ...
  _client = new AzureOpenAI({ endpoint, apiKey, deployment, apiVersion: '2024-08-01-preview' })
  return _client
}
```
And reuse in `analyzeImage`, `promptArchitect`, etc.
