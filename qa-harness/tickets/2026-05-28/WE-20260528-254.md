## Description

The banner sits at `bottom-4 left-1/2` z-100 with width `min(92vw, 520px)`. On a 375px-wide viewport the banner covers the chat composer pill / send button. Until the user dismisses the banner with Decline/Accept, the primary chat action is occluded. A keyboard-only or motor-impaired user may not even discover the chat input until they happen to interact with the banner.

## Steps to reproduce

1. Clear localStorage `ph_consent`.
2. Open `/` at 375×812 (iPhone) viewport.
3. Observe banner sits on top of the chat input bar.

## Expected

Banner should not overlap primary interactive areas, especially at small viewports. Either inline at top, or temporarily push the chat input up while visible.

## Actual

Banner covers send/mic/attach buttons on mobile until dismissed.
