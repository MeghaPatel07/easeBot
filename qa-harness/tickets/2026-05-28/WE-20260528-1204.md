## Description

`track(event, props: Record<string, unknown>)` is a freeform passthrough. The `EventName` union enforces *which events exist*, but the props are typed `Record<string, unknown>` so a developer can ship any field they like.

I audited 110+ call sites. Today's call sites are mostly PII-clean (IDs, counts, lengths, enums). But the contract has no enforcement, so a regression at any of these sites would silently leak. The docs/PostHog-EVENTS.md file is referenced but unverified — there is no schema that ties the EventName union to a `Record<EventName, ZodSchema>` of allowed properties.

Examples of brittle props observed:
- `analytics_consent_changed` ships `{ consent: 'accepted' | 'declined' }` — safe today.
- `signup_completed` ships `{ method, is_guest_conversion }` — safe today, BUT `AuthContext.tsx:153` also calls `setUserProperties({ signup_source, created_at })` immediately after with `new Date().toISOString()` — fine, but a future change to add `email` to that call would not error.
- `note_image_uploaded` ships `{ note_id, size_kb }` — but `useChat.ts:608` ships `{ tool_name, error_code }` where `error_code` is taken from `ev.errorCode` (LLM-produced) without a length cap.
- `transcription_failed` ships `{ error: (name||msg).slice(0,64) }` — the slice guards length but the message itself may contain user audio metadata.

## Steps to reproduce

1. `cd Wedding-Ease-Viva-Chat && grep -rn "track('" src --include="*.tsx" --include="*.ts" | wc -l` → 110+.
2. Inspect each call. There is no static-analysis or runtime gate.

## Expected

A per-event Zod schema in `analytics.ts` that `track()` validates against before calling `posthog.capture`. Refusing unknown props in production builds prevents drift.

## Actual

Free-form Record. Test coverage exists for none of the call sites.

## Notes

`fix-frontend` could land a typed event registry: `const EVENT_SCHEMAS: Record<EventName, ZodSchema> = { ... }`. Stretch goal — not urgent — but the lack of a contract is what S1 -242 surfaced; this ticket captures the **enforcement** gap (S1 -242 surfaced the data-shape gap).
