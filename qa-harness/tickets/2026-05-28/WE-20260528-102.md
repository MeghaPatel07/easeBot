## Description

Journey 2 (guest hits cap) leaves the user stranded. When a guest exceeds the 10-message client-side cap, `useChat.ts:839-840` injects an error chat bubble:
```ts
errorText = "You've reached the guest limit. [Sign up](/signup) for a free account to keep chatting."
```
The Markdown link points to `/signup`, but `App.tsx` Routes contain no `/signup` route — only `/login`. Clicking the link renders the `<NotFound />` page (App.tsx catch-all `*`), which has no recovery path back to chat or to the SignUpModal.

The other CTAs in `Index.tsx` (the inline banner button and the cap-hit indicator JSX) correctly call `setShowSignUpModal(true)` — so this is a single inconsistency in the streamed error text path.

## Steps to reproduce

1. Open the app as a guest. Send 10 messages (or seed `localStorage.easebot-guest-msg-count = 11` for speed).
2. Send an 11th message — backend returns 429 with body `{reason:'guest_limit_exceeded'}` (or the client-side check fires first).
3. Click the "Sign up" link rendered inside the error bubble.

## Expected

The SignUpModal opens (matching the banner + indicator buttons). Or the link routes to `/login` which has a "Create an account" toggle.

## Actual

Navigates to `/signup` → React Router catch-all → NotFound page. No way back to the chat without using the browser back button. SignUpModal is never offered.

## Notes

- Quick fix options:
  (a) Change error text to remove the link and instead instruct user to click the banner button.
  (b) Add `<Route path="/signup" element={<Index />} />` and have Index open the modal when search-param `?signup=1` is present.
  (c) Add `/signup` as alias to existing `/login` with a tab pre-selected to Sign-Up.
- Affects every guest who burns the cap — funnel-blocker for the entire upgrade path.
