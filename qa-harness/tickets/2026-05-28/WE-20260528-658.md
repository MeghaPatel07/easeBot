## Description

`src/components/ui/sonner.tsx` line 11 hard-codes `theme="dark"` ignoring the `theme` prop pulled from `useTheme()` on line 7. Two consequences:

1. Light-mode users get a dark toast on a light background — readable but visually jarring; contrast values are tuned for dark-mode only.
2. Sonner's default toast emits `role="status"` (polite) for all variants. Error toasts (`toast.error()`) should be `role="alert"` (assertive) but Sonner doesn't auto-promote them unless `important: true` is passed. The codebase calls `toast.error(...)` in useChat.ts:607 and ChecklistDetail.tsx:223 without the `important` flag — these errors may not interrupt SR users.

## Steps to reproduce

1. Switch theme to light via ChatHeader theme-toggle
2. Trigger any toast (e.g. copy a message)
3. Observe dark toast on light page

## Expected

`theme={theme}` (already destructured but unused). Error toasts get `important: true` or explicit `richColors` + `closeButton`. Optionally add `containerAriaLabel="Notifications"` for clarity.

## Actual

Hard-coded dark; polite-only announcements.

## Notes

Fix is two-line: `theme={theme === "system" ? undefined : theme as ToasterProps["theme"]}` plus a sweep of `toast.error(...)` calls to add `{ important: true }`. Consider centralizing via a `notify()` helper.
