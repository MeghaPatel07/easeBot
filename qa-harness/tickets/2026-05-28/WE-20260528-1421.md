## Description

```ts
function guestFingerprint(req: Request): string {
  const ua = req.headers['user-agent'] || ''
  const al = req.headers['accept-language'] || ''
  const ip = (req.ip || req.socket.remoteAddress || '').toString()
  return 'g:' + crypto.createHash('sha256').update(`${ua}|${al}|${ip}`).digest('hex').slice(0, 16)
}
```

Three coworkers in the same office on Chrome same-version-same-locale → same fingerprint. They share a 10 msgs / 10s budget. Any one of them sending 5 messages locks the others out for 10s.

Compounds with -202 (no real auth): logged-in users without `req.user?.uid` fall back to fingerprint too. The fingerprint is also trivially client-spoofable — change Accept-Language string slightly, change UA — to evade the limit entirely.

The fingerprint approach is sound for SOME use cases (catching basic abuse) but it's the WRONG granularity for chat-burst limits.

## Expected

- Use `X-Guest-Id` (already established for quotaCheck) as the key when present.
- If absent, mint and return one (current pattern in quotaMiddleware).
- Drop UA/AL fingerprinting — keep only the guest-id capability.
