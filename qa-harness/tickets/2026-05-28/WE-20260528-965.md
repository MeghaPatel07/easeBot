## Steps to reproduce
1. Tab A, chat sidebar visible with 3 threads.
2. Tab B (same user), start a brand-new conversation; send a message. New thread created.
3. Wait 5 minutes.
4. Return to Tab A. Observe sidebar.

## Expected
New thread appears at the top.

## Actual
- `subscribeToThreads` should keep the list in sync. But if the listener was killed by token expiry mid-idle (see 957) or if a permission-denied error was swallowed, the list stays at 3 items.
- Sort order: when listener does reconnect, the new thread is inserted in the right spot, but during the idle window the order is wrong.
