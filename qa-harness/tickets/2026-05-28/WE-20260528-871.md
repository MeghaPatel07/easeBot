## Description

VibeDNAStrip imposes `maxLength={30}` on its title input. CustomVibeForm imposes `maxLength={40}` on its descriptor input. Both inputs:
- Silently stop accepting input at the cap (HTML behavior).
- Show no counter ("12 / 30") and no message ("Up to 30 characters").
- Users wanting longer descriptors get no feedback as to why the field stopped accepting their keystrokes.

Compare to the correct pattern in PersonalizationTab.tsx:406 — visible "0 / 1500" counter that updates live.

## Steps to reproduce

1. Open the image generation flow → VibeComposer → pick a custom vibe.
2. Type a 35-character descriptor (e.g. `boho-chic outdoor garden ceremony with peonies`).
3. Observe: cursor stops moving at char 30 with no UI feedback.

## Expected

Below each capped input:
```
<p className="text-2xs text-foreground/40">{value.length} / {MAX}</p>
```

Or use the existing pattern from PersonalizationTab.

## Actual

Silent cap; user friction.

## Evidence

- VibeDNAStrip.tsx:127 — `maxLength={30}` with no counter sibling element.
- CustomVibeForm.tsx:75 — `maxLength={40}` same.

## Notes

Also applies to FeedbackDialog.tsx:139 (`maxLength={5000}`) and CheckoutModal.tsx:129 (`maxLength={15}`). 5000 is high enough that a counter would be useful; 15 is short enough that one would prevent confusion.
