## Description

Both checkout phone inputs use `maxLength={15}`. This was likely a guess at "phone number length" — but the actual maximum E.164 number length is 15 digits NOT INCLUDING country code prefix `+`. With spaces typically inserted by formatters:
- Indian: `+91 98765 43210` = 15 chars (just fits if no other formatting).
- UAE: `+971 50 123 4567` = 16 chars → truncated.
- UK: `+44 20 7946 0958` = 16 chars → truncated.
- US with country: `+1 415 555 2671` = 15 chars (fits).

UAE is a target market per pricing memory. Truncation = invalid phone → PayU webhook fails → user can't pay.

## Steps to reproduce

1. Open /pricing → click any paid tier → CheckoutModal opens.
2. Type a UAE phone: `+971 50 123 4567`.
3. Observe input stops at 15 chars; last digit lost; PayU rejects.

## Expected

- Use the validated PhoneInput component (src/components/auth/PhoneInput.tsx) which dynamically computes maxLength per country, OR
- Increase cap to 20 to accommodate all formatting variations, OR
- Strip non-digits before length-check (E.164 max 15 DIGITS).

## Actual

Hard cap 15 chars including spaces → international users blocked.

## Evidence

- CheckoutModal.tsx:129.
- Checkout.tsx:414.
- PhoneInput.tsx:158-208 has correct dynamic maxLength pattern.
