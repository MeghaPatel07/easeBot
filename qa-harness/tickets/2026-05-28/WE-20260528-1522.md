# WE-20260528-1522 — Conversation summarizer ignores the Azure OpenAI streaming option — blocks for full 300-token output

**Severity:** P2
**Status:** triaged
**Assigned:** fix-performance
**Area:** Performance / Summarizer latency
**Discovered:** 2026-05-28

## Symptom
`conversationSummarizer.ts:39-47` uses non-streaming `client.chat.completions.create()` with `max_tokens: 300`. The full ~3s LLM call blocks before returning. The summary is then used in `effectiveHistory` for the same-turn LLM call — pure dead time on the user's clock.

## Why this matters
The summary call is in the critical path: user sends msg → summarize → wait → call LLM with summarized history → stream response.

## Suggested fix
1. **Best option:** kick off summarization async, persist to thread (`chats/{tid}.summary`), and use the previous summary for the current request. The summary is one turn behind, which is acceptable for conversation context.
2. **Alternative:** stream the summarizer call. But since the entire summary is needed before the next LLM call, streaming doesn't help here.
3. **Cheapest option:** lower `max_tokens` from 300 to 200 (the prompt says "be concise" — current avg output likely 200-250 tokens anyway). Saves ~600ms.
