## Description

The summarizer joins `${m.role}: ${m.content}` and asks for a "concise" summary. The system prompt says:

> Summarize this wedding planning conversation, preserving key decisions, dates, budgets, preferences, and action items. Be concise.

It does NOT instruct the model to preserve **tool calls** — i.e. "I created a checklist X with 8 items" or "I added a reminder for venue visit on 2026-06-12". These are critical state markers that the live `recentMessages` window doesn't always carry once the older window is collapsed.

Consequence: at turn 13, user says "remind me about my budget checklist". Assistant looks at recent 5 messages + a generic summary that says "user discussed budget and venue" and replies "What checklist? Want me to create one?" — even though the user already had a checklist created at turn 4.

The summarizer should be told to enumerate `ai_checklist_created`/`ai_note_created`/`ai_reminder_created`/`ai_timeline_event_created` actions from the older window, OR the chatController should preserve a parallel "actions taken so far" struct outside the LLM-input history.

## Steps to reproduce

1. Planner mode. Send a request that creates a checklist (e.g. "Make me a budget checklist with 5 items").
2. Send 9 more messages on other topics.
3. At turn 11, ask "remind me about that checklist I created earlier".
4. Assistant either fabricates or doesn't recall.

## Expected

Tool-call results from the older window are summarized explicitly, e.g.:

> Summary: …user discussed venue. Action items already taken: created checklist "Budget" (id ck_xxx) with 5 items at turn 4; created reminder "Venue visit" at turn 7…

## Actual

Tool calls are flattened into prose summary; IDs lost.

## Evidence

- `easebot-backend/src/services/conversationSummarizer.ts:7-8` (system prompt lacks tool-call directive)
- `easebot-backend/src/controllers/chatController.ts:725-728` (only role/content passed; toolActions on the message metadata layer not forwarded to summarizer)

## Notes

Fix-backend-api. Either enrich the summarizer prompt + pass artifact IDs explicitly, or stop summarizing tool-call turns (keep them verbatim) by partitioning olderMessages into prose-turns + tool-turns and only summarizing the prose.
