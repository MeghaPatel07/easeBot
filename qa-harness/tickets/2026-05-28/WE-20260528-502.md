## Description

While an SSE stream is producing tokens, if the user clicks browser-back (or routes away within the SPA), the `useChat` hook unmounts but the `AbortController` stored in `abortControllerRef` is never aborted. The fetch loop and SSE socket keep running on the dead component, costing tokens and producing no useful UX.

On forward-nav back to the chat, the partial assistant message is gone (state was lost on unmount) and there is no resume — the user sees the user bubble but no assistant reply.

## Code evidence

`useChat.ts`:
- `const abortControllerRef = useRef<AbortController | null>(null)` (line 203)
- `const controller = new AbortController(); abortControllerRef.current = controller` (line 409)
- `stopGeneration` is the ONLY function that aborts (line 941)

No `useEffect(() => { return () => controller.abort() }, [])` cleanup. No `popstate` / `beforeunload` listener that calls `stopGeneration()` in the chat page (`pages/Index.tsx` only has `beforeunload` for guest-session-data cleanup, line 858-868).

## Steps to reproduce

1. Start a long prompt: "give me a 2000-word essay about wedding venues".
2. After 1-2 seconds of token streaming, click browser back button.
3. Click forward.
4. Observe: user bubble present, NO assistant reply, NO retry affordance.
5. Open DevTools network: the original SSE request continues until BE completes (still costs OpenAI tokens).

## Expected

On unmount or popstate, abort the in-flight controller + call `/api/chat/cancel` so the BE stops the OpenAI call. The partial assistant text should either be persisted (Firestore for logged-in) or render a "this response was interrupted" hint.

## Actual

Stream orphaned. Tokens wasted. User sees no reply.
