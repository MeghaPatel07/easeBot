## Description

`computeStats` derives `today = new Date().toISOString().slice(0, 10)` at call time. The function is only re-invoked when `checklists` (the subscribe payload) changes — so a tab left open across midnight UTC will not promote newly overdue items into the overdue bucket until either Firestore pushes an unrelated update or the user reloads. While checklist toggles propagate fine via subscribeToChecklists, the time-derived metric is stale.

## Steps to reproduce

1. Add a checklist item with dueDate = today (UTC). Leave the tab open and idle.
2. Wait until just after 00:00 UTC.
3. Observe the overdue badge.

## Expected

Item moves to overdue at midnight UTC.

## Actual

Item stays in `todo` until any other checklist event re-triggers `computeStats`, or the user reloads.

## Evidence

- Screenshot(s): `qa-harness/evidence/WE-20260528-165/screenshots/`
- Console log: `qa-harness/evidence/WE-20260528-165/console.log`

## Notes

Add a `setInterval(() => forceRecompute(), 60_000)` in the Planner consumer OR move the today comparison into a memo that uses a state `now` value updated on a timer.
