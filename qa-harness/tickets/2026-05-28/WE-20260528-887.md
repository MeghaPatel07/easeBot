## Description

On mobile/tablet, the active note opens in a sheet/modal-ish surface. Clicking a different note in the sidebar list triggers state change (`activeNoteId`) AND the editor transitions content. For ~1 frame the previous note's content can render under the new note's title — a transient flash visible on slower devices (Android low-end).

Suspect cause: the editor's `useEffect([activeNoteId])` resets content asynchronously; the sidebar click optimistically updates `activeNoteId`; the render happens before the editor re-mounts with the new content.

## Steps to reproduce

1. Open /notes on mobile.
2. Open Note A.
3. Tap Note B in the sidebar quickly.
4. Observe 1-frame flash where Note A's body is visible under Note B's title.

## Expected

Either:
- `key={activeNoteId}` on the editor → React re-mounts cleanly per note.
- Transition between notes with a brief loading skeleton.

## Actual

Flash on transition.

## Evidence

- Reproducible at 4x CPU throttle.
