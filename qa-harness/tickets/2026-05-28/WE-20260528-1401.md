## Description

The streaming chat handler creates `const streamAbort = new AbortController()` on every request and wires it to `req.on('close', () => streamAbort.abort())`. The signal IS plumbed into `handleImageToolCall` (image gen + Firebase Storage upload honor it), but is NEVER passed to the Azure OpenAI client `chat.completions.create({...})` call inside `streamCallAzureAI` / `streamCallAzureAIWithToolResults`. There is no `signal` parameter on the OpenAI SDK call.

```ts
// services/azureAI.ts line 121
const stream = await client.chat.completions.create({
  model: process.env.AZURE_DEPLOYMENT_NAME!,
  messages,
  max_tokens: 4096,
  temperature,
  stream: true,
  stream_options: { include_usage: true },
  ...(tools && tools.length > 0 ? { tools, tool_choice: 'auto' } : {}),
})
// no signal: streamAbort.signal
```

Consequence: when a user stops generation mid-stream (or the client disconnects, or the LB drops the SSE socket), the Azure OpenAI completion **runs to completion** server-side. The full `completionTokens` are still consumed by Azure, AND `reconcile()` already debited `streamUsage.promptTokens + completionTokens` against the user's monthly cap because the for-await loop continues until `done` arrives. The user paid for tokens they never saw.

For a 4096-max-token completion that the user stops after 50 tokens streamed, the system still pays for ~4000 generated tokens. At pro-tier conversion: each cancelled long completion debits ~4000 tokens against the user's monthly 3M cap — a free-rider can't exploit this but a real user who hits Stop frequently will hit their cap orders of magnitude faster than they should.

## Steps to reproduce

1. Start a stream: `curl -N -X POST localhost:3001/api/chat/stream -d '{"message":"write a 2000-word essay on Indian weddings"}' -H "Content-Type: application/json"`
2. After ~3 chunks (~50 chars) arrive, Ctrl-C the curl process.
3. Watch backend logs — the `[chatController:stream] usage` line still fires with full `completionTokens` (1500+).
4. Inspect `X-Easebot-Tokens-Charged` on the partial response: full debit landed.

## Expected

Pass `signal: streamAbort.signal` into both `client.chat.completions.create` calls. When the client disconnects, the OpenAI SDK throws an AbortError and the upstream HTTPS connection to Azure is reset, stopping further token generation. The reconcile path should also debit only the tokens received before abort (using a running counter, not the SDK's final usage event which may not even arrive).

## Cost impact

Pro user at 30 sends/day × 25% stop rate × 4000 wasted completion tokens = **30,000 wasted tokens/day = 900K/month, 30% of their 3M cap consumed by cancelled completions they never read**. At scale of 1000 pro users: ~900M tokens/month wasted = real dollar cost.
