## Description

A message consisting purely of zero-width characters (ZWSP `U+200B`, ZWNJ `U+200C`, ZWJ `U+200D`, BOM `U+FEFF`) passes the sanitizer (which only strips `\x00-\x1F` ASCII control) and the Zod `.min(1)` check (length is non-zero).

Backend accepts and runs a full LLM call — burning tokens + quota — to handle effectively empty input. LLM responded "It seems like you might have something on your mind!" — wasted round-trip.

## Steps to reproduce

```bash
curl -s -X POST http://localhost:3001/api/chat \
  -H "Content-Type: application/json" \
  -d $'{"message":"​‌‍﻿"}'
# HTTP 200, LLM response generated, tokens billed.
```

## Expected

After trim, also strip default-ignorable codepoints (zero-width chars, BOM, soft hyphen). If empty, return 400 like other empty inputs.

## Actual

Zero-width chars pass; LLM call proceeds; tokens spent.

## Evidence

- `qa-harness/evidence/WE-20260528-205/repro.txt`

## Notes

Fix in `inputSanitizer.ts`:

```ts
function sanitizeString(value: string): string {
  return value
    .replace(/[\x00-\x08\x0B\x0C\x0E-\x1F\x7F]/g, '')
    .replace(/[​-‍﻿]/g, '')  // strip ZW chars + BOM
    .trim();
}
```
