## Steps to reproduce
1. Open reminders panel (active `subscribeToReminders` listener). Confirm it shows current list.
2. Disable network for 90s, then re-enable (simulate flaky wifi).
3. From another device/admin tool, create a new reminder.
4. Wait 30s in the original tab.

## Expected
Firestore SDK auto-reconnects the listener and new doc appears within 1-2s.

## Actual
- Firestore listeners DO auto-reconnect, but in our codebase the error handlers only `console.error` (e.g. reminderService.ts:283 — `(err) => console.error('[subscribeToReminders]', err.message)`).
- If the auth token expired during the offline window, `permission-denied` error is logged silently; UI shows stale list with no "reconnecting" indicator and no manual retry button.
- User has no signal anything is wrong until they reload.

## Root cause
No error-state propagation from listener error callbacks to UI.
