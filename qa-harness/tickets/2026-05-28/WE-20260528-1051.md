## Description

NONE of the email/password/phone Inputs in SignInModal, SignUpModal, or the forgot-password flow have `autocomplete=` attributes. WCAG 2.2 SC 3.3.8 explicitly requires that password fields support password-manager autofill — without `autocomplete="email"`, `autocomplete="current-password"`, `autocomplete="new-password"`, `autocomplete="one-time-code"`, password managers can't reliably populate, forcing users to manually transcribe credentials. This is the cognitive-test SC introduced in 2.2 and the most-cited failure path.

Affected fields (grep `type=` confirms zero `autoComplete` attributes in those files):
- Sign-in email + password
- Sign-up name, email, password, confirmPassword
- Forgot-password email + 6 OTP digit boxes (need `autocomplete="one-time-code"`)
- New password + confirm password steps

## Steps to reproduce

1. Open `/` → click "Sign in" in profile menu
2. Use a password manager (1Password / Bitwarden / iCloud Keychain)
3. PM does not auto-suggest credentials for this site because no semantic hint exists

## Expected

Per WCAG 2.2 3.3.8: form fields participating in authentication must support browser/password-manager autofill via `autocomplete` attributes.

## Actual

No autocomplete anywhere — users must remember and type credentials, defeating the purpose of password managers and excluding users with cognitive impairments.

## Notes

Fix: add `autoComplete="email"`, `autoComplete="current-password"` (sign-in), `autoComplete="new-password"` (sign-up + reset), `autoComplete="one-time-code"` (OTP inputs), `autoComplete="tel"` (PhoneInput), `autoComplete="name"` (full name).
