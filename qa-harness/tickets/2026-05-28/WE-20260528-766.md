## Description
The toneInjector line 89 reads `parts.push('Use relevant emojis throughout your responses to add warmth and visual appeal. 💕')` — note the literal 💕 in the instruction itself. When `emojis>70`, this emoji is in the system prompt verbatim. Models occasionally echo characters from their instructions, so this can leak a stray 💕 even into runs where the request doesn't merit one.

More importantly: when `emojis<30`, the line is `'Do not use emojis in responses.'` — but the assistant prompt baseline says "Use proper exclamations where natural" (line 18 of assistant.ts) and the baseline tonal warmth often produces unicode emojis like ✨ or 💐 organically. The hard "do not use emojis" suffix loses against the warm-baseline behavior unless emphatically overridden ("OVERRIDE: STRICTLY no unicode emoji characters U+1F300-U+1F9FF, no decorative symbols, no hearts").

## Steps to reproduce
1. `toneSettings.emojis=10` + "tell me about Indian weddings".
2. Count emoji in response — should be 0; will sometimes contain 1-3.
3. `emojis=90` + "give me planning advice" → check for 💕 specifically (the in-prompt char often echoes through).

## Expected
- Move 💕 out of the instruction string itself; describe emojis abstractly.
- For emojis=0, hard-override with "STRICT: zero unicode emojis. No hearts. No sparkles." + a post-response strip pass.

## Actual
Soft, occasionally violated by the model's own warmth heuristics. The literal 💕 in the system prompt is a leak vector.

## Notes
Easy code-only fix. Pair with a regex strip in the outbound pipeline as defense in depth.
