## Description

Chat-title strings auto-generated from first user message can include mixed bidi content: emoji at the start, Arabic in the middle, English at the end. Combined with `line-clamp-1` (which CSS-truncates with ellipsis) and a parent that doesn't set `dir="auto"`, the truncation truncates the START of the title in mixed-RTL scripts and pushes the visible portion to the wrong logical edge.

Example title: `💐 احتفال الزفاف with vendor list` (auto-generated by the chat-title summarizer).
Rendered in a LTR-default sidebar at mobile width:
- `line-clamp-1` cuts at character ~22.
- Browser renders: `💐 احتفال الز…` — but the ellipsis position depends on the bidi base direction, and in mixed content with no `dir="auto"`, browsers vary.
- On WebKit (iOS Safari, Chrome 120+) the Arabic chunk visually flows right-to-left inside an LTR container, making the truncation appear arbitrary.

Verified by source: `grep -rn "dir=" src/components/chat/ChatSidebar.tsx` → no matches.

## Steps to reproduce

1. Manually rename a chat to `💐 احتفال الزفاف with vendor list` (or send a message that generates a similar mixed title).
2. Open the sidebar at mobile width.
3. Observe truncated rendering varies per browser; bidi unclear.

## Expected

- Add `dir="auto"` to each chat-list item's title span.
- Test ellipsis position with `text-overflow: ellipsis` + `unicode-bidi: plaintext` for stable rendering.

## Actual

Inconsistent truncation in mixed-script titles.

## Evidence

- ChatSidebar.tsx (no dir attr on title span).
- Sprint 1 -210 covered chat bubbles only; this is sidebar titles.

Companion to -851 (system-wide RTL gap). This is the narrow case where the fix is one attribute.
