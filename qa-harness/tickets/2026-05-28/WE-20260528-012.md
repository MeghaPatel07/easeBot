## Description

Companion to WE-20260528-011 (FE). The backend payment row table is the source of truth for PayU initiate:

```ts
const PRICING: Record<string, Row> = {
  'pro:monthly':    { plan: 'pro',    cycle: 'monthly', usd: 10,  productinfo: 'Easebot Pro — Monthly' },
  'pro:annual':     { plan: 'pro',    cycle: 'annual',  usd: 79,  productinfo: 'Easebot Pro — Annual' },
  'promax:monthly': { plan: 'promax', cycle: 'monthly', usd: 39,  productinfo: 'Easebot Pro Max — Monthly' },
  'promax:annual':  { plan: 'promax', cycle: 'annual',  usd: 299, productinfo: 'Easebot Pro Max — Annual' },
  'topup_2m:once':  { plan: 'topup_2m', cycle: 'once', usd: 10,  productinfo: 'Easebot Top-up — 2M tokens' },
}
```

Locked memory (`project_pricing_rollout` §6) says **Pro = $14.99/mo or $119/yr**. The payment-hash test fixtures use a price of `1299.00` INR (≈ $14.99 × ~86), so the original spec contract was the locked value; the runtime table never caught up.

Result: every real PayU initiate today sends the wrong amount in the hash. Invoice generator (`invoiceService.ts:74`) reads `priceUsd` from the stored row and propagates the wrong number through the entire downstream subscription state machine.

## Steps to reproduce

(read-only confirmation — no live PayU call)

```
grep -n "'pro:" easebot-backend/src/controllers/paymentController.ts

```


→ test fixture uses `1299.00` (the *correct* INR amount for $14.99 at the locked rate).
