## Description

Voice control users say "Click [label]" to activate controls. The label must match the visible / accessible name. Several icon-only buttons:
- AudioPlayer Close `<button onClick={onClose}>` line 258 — NO aria-label, just X icon. Voice user says "Click X" → may match or may not.
- AudioPlayer Retry button line 251 — has visible "Retry" text so OK
- ImageActions.tsx — multiple icon-only buttons without aria-label
- The reset chip at Index.tsx:1608 has both `title` and `aria-label="Reset occasion and mode"` — good example, but title-only buttons elsewhere only show on hover (mouse-only), not announced to voice control

Voice Control specifically uses `accessibility label` AND `name` AND any visible text. Without aria-label on icon-only buttons, the user must say something like "Click button" and pick from numbered overlay — friction multiplier ~3×.

## Steps to reproduce

1. macOS: System Settings → Accessibility → Voice Control ON
2. Open `/`, say "Show numbers"
3. Numbered targets appear; many icon-only buttons get numbers but no semantic label — user must memorize numbers per session

## Expected

EVERY icon-only `<button>` has `aria-label="<verb> <object>"` matching the user's mental model — "Close", "Play audio", "Pause audio", "Share image", "Like image", "Delete image", etc.

## Actual

Mix: some buttons labeled, many not. Inconsistent.

## Notes

Combine with Switch Control review — same buttons are scanned by switch users; missing labels = inscrutable.
