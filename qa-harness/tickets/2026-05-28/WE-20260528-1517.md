# WE-20260528-1517 — Two Firebase SDKs loaded: firebase-admin (backend) AND firebase JS web SDK (also backend) via imageStorage

**Severity:** P2
**Status:** triaged
**Assigned:** fix-performance
**Area:** Performance / Backend bundle
**Discovered:** 2026-05-28

## Symptom
The backend imports BOTH:
1. `firebase-admin/app|auth|firestore` — used in `lib/firebaseAdmin.ts` for auth verification and admin Firestore writes
2. `firebase/firestore`, `firebase/storage` (JS web SDK) — used in `services/imageStorage.ts` via `lib/firebase.ts`

Two competing SDKs both initialized at process start, both holding gRPC connection pools, both with different auth flows.

## Why this matters
- **Cold-start cost:** ~150-300ms additional JS parse + initialization for the web SDK
- **Memory:** ~30-50MB resident for duplicated Firestore client code
- **Auth confusion:** Storage uploads via web SDK use anonymous-ish auth; the admin SDK uses service-account — security implication noted but out of scope for perf ticket

## Suggested fix
Migrate `imageStorage.ts` to use `firebase-admin/storage` (`getStorage(adminApp).bucket(...).file(...).save()`) and `adminDb` from `firebaseAdmin.ts`. Remove the `firebase` (web) dependency from the backend.
