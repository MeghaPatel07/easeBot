## Description

Sending a 22MB body returns:

```
HTTP/1.1 413 Payload Too Large
Content-Type: application/json
{"error":"request entity too large","code":"INTERNAL_ERROR"}
```

The status code 413 is correct. The error.code field labels it `INTERNAL_ERROR` — same mislabeling as WE-20260528-209 (malformed JSON returned `INTERNAL_ERROR` for a 400). Anything not matched explicitly is funneled into one generic code, polluting alerts.

## Steps to reproduce

```bash
python3 -c "import json; print(json.dumps({'message':'hi','imageData':'x'*(22*1024*1024)}))" > /tmp/huge.json
curl -s -X POST http://localhost:3001/api/chat -H "Content-Type: application/json" -d @/tmp/huge.json
```

## Expected

```json
{ "error": "Request body too large (limit 20MB)", "code": "PAYLOAD_TOO_LARGE" }
```

## Actual

```json
{ "error": "request entity too large", "code": "INTERNAL_ERROR" }
```
