# WE-20260528-1118 — Translator `withRetry` adds up to 4.5s on a cold call before failing — no circuit-fast-path on first attempt

**Severity:** P3
**Status:** triaged
**Assigned:** fix-performance
**Area:** Performance / External service retry policy
**File:** `easebot-backend/src/services/translation.ts:32-52`
**Discovered:** 2026-05-28

## Symptom
`detectLanguage()` and `translateText()` wrap their fetches in:
```ts
withRetry(async () => { ... }, { maxRetries: 2, baseDelayMs: 500, maxDelayMs: 4000 })
```

In the worst case Azure returns 429 or 5xx three times consecutively:
- Attempt 1: ~150ms
- Sleep 500ms → Attempt 2: ~150ms
- Sleep 1000ms (exp backoff) → Attempt 3: ~150ms
- Total: ~2000ms before the circuit breaker can even kick in.

Measured live: one of 5 detect calls took 442ms (3× the median). One translate call took 1048ms — likely Azure throttling.

## Why P3
This is a tail-latency concern, not a steady-state issue. But when it stacks with image post-processing (-1103, 8s), summarization (-1110, 2s), and uncached TTS (-1105, 1s), the worst-case turn latency exceeds 15s.

## Suggested fix
1. Skip retry on `detect()` entirely — wrong-language default is "en" anyway, a single attempt is fine. Saves up to 1.5s.
2. Reduce `maxRetries` from 2 → 1 on `translate()` for non-critical short text (mascot prompts, system strings).
3. Add `AbortSignal` with 1s timeout per attempt so a hung Azure connection can't block the whole turn.
