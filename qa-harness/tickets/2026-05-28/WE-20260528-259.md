## Description

Page hierarchy: h1 "Help & Feedback" → (no h2) → h3 inside each accordion trigger. WCAG heading-order requires monotonic increase. Axe flags `heading-order` violation. SR users navigating by headings hop straight from h1 to h3, implying a missing h2 group ("FAQ" should logically be the h2 wrapper).

## Steps to reproduce

1. Open `/help`.
2. Use SR Headings rotor.

## Expected

h1 Help & Feedback → h2 FAQ → h3 question → h3 question; then h2 Support & Feedback for tab 2.

## Actual

h1 → h3, h3, h3 directly.

## Evidence

- `qa-harness/evidence/a11y-2026-05-28/help/axe.json` — `heading-order` violation.

## Notes

shadcn `AccordionTrigger` renders an `<h3>` via `AccordionPrimitive.Header`. The wrapping group should declare an h2 above the Accordion (e.g. visually-hidden if design doesn't want it visible).
