## Description

Sending a malformed JSON body returns:

```json
{"error":"Expected property name or '}' in JSON at position 1","code":"INTERNAL_ERROR"}
```

HTTP status is 400 (correct), but:
1. `code: "INTERNAL_ERROR"` is wrong — this is a *client* error (malformed body). The code should be `BAD_REQUEST` / `MALFORMED_JSON`. This routing of all errors through the same code complicates alerting (any spike in INTERNAL_ERROR could be hostile parsing attempts or a real backend exception — indistinguishable).
2. The raw JSON parser message (`"Expected property name or '}' in JSON at position 1"`) leaks the internal parser implementation. Low-stakes, but inconsistent with the otherwise clean error surface.

## Steps to reproduce

```bash
curl -s -X POST http://localhost:3001/api/chat -H "Content-Type: application/json" -d "{message:notjson"
```

## Expected

```json
{ "error": "Invalid JSON in request body", "code": "BAD_REQUEST" }
```

## Actual

```json
{ "error": "Expected property name or '}' in JSON at position 1", "code": "INTERNAL_ERROR" }
```
