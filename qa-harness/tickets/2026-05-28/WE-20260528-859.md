## Description

App.tsx mounts **two competing toast systems** simultaneously:
```tsx
import { Toaster } from "@/components/ui/toaster";                    // shadcn Radix toaster
import { Toaster as Sonner } from "@/components/ui/sonner";           // sonner library
…
<Toaster />   // line 62 — Radix viewport at top-0 / sm:bottom-0 right-0
<Sonner />    // line 63 — sonner viewport (default bottom-right)
```

Consequences:
- Every call to `toast()` from `@/hooks/use-toast` (Radix) fires in the Radix viewport. Every call to `toast()` from `sonner` (e.g. some `import { toast } from "sonner"`) fires in the sonner viewport. Same global JS identifier but different routing.
- The two viewports both want bottom-right on desktop → they STACK on each other, creating two parallel toast columns separated by ~16px.
- The shadcn toaster theme is `bg-card-elevated` and gets dark/light from theme tokens. The sonner config (`src/components/ui/sonner.tsx`) hard-codes `theme="dark"` — sonner toasts are always dark even in light mode (visible inconsistency).
- Bundle weight: sonner ~12KB, Radix toast ~6KB — paying for both for no reason.

## Steps to reproduce

1. `grep -rn 'import.*toast' src/` shows mixed imports — some files use `@/hooks/use-toast`, others use `sonner`. Both end up on screen.
2. Trigger one of each (e.g. open FeedbackDialog → success uses `useToast`; open ImagesHub → some flows use sonner directly).
3. Observe two viewports.

## Expected

Pick one. Recommend keeping `@/hooks/use-toast` (matches our shadcn/Radix stack) and removing sonner entirely:
- Delete `src/components/ui/sonner.tsx`.
- Remove `<Sonner />` from App.tsx:63.
- Remove the `sonner` package from `package.json`.
- Rewrite the few `import { toast } from 'sonner'` callsites to use `useToast()`.

## Actual

Two systems running in parallel.
