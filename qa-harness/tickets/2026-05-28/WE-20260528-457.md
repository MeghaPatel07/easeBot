## Description

Confirmed by automated audit: there are **zero** `print:hidden` Tailwind utility classes anywhere in the rendered DOM and **no `@media print` block** in `index.css`. Print preview on /privacy, /terms, /help shows:
- The decorative rose-gradient + pink-mosaic background fills every page (wastes ink, possibly unreadable on cheap printers)
- The WeddingEaseFloater mascot button prints in lower right of every page
- The header "Back to TheWeddingBot" navigation prints
- The AnalyticsConsent banner prints if the user hasn't dismissed it
- No page-break-after on h2 section dividers in /privacy → sections split awkwardly

For a wedding-planning app where legal docs and helper guides are commonly printed/PDF-saved, this is a regression from baseline web hygiene.

## Steps to reproduce

1. Open `http://localhost:8081/privacy`
2. File → Print (or DevTools → Rendering → Emulate CSS media `print`)
3. Note background gradients, floating button, header nav all present

## Expected

A scoped `@media print` block that:
- Removes decorative backgrounds (`background: none !important`)
- Hides interactive chrome (`header, footer, nav, .floater, .analytics-consent { display: none }`)
- Sets `color: black; background: white` on body
- Adds `page-break-after: avoid` to h2 headings

## Actual

App prints as if it's a screen render — wasted ink, visually messy PDF saves.
