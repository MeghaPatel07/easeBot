## Description

The single most important interactive element in the product — the chat composer `<textarea>` — has no `aria-label`, no `<label for>` association, no `aria-labelledby`. Screen readers announce only "edit, blank" with no purpose. Placeholder text is dynamic ("Recording…", "Transcribing…", or props value) and disappears as soon as the user types, so it cannot substitute for a real label.

## Steps to reproduce

1. Open `http://localhost:8081/` with VoiceOver enabled (Cmd+F5).
2. Tab to the composer textarea at the bottom of the page.
3. Listen to the announcement.

## Expected

Screen reader announces: "Message TheWeddingBot, edit text" (or similar persistent purpose).

## Actual

Announces only "edit, blank" — no semantic context.

## Evidence

- Source: `src/components/chat/ChatInput.tsx:393` — `<textarea>` with `placeholder=` only, no `aria-label`.
- Axe rule: `label` violation present on home in `_summary.json` (`inputsNoLabel` includes ChatInput textarea).
- Screenshot: `qa-harness/evidence/a11y-2026-05-28/home/page.png`.

## Notes

Recommend `aria-label="Message TheWeddingBot"`. This blocker prevents an SR user from operating the product at all.
