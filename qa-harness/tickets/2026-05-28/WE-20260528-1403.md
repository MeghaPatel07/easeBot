## Description

`schemas/chat.ts`:
```ts
mode: z.enum(['planner', 'styler', 'knowledge']).optional(),
```

But everywhere else in the codebase: `'stylist'`. `chatController.buildSystemPrompt` switches on `mode === 'stylist'` and `getStylistPrompt()`. The non-stream `/api/chat` accepts `mode: 'styler'` (validateBody passes) but the controller's switch never matches, falling through to assistant mode. Sending `mode: 'stylist'` on `/api/chat` returns 400 from validateBody before reaching the controller.

Net effect: client requests for stylist mode either silently misroute to assistant (if they happen to send 'styler') or fail with 400 (if they send the correct 'stylist'). The stream endpoint accepts both (no validation — see -1402).

## Steps to reproduce

```bash
# Correct mode rejected
curl -s -X POST http://localhost:3001/api/chat -d '{"message":"hi","mode":"stylist"}' -H "Content-Type: application/json" -w " %{http_code}\n"
# → 400

# Typo'd mode accepted but silently downgrades
curl -s -X POST http://localhost:3001/api/chat -d '{"message":"hi","mode":"styler"}' -H "Content-Type: application/json" -w " %{http_code}\n"
# → 200 (but controller routes to default/assistant — stylist prompt never loaded)
```

## Expected

Schema enum should be `['planner', 'stylist', 'knowledge', 'assistant']` (or whatever the canonical set is — `Mode` type lives in `src/types.ts`).
