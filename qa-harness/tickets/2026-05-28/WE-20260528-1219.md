## Description

`GeolocationService.getUserCurrency` is invoked from `Pricing.tsx:258` on mount. Without override, it fetches `ipgeolocation.io/ipgeo` and caches in localStorage for 24h. On an incognito session or a fresh device this is **one network round-trip on the critical-path LCP** to render the price.

ipgeolocation latencies observed in prior QA: 200-800ms from non-IN egress. Pricing UI flashes USD→INR (or whatever) after this fetch lands.

## Steps to reproduce

1. Clear localStorage. Hard-load `/pricing`. DevTools network → see `ipgeolocation.io/ipgeo` and its latency.
2. Compare to LCP. Pricing currency-dependent fields (the displayed amount) won't render finally until this resolves.

## Expected

Use the existing `Accept-Language` header heuristic to seed an initial guess synchronously (e.g. `en-IN` → INR, `en-US` → USD) and lazy-fix to ipgeo result. Or render USD immediately and update post-hydration without layout shift.

## Actual

Network-blocking currency resolution on first paint of /pricing.
