## Description

Flip `users/{uid}.tierMirror = 'pro'` (or `plan = 'promax'`) directly in Firestore to simulate the post-upgrade webhook fan-out. The three tier-aware UI surfaces show inconsistent behaviour:

- **TokenPoolBar / TokenMeter**: `useTokenPool` derives tier via `resolveTier(profile)` where `profile` is `useAuth().profile` — the frozen sign-in snapshot (WE-20260528-152). Tier badge remains `Free`. `getLimits(tier)` returns Free limits, so the bar mathematically caps the bar at the WRONG maximum (e.g. 100k tokens instead of 3M).
- **ProfileMenu**: `tier = plan?.tier ?? profile.plan ?? …` — `plan` comes from `useAccount()` which has `staleTime: 30_000` and only invalidates on `updateProfile` mutations called from inside the app. A backend-driven flip never invalidates. So upgrade CTA "Upgrade plan" continues to display for up to ≥30s and indefinitely if the user doesn't trigger a refetch.
- **AccountTab Plan badge**: same as ProfileMenu — uses `useAccount`.

Net: a user who just paid will keep seeing "Upgrade plan" + Free-tier token limits until they reload, an embarrassing experience post-purchase.

## Steps to reproduce

1. Sign in as a Free-tier user. Open ProfileMenu — note "Free" badge + "Upgrade plan" CTA + token meter showing Free caps.
2. In Firebase console, edit `users/{uid}` → set `tierMirror = 'pro'` AND `plan = 'pro'`. Save.
3. Without reloading the browser, re-open the ProfileMenu and observe TokenPoolBar.

## Expected

Within ~1 s the badge flips to Pro, CTA changes to "Manage plan", token-meter caps re-scale.

## Actual

Badge stays Free, CTA stays "Upgrade plan", token meter still scaled to Free caps. Reload required.

## Notes

This is the most user-visible state-sync failure tied to revenue. Fix requires the AuthContext listener (WE-20260528-152) AND either dropping `useAccount`'s `staleTime` to 0 for the plan portion or invalidating `['account','me']` from the user-doc listener.
