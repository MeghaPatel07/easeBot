## Description

The eye / eye-off button to toggle password visibility carries `tabIndex={-1}`. Mouse users can reveal their password; keyboard-only and switch users cannot. Same pattern on the new-password and confirm-password fields in the forgot-password flow.

## Steps to reproduce

1. `/login` → enter email → continue → land on password step.
2. Use only Tab — focus skips the eye toggle, lands on Sign In.
3. There is no keyboard path to reveal what was typed.

## Expected

`tabIndex={0}` (or simply remove the attribute — default for `<button>` is 0). Provide accessible name `aria-label="Show password" | "Hide password"` that flips with state. Optionally, allow Space/Enter to toggle.

## Actual

Keyboard users cannot verify typed password content before submission.

## Notes

The button already has visual feedback; only keyboard reachability + accessible name needs fixing.
