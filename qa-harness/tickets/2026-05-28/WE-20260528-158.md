## Description

`Index.tsx:250-253` syncs `preferredLang` local state from `profile?.preferredLanguage` only when the latter changes. Since `useAuth().profile` is the frozen sign-in snapshot (WE-20260528-152), changing `preferredLanguage` via Settings won't fire the dep change — the effect never re-runs. Downstream: `useVoice` STT calls use the OLD language, TTS playback uses the OLD language (the previous chat header dropdown selection persists), and chat send-message payloads reference `preferredLang` from local state. The header dropdown does call `setPreferredLang` directly so changing language THERE works, but the Settings tab path is broken.

## Steps to reproduce

1. Sign in. Pull up Settings → Personalization. Change preferredLanguage from "en" to "hi". Save.
2. Without reload, click the mic and speak a phrase in Hindi.

## Expected

STT recognizes Hindi (the new pref).

## Actual

STT still uses English (the previously-cached value). Reload restores expected behaviour.
