## Description

Sprint 3 brief regression-checklist line: "PR #33 fixes WE-20260527-211 (system-role filter) — already verified live via WE-20260528-201 in Sprint 1; re-confirm now."

Confirmed at 17:30Z that the schema still accepts `role: 'system'` in `history[]` and the controller continues to spread the entire history (including system entries) into the LLM call. PR #33 has NOT been merged to `main` and the running backend on :3001 still exposes the channel.

Today the LLM happened to resist the "pirate slang" override variant, but more aggressive payloads (Felicity rename per WE-20260528-016, identity reveal) still succeed. The CHANNEL is the bug — not which specific payload lands. Until the schema drops `'system'` and the controller filters defensively, this is a P0 prompt-injection vector.
