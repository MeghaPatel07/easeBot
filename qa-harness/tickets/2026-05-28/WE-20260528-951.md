## Steps to reproduce
1. Open app at `/`, sign in, open a conversation.
2. Chrome DevTools, Network, Offline.
3. Type and send a message. `userMsg` is appended optimistically by `useChat.sendMessage` (useChat.ts:406).
4. The fetch fails immediately with TypeError (offline). The catch path appends an AI error bubble "Something went wrong" (useChat.ts:854).
5. Toggle "Online" — observe.

## Expected
Either the original user message stays clearly marked "queued" / "failed — tap to retry", OR a retry happens automatically once `navigator.onLine` flips true.

## Actual
- Optimistic user bubble persists with no failure marker (no `pending`/`failed` flag exists on the Message type).
- A generic AI error bubble is appended.
- On reconnect, nothing retries; the user must manually re-type and resend.
- No `window.addEventListener('online', ...)` exists anywhere — verified `grep -rn "addEventListener.*online" src` returns 0 matches.

## Root cause
`useChat.ts` has no offline detection, no retry queue, no message status field. Messages move directly from optimistic-append, to AI-error-bubble with no intermediate "failed" state and no reconnect handler.
