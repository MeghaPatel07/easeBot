# WE-20260528-1527 — Vite dev proxy `/ingest` → backend even though PostHog SDK ingests events the same way — config drift

**Severity:** P3
**Status:** triaged
**Assigned:** fix-frontend
**Area:** Performance / Dev DX
**Discovered:** 2026-05-28

## Symptom
`vite.config.ts:21-25` proxies `/ingest` to the backend (`localhost:3001`). The backend then has `ingestRouter` mounted at `app.ts:68` that forwards to PostHog. In production, PostHog is hit directly via `VITE_POSTHOG_HOST`.

Each `track()` call in dev makes a hop: browser → vite dev server (8080) → backend (3001) → PostHog (us.i.posthog.com). Adds ~5-20ms per event in dev. In dev, with high-frequency events (`message_sent`, `gallery_image_viewed`), this proxy roundtrip can show up as fake "slow analytics" timings.

## Why this matters
- Devs reading dev tools network panel see spurious 50-100ms delays on /ingest that don't exist in prod.
- Backend dev terminal is noisier than necessary.

## Suggested fix
1. In dev, bypass the proxy and hit PostHog directly: `VITE_POSTHOG_HOST=https://us.i.posthog.com`.
2. OR document this clearly in `claude_code_setup.md` so future agents don't chase a phantom regression.
