## Description

Two small but compounding edge cases:

1. Emoji-only message (`"🎉🎉🎉"`) passes both client and server validation, gets sent. Server responds in English (no detected language anchor). Acceptable, but note that PostHog `data-ph-mask` strips text — the analytics dashboard sees an empty body.

2. While recording, the placeholder swaps to `'Recording…'` / `'Transcribing…'` (line 405-407) using a horizontal ellipsis `…` (U+2026). In RTL mode (after WE-20260528-210 fix), this character's bidi class is ON (Other Neutral), meaning placement depends on surrounding chars. With no `dir="auto"` on the textarea, it renders mid-line in unpredictable position when the user has typed Arabic before recording.

## Steps to reproduce

1. Emoji-only: type `🎉🎉🎉` → Send → server returns a generic response.
2. Bidi: in Arabic mode, start a voice recording → observe placeholder position.

## Expected

- For analytics, hash the message length + has-emoji flag instead of full mask, so the funnel can detect "emoji-only message" as a pattern.
- For RTL composer placeholder, use `dir="auto"` (links to WE-20260528-210).

## Actual

Emoji passes silently; ellipsis placeholder positions unpredictably in RTL.
