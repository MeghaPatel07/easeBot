## Description

SSE event delimiter is `\n\n`. If the JSON payload in `data:` contains a literal `\n\n` (e.g. `{"t":"c","v":"line1\n\nline2"}` — possible if the LLM emits two consecutive newlines in a single chunk), the on-wire bytes will be:

```
data: {"t":"c","v":"line1

line2"}

```

Most SSE parsers (EventSource, custom fetch-stream readers) split on `\n\n` AT THE WIRE LEVEL, not inside the data field. The chunk after the embedded `\n\n` becomes an orphan "line2"}" frame and either:
- Throws JSON.parse error in the client → swallowed by try/catch, missing tokens in display.
- Crashes the stream loop if no try/catch.

Server-side fix: JSON.stringify the data BEFORE writing the SSE frame, AND escape any embedded `\n` in the wire encoding (the standard is to prefix each `data:` line; multi-line data uses repeated `data:` lines).
