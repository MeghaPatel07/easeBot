## Description

```
curl http://localhost:3001/api/notes/shared/AAAA...(5000 chars)
HTTP 500 {"error":"value for publicShareId is too large to be used in a query"}
```

The handler catches `err` and only routes "Shared note not found" -> 404; everything else -> 500 with `err.message` as the body. This leaks:
1. The backing store is Firestore (the error wording is Firestore-specific).
2. The query field is literally named `publicShareId` (confirms our schema for blind reconnaissance).

Per Sprint 1 ticket WE-20260527-201 the same pattern was filed on `requireAuth`. The notes controller has identical raw-error passthrough on every method (`handleCreateNote:25`, `handleGetNote:39`, `handleUpdateNote:55`, etc.).

## Suggested fix

1. Length-validate `req.params.shareId` early: reject anything outside `/^[a-f0-9-]{36}$/` (UUID v4 shape) with 404.
2. Globally, never echo `err.message` from a 500 path. Log internally, return `{error:"Internal server error", code:"INTERNAL"}`.
