## Steps to reproduce
`grep -rn "BroadcastChannel" /Users/krish/Desktop/easebot/Wedding-Ease-Viva-Chat/src` → 0 results.

## Expected
For events that don't fit the localStorage pattern (e.g. "user just sent a message in tab A → tab B's notification dot should clear", "conversation just deleted in tab A → remove from tab B's history list", "subscription upgraded in tab A → tab B's token meter should refresh tier label"), the app should use `BroadcastChannel('easebot')` to fan out signals.

## Actual
No cross-tab event bus. The only cross-tab pathway is Firestore `onSnapshot` (which works for data persisted to Firestore) — but per-session UI state (active conversation id, draft text, scroll position, notification badge) has no propagation at all.

## Impact
P2 — degraded multi-tab UX; not a data-loss bug per se, but compounds with the per-feature stale issues filed individually (theme, auth, drafts, guest counts).

## Fix direction
Add `src/lib/broadcastBus.ts`:
```ts
const bc = typeof BroadcastChannel !== 'undefined' ? new BroadcastChannel('easebot') : null
export const broadcast = (type: string, payload?: unknown) => bc?.postMessage({ type, payload })
export const subscribe = (handler: (msg: {type:string, payload?:unknown}) => void) => {
  if (!bc) return () => {}
  bc.addEventListener('message', e => handler(e.data))
  return () => bc.removeEventListener('message', e => handler(e.data))
}
```
Then publish from logout, profile patch success, conversation delete, plan upgrade webhook handler. Subscribers invalidate React Query keys + Zustand stores.
