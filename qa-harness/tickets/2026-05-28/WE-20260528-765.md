## Description
`concise>70` → "Answer in 1–3 sentences unless more detail is truly necessary." `concise<30` → "Be thorough and detailed." Sprint 1 -353 saw verbosity=0 ignored — this is the related concise slider sibling. The bigger problem: BOTH the assistant.ts and planner.ts prompts have hardcoded RESPONSE STRUCTURE blocks (ACKNOWLEDGE → GUIDE → LEADING QUESTION) that mandate 3 sections. So even with concise=100, the model is structurally compelled to emit 3 sections — it just makes each shorter.

Real-world target: concise=100 should produce a SINGLE-SENTENCE answer with maybe a one-word question hook. Current output remains 3 lines minimum.

## Steps to reproduce
1. `concise=100` + "what's the best wedding date in december?" → expect ≤2 sentences. Get 3-4 sentences across ACKNOWLEDGE / GUIDE / QUESTION.
2. `concise=0` + same → expect 6-8 sentences. Get ~4-5.

## Expected
- At concise≥90, override the RESPONSE STRUCTURE: "Collapse to ONE sentence + ONE 3-word question. Skip ACKNOWLEDGE."
- At concise≤10, expand: "Use 5-7 sentences per section, give 2 examples."

## Actual
Mild observable diff. Sliders feel ornamental, not functional.

## Notes
Related: -353, -764. All slider tickets share the same root cause: the structural prompt overrides the slider suffix. Need an "OVERRIDE STRUCTURE" mode for extreme slider values.
