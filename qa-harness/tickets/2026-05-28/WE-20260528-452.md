## Description

At iPad Pro 1024 portrait, the AnalyticsConsent banner sits centered low-bottom but its width spans across the chat-input + chip rail area. The send-button + mascot trigger are clipped behind the banner. The theme-chips ("Cocktail", "Wedding", etc.) are HALF behind the banner. A guest cannot dismiss the banner without first tapping inside it — and cannot start a chat until they do.

iPad-Pro-portrait users (wedding planners, common per project notes) **cannot type or send their first message until they accept/decline analytics**. This is a P0 onboarding flow blocker on that device class.

## Steps to reproduce

1. Clear cookies/localStorage
2. Open http://localhost:8081/ at iPad Pro 1024×1366 portrait
3. Try to find / tap chat input — it is behind the consent banner

## Expected

Banner is anchored above the chat-input rail with `padding-bottom: env(safe-area-inset-bottom) + input-rail-height` OR rendered as a top-of-page strip. Primary chat surface always reachable.

## Actual

Chat surface obscured; new user cannot begin onboarding flow on iPad portrait.
