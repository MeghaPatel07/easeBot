## Description

Login error banners are correctly `role="alert"` (good — assertive announcement) but:

1. The error text passed to `setError(...)` is the raw Firebase error (e.g. "auth/invalid-credential" or "auth/email-already-in-use") — not user-friendly OR mapped to a recovery action.
2. The alert is not programmatically associated with the form field that caused the error. SR users hear the error in isolation, then must re-navigate to figure out which field.
3. The same `<div role="alert">` is rendered above the form (never below the offending field), so the spatial relationship is lost for sighted users too.

## Steps to reproduce

1. SR on, /login
2. Enter wrong password, submit
3. Listen — "auth/wrong-password" or similar raw code, no field reference

## Expected

Map every Firebase error to a friendly sentence ("That password doesn't match. Try again or tap 'Forgot password?'"). Add `aria-describedby` from the password input to the alert id. Optionally render the error inline beneath the failed field.

## Actual

Raw codes, banner-only placement, no field linkage.

## Notes

Same pattern in SignInModal.tsx and SignUpModal.tsx — propagate fix.
