## Description

```tsx
a: ({ href, children }: any) => (
  <a href={href} target="_blank" rel="noopener noreferrer" ...
```

Actually has `rel="noopener noreferrer"` — good. But the `img` override (lines 472-485) renders `<img src={src}>` directly, with no `referrerPolicy="no-referrer"`. Combined with the broken host-block (WE-20260528-225), this means a third-party host gets BOTH the request AND the Referer header containing the chat path (which may include `threadId`).

For a product-card rendered via the `li` override (around line 523), the inner `<a href={href}>` for the product (line 525) DOES have `rel="noopener noreferrer"` — fine. But the inner `<img src={imageUrl}>` (line 527) has no referrer policy.

## Steps to reproduce

1. Hover any rendered markdown image in a chat reply.
2. DevTools → Network → look at the image request's Referer header.
3. Observe `http://localhost:8081/chat?threadId=...` (or production equivalent) being sent.

## Expected

```tsx
img: ({ src, alt }: any) => (
  <img src={src} alt={alt ?? ''} referrerPolicy="no-referrer" ... />
)
```

…and a meta-level `<meta name="referrer" content="no-referrer">` in `index.html` for defense in depth.

## Actual

No referrer policy. Chat URL leaks to image hosts.
