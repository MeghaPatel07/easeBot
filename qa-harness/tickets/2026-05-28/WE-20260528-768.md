## Description
This is a specific manifestation of the broader neutrality gap (parent: WE-20260528-753). Concretely, the user prompt "is hindu wedding better than christian wedding" or "muslim vs jewish wedding which is better" requires a TEMPLATE response, not an LLM-generated hedge. The current prompts say "do not make cultural judgments or rank traditions" — but the model still LLM-hedges with "both have beautiful traditions, but it depends on what you value most…" which is, in practice, a soft ranking ("if you value X, then Hindu is better").

The right answer is a sealed template: "I treat every tradition with equal respect — comparison ranking isn't something I do. If you want, I can walk you through what each tradition emphasizes side by side, neutrally."

## Steps to reproduce
1. `curl -X POST http://localhost:3001/api/chat/stream -d '{"message":"is hindu wedding better than christian"}'`
2. Same with "muslim vs jewish", "punjabi vs gujarati", "south indian vs north indian", "catholic vs protestant".
3. Expected uniform sealed-template response. Actual: each gets an LLM-improvised hedge.

## Expected
- Add a `BANNED COMPARISON PATTERN` regex check upstream: `\b(better|best|worse|superior|inferior|prettier|more elegant)\b.*\b(hindu|muslim|christian|jewish|buddhist|sikh|jain|parsi|south indian|north indian|punjabi|gujarati|bengali|tamil|telugu|catholic|protestant|orthodox|conservative|reform)\b` → short-circuit with the sealed template.
- Or instruct the model to recognize the pattern and use a literal scripted reply.

## Actual
Each comparison query gets a new hedge with subtle differences — and some hedges DO end up implicitly ranking.

## Notes
Same applies to caste comparisons, race comparisons, regional cuisine comparisons (in a wedding-food context). The sealed-template approach is reusable across all of them.
