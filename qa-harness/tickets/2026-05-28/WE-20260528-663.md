## Description

The consent banner uses `role="dialog"` and `aria-label="Analytics consent"`. However:

- It is NOT modal — focus stays in the page behind, no Escape behavior, no focus trap
- The 3-line privacy explanation has no associated heading — SR users hear "dialog, Analytics consent" then unrelated paragraph text
- It's actually closer to a `region` or `complementary` landmark than a dialog. Using role=dialog implies modality

This is the *first* thing a guest user encounters on the site. If SR users hit it and find it confusing, they may abandon the entire experience.

## Steps to reproduce

1. Clear localStorage (or use a fresh incognito window)
2. SR on, load `/`
3. Listen — "dialog: Analytics consent" then awkward paragraph text without context

## Expected

Either: (a) make it a real Radix Dialog with DialogTitle, OR (b) downgrade to `<aside role="region" aria-labelledby="consent-heading">` with a visible `<h2 id="consent-heading">`. The latter is preferable — it's a persistent banner, not a blocking modal.

## Actual

Faux-dialog with no title.

## Notes

Bonus: the Decline button is rendered first in DOM order (line 53) before Accept (line 59). For keyboard users, default focus follows DOM order — meaning the "destructive" decline option is focused first. Swap order so Accept is the primary visual + DOM focus.
