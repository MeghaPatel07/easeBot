# WE-20260528-1532 — Frontend has 138 track() call sites — bundled localStorage write storm during peak interaction

**Severity:** P3
**Status:** triaged
**Assigned:** fix-performance
**Area:** Performance / Analytics overhead
**Discovered:** 2026-05-28

## Symptom
`grep -rn "track(" /Users/krish/Desktop/easebot/Wedding-Ease-Viva-Chat/src/ | wc -l` → **138 call sites.**

posthog-js by default writes to localStorage on every event capture (for persistence + de-dup). Each call:
- Serializes the event payload to JSON (~50-200 bytes)
- Reads existing queue from localStorage
- Appends + writes back

On the chat send path, a single send fires: `first_message_sent` (if first), `message_sent`, internally `$pageview` may also fire — 2-3 writes within 50ms.

## Why this matters
- localStorage writes are synchronous and block the main thread (~1-3ms each on cold cache, 0.2-0.5ms warm).
- 50+ chat sends in a session = ~75-150 writes, mostly within ms of each other.
- On Brave/iOS with isolated storage, write latency can spike to 10-20ms.

## Suggested fix
1. Configure `posthog.init({ persistence: 'memory' })` for high-traffic events; use localStorage only for identity (distinct_id) and session_replay state.
2. OR throttle/batch: capture multiple events in a single localStorage write via `posthog.opt_capture_by_textcontent` or custom queue.
