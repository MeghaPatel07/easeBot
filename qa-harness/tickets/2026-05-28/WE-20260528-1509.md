# WE-20260528-1509 — React Profiler estimate: every keystroke in ChatInput re-renders ChatInput + Index header chain

**Severity:** P1
**Status:** triaged
**Assigned:** fix-frontend
**Area:** Performance / React rendering
**Discovered:** 2026-05-28

## Symptom
Per static analysis (chrome-devtools MCP not available, profiler estimate):

### Typing in chat input
`pages/Index.tsx:1371` passes `inputText` and `onInputChange: setInputText` to ChatInput. Index.tsx holds 43 `useState` hooks at top level. Every keystroke:
1. `setInputText(e.target.value)` runs in Index
2. Index re-renders the entire JSX subtree (no `useMemo`/`React.memo` on intermediate children)
3. `inputBarProps` (Index.tsx:1369) is rebuilt as a fresh object literal each render
4. ChatInput receives "new" props (referential inequality) → re-renders
5. ChatHeader / ChatSidebar / ChatMessages all rebuild via the Index parent re-render

**Estimated renders per keystroke: 4-6 component re-renders.**

### SSE chunk arrival (streaming AI response)
- `useChat.ts` appends chunks to `messages` via `setMessages(prev => ...)` — currently on every chunk
- ChatMessages is NOT wrapped in `React.memo` (line check: 4 matches for memo/useCallback total, none on default export)
- **Estimated renders per chunk: ~10/sec at 50 tokens/sec = ChatMessages full re-renders 10×/sec, ~5-15ms each**

### Mode switch
- `setSelectedMode(...)` triggers Index re-render + a separate `useEffect` running `track('mode_selected')` + `register({...})` — see -1505
- ChatInput re-renders, ChatHeader re-renders, MessageList re-renders → ~6 component re-renders

## Why this matters
For 50-message thread, the chunk-stream causes ChatMessages.map to re-walk 50 items, 10×/sec → ~500 reconciliations/sec.

## Suggested fix
1. Wrap ChatInput in `React.memo` and pass setters via `useCallback`.
2. Wrap ChatMessages in `React.memo`. Internally key each message by id and render via `<Message key={m.id} message={m} />` with `Message = React.memo(...)`.
3. Move `inputText` state INTO ChatInput (uncontrolled at parent level), expose imperative `submit()` via ref. Parent only owns the persisted history.
