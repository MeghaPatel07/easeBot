## Description

Multiple chat-message and thread-level actions are revealed only on hover (`opacity-0 group-hover:opacity-100`). Examples found:

- ChatSidebar.tsx:210 — thread overflow `MoreHorizontal` button is hidden until hover (covered by -260)
- GalleryView.tsx:171 — attach + delete buttons on thumbs are hover-only
- ChatMessages.tsx:929-930 — Tone Modifier buttons (Shorter/Longer/Simpler) appear only on hover

For keyboard-only users:
- The action exists in the DOM (so Tab visits the button) but the user sees an empty spot — extremely disorienting
- Or the hover-only buttons have `opacity-0` which may also mean they're not visible at any time without a mouse, so Tab focus ring lands on an invisible target

When Sprint 1 -260 fixed sidebar overflow trigger, this Sprint 2 ticket extends to the same pattern across chat-messages, gallery actions, tone modifiers — they all need `focus-within:opacity-100` or always-visible variants.

## Steps to reproduce

1. Hide mouse, keyboard only
2. Tab into chat sidebar threads — try to reach Delete on a thread
3. Tab into gallery — try to reach Delete on an image
4. Tab into an assistant message — try to reach Shorter/Longer

## Expected

All actions either always-visible OR use `focus-within:opacity-100` so keyboard focus reveals them. Add visible focus rings.

## Actual

Hover-only reveal; keyboard users land on invisible buttons.

## Notes

Same hover-reveal anti-pattern: ChatSidebar:210 (thread overflow), GalleryView:171 (image action buttons), ChatMessages:929 (tone modifiers), inlineEdit image preview:280 (replace/remove on image).
