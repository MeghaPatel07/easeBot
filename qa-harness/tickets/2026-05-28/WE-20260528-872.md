## Description

Two visual brand surfaces use `alt=""`:
- ChatHeader.tsx:222 — `<img src={weddingEaseLogo} alt="" />` (the WeddingEase brand logo at top right on mobile).
- ChatMessages.tsx:428 — `<img src={easebotAvatar} alt="" />` (the assistant avatar bubble).

Per WAI guidelines, `alt=""` means "purely decorative, skip in screen reader". That's defensible for the chat-bubble avatar (the role of the bubble is already conveyed by container styling). But the **brand logo** in the header should have `alt="WeddingEase"` so:
- VoiceOver / NVDA / JAWS announce the brand mark when navigating header.
- If image fails to load, browser displays alt text instead of an empty box.
- Open Graph crawlers / read-it-later tools pick up the alt as brand context.

## Steps to reproduce

1. Open /chat.
2. Inspect element on the top-right logo → alt="".
3. Disable images in DevTools → Settings → Preferences. Reload → logo area is a tiny empty box with no label.

## Expected

- ChatHeader.tsx:222 → `alt="WeddingEase"`.
- ChatMessages.tsx:428 → keep `alt=""` (bubble role is already conveyed by visual + ARIA).

## Actual

Both empty.
