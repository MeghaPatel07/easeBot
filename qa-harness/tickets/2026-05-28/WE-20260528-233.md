## Description

Free-text fields (`vibeTitle`, presumably user display name in account routes, note titles, etc.) accept any Unicode without normalization. A user can:
- Submit a `vibeTitle` with mixed Cyrillic + Latin homoglyphs that look identical to another vibe ("Wеdding" with Cyrillic е).
- Submit emoji-with-modifier sequences that render correctly but break length validation when downstream code measures with naive `.length`.
- Submit combining mark sequences that, when displayed, overflow the visual width of the UI (Zalgo text).

For chat/social surfaces this enables phishing-by-confusion ("I am Vendor A" using a homoglyph that matches a real vendor name).

## Steps to reproduce

```bash
# Vibe title with Cyrillic homoglyph (looks like "Wedding")
curl -s -X POST http://localhost:3001/api/chat -H "Content-Type: application/json" \
  -d '{"message":"hi","forceImageGeneration":true,"vibeTitle":"Wеdding"}'
# Accepted; if rendered alongside real "Wedding" entries, indistinguishable.
```

## Expected

For user-visible labels:
- NFC-normalize on input.
- Optionally reject mixed-script strings unless they match the user's preferred language.
- For length validation, use grapheme-cluster count, not `.length`.

## Actual

Raw Unicode accepted.
