## Description

`rateLimitMutations` (10/min/uid) and `rateLimitSensitive` (5/hour/uid) are backed by `new Map<string, {count, resetAt}>` defined at module scope. There is no shared store (Redis, Firestore counter, etc.). When the backend runs N replicas behind a load balancer (the entire point of `trust proxy`), each replica has its own bucket -- the real per-uid cap is `N * declared limit`.

For sensitive ops this matters most: account-delete can be triggered up to `N * 5/hour` instead of 5; sign-out-everywhere likewise. Same critique applies to `chatBurstRateLimiter`, `apiRateLimiter`, and `imageRateLimiter`.

## Suggested fix

Swap to `rate-limit-redis` (or a Firestore-backed token bucket using a transaction) for any limiter that protects security-relevant invariants.
