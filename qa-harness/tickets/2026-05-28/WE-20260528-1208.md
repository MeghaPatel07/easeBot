## Description

```ts
} catch (err) {
  console.error('[chatController] summarization failed, using full history:', err)
  // Fall back to full history on error
}
```

If summarization fails (Azure 429, schema rejection, network hiccup), the code logs to console and falls back to the **full history** — which is the exact scenario that was about to bust the context window. The next call then either:
1. Hits Azure with an over-budget request → another error.
2. Or worse, the request succeeds but the user pays for the full history every turn at >10 messages.

There's no `emit('chat.summarization_failed', ...)` for observability (unlike the existing `subscription.invoice_queue_failed` pattern at line 95 of subscriptionController). The PostHog `conversation_summarized` event type exists at `lib/posthog.ts:49` but is never fired here for success OR failure.

## Steps to reproduce

1. Mock the summarizer to throw (e.g. stub `summarizeConversation` to reject).
2. Send 11+ messages.
3. Verify: no posthog event, no observability emit, no fail-fast / no truncation.

## Expected

On failure: emit `chat.summarization_failed` to observability. Truncate history to the last N (e.g. 5) recent messages rather than passing the whole thing. Fire a `quota_warning` if token estimate >context_window.

## Actual

Silent fall-through. Cost amplification.

## Notes

Fix-backend-api. Quick add: `emit('chat.summarization_failed', { uid, error: (err as Error).message })` and `effectiveHistory = recentMessages` (drop older silently rather than pass full history).
