## Description
Sending non-JSON to a POST endpoint produces a 500 (logically should be 400 — client sent bad input) with the raw `JSON.parse` error verbatim in the response body, which leaks the internal parser implementation detail.

## Steps to reproduce
```bash
curl -s -i -X POST http://localhost:3001/api/chat/stream \
  -H "Content-Type: application/json" -d 'not-json'
```
Response:
```
HTTP/1.1 500 Internal Server Error
{"error":"Unexpected token 'n', \"not-json\" is not valid JSON","code":"INTERNAL_ERROR"}
```

## Expected
```
HTTP/1.1 400 Bad Request
{"error":"Invalid JSON body","code":"BAD_REQUEST"}
```

## Actual
500 with `code:"INTERNAL_ERROR"` and the V8 parser's own error string. Misleading for monitoring (every fuzz/script will register as a server error) and slightly leaky (exposes that you're using the V8 / Node JSON parser).

## Evidence
- Reproducible inline above.

## Notes
The `express.json()` body parser throws `SyntaxError` with `.type === 'entity.parse.failed'` on bad JSON. `errorHandler.ts` likely catches all errors and maps to 500. Add a branch:
```ts
if (err instanceof SyntaxError && (err as any).status === 400 && 'body' in err) {
  return res.status(400).json({ error: 'Invalid JSON body', code: 'BAD_REQUEST' })
}
```
