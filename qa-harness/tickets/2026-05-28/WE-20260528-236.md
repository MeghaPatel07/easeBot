## Description

```tsx
const TypewriterMarkdown = ({ text, isStreaming, remarkPlugins, components }) => (
  <ReactMarkdown remarkPlugins={remarkPlugins} components={components}>
    {text}
  </ReactMarkdown>
);
```

`text` is the FULL message string-so-far on each render. ReactMarkdown re-parses + re-renders the entire markdown tree on every state update. For a 4K-token assistant reply that streams ~600 chunks at ~6 chars/chunk, that's 600 parses of progressively-longer strings → O(N²) work.

User-visible effect: long replies (recipe expansions, detailed style guides) feel sluggish to scroll while still streaming. CPU spikes; battery drains on mobile.

## Steps to reproduce

1. Open chat with chrome-devtools CPU 6× throttle.
2. Send "Write me a 2000-word essay on Indian wedding traditions".
3. Observe: stream feels jerky; React DevTools Profiler shows render time growing with each chunk.

## Expected

Either:
- Memo per-paragraph: split text on `\n\n`, render each paragraph through its own memoized ReactMarkdown that only re-renders when that paragraph's text changes.
- Or buffer chunks for ~50ms before flushing to the rendered text (batch coalescing).

## Actual

Full re-parse per chunk.
