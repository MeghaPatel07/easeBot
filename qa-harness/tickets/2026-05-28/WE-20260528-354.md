## Description
A request with `mode:"hacker"` (or any unrecognized string) is accepted by the SSE endpoint, the controller does NOT validate it against the `Mode` enum, and the assistant returns a normal reply with `mode:"hacker"` echoed in the `t:"d"` final SSE frame. Downstream, `getToolsForMode(mode, isLoggedIn)` falls into the `default` branch (line 288) which silently grants the assistant-mode tool set, so a malicious / fuzzed client can probe what tools are bound by passing arbitrary mode strings and watching which tool calls succeed.

In addition: the non-stream `/api/chat` route mounts `validateBody(ChatRequestSchema)` (chat.ts:11), but the streaming route does NOT — line 37 only chains `requireAuth → chatBurstRateLimiter → quotaCheck → handleChatStream`. So mode validation never runs for the SSE path that the production frontend uses.

## Steps to reproduce
1. `curl -s -X POST http://localhost:3001/api/chat/stream -H "Content-Type: application/json" -d '{"message":"hi","mode":"hacker"}'`
2. Last SSE frame:
   ```
   data: {"t":"d","text":"Hi there! How can I help you with your wedding planning today?",
          "mode":"hacker","detectedLanguage":"en", …}
   ```

## Expected
Either (a) 400 with `{"error":"mode must be one of: planner|stylist|knowledge|assistant"}`, or (b) silently fall back to `detectMode(englishText)` and emit the actual valid mode in `t:"d"`. Either way `mode` field of the response must be a member of the `Mode` enum.

## Actual
Arbitrary string echoed back as the response's `mode`. No validation, no warning logged.

## Notes
Two fixes needed:
1. **Schema-level**: add `mode: z.enum(['planner','stylist','knowledge','assistant','image']).optional()` to `ChatRequestSchema` so the non-stream path also gives a nice 400.
2. **Route-level**: mount `validateBody(ChatRequestSchema)` on `/stream` too (currently skipped — see `chat.ts:74-77` comment which acknowledges it's deferred to "the controller" but the controller does no validation).
3. **Defense-in-depth**: in `chatController.ts:679` & `1185`, coerce unknown `requestedMode` values via `if (requestedMode && !KNOWN_MODES.has(requestedMode)) requestedMode = undefined`.
