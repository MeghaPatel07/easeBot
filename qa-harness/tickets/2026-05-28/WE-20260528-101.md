## Description

Journey 1 (guest first-message → image mode) breaks on the Vibe-mode / Images-Hub path. When the client posts to `/api/chat` (NOT `/api/chat/stream`) with `forceImageGeneration: true`, the server returns HTTP 500 with an error body whose first field is literally a string starting with `Invalid regular expression: /!\[[^\]]*\]\(data:image\/png;base64,iVBOR...` followed by the entire 2 MB base64 PNG.

Root cause: `chatController.ts:1062` (the non-stream path) does:
```ts
const esc = u.replace(/[.*+?^${}()|[\]\\]/g, '\\$&')
textForClient = textForClient.replace(new RegExp(`!\\[[^\\]]*\\]\\(${esc}\\)`, 'g'), '')
```
When `u` is a `data:image/png;base64,...` URL (Vibe mode returns inline data URIs to guests), `esc` exceeds the V8 regex max compiled-pattern size and `new RegExp(...)` throws "Invalid regular expression" / "Regular expression too large", bubbling as an unhandled 500.

The streaming path at `chatController.ts:1640-1648` already has the correct guard (`if (!u || u.startsWith('data:')) continue`) — the non-stream path was never patched. Comment at :1638 explicitly acknowledges this is a known failure mode for data URIs.

## Steps to reproduce

1. With backend running on :3001, POST to `/api/chat` (NOT the streaming path) with body:
   `{"message":"sunset wedding mandap","history":[],"forceImageGeneration":true,"preferredAspectRatio":"1024x1024"}`
2. Wait ~50s (image-gen latency).
3. Observe response.

## Expected

200 with `{text, imageUrl, ...}` — same as the stream path produces. Markdown `![](data:...)` is stripped (or skipped) without crashing.

## Actual

```
HTTP/1.1 500 Internal Server Error
{"error":"Invalid regular expression: /!\\[[^\\]]*\\]\\(data:image\\/png;base64,iVBOR...<2 MB of base64>.../"}
```

The 500 also leaks ~2 MB of compiled image content to the client over a JSON error envelope.

## Notes

- The streaming path was patched (see comment at 1638). Same one-line guard `if (!u || u.startsWith('data:')) continue` resolves this.
- Vibe Mode / Images Hub is Sprint 1 closed (see `project_pricing_rollout`) — this regression makes the entire vibe-card image flow unusable for guests who hit the non-stream path.
- Also: a 500 response containing 2 MB of base64 PNG bytes is a separate concern — error envelopes should not echo user-supplied or LLM-generated payloads at all. File a follow-up for error-handler hygiene.
