## Description

Spot-grep across `notesController.ts` shows the pattern `res.status(...).json({ error: err.message })` 20+ times. The shareId-oversize case (WE-20260528-1005) is one symptom, but the systematic risk is every notes handler can spill raw exceptions to the network (internal field names, validation messages from helper modules, stack-trace fragments depending on `err.message` content).

Same pattern exists in `checklistController.ts` (every handler). `feedbackController.ts` returns generic strings (good). Notes is the worst because it has the public `/shared/:shareId` endpoint, so anonymous callers can probe.

## Suggested fix

Use the existing global `errorHandler` middleware (mounted in `app.ts:106`). Have controllers `next(err)` instead of formatting their own 500 responses. The global handler can do `{error:"Internal server error", code:"INTERNAL", requestId:<id>}` and log internally.
