## Description

The Radix toast `overflow-hidden` clips overflowing text. Toast descriptions render via the ToastDescription sub-component. There's no `break-words` / `overflow-wrap-anywhere` on either. When the backend bubbles up a raw error (which it sometimes does — see -862 — including a stack trace or a 1KB JSON), the toast renders a single line with `text-overflow: clip` (no ellipsis since the parent uses `overflow-hidden` not `text-overflow: ellipsis`). User sees half-truncated cryptic strings.

Combined with -858 (z-index) and -889, the toast is functionally useless for any error wider than the toast's `max-w-[420px]`.

## Steps to reproduce

1. Trigger a backend 500 that returns a long error body.
2. Observe toast clips mid-word with no ellipsis or wrap.

## Expected

Description container: `break-words [overflow-wrap:anywhere]` + `max-h-32 overflow-y-auto` to scroll long content inside the toast (or cap with line-clamp-4 + "View details" expander).

## Actual

Hard clip.
