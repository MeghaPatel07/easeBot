## Description

The whole `/api/*` surface returns JSON for every code-path (200 ok, 400 validation, 401 unauthorized, 429 rate-limit, 500 error). But unmapped routes fall through to Express's default 404 which returns:

```
HTTP/1.1 404 Not Found
Content-Type: text/html; charset=utf-8
Content-Length: 156

<!DOCTYPE html>
<html lang="en">
<head><meta charset="utf-8"><title>Error</title></head>
<body><pre>Cannot GET /api/checklists</pre></body>
</html>
```

Frontend clients that do `await fetch(...).then(r => r.json())` will throw `SyntaxError: Unexpected token '<'` on every 404, which surfaces to the user as a generic "Something went wrong" (per WE-20260527-223 catch-all). The user can't tell that the route is wrong vs. server down vs. malformed body.

Live examples observed:
- `GET /api/checklists` → 404 HTML (only `/stats`, `POST /`, `PATCH /:id`, `DELETE /:id` are defined; root GET is not).
- `GET /api/notfound` → 404 HTML.
- `GET /totally-fake-path` → 404 HTML.

## Steps to reproduce

```
curl -sS http://localhost:3001/api/checklists -i | head -20
# Expect JSON {error:"...", code:"NOT_FOUND"}; observe HTML
```

## Expected

Catch-all 404 middleware before `errorHandler`:

```ts
app.use((req, res) => res.status(404).json({ error: 'Not found', code: 'NOT_FOUND', path: req.path }))
```

Or — even better — define a GET handler on `/api/checklists` that returns the caller's checklists (matches the FE service's expectation of "list all my checklists").

## Actual

Express default HTML response with no `code` field.
