## Description

Sprint-1 ticket -254 documented the AnalyticsConsent overlap with chat input visually. Sprint 3 angle: Voice Control + Switch Control users have NO mechanism to dismiss the consent banner if it's covering the controls they want. Voice user says "Click Send" → may get the consent Decline button (also small, near bottom) → unintended consent action.

Worse: focus order — Tab into the page may land on Send (covered by overlay), so `prefers-reduced-motion` overrides + focus position both leave the user in an unrecoverable confused state.

## Expected

- AnalyticsConsent's z-index must NEVER cover primary action zones
- Voice control should see the consent banner's buttons FIRST (banner is the foreground task)
- Add `aria-modal="true"` to the banner so it semantically "captures" focus

## Actual

Mouse users click around it; voice/switch/SR users can fall through and trigger wrong actions.

Extends -254 (visual overlap → all AT modalities affected).
