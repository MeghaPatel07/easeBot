## Description

Sprint 1 ticket -237 documented that `truncate(att.title, 30)` is byte-length-based and breaks multi-byte characters (emoji, combining marks). This ticket addresses the **visual** symptom: in MessageAttachmentChips, when a chip's truncated title is rendered:
- The truncation can land mid-grapheme producing a "tofu" glyph or replacement-character.
- The chip width then jumps when the next render fixes it.
- On mobile (chip rail width ~300px) the per-chip max width forces another CSS truncation on top of the JS truncation — double-truncation produces "abcd…ef…" patterns.

Visual fix is independent of the JS-truncation fix in -237 — apply CSS `.chip-title { max-width: 18ch; overflow: hidden; text-overflow: ellipsis; white-space: nowrap; }` and remove the JS-side truncation (let CSS handle it).

## Steps to reproduce

1. Create a checklist named `📋 الزفاف Vendor checklist with very long title text` (mixed bidi + emoji + long).
2. Attach it to a chat message.
3. Observe rendered chip — truncation lands mid-character; width may not match the visual character count.

## Expected

Single-layer CSS truncation (`text-overflow: ellipsis`) on the chip title, no JS-side substring.

## Actual

JS truncation breaks graphemes; double-truncation with CSS produces unstable widths.

## Evidence

- AttachmentPicker.tsx line ~171 (chip render).
- Sprint 1 -237 (byte-length sanitizer issue).

## Notes

Sub-case of broader long-text testing. Filing because chips are a unique surface (not bubbles, not nicknames).
