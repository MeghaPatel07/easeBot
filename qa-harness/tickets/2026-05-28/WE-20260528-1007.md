## Description

```ts
try {
  const pending = await isDeletionPending(req.user.uid)
  if (pending) { res.status(403).json({...}); return }
} catch (err) {
  console.error('[requireStrictAuth] deletion-gate lookup failed:', ...)
  // Fail-open on lookup error to avoid locking users out
}
next()
```

If the RPC throws (network flap, IAM, quota, transient), the deletion gate is silently bypassed. A user whose account was flagged for deletion can still mutate their profile / preferences / sensitive ops during a degraded window. Combined with WE-20260528-1001 (no actual purge happens), this means a "deleted" account can be reactivated during any blip.

## Suggested fix

Fail-CLOSED on lookup error (`res.status(503).json({error:"service unavailable"})`). Pair with a circuit-breaker that flips to a stale-cache fallback rather than skipping the check entirely.
