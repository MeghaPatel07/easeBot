# WE-20260528-1533 — Cold-start Azure init: 3 separate clients constructed at first request (azureAI, promptArchitect, imageGeneration analyzeImage)

**Severity:** P2
**Status:** triaged
**Assigned:** fix-performance
**Area:** Performance / Backend cold-start
**Discovered:** 2026-05-28

## Symptom
First chat request triggers up to 3 `new AzureOpenAI(...)` calls within ~10ms:
1. `azureAI.getClient()` at `streamCallAzureAI` for the main chat LLM
2. `promptArchitect.expandWithPromptArchitect` inside its function body (line 200-205)
3. `imageGeneration.analyzeImage` inside its function body (line 515-520)

Each construction triggers env variable parsing, an internal `fetch` HTTP client setup, and JSON schema cache init.

## Why this matters
- All 3 hit the same Azure endpoint — could share a single client with one connection pool.
- Each adds ~30-80ms of cold-start overhead.

## Suggested fix
Singleton in `azureAI.ts`:
```ts
let _client: AzureOpenAI | null = null
export function getSharedAzureClient(): AzureOpenAI {
  if (_client) return _client
  // env validation
  _client = new AzureOpenAI({ endpoint, apiKey, deployment, apiVersion: '2024-08-01-preview' })
  return _client
}
```
Replace all 3 sites with `getSharedAzureClient()`.

Related to -1521 (singleton scope).
