## Description

The frontend `ExchangeRateService.getRate` caches per-pair for **5 minutes** (line 13). The backend `getLockedRate` caches per-currency for **60 seconds** (line 21). 

Sequence:
1. User loads `/pricing` at T0. FE fetches USD→INR=83.5, caches until T0+5min.
2. User clicks "Choose Pro" at T0+90s. `/checkout` reuses the same rate (still cached in FE for ~4.5min more).
3. User submits the form at T0+120s. Backend `/api/payment/initiate` calls its OWN getLockedRate. If the previous 60s window expired, the backend fetches a **fresh** rate (e.g. 84.1).
4. The PayU form is signed with `amountLocal = priceUsd * 84.1` (backend) but the FE just showed `priceUsd * 83.5`.

The user sees a different number on the PayU page than the price they clicked-to-confirm. Discrepancy is small (~0.7%) but visible and is a contract bug.

## Steps to reproduce

1. Open `/pricing` at T0. Note INR price.
2. Click Pro → continue → land on `/checkout`.
3. Wait 61 seconds (backend cache expires; FE cache still warm).
4. Submit. Inspect the auto-posted PayU form `amount` field vs the price shown on Checkout summary.

## Expected

Backend rate-lock should be authoritative; the FE should display the backend-locked rate after `initiate` returns, before redirecting to PayU. Or both caches should align (60s on both sides), OR the FE should pre-fetch the backend rate via a read-only `/api/payment/quote` endpoint at checkout-render time.

## Actual

Two independent rate sources with different TTLs; user-visible mismatch possible.

## Evidence

- FE service: `Wedding-Ease-Viva-Chat/src/services/exchangeRateService.ts:13` (5 min)
- BE service: `easebot-backend/src/services/exchangeRateService.ts:21` (60s)
- Submit handler: `Wedding-Ease-Viva-Chat/src/pages/Checkout.tsx:188-216` — does not re-validate display rate against `init.rate` before posting form.

## Notes

Spec locked decision per `project_pricing_rollout §11`: server-locks rate at initiate. FE should treat its own rate as preview only. Fix: after `initiate(...)` returns, update the displayed total from `init.rate` for 0.5s before auto-submit; OR add a `/api/payment/quote` GET endpoint to back the Checkout summary.
