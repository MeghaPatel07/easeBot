## Description

Note + checklist titles don't have a consistent length cap:
- Note title input: no `maxLength` (audit: `grep -rn 'maxLength' src/components/notes/` shows no title cap).
- Checklist title input (ChecklistDetail.tsx): no cap visible at line where title is edited.
- Sidebar truncation uses `line-clamp-1` so display is bounded.

Issue: when a user enters a 200-char title:
- Sidebar uses line-clamp-1 — visually OK.
- The note-editor header (where you re-edit the title) may render the full string in a contenteditable — long titles overflow into the editor body.
- The collaboration-shared link surfaces the title in metadata (page `<title>` for SEO/shares) — 200-char title renders awkwardly.

## Steps to reproduce

1. Open /notes.
2. Create a new note. Title: 200 'A's.
3. Observe sidebar render (truncates fine), then click into the note.
4. Observe header expands awkwardly to fit the title.

## Expected

- Soft cap title to 80 chars via `maxLength={80}` + `setX(value.slice(0, 80))`.
- Show counter when within 10 of limit.
- Editor header `truncate` + `max-w-full` so long titles ellipsize.

## Actual

No cap; visual layout strains.

## Evidence

- Source paths cited above.

Lower priority than -853 (nickname) because notes are personal-only; nicknames render in shared surfaces.
