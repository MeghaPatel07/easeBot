## Description

PostHog payload audit, checkout funnel. Three captures fire on the checkout submit:

- `track('checkout_started', { tier, cycle, amount: state.priceUsd, currency: state.currency })` — line 190-195
- `track('payu_redirect_started', { order_id, tier, amount, currency })` — line 209
- `track('plan_activated_direct', { tier, cycle, amount, currency })` — line 219

While the **event props** themselves don't include email, the surrounding flow:

1. **Replay is forced to 100% on checkout** (`analytics.ts:218` — `forceOn = isPaying || route.includes('/checkout')`). 
2. The checkout form contains `fullName`, `email`, `country`, `state`, `city`, `postalCode`, `line1`, `gstin` as plain `<input>` elements without `data-ph-mask` attributes. The session-recording config at `analytics.ts:191-194` uses `maskAllInputs: true` which **does** mask values, but **placeholder labels and DOM IDs are not masked** — they're still visible in the replay.
3. The pricing rollout memory says billing address is shipped to the backend (correct), but it is also incidentally retained in the DOM during the replay window.

## Steps to reproduce

1. Open `/checkout` with an active plan in route state.
2. DevTools → Network → look for `/decide`. Confirm replay is started (look for `/e/?` chunks with `$snapshot`).
3. Submit form. Inspect events:
   - `checkout_started` payload contains `amount: priceUsd` — no PII per se but useful for fingerprinting (linked to `email` via `$identify`).
   - The DOM snapshot captures field structure even when values are masked.

## Expected

Either replay is paused while focus is inside the billing-address card OR fields carry `data-ph-block` so the snapshot omits them. Per `analytics.ts:194` the spec is `blockSelector: '[data-ph-block],input[type=password]'` but no checkout input opts in.

## Actual

Full checkout form structure is captured in 100%-sampled replays for every paying user.

## Evidence

- Code: `Wedding-Ease-Viva-Chat/src/pages/Checkout.tsx:190-224,279-460` (no `data-ph-block` on any input)
- Code: `Wedding-Ease-Viva-Chat/src/lib/analytics.ts:188-194` (block selector spec)

## Notes

Quick win: add `data-ph-block` to `<Card>` containing billing address inputs in Checkout.tsx. Separately, add the same to the `<form>` element in `SignUpModal.tsx` (phone, name, password).
