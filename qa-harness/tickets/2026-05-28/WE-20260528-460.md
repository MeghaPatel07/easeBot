## Description

Tested via Chrome `forcedColors: 'active'` emulation. The app's CSS does not declare any `@media (forced-colors: active)` overrides nor any `forced-color-adjust: none|auto` properties. Result:
- Decorative pink-mosaic gradient backgrounds and brand orange primary buttons retain their original colors — the OS-level high-contrast palette overrides text but leaves background imagery confused.
- Icon-only buttons (theme toggle sun-icon, sidebar collapse) retain their original SVG fills, becoming low-contrast against the OS-forced background.
- Focus rings rely on `box-shadow` / `ring-*` Tailwind classes that may be ignored under forced colors.

Windows users running High Contrast mode (default after a11y onboarding, also auto-enabled by some screen readers) will see a half-styled UI rather than a clean OS-controlled palette.

## Steps to reproduce

1. Windows: Settings → Ease of Access → High Contrast → On (or Chrome DevTools → Rendering → Emulate CSS media feature `forced-colors: active`)
2. Open any page

## Expected

A `@media (forced-colors: active)` block in `index.css` that:
- Sets `forced-color-adjust: none` on logo + brand icons we want to preserve
- Sets `background: Canvas; color: CanvasText` on body and cards
- Uses `ButtonText`/`Highlight` system colors for primary buttons
- Reinforces focus ring with `outline: 2px solid Highlight`

## Actual

CSS ignores forced colors; mixed-mode rendering.
