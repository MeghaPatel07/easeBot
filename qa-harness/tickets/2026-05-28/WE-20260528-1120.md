# WE-20260528-1120 — `/chat` ships 559KB across 19 requests on first paint — bundle / image budget missing

**Severity:** P2
**Status:** triaged
**Assigned:** fix-performance
**Area:** Performance / Network budget
**Discovered:** 2026-05-28

## Symptom
Lighthouse mobile run on `http://localhost:4173/chat` reports:
- Total network requests: **19**
- Total transfer: **559 KB**
- Unused JS: 174 KiB savings available
- Render-blocking resources: 600ms savings available

Composition (from build artifacts referenced via index.html + prerender):
- `index-BFQDlZeM.js`: 331 KB gzip (the SPA entry, includes Auth, routing, Toaster, etc.)
- Plus `Index-BI9zObHt.js` (354 KB gzip) only loads on /, not /chat — but routing is JS-driven, so the page still pulls a lot.

## Reading
- 19 requests is *not* obscene, but for a chat UI that should be "send a message in 1 second" it's heavy.
- 174 KiB of unused JS confirms tree-shaking is leaky (cross-ref Sprint 1 -311 lucide-react barrel imports).

## Suggested fix
1. **Critical-path budget**: enforce in CI that any route ships ≤ 200KB JS + 50KB CSS gzipped, ≤ 10 critical-path requests.
2. Audit which 174KB is unused — likely TipTap extensions (NoteEditor) leaking into chat, or shadcn components that are imported via barrels.
3. Lazy-load PostHog client (currently in main bundle); load it post-FCP.
