## Description

The textarea is a CONTROLLED input: every keystroke / paste triggers `onInputChange(e.target.value)` → React state update in parent → re-render of `<ChatInput />` AND its many siblings (mode dropdown, attachment chip row, etc.).

Pasting a multi-thousand-character block runs the React render in the same task as the paste, plus the auto-grow `useEffect` (line 90-97) reads `el.scrollHeight` synchronously → forced layout. The combined effect is a perceptible freeze on weaker hardware (Chromebook, low-end Android).

## Steps to reproduce

1. Open chat at localhost:8081 on a slower device or with CPU throttling 4×.
2. Paste a 5K-character block.
3. Observe input freeze 100-300 ms.

## Expected

Debounce the parent state update (the LAST value-before-send is what matters). Locally `useState` the textarea value and `useEffect` push it up at 16ms tick or `useDeferredValue`.

Alternatively, switch the textarea to UNCONTROLLED (`defaultValue`) and read `.value` only on send.

## Actual

Controlled input → render on every keystroke / paste-tick.
