## Description

Brief mentions "Gemini primary fails (force malformed prompt), does Azure fallback fire? Tokens debited once or twice?" — actual code uses **Azure as both primary AND fallback** (GPT-Image-1.5 → GPT-Image-1). No Gemini. So the Gemini-fallback question is moot, but the underlying chaos question is valid for the Azure-only pair:

In `generateImageGptImage1`:
```ts
try {
  const images = await withRetry(() => callAzureImageGeneration(...primary...), {maxRetries: 1, ...})
  if (images.length > 0) { /* phCapture(image_generated, {model: primary}) */; return images }
} catch (err) {
  if ((err as Error).name === 'AbortError') throw err
  console.warn('[imageGeneration] GPT-Image-1.5 failed, trying fallback:', err.message)  // logged but NOT phCaptured
}

try {
  const images = await withRetry(() => callAzureImageGeneration(...fallback...), {maxRetries: 1, ...})
  if (images.length > 0) { /* phCapture(image_generated, {model: fallback}) */; return images }
} catch (err) { /* phCapture image_generation_failed with error_code */ }
```

Token charge happens once per call to `handleImageToolCall` via `chargeTokens({kind:'image', count: base64Images.length})` — based on **how many images came back**, regardless of which model produced them. So tokens are debited once (correct).

But:
- The primary failure is NOT captured in PostHog (only the success or the final failure is). Ops cannot see how often primary is degraded; cost analysis is blind to which model is producing each image.
- `phCapture` distinct_id is `options.distinctId` which is `req.phDistinctId ?? req.user?.uid` — for guests with no `x-ph-distinct-id` header set by `posthogContext`, this can be undefined and the capture silently skipped.
- Both calls use `withRetry({maxRetries: 1, baseDelayMs: 1000-2000})` → on a 503 from primary it retries once (1s delay), THEN tries fallback (1s + fallback latency). Worst case user waits 2+ Azure latencies before fallback succeeds.

## Steps to reproduce

Force primary failure by setting `AZURE_GPT_IMAGE_15_DEPLOYMENT` to a non-existent name:
```bash
# in env: AZURE_GPT_IMAGE_15_DEPLOYMENT=does-not-exist
# Send image request via /chat:
curl -s -X POST http://localhost:3001/api/chat \
  -d '{"message":"draw an image of a mandap"}' -H "Content-Type: application/json"
# Backend logs: [imageGeneration] GPT-Image-1.5 failed → fallback. Fallback succeeds.
# PostHog: only image_generated{model:fallback} fired. No primary_failed event.
# User: 1 normal error (none if fallback succeeded).
# Token meter: charged once (correct).
```

## Expected

Add `phCapture(distinctId, 'image_primary_failed', { model: primary, error_code, latency_ms })` on the primary catch BEFORE invoking fallback. This unblocks the ops team's ability to detect Azure GPT-Image-1.5 outages.
