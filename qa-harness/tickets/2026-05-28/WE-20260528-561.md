## Steps to reproduce
1. Fresh browser context. Open app in tab A and tab B simultaneously (both render the consent banner — `ph_consent` key missing).
2. In tab A, click "Decline".
3. Tab A: banner disappears, PostHog opts out.
4. Tab B: banner still visible.

## Expected
Tab B's banner disappears within ~1s, AND its in-memory PostHog client opts out (per tab A's decision).

## Actual
Verified live: tab B keeps the banner. `AnalyticsConsent.tsx:16` reads localStorage in `useEffect([])` only — no storage listener, no BroadcastChannel.

User may click "Accept" in tab B to dismiss the annoying overlay, undoing their tab A "Decline" decision. The last write wins for the `ph_consent` key but PostHog opt-in is per-tab and now inconsistent (tab A opted-out, tab B opted-in, both live).

## Impact
P2 normally, but borderline P1 in a GDPR-strict jurisdiction — the user told the app once not to track, but tab B is now sending events.

## Fix direction
Add a `storage` listener inside the `useEffect`:
```ts
const onStorage = (e: StorageEvent) => {
  if (e.key !== STORAGE_KEY) return
  if (e.newValue === 'accepted') { posthog.opt_in_capturing?.(); setNeedsChoice(false) }
  else if (e.newValue === 'declined') { posthog.opt_out_capturing?.(); setNeedsChoice(false) }
}
window.addEventListener('storage', onStorage)
return () => window.removeEventListener('storage', onStorage)
```
