## Description

`SettingsModal.handleSave` calls `savePersonalization(user.uid, …)` which is a thin `updateDoc` wrapper. There is no `useQueryClient().invalidateQueries(['account','me'])`, no `setQueryData` patch, no AuthContext setProfile. As a result, every TanStack-Query consumer (`ProfileMenu`, `AccountTab`, `PersonalizationTab`, `AiBehaviorTab`) keeps showing the OLD value for at least 30 s (the `useAccount` staleTime) — and longer if no refetch trigger fires. The architectural inconsistency: AccountTab uses `useAccount.updateProfile` (which invalidates correctly); the legacy SettingsModal does not.

## Steps to reproduce

1. Open Settings → Personalization tab (uses `useAccount`). Note nickname.
2. Open SettingsModal (legacy). Change nickname. Save.
3. Without reload, switch back to Personalization tab and check the form initial value.

## Expected

Personalization tab shows the just-saved nickname.

## Actual

Personalization tab shows the previous nickname — `useAccount` data is stale because nothing told TanStack Query to refetch.

## Notes

Route SettingsModal saves through `useAccount.updateProfile` instead of `savePersonalization`. Bonus: removes duplicate write path.
