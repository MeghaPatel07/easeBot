## Description

Lighthouse synthetic runs don't directly measure INP under user-driven streaming. However, the combination of:
- 5 long tasks (566ms+ total) during initial load (311)
- ChatMessages re-renders on every parent re-render (310)
- setMessages(prev => prev.map) on every streaming chunk (321)
- Inline handlers in Index.tsx invalidating memo on every render (316)
- ChatInput's inputText lives in Index — every keystroke re-renders the whole tree

…makes it essentially certain that INP during streaming will exceed the 500ms 'needs work' threshold, and very likely the 1000ms P0 floor.

Recommend a manual Chrome DevTools 'Performance' tab recording during streaming + 10 rapid keystrokes to confirm and quantify.

## Steps to reproduce

1. Open /chat, send a long-response message
2. Open Chrome DevTools → Performance → Record
3. Type 10 characters rapidly in the input while AI is still streaming
4. Stop record, observe long tasks + INP in summary

## Expected

INP ≤ 200ms during steady-state streaming.

## Actual

Synthetic signals strongly suggest INP > 500ms; needs manual confirmation.
