## Description

Every `<Label>` in the Support form (Your name, Email, Category, Subject, Description, rating) is rendered as a bare `<label>` with no `htmlFor`, and corresponding `<Input>` / `<Textarea>` / Radix `<Select>` triggers have no `id`. Clicking the label does not focus the input. Screen readers do not announce the label when the input gains focus — they read only the placeholder, which is informational text, not a persistent label.

This duplicates the auth-form issue tracked as WE-20260527-252 (still `in_review`) but the Help page is a different file and was not patched.

## Steps to reproduce

1. `/help` → Support & Feedback.
2. Click "Subject" label text — input does not focus.
3. Tab to the Subject input with VoiceOver — only placeholder is announced.

## Expected

`<Label htmlFor="ticket-subject">` and `<Input id="ticket-subject" />` pattern; clicking label focuses input; SR reads label name.

## Actual

No association; clicks fall through; SR announces placeholder only.

## Notes

Repeat for all 5 fields + Category select trigger + star rating fieldset.
