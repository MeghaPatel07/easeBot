## Description

`ToastViewport` on mobile: `fixed top-0 z-[100] flex max-h-screen w-full flex-col-reverse p-4` — stacks toasts from top to bottom, capped at `max-h-screen` height. When >10 toasts queue (e.g. rapid-fire validation errors on a form), the stack fills the entire viewport and pushes the oldest toast off-screen. There's no visible "more toasts above/below" indicator and no internal scroll.

The Radix Toast primitive has a `swipeThreshold` for dismissal but the implementation here doesn't enforce a `duration` short enough to prevent stack overflow. Also there's no `limit` prop on Toast.Provider.

## Steps to reproduce

1. Open /chat.
2. DevTools console:
```js
import('./src/hooks/use-toast').then(({toast}) => {
  for (let i = 0; i < 15; i++) toast({ title: `Toast ${i}` })
})
```
3. Observe stack covers viewport; oldest toasts unreachable.

## Expected

- `<Toast.Provider duration={4000} swipeDirection="right" limit={3}>` — cap at 3 visible at once, queue the rest.
- Internal scroll affordance if cap is raised.

## Actual

Unlimited stack on mobile.

## Evidence

- toast.tsx:17 + Provider config (`ui/toast.tsx` ToastProvider).
