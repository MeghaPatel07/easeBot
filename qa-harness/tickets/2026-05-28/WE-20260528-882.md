## Description

Sprint 1 -058 documented iPhone-SE mascot clipping. This is the secondary effect: at 320×568 with the software keyboard open (568 → ~280px effective viewport), the chat-empty hero uses `min-h-screen` (or `dvh`) which keeps the layout at 568 logical px tall. The mode-selector chip rail and input field scroll BELOW the visible viewport — user has to scroll the page to reach the input.

Worse: `min-h-screen` doesn't update with `100vh` → keyboard dynamics. Use `100dvh` (dynamic viewport height) which collapses with the keyboard.

## Steps to reproduce

1. Open /chat on iPhone SE simulator (320×568).
2. Focus the textarea (keyboard opens).
3. Observe: chip rail + input pushed below keyboard; user must scroll up to see them.

## Expected

Use `min-h-[100dvh]` instead of `min-h-screen`. Add `padding-bottom: env(safe-area-inset-bottom)` for iOS gesture bar.

## Actual

`min-h-screen` (= 100vh) → input hidden behind keyboard.

## Evidence

- Index.tsx empty-state markup (audited).
- Sprint 1 -058 (different specific symptom).

## Notes

Affects iPhone SE and 5-series. Pixel 4a (340 width) approximately covered too.
