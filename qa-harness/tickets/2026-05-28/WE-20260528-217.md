## Description

Grep `src/hooks/useChat.ts` for `addEventListener('storage'`, `onSnapshot`, `BroadcastChannel` — none of these patterns are wired for the active chat thread. Messages sent in tab A persist to Firestore but tab B's React state only updates on:
- a manual reload,
- the next time the thread is opened,
- (possibly) on visibility change if any hook is wired — not verified to be.

Real-world cost: a user with chat open in two windows (e.g. desktop + secondary monitor for product search) sends a message in one and the other displays a stale conversation. If they send a follow-up in the stale tab, they're talking past the LLM context they think they have.

## Steps to reproduce

1. Open localhost:8081/chat in two tabs (same logged-in user, same thread).
2. Send "what flowers for a beach wedding?" in tab A. Wait for the response.
3. Switch to tab B. Observe: no new messages visible.
4. Send a follow-up in tab B: "and for the bouquet?"
5. The follow-up was sent against a stale view; the user can't see what tab A's exchange was.

## Expected

Either:
- A `BroadcastChannel('chat:<threadId>')` that fires on every message commit so other tabs replay,
- OR a Firestore `onSnapshot` listener that's active while the thread tab is mounted (already a Firestore-backed app — cheap).

At minimum, show a toast in stale tabs ("New messages — refresh") on focus.

## Actual

No cross-tab sync. Tabs diverge silently.
