## Description

The PayU return handler issues a 302 redirect to `${FRONTEND_BASE_URL}/payment/(success|failure)?...`. The `.env.example` default is `http://localhost:8080`, and the dev `.env` does not appear to override it. But the actual Vite dev server is on port `8081` (per session-handoff doc + confirmed by `curl http://localhost:8081`). After a real PayU sandbox transaction, the browser will be redirected to `http://localhost:8080/payment/...`, which is **nothing** in dev — the user sees a blank "site cannot be reached" page and the entire payment flow's success/failure surface is unreachable.

This is dev-environment-only IF the prod env has `FRONTEND_BASE_URL` set correctly, but the example contradicts the actual port in CLAUDE.md/session_handoff, so any new dev who copies `.env.example` is broken on payment day-1.

## Steps to reproduce

```
curl -sS -X POST http://localhost:3001/api/payment/return \
  -H 'Content-Type: application/x-www-form-urlencoded' \
  -d 'status=success&txnid=test' -i \
  | grep -i location
```

→ `Location: http://localhost:8080/payment/failure?reason=bad_payload` (note: 8080, not 8081).

Then `curl -I http://localhost:8080` → connection refused (no service on 8080 in dev).

## Expected

- `.env.example`'s `FRONTEND_BASE_URL` matches the documented dev port (8081 per `CLAUDE.md` workspace root sessionhandoff).
- OR backend reads the request `Origin`/`Referer` header to compute the redirect dynamically.

## Actual

- Default hard-coded to `:8080` in the example file.
- No fallback to request origin.
