## Description

The Voice preview affordance is rendered as:

```jsx
<button …>  // the outer voice-preset selection button
  …
  <span
    role="button"
    title={isPreviewing ? 'Stop preview' : 'Preview voice'}
    onClick={(e) => previewVoice(preset.id, e)}
    …
  >
    {/* play icon */}
  </span>
</button>
```

This is invalid (interactive inside interactive). Consequences:
- Screen readers may announce the nested element as part of the outer button's name
- Keyboard activation is inconsistent — Tab cannot land on the inner span (no tabIndex)
- HTML5 spec disallows interactive controls inside `<button>`

A click on the inner span calls `e.stopPropagation()` to prevent the outer selection — fragile.

## Steps to reproduce

1. Settings → Voice tab
2. Tab through voice presets
3. Try to invoke preview via keyboard — only mouse works

## Expected

Pull the play affordance OUT of the outer button. Two separate sibling controls: (a) "Select voice {name}" button selects, (b) "Preview voice {name}" icon-button plays.

## Actual

Nested interactives, mouse-only preview.

## Notes

A common React anti-pattern. Also relevant: ChatMessages.tsx shareKeyDown spans are also functioning as buttons (line 228-234) — but those are intentional keyboard-only handlers on Lucide icons, less serious but worth a separate ticket.
