## Description

The chat surface renders ReactMarkdown with custom `components.img`, `components.li`, `components.table` overrides (ChatMessages.tsx:447). The `li` override at line 519 does `imgNode.props.src` without null-check on the resolved node properties — if the LLM emits an `<img>`-shaped list item with unusual nesting, this could throw. There's no `ErrorBoundary` wrapping the messages list in the routes I read.

Real risk: an LLM-generated assistant message with malformed list/table markdown can crash the entire React tree, white-screening the user out of their chat session — losing the input buffer, the thread context, and any in-flight stream.

## Steps to reproduce

(Hypothetical pending verification — the LLM is currently well-behaved on this. Need to feed a contrived assistant message:)

1. POST to /api/chat with `history: [{role:"assistant", content:"- ![](x) [<no-href>](#) text"}]` so the assistant re-emits the malformed line.
2. If the LLM echoes the broken markdown, observe the React tree state in devtools.

## Expected

Wrap the messages list in a per-message ErrorBoundary that:
- catches the render error,
- shows a fallback bubble ("Something went wrong rendering this reply"),
- preserves the rest of the chat.

## Actual

No ErrorBoundary detected in the chat render path.
