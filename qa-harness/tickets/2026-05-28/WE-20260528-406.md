## Description

The chat image-attach input narrows the accept attribute to
```html
<input type="file" accept="image/png,image/jpeg,image/gif,image/webp" …>
```
…BUT the validation in `handleFileSelected` (`Index.tsx:367`) only checks `file.type.startsWith('image/')`. iOS Safari delivers HEIC photos with `file.type === "image/heic"`, which satisfies the prefix check, so the file is accepted.

Then:
1. `FileReader.readAsDataURL(file)` produces `data:image/heic;base64,...`.
2. Frontend ships this to `/api/chat` as `imageBase64 + imageMimeType: 'image/heic'`.
3. Backend `azureAI.callAzureAI` passes vision payload to Azure OpenAI GPT-4o with `image/heic` MIME.
4. Azure GPT-4o **does not support HEIC** — responds with a 400 ("Invalid image format") OR silently treats the image as unreadable.
5. User sees a chat response that ignores the photo, or an unhelpful "I had trouble processing the image" reply.

There is no client-side HEIC→JPEG transcoding, no `heic2any` import, no server-side `sharp().toFormat('jpeg')` for HEIC inputs.

## Steps to reproduce

1. On an iPhone (Safari, default camera format = HEIC), attach a photo from camera roll to the chat input.
2. Send. Observe: in DevTools Network, the `/api/chat` request includes `imageMimeType: 'image/heic'`.
3. Server logs (if accessible) show Azure OpenAI rejecting the image, OR the assistant reply ignores the photo entirely.

## Expected

Either:
- Reject HEIC in the frontend handler with a clear toast: "iPhone HEIC photos aren't supported yet. Tap Edit → Convert to JPEG, or take a screenshot."
- Or transcode HEIC → JPEG client-side (via `heic2any` ~50 KB worker) before upload.
- Or pipe HEIC through `sharp` on the backend (`sharp(buf).toFormat('jpeg').toBuffer()`).

## Actual

Silent acceptance, silent backend failure, user-visible model "ignores" the photo.

## Evidence

- Source: `Index.tsx:367` — only `file.type.startsWith('image/')` check.
- Source: `Index.tsx:1496,1592` — `accept="image/png,image/jpeg,image/gif,image/webp"` (note: no `image/heic` — but browsers still allow it).
- Spec: Azure OpenAI Vision docs — supported formats are JPEG, PNG, WEBP, GIF (animated unsupported); HEIC is NOT listed.

## Notes

This is a real iOS UX hole — most iPhone photos are HEIC by default. The "QA only browsers" path won't catch it unless tested on Safari iOS.
