## Description

Verified on main today (2026-05-28): the two `<input type="file" accept="image/*">` instances in `ChatMessages.tsx` still call `FileReader.readAsDataURL(file)` with no `file.size` guard.

Read of `src/components/chat/ChatMessages.tsx` around line 296 and 322 confirms: `const reader = new FileReader();` then `reader.readAsDataURL(file);` — no size check between them.

Backend `express.json({ limit: '20mb' })` rejects at 413 for the wire payload, but only AFTER the client has burned 3-5s on a synchronous base64 encode of a large image (iOS Safari tab-kill at ~50MB).

## Steps to reproduce

1. Open chat at http://localhost:8081.
2. Click image-attach in a message edit / new message.
3. Pick a 50MB image (or any >10MB).
4. Tab freezes during base64; eventually 413 from backend.

## Expected

Reject before `readAsDataURL` with a toast — matching the existing `MAX_FILE_BYTES = 8MB` pattern in `VibeComposer.tsx`.

## Actual

No size check. Tab freezes.

## Evidence

- `qa-harness/evidence/WE-20260528-204/code-refs.txt` — line pointers
- Verifies: WE-20260527-220 is still open

## Notes

The PR for WE-220 needs to be merged. Suggested fix:

```ts
const MAX_CHAT_IMAGE_BYTES = 8 * 1024 * 1024;
if (file.size > MAX_CHAT_IMAGE_BYTES) {
  toast.error('Image too large — max 8MB.')
  e.target.value = ''; // clear input so the same file can be re-picked
  return;
}
```
