## Description

App declares `<html lang="en">` permanently in `index.html`. The chat backend correctly detects/returns `language` per message (Hindi, Gujarati, Arabic, Spanish, French, etc — see `SUPPORTED_LANGUAGES`), but the `<div>` wrapping `message.content` is never given a corresponding `lang=` attribute. Result: NVDA (English voice) reads Hindi text using English phonemes — garbled, incomprehensible. Same for Gujarati, Arabic, Chinese. This fails 3.1.2 directly.

`grep "lang=" src/` returns zero hits in source (only index.html). Likewise no `dir="rtl"` for Arabic — Arabic text renders LTR which screen readers + sighted users find jarring.

## Steps to reproduce

1. Open VoiceOver (English voice)
2. Switch language picker to Hindi
3. Send "नमस्ते" or any Hindi greeting
4. Listen to the SR announce the Hindi response — phoneme garbage

## Expected

- On each chat message render, set `lang={message.language}` (BCP-47) on the markdown wrapper div.
- For RTL languages (ar, he, fa, ur), also set `dir="rtl"` on the message bubble.
- Optionally update `<html lang>` when the active conversation language settles, so page-level SR voice can switch.

## Actual

All content rendered as English regardless of detected language.

## Notes

The detection signal exists at `useChat.ts:52` (`language?: string // detected response language (BCP-47)`) — just needs to flow into the DOM. ~15-line fix.
