## Description
A 10-turn planning session for "200-guest Bangalore Konkani wedding, December 2027, $25k budget" requires the model to (a) remember Konkani / Bangalore / December / $25k across all turns, and (b) re-arithmetic when the user changes parameters ("add 50 more guests"). Empirically, large-context history is truncated to last 10 messages (`getChatHistory(historyLimit=10)` at chatController.ts:383) which means by turn 8 the original "Konkani" and "$25k" are likely OUT of the active context window.

Without a structured user-state object (budget, guests, location, religion, date) injected into every system prompt, the LLM is forced to re-extract from the last ~10 raw messages — and "$25k" becomes "around $30k or so" or just "your budget" by turn 9. The summarizer (`conversationSummarizer.ts` exists) might mitigate but is not visible in the prompt path.

## Steps to reproduce
10-turn script:
1. "Plan my 200-guest Bangalore Konkani wedding for December 2027, budget is $25k."
2. "Suggest 3 venues."
3. "What about catering — vegetarian Konkani menu?"
4. "How about bridal outfits — mid-budget."
5. "Switch to invitations now — 200 cards."
6. "Add 50 more guests — make it 250."
7. "How much should I budget for photography in our total?"
8. "Sangeet ideas?"
9. "Reminder: when should we book venue?"
10. "Quick recap — what's my total budget?" → expects to recall $25k AND prompt user that 50 added guests will push it.

## Expected
- A persisted "session state" object (budget, guestCount, location, culture, date) extracted by an upstream classifier and injected into every system prompt as: "User context: 250 guests (was 200), Bangalore, Konkani, December 2027, $25,000 USD budget."
- Re-affirm budget in turn 10 with $25k exactly.

## Actual
By turn 8-10, budget loosely recalled as "around $25-30k", guest count may drift, location and culture sometimes lost.

## Notes
`conversationSummarizer.ts` service exists — wire it into the planner/assistant system-prompt path. Cheaper alternative: add a "WeddingProfile" sticky field to the user document with budget/guests/etc that the controller always reads and prepends.
