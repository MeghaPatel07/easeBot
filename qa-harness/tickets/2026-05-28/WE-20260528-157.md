## Description

`useChat.ts:219-255` runs a one-shot `getDocs` fan-out at login that collects every liked message across every thread into `allLikedMessages`. The effect's only dep is `[user?.uid]`, so it never re-runs after sign-in. Liking a NEW message later only updates the per-thread `subscribeToMessages` stream (which fixes the current view) but never the global liked-collection — the sidebar's Liked Messages view therefore omits anything liked in the current session. Unliking a previously-liked message similarly leaves a stale entry that disappears only after reload.

## Steps to reproduce

1. Sign in. Open the sidebar "Liked messages" view; note current count.
2. Return to the chat, like a fresh AI message (heart icon).
3. Reopen the Liked messages view without reload.

## Expected

The newly-liked message appears in the list within ~1 s.

## Actual

The Liked-messages list is unchanged; the new like is invisible. Reload required.

## Evidence

- Screenshot(s): `qa-harness/evidence/WE-20260528-157/screenshots/`
- Console log: `qa-harness/evidence/WE-20260528-157/console.log`

## Notes

Fix: replace the one-shot fan-out with `onSnapshot` per thread (re-runs when threads list changes) or maintain `allLikedMessages` reactively by listening to per-thread `messages` collections with `where('liked','==',true)`.
