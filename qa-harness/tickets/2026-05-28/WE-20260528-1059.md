## Description

WCAG 2.2 3.2.6 (NEW at Level A) requires that when one of the help mechanisms (contact info, human assistance link, self-help link, contact mechanism) appears on multiple pages, it appears in the *same relative order* in the page repeated content.

The app has a `/help` self-help link inside `ProfileMenu` and `ChatSidebar` only. On every other page (`/checkout`, `/pricing`, `/privacy`, `/terms`, `/payment-failure`, `/payment-success`, `/login`, `/404`, `/shared/...`) there is NO ChatSidebar visible AND NO ProfileMenu — therefore NO help link is reachable. A user who hits an error on `/checkout` or `/payment-failure` cannot find Help without navigating back to `/`.

## Steps to reproduce

1. Navigate to `/checkout` from `/pricing`
2. Visually scan / Tab through the page
3. Confirm: no link to Help, no contact, no support email visible

## Expected

Per 3.2.6: a Help mechanism (link to `/help`, mailto, or contact widget) MUST be in a consistent position on every page that has repeated content. Add a persistent footer Help link or a top-right Help icon on every standalone page.

## Actual

Help is only reachable from main app surfaces (`/`, settings) — not from any error/checkout/legal page.

## Notes

Especially severe on `/payment-failure` — user fails to pay, can't find Help, abandons. Combine with -064 (payment-failure reason-unknown UX copy).
