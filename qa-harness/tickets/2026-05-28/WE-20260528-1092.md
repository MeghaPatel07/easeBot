## Description

Delete checklist: `.catch(() => toast.error('Failed to delete'))` — implies a direct delete without confirmation. For users with motor impairments / switch / voice control, an accidental delete is unrecoverable.

WCAG 3.3.4 is technically for legal/financial/data submissions, but the spec's intent extends to "user data that takes effort to recreate" — checklists fit.

## Expected

- Delete actions show confirmation dialog ("Delete this checklist? This cannot be undone.")
- OR: implement soft-delete with "Undo" toast for 10s
- Visible "Type DELETE to confirm" pattern for destructive bulk actions

## Actual

Single-tap destructive actions.

## Notes

The Notes architecture (per project memory) has trash semantics — apply same pattern to planner/timeline.
