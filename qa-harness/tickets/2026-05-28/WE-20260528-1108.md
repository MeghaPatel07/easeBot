# WE-20260528-1108 — Cannot perform authenticated end-to-end perf measurement — Sprint 3 limited to unauthed routes + isolation benches

**Severity:** P2 (BLOCKER for full backend perf signal)
**Status:** triaged
**Assigned:** fix-performance
**Area:** Performance / QA tooling
**Discovered:** 2026-05-28

## Symptom
Several Sprint 3 measurements (per the brief) require an authenticated Firebase ID token:
- Streaming throughput (SSE first-chunk, tokens/sec on `/api/chat/stream`)
- Tool execution overhead (first LLM call + tool exec + second LLM call on /api/chat with `create_checklist` tool)
- Cache hit ratios over 50 real chat requests
- Translation cache effectiveness inside the actual handler

The QA agent has no service-account credential to mint tokens (per project rule "Never read `*-firebase-adminsdk-*.json`") and no test-user JWT was provided. Probes to `/api/chat`, `/api/chat/stream`, `/api/checklists`, `/api/notes` all return either 401 (with bearer faketoken) or 429 (rate-limited unauth).

What we did measure successfully without auth: Sharp ops in-process, Azure Translator REST direct, /api/health under load, build artifacts, Lighthouse on the prerendered prod.

## Suggested fix
1. Add a `DEV_PERF_BYPASS_TOKEN` env-gated middleware that issues a synthetic `req.user` only when `NODE_ENV !== 'production'` AND a per-deploy random token matches. This unblocks load testing without requiring a real Firebase user.
2. Alternative: provide `qa-harness/scripts/get-test-token.mjs` that uses Firebase JS SDK + a dedicated `qa-perf@weddingease.ai` user to mint short-lived ID tokens, gitignored.
3. Once unblocked, refile this as `WE-20260528-1108-followup` with concrete measurements.
