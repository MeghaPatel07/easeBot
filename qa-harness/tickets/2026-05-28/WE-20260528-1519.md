# WE-20260528-1519 — Helmet contentSecurityPolicy disabled — perf-neutral but blocks Server-Timing header passthrough

**Severity:** P3
**Status:** triaged
**Assigned:** fix-performance
**Area:** Performance / Headers
**Discovered:** 2026-05-28

## Symptom
`app.ts:43` disables CSP for SSE compatibility. Helmet ALSO does not set `Server-Timing` headers automatically (which the controllers don't emit either).

`Server-Timing` would let the frontend automatically capture backend phase timings (e.g. `prompt_architect_ms`, `llm_ms`, `image_api_ms`) in `PerformanceObserver` without any client work.

## Why this matters
- Without `Server-Timing`, the only way for FE to know backend phases is to parse SSE chunks for timing markers — currently not done.
- Adding it requires per-controller instrumentation but cost is ~0.1ms per request.

## Suggested fix
Add a middleware that wraps `res.json` and emits `Server-Timing: prompt-architect;dur=3200, llm;dur=8400, image-api;dur=22000`. Hook it into `chatController.ts`'s existing `phStart` timing.
