## Description
Stylist mode's system prompt scopes it to aesthetic/styling work ("Help couples define their wedding aesthetic … color palettes … silhouettes … bridesmaid styling"). When the user asks a pricing question while in stylist mode, the model answers with a detailed cost-tier breakdown (USD + INR conversions, named designer luxury tier) instead of either (a) declining the off-scope ask, or (b) handing off to assistant/planner. With consultant mode commented out, no other route catches "cost" questions, so stylist becomes a de-facto fallback budgeting service.

## Steps to reproduce
1. `curl -s -X POST http://localhost:3001/api/chat/stream -H "Content-Type: application/json" -d '{"message":"What is the average cost of a wedding lehenga?","mode":"stylist"}'`
2. Observe response: itemized cost ranges across "Local Boutiques" / "Mid-Range" / "Luxury Range" with USD + INR figures and named luxury designers (Sabyasachi, Manish Malhotra).
3. Note `final mode = stylist` in the `t:"d"` SSE frame — model never tried to hand off.

## Expected
Stylist mode either (a) gracefully redirects pricing questions to the assistant prompt's broader scope, or (b) the model explicitly says "pricing is outside my styling lens — let me hand you back to general planning" and continues with general guidance. No INR/USD ranges with named luxury vendors from a styling sub-agent.

## Actual
```
"1. **Budget Range**: Local Boutiques: $200–$800 (₹15,000–₹60,000) …
 2. **Mid-Range**: Established Designers or High-End Stores: $800–$3,000 …
 3. **Luxury Range**: Top Designers (e.g., Sabyasachi, Manish Malhotra): $3,000–$10,000+ …"
```
Numbers are also unsourced and likely stale — the prompt explicitly bans pricing-as-fact behavior elsewhere (see WE-20260527-355) but stylist prompt has no equivalent guard.
