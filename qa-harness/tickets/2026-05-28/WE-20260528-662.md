## Description

The thread list is a flat sequence of `<button>` elements (one per thread). For a user with 30+ threads:

- Tab cycles through every thread one-by-one to reach the bottom
- No Home/End, no PageUp/PageDown, no arrow keys
- No `role="listbox"` / `role="option"` semantics — the section is just a column of buttons

This is the same pattern the Index page uses for sidebar nav (Planner / Liked / Gallery / Notes…), making keyboard-only navigation tedious. Sighted users skim the list visually in milliseconds.

## Steps to reproduce

1. Keyboard only, mouse hidden
2. Open sidebar, populate with 20+ threads
3. Try to reach the 18th thread

## Expected

Wrap thread list in `role="listbox"`; each thread `role="option" aria-selected={isActive}`. Implement arrow-key navigation (Up/Down moves focus, Enter activates) following ARIA Authoring Practices. OR use a single roving-tabindex pattern.

## Actual

Linear Tab through every entry.

## Notes

Same pattern in: notes list (NotesSidebar.tsx), gallery image grid (GalleryView.tsx — 3-col grid is also flat buttons). All would benefit from listbox + roving tabindex.
