## Description

Locked pricing decisions (auto-memory `project_pricing_rollout` §6) say:
- Free: $0
- **Pro: $14.99/mo or $119/yr**
- Pro Max: $39/mo or $299/yr

The current `Pricing.tsx` constant `PRICING_DATA` ships:

```ts
const PRICING_DATA: PricingRow[] = [
  { tier: 'free',   monthlyUsd: 0,  annualUsd: 0 },
  { tier: 'pro',    monthlyUsd: 10, annualUsd: 79, isRecommended: true },   // ❌
  { tier: 'promax', monthlyUsd: 39, annualUsd: 299 },                       // ✅
]
```

Pro monthly is **$10 vs locked $14.99** → −33%.
Pro annual is **$79 vs locked $119** → −34%.

Pro Max matches.

Additionally, the FAQ copy on the same page reinforces the wrong number:
> "Pro ($10/mo) adds more tokens, image generation, and advanced planning tools." (`Pricing.tsx:53`)

Anyone hitting `/pricing` today will be charged the wrong price by PayU (which receives the FE-computed amount). This is a direct revenue leak the moment a real customer checks out.

## Steps to reproduce

1. Open `http://localhost:8081/pricing`.
2. Inspect the Pro card price = `$10/mo`.
3. Compare to locked memory `project_pricing_rollout.md` §6: `pro: 300k/day + 3M/mo ($14.99/mo or $119/yr)`.

## Expected

## Actual
