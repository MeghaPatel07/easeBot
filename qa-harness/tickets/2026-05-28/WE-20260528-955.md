## Steps to reproduce
1. Sign in as same user in Chrome and Firefox (different storage; not same browser context).
2. In Chrome: Settings, Profile, change nickname from "A" to "B", Save.
3. In Firefox, click around (Chats, Planner, Chats) without reloading.
4. Observe nickname in ChatSidebar profile row and ChatHeader.

## Expected
On route change (or focus-back, or within 30s), Firefox should refetch and show "B".

## Actual
- `AuthContext.profile` only loads via `getDoc` ONCE per session (AuthContext.tsx:92, 166, 181, 221, 250, 264). No `onSnapshot`. Route change does not re-trigger.
- `useAccount` has `staleTime: 30_000` but `refetchOnWindowFocus` is TanStack default true — so focus refetch only updates `['account','me']` query cache, NOT `AuthContext.profile`. ChatSidebar reads `useAuth().profile.nickname` directly, still "A".
- Only F5 or explicit sign-out/in fixes Firefox.

## Root cause
AuthContext is the source of truth for nickname/name; useAccount is parallel cache. Refetching one does not update the other.
