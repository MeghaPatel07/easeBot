## Description

Backend SUPPORTED_CURRENCIES at paymentController.ts:53-55:
```
['USD', 'INR', 'GBP', 'EUR', 'AUD', 'CAD', 'JPY', 'AED', 'SGD']
```

Frontend Pricing.tsx dropdown options — verified the user is allowed to override to whatever currency ipgeolocation returns. ipgeolocation returns many more codes (NZD, ZAR, CHF, BRL, MXN, etc.). Without a guard in `handleCurrencyOverride`, the user can set currency='CHF' (Swiss franc); their pricing displays in CHF; they go to /checkout; the call to `/api/payment/initiate` returns 400 `unsupported_currency`.

The FE never validates the override list against the BE allowlist; the BE rejection happens at submit-time, after the user has filled the entire billing form.

## Steps to reproduce

1. Spoof IP via proxy to Switzerland (or temporarily set `localStorage[eb_currency_override] = 'CHF'`).
2. Load /pricing. Currency shows CHF.
3. Click Pro. Land on /checkout. Fill the form. Submit.
4. `/api/payment/initiate` → 400 `unsupported_currency`.

## Expected

FE pulls supported list from a shared constant or BE GET endpoint; dropdown only shows the 9 supported codes; geo-detected unsupported → fallback to USD with a small "We don't yet support {ipgeo_currency} for billing; showing in USD" notice.

## Actual

Lazy currency surface → 400 at submit.

## Notes

Fix-frontend + shared types. The 9-currency constant should live in a single shared `src/constants/currencies.ts` consumed by both repos OR fetched at app-start.
