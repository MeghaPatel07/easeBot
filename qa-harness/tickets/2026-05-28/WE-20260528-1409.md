## Description

`circuitBreaker.ts` exports four ready-to-use breakers:
- `llmCircuitBreaker` (threshold 5/60s, cooldown 30s) — meant to wrap Azure OpenAI calls.
- `imageCircuitBreaker` — meant to wrap GPT-Image-1.5 / GPT-Image-1 calls.
- `speechCircuitBreaker` — Azure TTS/STT.
- `translatorCircuitBreaker` — Azure Translator.

`grep -rn "llmCircuitBreaker\|imageCircuitBreaker\|speechCircuitBreaker" src/` returns ZERO hits in code (only the export). Only `translatorCircuitBreaker` is actually used in `services/translation.ts`.

Consequence: when Azure OpenAI / GPT-Image / Speech goes down or starts 5xx-ing en masse, every chat request retries the upstream up to its internal retry budget (`withRetry` for image, none for chat-stream). No breaker trips. We hammer Azure with retries while Azure is degraded — making outages worse.

Brief scenario: "Force 10 consecutive image-gen failures via malformed requests, trip breaker. Then send valid request — does it 503 cleanly? Does it reset?" — answer: **breaker never trips because it isn't wired**. Every image request, even during an Azure outage, drives full retries (1 retry × ~5s = 5s of wasted backend latency per call × all concurrent users).

## Steps to reproduce

```bash
grep -rn "llmCircuitBreaker\|imageCircuitBreaker\|speechCircuitBreaker" /Users/krish/Desktop/easebot/easebot-backend/src
# Only the export line in circuitBreaker.ts. No callers.
```

## Expected

- `generateImageGptImage1` should wrap `withRetry(callAzureImageGeneration(...))` in `imageCircuitBreaker.execute(...)`.
- `callAzureAI` / `streamCallAzureAI` should wrap the upstream call in `llmCircuitBreaker.execute(...)`.
- `transcribeAudio` and `synthesizeSpeech` (or whatever the TTS entry is) should wrap in `speechCircuitBreaker.execute(...)`.
- When the breaker is OPEN, return 503 `{error: 'image_service_degraded', retryAfter: 30}` instead of letting the call try Azure.
