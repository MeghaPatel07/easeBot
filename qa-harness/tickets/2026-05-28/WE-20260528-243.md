## Description

When backend restarts (nodemon picks up a `.ts` change, tsx restarts, or PM2 reloads), there's a 1-3 second window where `localhost:3001` rejects connections (ECONNREFUSED). The frontend treats this as a generic network error → toast "Failed to send". No retry; user has to manually re-send.

In dev, the developer is the only victim. In prod, blue-green deploy windows have the same flavor.

## Steps to reproduce

1. Open chat at localhost:8081. Open backend in another terminal.
2. Type a long message. Edit a backend file (trigger nodemon reload).
3. Send the message at the moment of reload → "Failed to send" toast.

## Expected

Detect ECONNREFUSED / `TypeError: Failed to fetch` and retry up to 3× with backoff (200ms, 600ms, 1.5s). On final failure, show "Service restarting — try again in a moment" instead of generic.

## Actual

No retry. Generic toast.
