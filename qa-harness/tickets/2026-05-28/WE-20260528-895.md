## Description

VibeComposer.tsx:145 renders `<img>` for vibe-preview thumbnails without:
- `loading="lazy"` — image decoded synchronously even if below fold.
- `width` / `height` attributes — browser can't reserve space → layout shift when image loads.
- `decoding="async"` — sync decode blocks the main thread.

CLS impact: opening VibeComposer scrolls the user's prompt input area as images pop in. Lighthouse penalizes CLS heavily.

## Steps to reproduce

1. Open image-gen flow → VibeComposer with 10+ vibes.
2. DevTools → Lighthouse → Performance audit.
3. Observe CLS > 0.1 attributable to the vibe-image grid.

## Expected

```tsx
<img
  src={vibe.preview}
  alt={vibe.name}
  width={144}
  height={144}
  loading="lazy"
  decoding="async"
  className="..."
/>
```

## Actual

No lazy load, no dimensions.

## Evidence

- VibeComposer.tsx:145.

## Notes

Sprint 2 -313 covered /gallery LCP; this is the same class of issue in VibeComposer.

## Resolution

Added `width={48}`, `height={48}`, `loading="lazy"`, `decoding="async"` to the single reference-preview `<img>` at line 145. Tailwind `h-12 w-12` -> intrinsic 48×48 attributes match 1:1 so the browser can reserve the box before the blob URL decodes (CLS contribution -> 0). Decode moved off main thread.
