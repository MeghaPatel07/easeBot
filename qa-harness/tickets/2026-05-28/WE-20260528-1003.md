## Description

`handleGetSharedNote` does `res.status(200).json(note)` — passing the entire Firestore document to anonymous callers. The note document contains owner-scoped PII fields not intended for public viewing:

- `userId` (Firebase uid of the owner)
- `collaborators[]` (array of `{userId, email, permission}`)
- `lastEditedBy` (email of the most recent editor, set in `handleUpdateNote`)
- Any other internal fields (timestamps, internal IDs, audit metadata)

A public share link is meant to surface note CONTENT, not owner/collaborator identity. The leak gives anyone with the shareId a working email list to phish.

## Repro

1. As user A, create a note with a few collaborators and enable public link.
2. `curl http://localhost:3001/api/notes/shared/<shareId>` (no auth).
3. Response body contains `userId`, `collaborators[].email`, `lastEditedBy`.

(Live test of large-shareId path also reproduces; see WE-20260528-1005 for the separate Firestore error leak on the same handler.)

## Suggested fix

In `handleGetSharedNote`, build a public projection: `{ id, title, content, publicAccess: { permission }, updatedAt }` — strip `userId`, `collaborators`, `lastEditedBy`, `comments[].userId/email`, and any other identity fields before responding.
