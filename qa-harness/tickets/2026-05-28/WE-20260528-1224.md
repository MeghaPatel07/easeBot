## Description

The summary content respects targetLanguage (conversationSummarizer.ts:34-37 appends "Respond in {language}"). But the **wrapper string** in the controller is hardcoded English:

```ts
effectiveHistory = [
  { role: 'assistant' as const, content: `[Previous conversation summary]: ${summary}` },
  ...recentMessages,
]
```

For a thread running in Gujarati (`gu-IN`), the assistant's "memory" turn starts with an English bracketed token. The LLM then either (a) honors the wrapper as an English prefix and may switch mode/language on the next turn, or (b) translates the English wrapper inline, drifting tone.

## Steps to reproduce

1. Send 11 messages in Gujarati.
2. Inspect LLM input: English `[Previous conversation summary]:` followed by Gujarati summary body.
3. Watch the next reply for language drift on the opening phrase.

## Expected

Wrapper is either omitted (summary is just `summary` text), or rendered in the same language, or moved into the system prompt (which is mode/language-agnostic anyway — see -1207).

## Actual

English prefix interrupts non-English flow.

## Notes

Closes naturally with -1207's refactor (moving summary into the system prompt eliminates the prefix).
