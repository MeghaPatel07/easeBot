## Description

Tone settings (warm / analytical / friendly / professional / enthusiastic / concise / quirky / candid / emojis / headers) are written to `users/{uid}.toneSettings` via `savePersonalization`. If the chat send pipeline reads `profile.toneSettings` (or has the value baked into a request payload pulled from `useAuth().profile` at send time), the request body will carry the OLD tone for at least one message — the AuthContext profile is the cached object from sign-in. Even if downstream code re-reads via `useAccount()`, the `useAccount` query has `staleTime: 30_000` (see `src/hooks/useAccount.ts:81`) and is only invalidated when callers use `useAccount.updateProfile`. SettingsModal does NOT use `useAccount`, so the cache is never invalidated — first message after save uses prior tone, possibly forever depending on the consumer.

## Steps to reproduce

1. In Settings → Tone, push "Quirky" to 100, "Emojis" to 100, "Concise" to 0. Save.
2. Without reload, send a new message in chat (e.g. "Tell me about flower arrangements").

## Expected

Response visibly shifts (longer, more quirky, more emojis).

## Actual

Response style is identical to before the save. Reload required.

## Notes

Same root cause as WE-20260528-151..153. `SettingsModal` writes via raw Firestore `updateDoc` instead of `useAccount.updateProfile`; combined with the missing onSnapshot listener (WE-20260528-152) and the 30s staleTime, the AI pipeline reads stale state.
