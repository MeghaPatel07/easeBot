## Description

`createSharedChat(threadId, threadTitle)` writes `threadTitle` verbatim to the `sharedChats` doc without sanitization. If the thread title contains Markdown link syntax or HTML, and `SharedChat.tsx` renders the title via a Markdown component (likely, since chat content is rendered as Markdown elsewhere), then a user-controlled value reaches a renderer in a PUBLIC view.

Even if React's default escaping protects against direct `<script>` injection, this is still a Markdown injection vector: a malicious thread title like `[Click here](javascript:alert(1))` could surface in the SharedChat header. The risk increases if any link uses `dangerouslySetInnerHTML` for syntax-highlighting or KaTeX.

## Steps to reproduce

(Static, needs follow-up DOM verification.)

1. Create a thread.
2. Rename it to `[Pwned](javascript:alert(1))` or `<img src=x onerror=alert(1)>`.
3. Share it. Open `/share/:shareId` in incognito.
4. Inspect rendered HTML for the title element.

## Expected

Title is plain text, all Markdown/HTML stripped or escaped at share-creation time (or at minimum at render time).

## Actual

Unverified — but the source path shows no sanitization in `createSharedChat()` and the SharedChat page renders header content. Worth a 5-min DOM check.

## Evidence

- `qa-harness/evidence/2026-05-28-e2e/flow6/journey.log`

## Notes

- Easy fix: at write time, `threadTitle = threadTitle.replace(/<[^>]+>/g, '').replace(/[\[\]\(\)]/g, '').trim().slice(0, 80)`.
- Pairs with WE-20260528-106.
