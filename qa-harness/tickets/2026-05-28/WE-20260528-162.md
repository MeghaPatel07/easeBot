## Description

`ThemeContext.setTheme` writes the choice to localStorage (`easebot-theme`) and to the backend prefs (fire-and-forget). It does NOT listen for the cross-tab `storage` event, and the profile sync useEffect (`ThemeContext.tsx:78-85`) only fires when `profile?.preferences?.theme` changes — which it never will in Tab B because the AuthContext profile is frozen (see WE-20260528-152). So Tab B keeps its current theme until reload, even though localStorage now disagrees with the DOM.

## Steps to reproduce

1. Open the app in Tab A and Tab B (same browser, same origin).
2. In Tab A, toggle theme from light → dark.
3. Switch to Tab B without reloading.

## Expected

Tab B flips to dark within ~1 s.

## Actual

Tab B remains in light mode until reload.

## Evidence

- Screenshot(s): `qa-harness/evidence/WE-20260528-162/screenshots/`
- Console log: `qa-harness/evidence/WE-20260528-162/console.log`

## Notes

Add a `window.addEventListener('storage', e => { if (e.key === STORAGE_KEY && (e.newValue === 'light' || e.newValue === 'dark' || e.newValue === 'system')) setThemeState(e.newValue) })` in the ThemeProvider mount effect.
