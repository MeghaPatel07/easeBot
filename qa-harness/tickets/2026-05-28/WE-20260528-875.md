## Description

`index.html` ships with `<html lang="en">` and never updates this. Backend correctly detects user language and returns Arabic/Hindi/Spanish responses (per -210), but the document `lang` attribute stays "en". Effect:
- Screen readers use the wrong voice/pronunciation rules for non-English content.
- Lighthouse accessibility score deducts for `<html lang>` mismatch with content.
- Search engines (when authenticated SPA crawled) miss the actual content language.

## Steps to reproduce

1. Send Arabic chat messages.
2. Observe assistant reply in Arabic.
3. View DOM: `document.documentElement.lang === 'en'` still.
4. Lighthouse audit → "Document does not have a lang attribute" passes superficially but content-lang mismatch is flagged in a11y deep-audit.

## Expected

Sync `document.documentElement.lang` from the active conversation's `detectedLanguage` (already returned by backend per -210). Also sync `dir` (see -851).

## Actual

Static `lang="en"`.

## Evidence

- index.html:2.
- No `document.documentElement.lang = ...` anywhere in src (verified via grep).

Companion to -851 (RTL infra), -210 (chat bubble dir), -211 (translation degradation).
