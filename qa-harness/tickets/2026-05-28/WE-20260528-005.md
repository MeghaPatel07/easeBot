## Description

`authflow.md` (the canonical auth spec at workspace root) documents:
- Route: `/auth?mode=signup` / `/auth?mode=signin` → `src/pages/Auth.tsx`
- Components: `SignUpStep.tsx`, `SignInStep.tsx` (each ~500 LOC state machine)
- Cloud Functions: `sendVerificationEmail`, `verifyUserAccount`, `sendForgotPasswordOtp`, `updateUserAccountPassword`
- `AuthContext.tsx` methods: `signUp`, `sendManualVerificationEmail`, `sendPhoneOTP`, `verifyUserPhone`, `signInWithGoogle`, `sendForgotPasswordOtp`, `updatePasswordByEmail`

**None of the route / components exist in the active repo.** The actual auth surface is:
- Route: `/login` → `pages/Login.tsx`
- Modal components: `SignUpModal.tsx`, `SignInModal.tsx` (in `components/auth/`)
- Auth helpers: `services/authService.ts` using Firebase's built-in `sendEmailVerification` (no Cloud Function for verification)
- No phone OTP / no WhatsApp / no Twilio (`PhoneInput.tsx` exists but no `verifyUserPhone` wiring)
- Forgot-password OTP grid not present

Verification emails sent by Firebase point to its own action URL, but if any onboarding email or external campaign links to `/auth?mode=signup`, the user lands on the React `NotFound` page (`<Route path="*" element={<NotFound />} />`).

## Steps to reproduce

1. `curl -sI http://localhost:8081/auth` → HTTP 200 (Vite serves index.html for SPA) but the React Router resolves to `NotFound`.
2. Navigate to `http://localhost:8081/auth?mode=signin` in a browser → renders the NotFound page ("This page could not be found"), not the documented sign-in card.
3. `grep -r '"/auth"' Wedding-Ease-Viva-Chat/src/App.tsx` → no match.
4. `ls Wedding-Ease-Viva-Chat/src/pages/Auth.tsx` → no such file.

## Expected

Pick one of:
- Implement the documented `/auth` route + `Auth.tsx` page (per `authflow.md`), OR
- Update `authflow.md` to reflect the current `/login` + modal-based surface and remove references to Cloud Functions / phone OTP / `SignUpStep.tsx` etc.

Either way the docs and the running app must agree.

## Actual

The active app uses `/login` and inline modals; `authflow.md` describes an unrelated implementation that doesn't exist. There is no documentation of the modal flow.
