# WE-20260528-1110 — `summarizeConversation` called inside chat hot path on every history-overflow turn — should run async

**Severity:** P3
**Status:** triaged
**Assigned:** fix-performance
**Area:** Performance / Pipeline scheduling
**File:** `easebot-backend/src/controllers/chatController.ts:724, :1229`
**Discovered:** 2026-05-28

## Symptom
`await summarizeConversation(olderMessages, getClient(), targetLanguage)` runs synchronously on two hot paths in the chat handler. When the history window expires the user's next message waits for an entire extra LLM round-trip (typically 0.8-2.5s on Azure OpenAI) **before** the actual response stream even starts.

## Root cause
Summarization is treated as a precondition for the next call, but it's only needed to keep the *future* context window small — the current turn could use the older messages directly and let summarization happen in the background, swapping in the summary on the *next* turn.

## Suggested fix
1. Fire the summarization promise without `await` (`void summarizeConversation(...).then(s => persistSummary(uid, s))`).
2. Persist the resulting summary to `users/{uid}/summaries/latest` for the *next* request to consume.
3. On the current turn, accept slightly higher token spend (sending raw older history once) in exchange for ~1-2s TTFB win.
4. Combine with -1106 (cache the summary) for compounding wins.

## Evidence
- `easebot-backend/src/controllers/chatController.ts:724` and `:1229` — both `await` calls in handler critical path.
