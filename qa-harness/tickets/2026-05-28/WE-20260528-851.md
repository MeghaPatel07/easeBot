## Description

WeddingEase has zero RTL infrastructure. Confirmed via source audit:
- `index.html` ships `<html lang="en">` with no `dir` attribute and no language switcher in DOM.
- `grep -rn 'dir="rtl"\|dir="auto"\|dir={' src/` → zero matches (Sprint-1 ticket -210 was filed against chat bubbles only).
- `grep -rn 'ms-\|me-\|ps-\|pe-\|inset-inline\|margin-inline' src/` → zero matches (Tailwind logical-direction utilities never used).
- 90+ uses of physical `pl-/pr-/ml-/mr-` in `src/components/chat/` alone.

Flipping `document.documentElement.dir = 'rtl'` in DevTools at /chat causes:
- ChatSidebar slides in from the LEFT but the open-drawer trigger button stays bottom-LEFT — sidebar covers its own trigger.
- ChevronLeft/ChevronRight in GalleryView lightbox prev/next buttons point the wrong way for RTL reading.
- Send button (lucide-react `Send` icon, src/components/chat/ChatInput.tsx:2) points right-up — in RTL it should mirror to left-up.
- Message bubbles still right-align `assistant` and left-align `user` — backwards for RTL.
- Mode-dropdown `ChevronDown.rotate-180` arrow renders in wrong corner because `pr-`/`pl-` of trigger are physical.
- Settings dialog close-X stays top-right (correct in LTR, should be top-left in RTL); back-button uses `ArrowLeft` which doesn't auto-flip.

This is a primary-market blocker if WeddingEase expands to UAE / Saudi (announced GTM target per pricing notes that include AED region prices). Arabic users today get a half-broken mirror with backward chevrons and physical-side icons.

## Steps to reproduce

1. Open `http://localhost:8081/`.
2. DevTools console: `document.documentElement.dir = 'rtl'; document.documentElement.lang = 'ar';`
3. Navigate `/` → `/chat` (mode picker) → open ChatSidebar (`Cmd+B`) → open Settings (gear) → open Gallery.
4. Observe at each step: physical-side padding, non-flipped chevrons, sidebar-covers-trigger overlap.

## Expected

- `index.html` adds `dir="ltr"` default; root provides a context that flips to `rtl` based on profile language or `Accept-Language`.
- Sweep `pl-/pr-/ml-/mr-/border-l-/border-r-/rounded-l-/rounded-r-/left-/right-` for `ps-/pe-/ms-/me-/border-s-/border-e-/rounded-s-/rounded-e-/start-/end-` in chat shell, sidebar, settings.
- Directional icons (`ChevronLeft/Right`, `ArrowLeft/Right`, `Send`) get an `rtl:rotate-180` (or component-level swap).
- Drawer + Dialog slide-from-direction tokens flip in RTL.
- Add `dir="auto"` to message bubble + textarea (covered by -210 — this ticket is the system-wide structural gap).

## Actual

Zero RTL support. Visually broken end-to-end when `dir="rtl"` is set.

## Evidence

- src/components/chat/ChatInput.tsx:191 — `rotate-180` is symmetry-axis dependent, breaks in RTL.
- src/components/GalleryView.tsx:221,231 — ChevronLeft/Right used literally (not direction-aware).
- index.html:2 — `<html lang="en">`, no `dir`, no swap mechanism.
