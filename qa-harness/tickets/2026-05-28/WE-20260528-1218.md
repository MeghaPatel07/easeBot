## Description

```ts
private static readonly API_KEY =
  import.meta.env.VITE_IP_GEOLOCATION_API_KEY ||
  'f92eea25a17246a09563543976ca23d7'
```

A literal ipgeolocation.io API key is hardcoded as fallback. Even when the env var IS set, the literal still ships in the bundle (Vite inlines both sides of the `||`). Anyone can view-source and:

1. Burn the WeddingEase quota (free tier is 1k/month).
2. Use the key for unrelated services.

Same pattern check needed for `VITE_EXCHANGE_RATE_API_KEY` in `exchangeRateService.ts:20` (verified: no literal fallback — that one is safe).

## Steps to reproduce

1. Open production bundle. Search for `f92eea25a17246a09563543976ca23d7`. Present.
2. `curl "https://api.ipgeolocation.io/ipgeo?apiKey=f92eea25a17246a09563543976ca23d7"` → 200, billed to WeddingEase.

## Expected

No literal key in source. If env not set, log a warning and use `FALLBACK` country/currency without a network call.

## Actual

Key burned into every shipped bundle.

## Notes

Fix-frontend. Quick patch:

```ts
private static readonly API_KEY = import.meta.env.VITE_IP_GEOLOCATION_API_KEY || ''
// in getUserCurrency: if (!this.API_KEY) return FALLBACK
```

Rotate the leaked key after fix lands (Krish — Firebase write rule applies to nothing here; ipgeolocation has its own dashboard).
