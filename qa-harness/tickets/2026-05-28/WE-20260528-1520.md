# WE-20260528-1520 — Sharp module loaded twice: imageGeneration.ts AND imagePostProcessor.ts both `import sharp`

**Severity:** P3
**Status:** triaged
**Assigned:** fix-performance
**Area:** Performance / Backend cold-start
**Discovered:** 2026-05-28

## Symptom
Static analysis:
- `imageGeneration.ts:22` — `import sharp from 'sharp'`
- `imagePostProcessor.ts:1` — `import sharp from 'sharp'`
- `chatController.ts:9` — `import sharp from 'sharp'` (also imported but no usage found in the read range — DEAD IMPORT)

Each `import sharp from 'sharp'` triggers `require('sharp')` at module init, which loads a ~12MB native binary + libvips bindings. Node caches this so subsequent imports are fast, but the first load is ~100-300ms.

## Why this matters
- The dead import in `chatController.ts` adds zero benefit but contributes to cold-start parse time.
- Validates the cold-start figure in -1501.

## Suggested fix
1. Remove dead `import sharp` from `chatController.ts:9`.
2. Lazy-load Sharp inside the two callers via dynamic import:
```ts
let sharpModule: typeof import('sharp') | null = null
async function getSharp() { return sharpModule ??= (await import('sharp')).default }
```
3. Verify all callsites of Sharp can tolerate the async boundary (they're already inside async functions).
