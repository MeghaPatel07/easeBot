## Description

The empty-state branch (line 718) only fires when **both** `entries.length === 0` **and** `weddingDate` is null. A new user who:
1. Sets their wedding date in onboarding (very common — it's the first ask in the planner flow),
2. Then opens /timeline before adding any checklist items,

… falls through the guard. They see the rendered timeline axis with date labels but ZERO event chips — looks like a broken empty graph, not an intentional empty state. There's no copy explaining "you have a wedding date but no events yet — go add one".

A second related branch issue: when `entries.length === 0 && weddingDate` exists, the user gets the toolbar at the top but no body explanation. The toolbar's "Add Event" button is the only path forward, but it's not visually emphasized.

## Steps to reproduce

1. Sign up with a fresh account.
2. Set a `weddingDate` via Settings → Personalization (or via onboarding).
3. Don't add any checklists/events.
4. Open /timeline.
5. Observe rendered axis with date marks but no events; no body text guides the user.

## Expected

Change guard to:
```ts
if (entries.length === 0) { return <EmptyState weddingDate={weddingDate} /> }
```

Empty state shows:
- Icon + heading.
- Copy: "Your wedding is on [formatted date]. Add events or due dates to see them on this timeline."
- Primary CTA: "Add an event" → opens TimelineEventDialog.
- Secondary CTA: "Go to checklists" → links to /planner.

## Actual

Half-empty axis render confuses users into thinking the page is broken.

## Evidence

- TimelineView.tsx:718.
- Tested by setting weddingDate in profile then clicking Timeline.
