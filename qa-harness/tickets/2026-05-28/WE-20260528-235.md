## Description

The custom `a` override:

```tsx
a: ({ href, children }: any) => (
  <a href={href} target="_blank" rel="noopener noreferrer" ...>{children}</a>
)
```

Passes `href` through verbatim. ReactMarkdown ≥9 has a default `urlTransform` that strips `javascript:`, `data:`, `vbscript:` from `href`/`src`. Currently react-markdown@^10.1.0 (per package.json) DOES filter `javascript:` by default.

However:
1. The team explicitly overrides `a` — `urlTransform` still applies, but if someone later passes a custom `urlTransform` that bypasses the filter (e.g. to support `tel:` links), they could inadvertently re-open the `javascript:` hole.
2. There's no explicit "trusted href schemes" allowlist call-out in the code, so the security depends on transitive library behavior.

This is preventive — recommend explicit allowlist on `href` schemes (`http`, `https`, `mailto`, optionally `tel`).

Same applies to `img.src`.

## Steps to reproduce

Inject an assistant message (via WE-20260528-201 channel) with `[click](javascript:alert(1))`. Render. Click. Current behavior: `javascript:` filtered → href becomes empty → click does nothing. SAFE today.

## Expected

Explicit `urlTransform={(url) => /^(https?:\/\/|mailto:|#|\/)/i.test(url) ? url : ''}` on the `<ReactMarkdown>` component.

## Actual

Relies on library default; no allowlist.

## Evidence

- Manual probe — current behavior is safe but undocumented as such.
