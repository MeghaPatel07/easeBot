## Description

The empty-state has 2×2 / 4-across "Quick prompt cards" rendered as `<button>` with `<btn.icon>` + `<span>{btn.text}</span>`. The card buttons fire `handleQuickPrompt(btn.action)` — the action might be different from the text label (e.g. text "Plan timeline", action prefills "Help me plan a 12-month wedding timeline for 150 guests"). For SR users:
- They hear the visible label only
- They have no context for *what will happen* when they click (the auto-filled prompt is long and specific)

Cognitively, autistic users or users with anxiety often need to KNOW what will happen before they activate. The current chips are like surprise lucky-dip buttons.

## Expected

- Add `aria-describedby` linking each chip to a brief hidden description ("Inserts a prompt about planning a timeline")
- Or use `title=` to surface tooltip on hover (mouse-only fallback)
- Better: change activation pattern — first click previews the prompt in the composer; second click sends

## Actual

Single-click sends a templated prompt with no preview.

## Notes

This is a UX cognitive issue more than a strict WCAG fail, but it crosses 4.1.2 (announced name vs actual action mismatch).
