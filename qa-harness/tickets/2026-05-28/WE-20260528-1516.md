# WE-20260528-1516 — Vite build: zero manualChunks splits — 1MB+ vendor bundle on initial page load

**Severity:** P1
**Status:** triaged
**Assigned:** fix-performance
**Area:** Performance / Bundle
**Discovered:** 2026-05-28

## Symptom
`vite.config.ts` has NO `build.rollupOptions.output.manualChunks` config. All vendor deps (React, TipTap suite, Radix, Firebase, posthog, sharp's transpiled bits, recharts if present) get bundled per route-chunk by Rollup's default heuristics.

Sprint 1 -312 noted ChatMessages already hits a >150KB chunk. Static analysis suggests the cumulative vendor blob is 800KB-1.2MB gzipped because:
- TipTap (8+ extensions per package.json) → ~95KB gzipped
- Radix (multiple primitives, dialogs, dropdowns, etc.) → ~65KB gzipped
- Firebase web SDK (auth + firestore + storage) → ~120KB gzipped
- posthog-js → ~50KB gzipped
- React + ReactDOM → ~45KB gzipped

## Why this matters
- LCP is currently 6.5s per Sprint 3 -1102 — bundle size is a primary driver.
- TipTap is only needed in NoteEditor — currently it ships in every chat session.

## Suggested fix
Add to vite.config.ts:
```ts
build: {
  rollupOptions: {
    output: {
      manualChunks: {
        'tiptap': ['@tiptap/react', /^@tiptap\//],
        'firebase-auth': ['firebase/auth'],
        'firebase-firestore': ['firebase/firestore'],
        'firebase-storage': ['firebase/storage'],
        'radix': [/^@radix-ui\//],
        'posthog': ['posthog-js'],
      }
    }
  }
}
```
Plus: `React.lazy(() => import('./pages/NoteEditor'))` — verify NoteEditor is already a route-split chunk (dist/assets/NoteEditor-D1BRRvzy.js exists — good — but tiptap should still be a separate vendor chunk).
