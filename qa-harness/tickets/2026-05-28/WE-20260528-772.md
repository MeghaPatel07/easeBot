## Description
Common wedding arithmetic — "200 guests × $150 per plate", "12-month timeline minus 4 months remaining", "$25k budget, 40% to venue, what's left" — is answered by the LLM doing mental arithmetic. GPT-4 family does ok on small numbers but routinely misses on:
- Multi-step ("calculate per-head cost if budget is $25k, venue is 40%, catering is 30%, leaves remainder split across 5 categories")
- Currency mixed ("if catering is $150pp for 200 guests, what's that in INR at 83.5")
- Large numbers ("$1.2M budget for a 500-guest wedding, what's per-head capacity")

There's no exposed arithmetic tool. plannerTools.ts has create_checklist / edit_checklist_item / mark_as_done / get_checklist_stats / create_reminder / create_note / append_to_note / create_timeline_event — no calc_cost or budget_split tool.

## Steps to reproduce
1. `curl -X POST http://localhost:3001/api/chat/stream -d '{"message":"my budget is $25,000. venue 40%, catering 30%, photography 15%, flowers 10%, miscellaneous 5%. tell me dollar amounts for each."}'`
2. Sum the answers — expect $25,000 exactly. Routinely off by a few hundred.

## Expected
- Add a `calculate_budget_split` tool: takes `{total, percentages: {category: pct}}` returns `{category: amount}`. Forces the LLM to delegate arithmetic.
- Add a generic `compute(expression)` tool for arbitrary arithmetic.
- Plumb in `getLockedRate` from exchangeRateService.ts as a tool so currency conversion is grounded.

## Actual
LLM does the math itself. Errors compound across multi-step calculations.

## Notes
exchangeRateService.ts is already implemented but only wired to paymentController. Promote it to a tool. Similar story for budgets — checklistService has CRUD but no math.
