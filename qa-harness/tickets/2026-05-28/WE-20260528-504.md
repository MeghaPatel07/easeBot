## Description

When the backend fails mid-send (network down, 5xx, 400, gateway timeout — anything except `quota_exceeded` which has its own copy), the FE appends a new AI bubble containing **"Something went wrong. Please try again."** and ends. The user must:

1. Re-type the prompt from memory, OR
2. Manually copy from their previous user-bubble (no copy affordance there either)

There is no "Resend" button on the failed turn, no `[Retry]` link in the error bubble, no auto-retry with exponential backoff.

## Code evidence

```ts
// useChat.ts:829
let errorText = 'Something went wrong. Please try again.'
// ... no retry action attached, just pushed as a plain message
setMessages((prev) => {
  const next = [...prev]
  ...
  next.push({
    id: (Date.now() + 1).toString(),
    text: errorText,
    sender: 'ai',
    ...
  })
})
```

## Steps to reproduce

```bash
# simulate by hitting a bad route from FE (or kill BE briefly)
# In FE: type a message → during send, BE returns non-200
# Observe: bubble "Something went wrong. Please try again." with no button
```

## Expected

The error bubble (or a toast) should include:
- A "Resend" button that re-runs `sendMessage(...)` with the same prompt/mode/attachments
- The most-recent user bubble should expose a "Try again" icon
- For HTTP 5xx, auto-retry once with 2s backoff

## Actual

User has to retype.
