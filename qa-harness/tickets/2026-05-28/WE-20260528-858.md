## Description

The `ToastViewport` (`fixed top-0 z-[100] ... sm:bottom-0 sm:right-0`) shares the same z-index as the AnalyticsConsent banner (`fixed bottom-4 ... z-[100]`). When both are visible, paint order is determined by DOM-mount order, not declared intent. The Toaster mounts in App.tsx:62 BEFORE AnalyticsConsent's typical mount path — so the banner usually wins, leaving the toast hidden behind it on **mobile** (banner is centered horizontally on mobile, toasts render at top — they don't collide there, OK) but **on desktop** (sm:bottom-0 sm:right-0 toast vs the centered consent banner) the toast bottom edge can be overlapped depending on toast height.

Separately, the `WeddingEaseFloater` mascot button at `fixed bottom-6 right-6 z-[60]` is hidden on mobile (`hidden sm:block`) but on **desktop** it sits in the same lower-right area as toast viewport. Z-[60] < z-[100] so toasts cover it — but a multi-toast stack covers most of the bottom-right column for 5 seconds, hiding the mascot CTA.

Multi-toast: try firing 4+ destructive toasts (5000-char message attempts → throw): they stack upward; the topmost toast at desktop reaches near the chat-input area; the bottommost overlays the consent banner.

## Steps to reproduce

1. Clear localStorage (so consent banner shows).
2. Open /chat at 1280×800.
3. Open DevTools console: `for (let i = 0; i < 4; i++) window.dispatchEvent(new CustomEvent('show-toast', { detail: { description: 'Error '+i } }))` — or trigger via 4 sequential failed sends.
4. Observe: bottom-right toast stack overlaps the AnalyticsConsent banner center-bottom, and covers the WeddingEaseFloater mascot.

## Expected

- Toast viewport z should be higher than AnalyticsConsent (z-[110] vs z-[100]) so toasts ALWAYS sit on top.
- AnalyticsConsent should reflow to `bottom-20` (or similar) when toasts are visible — listen to ToastProvider's open state.
- WeddingEaseFloater should hide while toasts are visible (or reposition to `right-24` to clear the toast column).
- On mobile, toast at top-0 collides with sticky ChatHeader (z-10) — that's fine because toast z-[100] > header z-10, but mobile users complain about toasts hiding the back-button. Consider top-4 + viewport-padding.

## Actual

Z-index race + toast/banner/mascot overlap on desktop bottom-right.
