## Description

OTP expires after 300 seconds. WCAG 2.2.1 requires that the user can: turn off, adjust to 10× default, OR extend before expiry. The current UI provides:
- Resend (a partial recovery, but the user must re-receive AND re-type)
- Countdown timer (`otpExpiryTimer`) — but small text on a verification step

There's no:
- 20-second-before-expiry warning ("Your code expires in 20 seconds — stay here?")
- "Need more time?" button that pauses or extends
- Audible/SR announcement when timer reaches ≤10s (the countdown is updated visually but the SR will keep silent — countdown counters are notoriously bad for SR)

For users with motor or cognitive impairments, typing 6 digits from SMS within 5 minutes is borderline; if they're interrupted (phone call, child) they lose the code with no recovery beyond Resend.

## Expected

- Visible countdown shown larger (≥18px text) above OTP inputs
- At 30s remaining: focus-poke + `aria-live="polite"` announcement "30 seconds remaining"
- At 0s: clear inputs and offer "Resend" + "Try a different way" links

## Actual

Silent countdown, smaller text.

## Notes

Combine with -1051 (autocomplete="one-time-code" on the 6 OTP digit boxes — iOS/macOS can auto-fill from SMS).
