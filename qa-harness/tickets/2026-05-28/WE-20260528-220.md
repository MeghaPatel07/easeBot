## Description

`toneSettings: z.record(z.number().min(0).max(100)).optional()` — `z.record(...)` allows ANY string key. The frontend uses a small known set (e.g. `formality`, `warmth`, `playfulness`), but the schema permits a caller to submit `toneSettings: { "key_${i}": 50, ... }` with thousands of unique keys. If those keys are persisted to Firestore or fanned out to PostHog as event properties, the schema explodes.

There's also no cap on the NUMBER of keys.

## Steps to reproduce

```bash
python3 -c "
import json
keys = {f'tone_key_{i}': 50 for i in range(2000)}
print(json.dumps({'message':'hi','toneSettings':keys}))
" > /tmp/tone-flood.json
curl -s -X POST http://localhost:3001/api/chat -H "Content-Type: application/json" -d @/tmp/tone-flood.json
```

## Expected

```ts
toneSettings: z.object({
  formality: z.number().min(0).max(100).optional(),
  warmth: z.number().min(0).max(100).optional(),
  playfulness: z.number().min(0).max(100).optional(),
  // ...known keys explicit
}).strict().optional(),
```

`.strict()` rejects unknown keys.

## Actual

Free-form record accepted.
