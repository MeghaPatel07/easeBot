## Description

Full route list mounted at `/api/checklists`:

```ts
router.get('/stats', requireAuth, handleGetStats)
router.post('/', requireAuth, handleCreateChecklist)
router.patch('/:id/items/:itemId', requireAuth, handleEditItem)
router.patch('/:id/items/:itemId/done', requireAuth, handleToggleDone)
router.delete('/:id', requireAuth, handleDeleteChecklist)
```

Sprint 3 task #3 was "POST /api/checklists, GET (verify), PUT /items, DELETE". Two requirements are unmet:

- **No `GET /api/checklists` list endpoint.** The only read is `GET /stats`. A logged-in user has no API surface to enumerate their checklists; the frontend must be reading Firestore directly via the client SDK. That couples the UI to schema and breaks future migration.

  Probe: `GET /api/checklists/` → 404 (`Cannot GET /api/checklists/`).

- **No DELETE for individual items.** You can DELETE the whole checklist or PATCH an item's text/done state, but there's no way to remove a single item via the API. The frontend must re-PATCH the checklist as a whole or do client-side Firestore writes.

Edge cases that were in scope (6th checklist on free tier; 100 items in one checklist) cannot be verified without these endpoints.

## Steps to reproduce

```bash
# list endpoint missing
curl -isS http://localhost:3001/api/checklists/
# → 404 Not Found, HTML "Cannot GET /api/checklists/"

# stats only — and 401 without auth, confirming the controller checks req.user
curl -isS http://localhost:3001/api/checklists/stats
# → 401 {"error":"Unauthorized"}

# no DELETE /:id/items/:itemId — grep proves it
grep -E "router\.(get|post|put|delete|patch)" easebot-backend/src/routes/checklists.ts
```

## Expected

- `GET /api/checklists` returning the caller's checklists (id, title, items[], updatedAt).
- `DELETE /api/checklists/:id/items/:itemId` to remove a single item.
- Both behind `requireAuth`.

## Actual

- No list endpoint at all.
- No item-level delete.
- Frontend likely bypasses the API for reads (raw Firestore via client SDK).
