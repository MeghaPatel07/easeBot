## Description

Backend correctly handles Arabic — request body with Arabic message returns Arabic assistant text with `"detectedLanguage":"ar","responseLanguage":"ar"`. But the frontend has zero `dir="auto"` or `dir="rtl"` attributes anywhere in the chat surface (grep result: empty).

That means:
- The Arabic message bubble renders with LTR text-direction. Arabic glyphs visually order correctly per Unicode bidi but punctuation lands on the wrong side, line wrapping breaks mid-word, and the bubble's text-align stays `left` instead of `right`.
- The composer textarea has the same issue — caret jumps around as the user types Arabic.

## Steps to reproduce

1. Open chat at localhost:8081.
2. Send: `ما هي تقاليد الزفاف العربية؟`
3. Observe Arabic response — punctuation `?` appears on left, text-aligns to left, paragraph indentation is reversed.

## Expected

Add `dir="auto"` to:
- The bubble `<div>` in `ChatMessages.tsx` that renders `message.text` (and the user bubble equivalent).
- The composer `<textarea>` in `ChatInput.tsx:393`.

This is the lowest-effort, highest-correctness bidi fix: the browser decides per-bubble based on first strong character.

## Actual

No `dir` attribute anywhere in chat. RTL renders against the bidi grain.

## Evidence

- Backend response: `qa-harness/evidence/WE-20260528-210/backend-arabic.json`
- Grep result: `grep -rn 'dir=\|rtl' Wedding-Ease-Viva-Chat/src/components/chat/` → empty
