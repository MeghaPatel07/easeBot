## Description

Live regression check of S1 -103 + S1 -202 on 2026-05-28 17:30Z. Still open. Adding three fresh data points the original ticket didn't surface:

1. **Bypassed Zod**: `routes/chat.ts:11` non-stream uses `validateBody(ChatRequestSchema)`. Line 37 stream omits it. Confirmed live: `POST /api/chat {"mode":"stylist"}` → HTTP 400. Same on `/api/chat/stream` → HTTP 200 with full streaming response.

2. **Bypassed auth**: My probe sent no `Authorization` header and `/api/chat/stream` returned 200 with valid SSE chunks. `requireAuth` is permissive (per S1 -202). The stream endpoint is the **public** endpoint that does inference work. Anyone can hammer it.

3. **Stream returns mode=`planner` regardless of requested mode**: With `{"mode":"stylist"}` the SSE chunks were fine, but the final `d` (done) event includes `mode: ...` from modeRouter's classification, **not** the requested mode (which would have been rejected by Zod if validated). So the FE thinks the user is in stylist; the backend ran whatever the classifier picked. UI/server disagree.

## Steps to reproduce

```bash
curl -X POST http://localhost:3001/api/chat -H 'Content-Type: application/json' \
  -d '{"message":"hi","mode":"stylist"}'
# → 400 {"error":"Validation failed",…}

curl -X POST http://localhost:3001/api/chat/stream -H 'Content-Type: application/json' \
  -d '{"message":"hi","mode":"stylist"}'
# → 200 SSE stream
```

## Expected

`/api/chat/stream` mounts `validateBody(ChatRequestSchema)` middleware. `requireAuth` actually rejects unauth callers. Mode enum aligned across FE (`stylist`) and BE (`styler` typo — pick one and migrate).

## Actual

Drift. Unauth public endpoint. Mode silently ignored.
