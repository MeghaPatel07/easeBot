## Description

`/api/chat/` (non-stream) is wired as:
```ts
router.post('/', requireAuth, chatBurstRateLimiter, validateBody(ChatRequestSchema), quotaCheck('chat'), handleChat)
```

`/api/chat/stream` is wired as:
```ts
router.post('/stream', requireAuth, chatBurstRateLimiter, quotaCheck('chat'), (req, res) => { ... handleChatStream(req, res) })
```

No `validateBody`. The trailing comment even acknowledges: *"validation runs inside the stream handler's wrapper above"* — but it doesn't. There is NO Zod validation inside `handleChatStream`; the only gate is `if (!message && !audioBase64 && !imageBase64) sse({t:'e'...})` which fires only when ALL three are missing.

Consequence:
- `message` can be any length (the non-stream cap is 10,000 chars; stream has no cap). I confirmed a 120 KB message is accepted.
- `history` has no item-count cap or per-item content cap in the schema itself (the non-stream path inherits it, but stream doesn't even apply that schema). I confirmed a 1.0 MB history payload (200 items × 5000 chars) is accepted and streams a real completion.
- `mode` (which the non-stream path constrains to `'styler'/'planner'/'knowledge'` — note this is also wrong, see WE-20260528-1403) is not constrained at all on stream.
- Arbitrary additional fields land in `req.body` and feed `quotaMiddleware.buildRawSkeleton` (chat case): `body.history` is iterated and concatenated. Pessimistic estimate still triggers a 402 IF the user is low on tokens, but the cost estimate uses `roughTokenCount(s) = ceil(len/4)` — for an attacker sending massive history the 1 MB / 4 = 250K tokens estimate would fail for most users, BUT the request body itself was already parsed up to the 20 MB express.json limit.

## Steps to reproduce

```bash
# 1.0 MB history payload — bypasses the non-stream 10K cap
python3 -c "import json,sys; sys.stdout.write(json.dumps({'message':'hi','history':[{'role':'user','content':'x'*5000}]*200}))" > /tmp/big.json
wc -c /tmp/big.json
# → 1006630 bytes
curl -s -X POST http://localhost:3001/api/chat/stream -H "Content-Type: application/json" -d @/tmp/big.json -w "\n%{http_code}\n" --max-time 5
# → 200 OK, real SSE stream begins (`{"t":"c","v":"Hi"}` etc.)
```

## Expected

Mount `validateBody(ChatRequestSchema)` on `/stream` BEFORE `quotaCheck`. Also tighten the schema (see WE-20260528-1410 for history-length cap and history.content max).

## Cost impact

A guest with 10 chat allotment can submit 10 × 1 MB messages = 10 MB of history each round-trip, each priced at the pessimistic 250K-token estimate, BUT some tiers (pro/promax) have monthly budgets large enough to absorb it. Single attacker drains a pro user's monthly cap in ~3 requests if they share a session.
