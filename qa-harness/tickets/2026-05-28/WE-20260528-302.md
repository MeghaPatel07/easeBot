## Description

Vite build produces dist/assets/index-BFQDlZeM.js at 1,196.48 KB raw / 331 KB gzipped, far above the 200KB initial-JS budget. There is NO build.rollupOptions.output.manualChunks configured in vite.config.ts, so all node_modules co-mingle into a single mega-chunk. Lighthouse reports 596 KiB of unused JavaScript on / and 572 KiB on /chat from this and the page chunk combined.

Top contributors that should be code-split:
- @tiptap/* extensions (forced eager by Index.tsx static import of NotesView — see ticket 304)
- posthog-js (~140KB raw — see 305)
- @radix-ui/* (multiple primitives in one chunk)
- firebase/firestore + auth + storage + functions (loaded all-at-once even when only auth is needed at boot)

Build output also warns: '(!) Some chunks are larger than 500 kB after minification.'

## Steps to reproduce

1. cd Wedding-Ease-Viva-Chat && npm run build
2. Inspect dist/assets/index-BFQDlZeM.js size
3. du -sh dist/assets/*.js | sort -h

## Expected

Vendor chunk ≤ 200KB gzipped; long-tail libs (tiptap, firebase, posthog, radix) in separate chunks loaded on demand.

## Actual

index-BFQDlZeM.js = 1,196.48 KB raw / 331.01 KB gzipped. Index-BI9zObHt.js = 1,316.92 KB raw / 354.70 KB gzipped. NoteEditor-D1BRRvzy.js = 513.09 KB raw / 157.90 KB gzipped.

## Notes

Recommend: add manualChunks in vite.config.ts splitting react/react-dom, @tiptap/*, firebase/*, posthog-js, @radix-ui/* into their own chunks, and adopt route-level Suspense for heavy primary chunks.
