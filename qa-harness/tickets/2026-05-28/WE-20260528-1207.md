## Description

When `history.length > 10`, the summarizer replaces older messages with:

```ts
effectiveHistory = [
  { role: 'assistant' as const, content: `[Previous conversation summary]: ${summary}` },
  ...recentMessages,
]
```

Two problems:

1. **Role choice is wrong.** The summary is meta-context, not a model utterance. Injecting it as `assistant` is treated by GPT-4o as if the model said it. The model may then refer to "I previously said X" — but the model didn't say X, the summarizer did. Spec/common practice is to inject as `system` (or as a prepended segment of the live system prompt).

2. **Threshold is precisely 10** (not 11 as the brief asked me to verify; verified at line 719 `if (history.length > 10)`). So the summarizer fires when `history` has 11+ items, i.e. on the **11th** turn. This matches the brief ("send exactly 11 messages, verify backend kicks in"). Trigger is correct.

3. **summarizeConversation** at `services/conversationSummarizer.ts:28-30` joins `${m.role}: ${m.content}` without any role filtering. If `history` contains messages with `role === 'system'` (e.g. tool-call hand-off from a prior turn, or a developer accidentally pushing a system turn into history), they get inlined into the **user**-role summarizer input. **Tool call results are NOT preserved separately** — they'll appear as `assistant: <serialized tool result>` if the upstream client put them under assistant, or be dropped if they had role `tool` (which doesn't exist in the FE history mapping).

4. The frontend at `useChat.ts:497-500` only builds history when `!user` (guest). Logged-in users send no history; backend rebuilds it from Firestore. So this summarizer path is **guest-only** in practice — but still wrong.

## Steps to reproduce

1. As guest, send 11 messages on a single thread.
2. On the 11th request, inspect the backend log — `[chatController] summarization failed` will NOT appear if it works; otherwise look for the LLM input in promptArchitect debug.
3. Verify the next reply doesn't say "earlier I told you" referring to summary content.

## Expected

Summary goes in as `role: 'system'` (or prepended to baseSystemPrompt). Tool-call traces, if present in history, are filtered out before summarization or surfaced separately. Threshold and slice-window are configurable (`SUMMARIZER_TRIGGER`, `SUMMARIZER_KEEP_RECENT`) per `project_backend_structure`.

## Actual

`role: 'assistant'`. No system instruction filter. No env-tunable threshold.
