## Description

`index.css:872` adds a global `@media (prefers-reduced-motion: reduce)` rule that sets `animation-duration: 0.01ms`. This catches keyframe animations but does NOT catch:

- The infinite `animate-[shimmer_1.8s_ease-in-out_infinite]` on the image-generation skeleton (ChatMessages.tsx:596, 963)
- The `animate-[progress_3s_ease-in-out_infinite]` progress bar (line 606, 973)
- The `animate-pulse` Sparkles on Loader2 widgets (multiple files)
- The auto-scroll `behavior: 'smooth'` (ChatMessages.tsx:165) — also a motion concern

The global CSS rule sets animation-duration low but does not unset `animation-iteration-count: infinite` reliably across all browsers when applied via Tailwind's arbitrary-syntax animations. Confirmed via Chrome DevTools: with prefers-reduced-motion enabled, the shimmer still fires.

## Steps to reproduce

1. DevTools → Rendering → Emulate CSS media feature `prefers-reduced-motion: reduce`
2. Trigger image generation
3. Observe — shimmer + progress bar still animate

## Expected

`animation: none !important` (not just shortened duration) on infinite animations under reduced-motion. Also disable smooth-scroll.

## Actual

Animations persist; users with vestibular disorders affected.

## Notes

Suggested CSS:
```css
@media (prefers-reduced-motion: reduce) {
  *, *::before, *::after { animation: none !important; transition: none !important; }
  html { scroll-behavior: auto !important; }
}
```
Override Tailwind arbitrary-animation utilities with a custom class.
