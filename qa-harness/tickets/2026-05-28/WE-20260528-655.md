## Description

The mode selector is rendered as a `<button>` showing the current mode label + ChevronDown. Selecting a new mode from the dropdown:

- Does not use `role="menu"` / `role="menuitemradio"` (these are flat `<button>` items)
- Does not announce the change via live region — the visual chip silently swaps from "Planner" to "Image"
- The trigger button's `aria-label` is unset; SR users hear only "Image, button" with no prefix like "Current mode" or "Mode selector"

WE-20260527-263 covers the missing aria-expanded/aria-haspopup on the trigger. This ticket extends to the missing role markup on the menu + missing post-selection announcement.

## Steps to reproduce

1. SR on
2. Tab to the mode chip on the chat input
3. Open the dropdown, pick "Image"
4. Listen — no confirmation, just the menu collapsing

## Expected

Trigger has `aria-label="Mode: {current}, change mode"`. Dropdown is `role="menu"` with each item as `role="menuitemradio" aria-checked={isActive}`. After selection, a polite `<span role="status">` says "Mode changed to Image".

## Actual

Flat buttons; silent transition.

## Notes

Use the existing Radix DropdownMenu primitive for free a11y. The `MODE_CONFIG` array shape is already compatible.
