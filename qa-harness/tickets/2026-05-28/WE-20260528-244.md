## Description

`formatDuration` (line 134-137):
```ts
const formatDuration = (s?: number): string => {
  if (s == null) return '0:00';
  return `${Math.floor(s / 60)}:${String(s % 60).padStart(2, '0')}`;
};
```

No max-duration ceiling visible in `ChatInput`. If `useVoice` permits unbounded recording, a user who starts recording and walks away records minutes or hours of audio → larger upload, longer STT job, larger Azure bill. Eventually the recording duration display reads `123:45` (123 minutes), which fits but looks broken.

Also `Math.floor(s / 60)` for very long durations doesn't show hours — `1:23:45` would be more natural beyond 60 minutes.

## Steps to reproduce

1. Hit voice record. Walk away. Come back in 30 minutes.
2. Observe display reading `30:00`. Send. Backend STT call uploads ~30MB audio.

## Expected

- `useVoice` should enforce a max recording duration (e.g. 5 minutes, matching most chat-voice products) with a 30s-warning toast.
- `formatDuration` should handle hours: `1:23:45` past 60 minutes.

## Actual

No visible cap.
