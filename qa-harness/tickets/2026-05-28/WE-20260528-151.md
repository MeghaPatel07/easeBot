## Description

`SettingsModal.handleSave` writes the new nickname via `savePersonalization(uid, …)` which calls `updateDoc(doc(db,'users',uid), …)` and then closes the modal. There is no `setProfile(...)` on the AuthContext, no TanStack Query invalidation, and no `onSnapshot` listener attached to the `users/{uid}` document anywhere in the app — `AuthContext` reads the profile exactly once with `getDoc` inside `onAuthStateChanged`. Therefore every component that consumes `useAuth().profile.nickname` (chat header initials, message bubble labels, system "Hi {name}" greeting, ProfileIcon initials, ChatSidebar profile row at `chat/ChatSidebar.tsx:502-509`) keeps showing the OLD nickname until a hard reload. This is the canonical "I changed it but the old value is still showing" bug for the primary identity field.

## Steps to reproduce

1. Sign in. Open ChatHeader / ChatSidebar profile row — note current nickname / initials.
2. Open SettingsModal (legacy personalization) → Identity → change nickname → Save.
3. Modal closes after the "saved" toast. Do not reload.
4. Look at ChatSidebar profile row + any view that reads `profile.name` (also fed from same profile object).

## Expected

Initials + visible name update within ~1 s of save in every consumer.

## Actual

ChatSidebar / ChatHeader / message bubble labels keep the previous value indefinitely. Only a full page refresh picks up the new nickname.
