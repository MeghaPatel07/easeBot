## Description

`AuthContext.useEffect` calls `getDoc(doc(db,'users',uid))` exactly once when `onAuthStateChanged` fires and never re-reads the profile thereafter. No `onSnapshot` is ever attached to the user document anywhere in the codebase (verified via `grep -rn "onSnapshot.*users" src` → 0 matches). Consequences this single root cause cascades into:

1. Server-driven changes (tier upgrades via PayU webhook, admin Firestore tweaks, `tierMirror` flips) never reach the client until reload.
2. Any local write that does not also call `setProfile(...)` (e.g. `savePersonalization`, scattered `updateDoc(doc(db,'users',uid),…)` calls in InvitePartner, AccountTab email patch, etc.) leaves the React tree out of date.
3. Two browser tabs in the same session cannot ever reconcile profile state — a name change in Tab A is invisible to Tab B forever (no BroadcastChannel, no storage event, no listener).

There are 25 sites in `src` calling `useAuth()` that depend on `profile`, all of them susceptible.

## Steps to reproduce

1. Sign in in Tab A (`http://localhost:8081`).
2. Sign in same account in Tab B.
3. In Tab A, change anything on the user profile via Settings → Account (e.g. name).
4. Switch to Tab B without reloading.

## Expected

Tab B reflects the new name within ~1 s.

## Actual

Tab B continues to show the previous value indefinitely; only a hard reload picks it up.

## Notes

This is the structural root cause behind WE-20260528-151, -153, -154, -155, -156, -157, -158, -159, -160. Recommended fix: replace the one-shot `getDoc` in `AuthContext.useEffect` with an `onSnapshot` listener; tear down on sign-out; return the unsubscribe from the auth callback. Doing this also makes cross-tab sync automatic via the Firestore SDK's per-client listener cache.
