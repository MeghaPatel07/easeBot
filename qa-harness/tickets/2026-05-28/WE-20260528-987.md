## Steps to reproduce
1. Tab A, open thread X. Same in Tab B.
2. Tab A, remove thread X via the sidebar menu.
3. Tab B, type a message and send.

## Expected
Tab B detects the removal (`subscribeToThreads` removes the thread from list) and either auto-navigates to a fresh thread or shows "This conversation was removed".

## Actual
- `subscribeToThreads` does remove X from Tab B's sidebar list.
- But `activeThreadId` in `useChat` is unchanged, send writes to `chats/X/messages`, permission-denied (because thread doc gone, rules likely require parent doc).
- Generic "Something went wrong" toast shown. User confused.
