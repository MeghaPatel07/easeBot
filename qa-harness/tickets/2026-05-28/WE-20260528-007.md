## Description

`CLAUDE.md` workspace root states "Active AI modes: `chat`, `planner`, `image`. Therapist + consultant modes are commented out." The Zod schema in `easebot-backend/src/schemas/chat.ts` rejects `mode: 'chat'` and `mode: 'image'`:

```
{"error":"Validation failed","details":[{"received":"chat","code":"invalid_enum_value","options":["planner","styler","knowledge"],"path":["mode"],"message":"Invalid enum value. Expected 'planner' | 'styler' | 'knowledge', received 'chat'"}]}
```

Either CLAUDE.md is wrong, or the schema should accept those values. Today the schema accepts only `planner | styler | knowledge`, NONE of which match CLAUDE.md's list ("chat / planner / image"). `styler` is in the enum but not in CLAUDE.md's active-modes line; the qa-prompt explicitly says "do not test therapist/consultant", so styler may also be a stale mode.

This is a true contract bug — frontend code that follows the docs ("send mode: 'chat'") will get blanket 400 errors. Frontend may rely on it being optional/omitted, in which case the enum is dead-code surface area.

## Steps to reproduce

```
curl -sS -X POST http://localhost:3001/api/chat \
  -H 'Content-Type: application/json' \
  -d '{"message":"hi","mode":"chat"}' --max-time 5
```
→ 400 with the enum error above.

Same with `mode:"image"`.

Omitting `mode` works (auto-routing). Setting `mode:"planner"` or `"knowledge"` works.

## Expected

Either:
1. Update CLAUDE.md "Active modes" to reflect the real enum (`planner | styler | knowledge`), OR
2. Add `chat` and `image` to the Zod enum and wire them to corresponding pipeline stages (knowledge=chat fallback, image routes to image-gen).

## Actual

Documentation and runtime disagree. New developer following CLAUDE.md will write broken code.
