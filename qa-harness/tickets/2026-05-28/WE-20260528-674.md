## Description

When the user clicks "Copy" on a checklist, the result is announced ONLY via Sonner toast. Sonner is polite by default, but:

- The toast may dismiss before SR users complete reading other content
- The Copy button itself doesn't update its visible state (no green check / "Copied!" inline) like ChatMessages.tsx does for the message copy action

Inconsistent feedback patterns across the app. Compare ChatMessages.tsx:181-196 which updates `copiedMsgId` and shows a Check icon — Checklist Copy doesn't.

## Steps to reproduce

1. Open a checklist, click Copy
2. Observe — toast briefly appears, button unchanged

## Expected

Either inline button state update (Copy → Check icon, "Copied" label for 2s, mirroring chat copy UX) AND/OR keep toast but bump to `important: true` so SR users definitely hear it.

## Actual

Toast-only, no inline change.

## Notes

P3 — workaroundable via Sonner toast. Primarily a consistency / discoverability issue.
