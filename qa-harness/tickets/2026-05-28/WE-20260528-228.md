## Description

The stream loop (useChat.ts ~409-613) reads SSE chunks via fetch's `ReadableStream` until done. There's no inactivity timer — if the backend stops sending (network blip, server hang, proxy drop) without closing the socket, the read loop blocks indefinitely and the typing indicator never clears.

Cancel via the Stop button works (line 941: `controller.abort()`), but that requires the user to NOTICE the hang. There's no auto-detect of "no chunk in N seconds → treat as timeout, retry once, then surface 'Connection lost'".

## Steps to reproduce

1. Use chrome-devtools throttling: set Network → "Offline" 5 seconds into a stream.
2. Observe: typing indicator persists indefinitely; no error surface.

## Expected

A `setTimeout(() => { reject('stream_silent') }, 30_000)` per chunk read, reset on every chunk received. On timeout, abort the stream and offer "Tap to resume".

## Actual

No timeout. Hangs visibly.
