## Description

The composer textarea has `data-ph-mask` (line 395 of ChatInput.tsx), which is PostHog's signal to MASK the field value in session replay. Good. BUT the `track('message_sent', { text: inputText, ... })` event (in useChat / analytics.ts) captures the actual text into the event property bag. PostHog masks pixel content but NOT custom event properties.

If a user pastes `<script>document.cookie</script>` into the composer, the literal cookie-stealing-looking string lands in PostHog as a `text` property and is queryable by anyone with PostHog access. Same for personally identifiable info or credentials accidentally pasted.

Need to verify the exact `track(...)` calls — confirm whether `text` is captured raw.

## Steps to reproduce

1. Paste `<script>document.cookie</script>` into chat composer.
2. Send.
3. Inspect PostHog: filter on `event = message_sent` and look for the `text` property.

## Expected

- Either OMIT `text` from PostHog events entirely (length + hash is sufficient for funnel analysis).
- OR hash/truncate before capture: `text_length`, `text_first_chars` (first 20), `text_hash`.

## Actual

Need to verify the capture call; if `text` is captured raw, this is a data-hygiene + privacy bug.
