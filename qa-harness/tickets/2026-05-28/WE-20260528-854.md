## Description

GalleryView has a global `loading` state with a single `Loader2` spinner (lines 107-115) — but once the **list** loads from Firestore the spinner disappears and the grid renders. Each `<img loading="lazy">` then begins decoding individually. While decoding, the tile shows only its 1px-bordered `bg-foreground/[0.04]` background (line 154) — no shimmer, no skeleton, no progress bar.

Throttled to Chrome DevTools "Slow 3G", a 20-image grid renders 20 blank squares for 6-12 seconds. There's:
- No `<Skeleton>` placeholder in each tile during decode.
- No `onLoad` handler on each `<img>` to fade-in once decoded → images pop in abruptly.
- No `decoding="async"` hint (Sprint 2 ticket -313 noted LCP 7.2s on /gallery — this compounds it).
- No `fetchpriority="high"` on the first 4 tiles (above-the-fold).

## Steps to reproduce

1. Open /?view=gallery with >10 images.
2. DevTools → Network → Throttling: Slow 3G.
3. Reload.
4. Observe: spinner disappears as Firestore list resolves (~500ms), then 20 blank squares persist until each PNG decodes individually.

## Expected

- Each tile renders a `<Skeleton className="animate-pulse aspect-square" />` placeholder while `imageLoaded[id] === false`.
- `<img>` gets `onLoad={() => setImageLoaded(prev => ({...prev, [id]: true}))}` and `className` toggles opacity 0→1 with a 200ms transition.
- Add `decoding="async"` and `fetchpriority="high"` on first 4 tiles, `"low"` on the rest.

## Actual

Blank dark squares with no shimmer until decode completes; jarring pop-in.

## Evidence

- GalleryView.tsx:154 — tile container has only border/bg, no skeleton inside.
- GalleryView.tsx:156-161 — `<img>` lacks `onLoad`, `decoding`, `fetchpriority`.
