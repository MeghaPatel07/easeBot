# WE-20260528-1525 — Index.tsx page-component holds 43 useState hooks — atomic state should be context-extracted

**Severity:** P2
**Status:** triaged
**Assigned:** fix-frontend
**Area:** Performance / React state architecture
**Discovered:** 2026-05-28

## Symptom
`grep -cn "useState" /Users/krish/Desktop/easebot/Wedding-Ease-Viva-Chat/src/pages/Index.tsx` → **43**. Every setState in the page triggers a re-render of the entire Index subtree.

Hot states include (from earlier reads):
- `inputText` — keystroke frequency
- `selectedMode`, `attachedImage`, `attachments`
- `inlineEditId`, `inlineEditText`, `inlineEditImage`, `inlineEditImageMime`
- `copiedMsgId`, `voiceState`, `interimText`, `recordingDuration`

Plus mode + attachment context providers wrap Index.

## Why this matters
- `inputText` keystroke + `interimText` voice updates cause Index to re-render even when no descendant depends on those fields beyond ChatInput.
- Components that have nothing to do with input text (like ChatHeader, ChatSidebar, PlannerView, NotesView) all re-render because they're children of Index.

## Suggested fix
1. Extract `inputText` into local state INSIDE ChatInput (the parent only sees the finalized text on submit).
2. Move `voiceState`/`interimText`/`recordingDuration` into a `VoiceContext` so only voice-aware components subscribe.
3. Move `attachedImage`/`attachments` already lives in `ChatAttachmentsContext` — confirm and remove the prop-drilling.

- `/Users/krish/Desktop/easebot/Wedding-Ease-Viva-Chat/src/pages/Index.tsx` — 43 useState hooks (count via grep)
