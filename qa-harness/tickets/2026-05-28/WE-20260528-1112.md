# WE-20260528-1112 — Cold-start measurement blocked: cannot restart backend without disrupting other agents

**Severity:** P3 (measurement gap, not a defect)
**Status:** triaged
**Assigned:** fix-performance
**Area:** Performance / Cold-start QA
**Discovered:** 2026-05-28

## Symptom
The Sprint 3 brief asks for "Cold start — restart backend, time first request, time second." Per the project hard rule "Don't sustain load that disrupts other agents," we did not restart the running backend (PID 68635, uptime 15957s at measurement time — other agents had open sessions).

## What we measured instead (proxy)
Cold-vs-warm middleware path latency without restart:

| Route | Run 1 | Run 2 | Run 3 |
|---|---|---|---|
| /api/health | 3.0ms | 1.2ms | 0.8ms |
| /api/v1/health | 0.7ms | 0.6ms | 1.2ms |
| /api/auth/me | 1.2ms | 0.7ms | 0.7ms (429) |
| /api/checklists | 0.6ms (429) | 0.6ms | 0.6ms |

Run 1 on /api/health was 3ms (vs 0.8ms warm) — module-graph + first-request JIT cost is ~2ms on a long-running node. Production cold start (container boot, before any traffic) will be dominated by:
- `firebase-admin` lib load + service-account decode: 200-500ms
- `microsoft-cognitiveservices-speech-sdk` import + native lib load: 100-300ms
- `sharp` native binding load: 100-200ms
- gRPC initial handshake (Firestore): 100-400ms

Expected cold-start TTFB: ~1-1.5s. Cannot confirm without restart.

## Suggested fix
1. Run this measurement during the next maintenance window with no other agents active. Capture: `time curl /api/health` immediately after `npm run start`.
2. Pre-warm: in `server.ts`, on startup, fire a dummy Firestore read + a Sharp `metadata` call + a Translator detect with `''` text so the native libs JIT before first user request.
3. For production: set up a smoke-test hit immediately after deploy that pre-warms the same paths.

## Evidence
- Backend PID 68635 with uptime 15957s (4.4h) — not restarted to respect agent isolation rule.
