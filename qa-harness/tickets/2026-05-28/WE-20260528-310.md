## Description

src/components/chat/ChatMessages.tsx exports a 994-line component WITHOUT React.memo. It receives 30+ props from src/pages/Index.tsx (lines 1403-1477) including multiple inline arrow function handlers (e.g. lines 1436-1454 onToggleProductLike, onShareProduct; 1455-1463 onRequestMoreProducts; 1464 onOpenPlanner; 1465 onShowSignIn).

Every render of Index — which happens on every keystroke (inputText state lives in Index, not ChatInput) and every streaming chunk update — re-renders ChatMessages and its full message list. With 50+ messages each containing ReactMarkdown + remarkGfm processing, this is the primary INP cliff during streaming.

Counterpart: ChatInput (493 lines) and ChatHeader (235 lines) are also un-memoized; ChatInput receives a fresh inputBarProps object literal every render (Index.tsx:1369-1386).

## Steps to reproduce

1. Open React DevTools → Profiler
2. Send a chat message, observe streaming chunks
3. ChatMessages re-renders once per chunk; observed > 30 renders for a single ~200-word response

## Expected

ChatMessages re-renders only when 'messages', 'isTyping', or visible state changes; ChatInput re-renders only on inputText/voiceState change.

## Actual

Both components re-render on every parent render, which fires for every keystroke + streaming chunk.

## Notes

Fix: wrap with React.memo + custom prop comparator; convert inline handlers in Index.tsx to useCallback; useMemo for the inputBarProps object. Consider extracting ChatInput's inputText to its own state.
