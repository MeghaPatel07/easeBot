## Description

Line 121: `const hasContent = inputText.trim().length > 0 || !!attachedImage;` — correctly trims and rejects whitespace-only at the disable check. BUT the user can type spaces and the send button stays disabled — fine.

The actual edge case: a user holds down spacebar (or paste-in spaces) on mobile. The textarea auto-grows (per `useEffect` line 90-97) because it tracks `el.scrollHeight`, which counts whitespace lines. The Send button stays disabled but the user sees their input pill expand to 8 lines while Send stays grey — confusing.

Secondary: line 478 — when `hasContent` is false on mobile, the Send button is `hidden`. That's good. But after pressing Enter on whitespace, nothing happens silently. No "type a message" hint, no shake animation. Quiet failure.

## Steps to reproduce

1. Open chat on mobile viewport.
2. Type many spaces / hold spacebar.
3. Observe: pill expands; Send button hidden; pressing Enter does nothing.

## Expected

- Either trim the whitespace from `inputText` on `onChange` (so pill doesn't expand).
- OR show a faint placeholder hint when the user attempts Send on empty/whitespace input.

## Actual

Silent: pill grows; Send hidden; Enter no-op.

- Code: `src/components/chat/ChatInput.tsx:121, 478`
