# WE-20260528-1506 — Conversation summarizer net cost analysis: saves ~6-8k input tokens but costs 1 LLM call (~3s, 2.5k tokens billed)

**Severity:** P2
**Status:** triaged
**Assigned:** fix-performance
**Area:** Performance / LLM cost
**Discovered:** 2026-05-28

## Symptom
`chatController.ts:719` triggers `summarizeConversation(olderMessages, getClient(), targetLanguage)` whenever `history.length > 10`. The summarizer:
- Sends `olderMessages` (history.length - 5 messages) as the user payload
- Receives a ~300 token summary
- Replaces the older messages with a single `{ role: 'assistant', content: '[Previous conversation summary]: ${summary}' }`

## Measured (token accounting)
Assume typical wedding-planning thread at 12 messages, each ~200 tokens (avg user+assistant turn):
- **Before summarization (no compression):** 12 × 200 = 2400 input tokens for next turn
- **After summarization:** 1 (summary, ~300 tokens) + 5 recent (~1000 tokens) = ~1300 input tokens
- **Savings:** ~1100 input tokens on subsequent turn

**But the summarizer itself costs:**
- Input: ~1400 tokens (7 older messages = system + 7 × 200)
- Output: ~300 tokens
- Total: ~1700 billed tokens AT temperature 0.3 + 3s wall-clock

## Why this matters
- **First time** at message #11: net LOSS of ~600 tokens, +3s p50 to that turn
- **Steady state** (every subsequent turn): net SAVINGS of ~1100 tokens per turn, +0 latency (summary cached in `effectiveHistory` only for this turn — re-runs next turn!)

**Bug**: The summary is computed PER REQUEST (`effectiveHistory = ...`) and not persisted to the thread. So message #12 re-summarizes messages 1-7 from scratch. Net cost on a 20-turn thread = 9 redundant summarizer calls (~9 × 3s = 27s extra cumulative latency, ~9 × 1700 = 15k wasted tokens).

## Suggested fix
1. Cache the summary on the thread doc (`chats/{tid}.summary` + `summaryUpToMessageIdx`).
2. Incremental summarization: only summarize the newly trimmed-off messages on each turn.
3. Or: raise the threshold from `>10` to `>20` so the cost is amortized over more turns.
