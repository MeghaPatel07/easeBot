## Description

Two custom modal implementations in `Index.tsx` are plain `<div>` overlays — not Radix Dialog, not `role="dialog"`. They:
- Have no `aria-modal="true"`.
- Have no `aria-labelledby` referencing the header h3.
- Do not trap focus inside the modal — Tab leaves into the underlying page.
- Have a close `<X>` button with no `aria-label`.
- No keyboard-driven Esc handler scoped to the modal (relies on global keydown if any).

This means a keyboard user can lose focus into the page beneath while the modal visually obscures the content, and an SR user is told nothing about a modal having opened.

## Steps to reproduce

1. From a chat, trigger the share modal (Share button on a message).
2. Tab — focus leaves the modal into the page behind.
3. Press Escape — no defined behavior.

## Expected

Use Radix `<Dialog>` (already imported elsewhere) or recreate the same a11y contract: `role="dialog" aria-modal="true" aria-labelledby="share-modal-title"`, focus-trap, Esc dismisses, close button `aria-label="Close share dialog"`, restore focus to invoker on close.

## Actual

None of the above.

## Notes

Same applies to `showShortcuts` modal (`/Index.tsx:935`).
