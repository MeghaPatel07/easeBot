## Description

```ts
app.use(helmet({ contentSecurityPolicy: false }))
```

Helmet CSP is DISABLED with a comment "so SSE / EventSource connections are not blocked". This is a misunderstanding — EventSource respects the `connect-src` directive, but if CSP is set with `connect-src self` (or the API origin), EventSource works fine. Disabling CSP wholesale leaves the API responses without CSP headers.

Why this matters:
- If a future change introduces `dangerouslySetInnerHTML` in the chat surface (none today), CSP is the last defense.
- A future XSS via the prompt-injection chain (WE-20260528-201) lands in a CSP-less context and JS executes.

## Steps to reproduce

```bash
curl -sI -X OPTIONS http://localhost:3001/api/chat | grep -i "content-security-policy"
# (empty — no CSP header)
```

## Expected

Define a minimal CSP that fits the chat use case (default-src self; img-src self + data + CDN; connect-src self + cloud APIs; frame-ancestors none).

## Actual

CSP disabled.
