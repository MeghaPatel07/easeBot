## Steps to reproduce
1. Sign in.
2. Open DevTools → Network → throttle to "Offline".
3. Toggle theme to dark.
4. Theme flips visually (good).
5. Re-enable network.
6. Reload.
7. Theme reverts to light (the persisted value).

## Expected
Either:
- (a) Show a toast "Theme couldn't be saved — please retry", then revert, or
- (b) Retry the write when network returns, or
- (c) Persist the optimistic value locally and reconcile on next sign-in.

## Actual
`ThemeContext.tsx:118` writes `patchAccountPreferences(merged).catch(() => { /* noop */ })`. The `.catch` swallows the error. localStorage holds the new value but is overridden on next mount because the profile sync useEffect (line 78) calls `setThemeState(t)` where `t` is the (stale) profile preference.

Same pattern on line 129 (guest → signed-in reconciliation push).

## Impact
P1 — silent data loss class. User believes their preference is saved; it isn't. Hits worst when changing tier-affecting prefs (notifications email opt-in, language) through the same code path — see related tickets in Sprint 1.

## Fix direction
Replace the bare `patchAccountPreferences` call with `useAccount.updatePreferences(merged)` mutation (already has retry policy + invalidation). On reject, revert `setThemeState` to the previous theme and `writeStoredTheme` to the previous value. Show toast.

## Evidence
- `src/contexts/ThemeContext.tsx:113-120, 126-131`
- `src/hooks/useAccount.ts:89-116` (proper path, comments warn explicitly: "mutations no longer swallow errors")
