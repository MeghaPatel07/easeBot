## Steps to reproduce
1. Open a thread with at least 5 AI messages.
2. Quickly click the like button on 5 different messages (target <200ms between clicks).
3. Watch `allLikedMessages` state and the sidebar Liked-messages count.
4. Open the Liked sidebar view.

## Expected
All 5 messages appear in the Liked view.

## Actual
- `toggleLike` (useChat.ts:869) updates local state immediately and fires-and-forgets the Firestore `setDoc` call (useChat.ts:896). Errors are caught and logged silently (useChat.ts:898).
- Firestore is generally OK with parallel `setDoc` calls on different docs, but the local `setAllLikedMessages` updater uses the closure-captured `prev` — if React batches updates, two near-simultaneous toggles can both compute `prev.filter(...)` against the same baseline, causing one liked entry to be lost.
- Even without batching, if any of the 5 Firestore writes fails (network blip), the local UI still shows liked but the server does not. On next reload, that message reverts to unliked silently.

## Root cause
No mutex / queue around concurrent like writes; no rollback on failure; local and server diverge silently.
