## Description

`useChat` keeps `abortControllerRef` and a `streamingMsgId` in the hook state. When the user navigates away (router back, or click into Notes / Profile) mid-stream, the React component that holds the hook UNMOUNTS — the ref clean-up at line 863 fires INSIDE the loop, but only on resolution. The fetch reader is left dangling on unmount; the abort never fires from a `useEffect` cleanup (none visible).

Returning to chat re-mounts the component with a fresh hook, no carry-over of the in-flight message — so the user sees their question with NO answer, and there's no UI affordance to retry. The Firebase backend may still write the assistant message asynchronously (if it completed), creating a divergence between what the user expected and what's saved.

## Steps to reproduce

1. Send a chat message. While streaming, navigate to `/notes`.
2. Wait 3 seconds. Navigate back to chat.
3. Observe: question is there; no answer; no spinner; no error. Refresh — the answer may or may not appear from Firestore.

## Expected

- `useEffect(() => () => abortControllerRef.current?.abort(), [])` on unmount → cancels the stream cleanly.
- Persist `isStreamingThreadId` to a global store so navigating back can pick up the stream / show "answer arrived while you were away" toast.

## Actual

Stream is orphaned. State diverges.

## Evidence

- Code: useChat.ts:203, 941 (cancel) — no unmount cleanup hook visible.
