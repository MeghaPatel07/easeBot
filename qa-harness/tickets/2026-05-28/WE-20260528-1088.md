## Description

Thread search uses 300ms debounce + setTimeout. For switch-control users (slow input) the debounce period may overlap their selection action — they activate a thread mid-debounce, results haven't updated yet, the selection lands on the OLD list position. Not a hard trap but creates "ghost" UX where what they see and what they activate diverge.

Also: no `aria-busy="true"` on the list during debounce; no announce "Searching..." or "N results".

## Expected

- Add `aria-busy="true"` on list while debounce pending
- Announce search results count via aria-live ("3 threads match Goa")
- Consider Enter-to-search instead of debounce for kbd users

## Actual

Silent debounce; selection-races possible.

## Notes

Edge case but real for slow inputs.
