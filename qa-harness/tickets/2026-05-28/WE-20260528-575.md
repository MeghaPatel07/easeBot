## Steps to reproduce
1. New user, never sent a message. Both tab A and tab B open. Both show onboarding modal.
2. In tab A, complete onboarding (send first message). Backend writes `profile.hasOnboarded = true` or similar.
3. In tab B, click the chat input — does the onboarding modal re-appear / persist?

## Expected
Tab B's onboarding modal dismisses automatically once tab A's flag write propagates.

## Actual
Tab B reads `profile.hasOnboarded` from `useAuth()` (which is `getDoc`-cached, see -152). Until tab B is reloaded or auth-flips, the modal can re-appear on next interaction.

## Impact
P2 — annoying repeat onboarding; user-perception bug suggesting the app forgot them.

## Fix direction
Same as -152 fix. Plus a BroadcastChannel `onboarding:done` from the completing tab.

## Evidence
- Behavior follows from -152 + -568 pattern; not separately reproduced live this sprint (no fresh user account at hand).
