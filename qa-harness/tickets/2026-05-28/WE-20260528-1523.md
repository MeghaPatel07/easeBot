# WE-20260528-1523 — TipTap loaded eagerly via NoteEditor route but extensions are commonjs-heavy — 12+ packages

**Severity:** P2
**Status:** triaged
**Assigned:** fix-performance
**Area:** Performance / NoteEditor bundle
**Discovered:** 2026-05-28

## Symptom
`package.json` lists 8+ `@tiptap/extension-*` packages. Bundle output shows `NoteEditor-D1BRRvzy.js` as a route-split chunk — good. But within that chunk, ALL extensions load synchronously even if the user never inserts a table, image, or color.

Conservative estimate of NoteEditor chunk: 250-400KB gzipped (TipTap core + 8 extensions + StarterKit).

## Why this matters
- First time a user opens a note: 2-4s parse on mid-tier mobile.
- Subsequent navigations are cached, so this is a one-time hit, but it stalls FCP for note-editing flows.

## Suggested fix
1. Split TipTap extensions out of the NoteEditor chunk:
```ts
const Table = lazy(() => import('@tiptap/extension-table'))
const Image = lazy(() => import('@tiptap/extension-image'))
// ...
```
   Lazy-extend the editor only after first use of the feature.
2. Drop unused extensions — audit which are actually wired up in the editor config vs imported but unused.
3. Add `vite-plugin-bundle-visualizer` to confirm the NoteEditor chunk size.
