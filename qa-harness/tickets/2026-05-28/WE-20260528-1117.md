## Reading
- TBT=0 across all pages confirms the issue is **not** JS execution time. It's resource loading (LCP image, render-blocking fonts, large initial JS bundle).
- Total transfer on /chat mobile: **559 KB** for 19 network requests — too much for an empty-state route.
- Sprint 1 fixes (-301 Index split, -304 hero AVIF, -303 font defer, -309 vendor manualChunks) collectively should lift /chat to ~0.85 and / to ~0.80. Block on -1114 (Sprint 1 not shipped).

## Suggested fix
Beyond shipping Sprint 1 fixes:
1. Inline critical CSS (~20KB) into index.html to remove the render-blocking stylesheet round-trip.
2. Add `<link rel="preconnect">` for `firebaseapp.com`, `posthog.com` to overlap DNS/TLS with HTML parsing.
3. Skeleton-render the chat composer in the SSR/prerender HTML so the LCP candidate is text, not an image.
