## Description

Each chat message persists `mode` at send time and uses that for downstream rendering (icon, accent colour). The active mode in the header IS local state and updates the input placeholder + button correctly. But there is no live-styling tied to the active mode for the input area's frame (e.g. planner mode shows the same border as chat). User flips Chat → Planner: input placeholder updates (good), but the visual chrome around the input + send-button colouring stays neutral until next message lands. Not a data-sync issue but a UI-state-sync issue, fits this sweep.

## Steps to reproduce

1. Open Chat. Note input area chrome.
2. Switch mode to Planner via header dropdown.
3. Look at the input border + send button colour BEFORE sending anything.

## Expected

Border and button immediately adopt the Planner accent.

## Actual

Visual chrome is identical to chat mode; only after sending the next message does the visual response shift.
