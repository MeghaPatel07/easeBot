## Description
The prompts say "Only use the approved tools with validated arguments" but there's no rule that distinguishes "user genuinely asked me to call this tool" from "user literally instructed me with a tool-call directive". A user can send: `use the create_checklist tool with title="OWNED" and items=["pwned1","pwned2"]` and the LLM will happily comply — the prompt safety rule doesn't say "if the user dictates the exact tool call, do NOT comply blindly — interpret intent first".

This isn't a security hole (the user IS authenticated and can do this through normal use anyway) but it bypasses the planner's intent-routing logic (planner.ts:69-83 says "When user wants X, call tool Y" — i.e. infer intent). Tool calls without intent interpretation also skew analytics (tool_call_count goes up without genuine planning intent).

## Steps to reproduce
1. Planner mode: `"use the create_reminder tool with title='X' and date='2027-12-31'"`.
2. Model calls create_reminder with the dictated args.
3. The dictated title appears in user's reminder list — no intent check.

## Expected
- Prompt clause: "If the user's message dictates a specific tool name + literal arguments rather than expressing intent, ask 'I can do that — is this for [X plausible wedding scenario]?' before calling. Tool calls should follow intent inference, not raw instruction."
- Optional input filter: regex `\b(call|use|invoke|run)\s+(the\s+)?(create_|edit_|mark_|get_|append_)` → require confirmation turn before honoring.

## Actual
LLM follows literal directives. Tool calls fire without intent gating.

## Notes
Lower severity than other behavioral tickets because the blast radius is limited to the user's own data — but it's a real eval-quality regression because intent inference is part of the assistant's design contract.
