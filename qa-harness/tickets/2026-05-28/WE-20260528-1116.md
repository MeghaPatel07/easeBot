## Measurement
1000 requests in 10 batches of 100 concurrent against `/api/health` (no auth, no DB):
- Wallclock: 1.9s
- Throughput: **538 req/s sustained**
- p50: 1.6ms, p95: 5.5ms, p99: 33.3ms, max: 38.9ms
- Errors: 0

Burst-200 in single shot: 624.6 req/s, p95 20.8ms, p99 22.5ms, max 22.5ms.

## Reading
- For a single-node Express on a dev macbook, this is healthy. Pre-routing middleware (helmet, CORS, sanitizer, posthogContext, rate limiter) adds < 1ms.
- /api/health is the **lower bound on real work** — actual /api/chat will be 1000-3000× slower because it does Firestore reads + Azure OpenAI calls.
- p99 33ms during the sustained run suggests rare GC pause or event-loop blip — normal.

## Why filed
For Sprint 3 traceability — anyone investigating "did we degrade" can compare against this baseline. Cross-reference -1107 (no Firestore pool tuning) and -1108 (cannot measure authed throughput).
