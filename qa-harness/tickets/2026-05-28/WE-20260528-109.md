## Description

Journey 2 surfaces that the marketed "10 free guest messages then sign up" is enforced **only** in `localStorage.easebot-guest-msg-count`. The backend has:
- `apiRateLimiter`: 30 req/min per IP across `/api/*`.
- `chatBurstRateLimiter`: 10 messages per 10 seconds keyed by `uid || guestFingerprint(SHA256(ua+al+ip).slice(0,16))`.

Neither enforces a lifetime cap of 10 messages per guest. A guest who:
- Opens incognito → `localStorage` empty → counter resets to 0.
- Clears site data → same.
- Refreshes after running `localStorage.removeItem('easebot-guest-msg-count')` from DevTools console → same.
- Uses two different browsers → two separate counters.

So the product cap is essentially advisory. The only real ceiling is the IP-based 30/min, which still permits **30 × 60 = 1,800 free chat messages per hour per IP** with zero authentication, burning Azure OpenAI quota.

This is the same root cause as already-filed WE-20260527-204 (no auth gate on `/api/chat`) but filed separately under e2e-flow because it surfaces a distinct **business** consequence — the pricing tier rollout (Sprint 1 closed) assumes a real guest cap exists; it doesn't.

## Steps to reproduce

```bash
# 11 messages succeed when not rate-limited
for i in $(seq 1 11); do
  curl -s -o /dev/null -w "msg $i: %{http_code}\n" \
    -X POST -H "Content-Type: application/json" \
    -d "{\"message\":\"msg $i\",\"history\":[]}" \
    http://localhost:3001/api/chat/stream
  sleep 2  # avoid burst limiter
done
# All 11 → 200, even with no auth token, no Cookie, no fingerprint pinning.
```

Browser side: open DevTools console as guest, run `localStorage.removeItem('easebot-guest-msg-count')` after sending 9 — the banner instantly says "10 messages remaining" again.

## Expected

- Server enforces the cap (preferably keyed by signed guest cookie / hashed fingerprint, persisted in Redis/Firestore with TTL).
- 11th message returns 429 with `reason='guest_limit_exceeded'` and the structured payload `CapHitBanner.tsx:43` expects.

## Actual

- localStorage-only. Bypassable in seconds.
- 429 returns only on IP-burst, not on lifetime guest cap.
