## Description

```ts
const truncate = (s: string, n = 30) => (s.length > n ? s.slice(0, n - 1) + '…' : s);
```

`s.length` counts UTF-16 code units, not grapheme clusters. For a title like `"My 🎉 Wedding Plans"`:
- `s.length` counts the emoji as 2 (surrogate pair).
- `s.slice(0, n - 1)` can cut MID-surrogate-pair → renders as a broken `\uD83C` followed by `…`, displayed as a `?` box on some platforms.

Same issue for combining marks (Hindi `नमस्ते`, Tamil scripts), where slicing mid-cluster produces a malformed display.

## Steps to reproduce

1. Attach a note titled `"My 🎉 Wedding Plans"`. (Or any title with emoji at position ~28.)
2. Observe chip — truncated render shows broken character.

## Expected

```ts
const truncate = (s: string, n = 30) => {
  const segments = [...new Intl.Segmenter().segment(s)];
  return segments.length > n ? segments.slice(0, n - 1).map(x => x.segment).join('') + '…' : s;
};
```

## Actual

Code-unit slicing.
