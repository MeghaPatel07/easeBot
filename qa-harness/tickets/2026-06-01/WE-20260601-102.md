## Description

`POST /api/generate-image` mounts `validateBody(ImageGenerateSchema)` (`routes/image.ts:11`). The
schema only allows `{ prompt, size?, quality?, style? }` (`schemas/image.ts:3-8`). Because `validateBody`
reassigns `req.body = result.data` and Zod strips unknown keys, every field the handler actually reads
that is NOT in the schema is deleted before `handleGenerateImage` runs.

`handleGenerateImage` destructures `{ prompt, imageBase64, imageMimeType, preferredAspectRatio }`
(`imageController.ts:6-11`). After validation:

- `imageBase64` is always `undefined` → the **image-to-image edit** branch
  (`imageController.ts:49`: `if (imageBase64 && prompt?.trim() && ...)`) can never execute.
- `imageMimeType` is always `undefined` → the **image-to-text / vision** branch
  (`imageController.ts:77`: `if (imageBase64 && imageMimeType)`) can never execute.
- `preferredAspectRatio` is always `undefined` → the quality heuristic
  (`imageController.ts:13`: `quality = preferredAspectRatio?.includes('1536') ? 'hd' : 'standard'`)
  always resolves to `'standard'`. HD is never chargeable/selectable on this endpoint.

Conversely, the schema's `size`, `quality`, and `style` are never read by the handler.

Live impact is limited because the only frontend caller (`functionsService.generateImage`,
`functionsService.ts:112-114`) sends `{ prompt }` only — and `generateImage()` currently has no call
sites in components — so the live image flow goes through `/api/chat/stream` instead. But the endpoint
is publicly mounted and authenticated; any client (or a future caller) sending an attached image or an
aspect ratio is silently degraded: edits/vision become a plain text-to-image generate, and HD is
ignored.

## Steps to reproduce (by reading)

1. `routes/image.ts:11` → `validateBody(ImageGenerateSchema)`.
2. `schemas/image.ts:3-8` → schema lacks `imageBase64`, `imageMimeType`, `preferredAspectRatio`.
3. `middleware/validateRequest.ts:15` → `req.body = result.data` drops unknown keys.
4. `imageController.ts:6-13,49,77` → handler reads the now-undefined fields; edit/vision branches
   become unreachable; quality pins to `standard`.

## Expected

Either the schema declares every field the handler consumes (`imageBase64`, `imageMimeType`,
`preferredAspectRatio`) so edit/vision/HD work, or the handler is simplified to match the schema's
documented surface. The endpoint's behavior must match its accepted payload.

## Actual

Validation silently removes `imageBase64`/`imageMimeType`/`preferredAspectRatio`; the edit and vision
code paths are dead and HD quality can never be selected via this route.

## Evidence

- `schemas/image.ts:3-8`, `routes/image.ts:11`, `middleware/validateRequest.ts:15`.
- `imageController.ts:6-13` (reads), `:49` (dead edit branch), `:77` (dead vision branch), `:13` (HD heuristic neutered).
- `functionsService.ts:112-114` sole caller sends `{ prompt }` only; no component call sites.
