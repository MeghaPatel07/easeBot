## Description

The free-tier "max 5 checklists" cap is enforced in exactly one place: the AI tool path
(`plannerTools.executeToolCall` → `__executeToolCallInner`, `plannerTools.ts:229-235`), which calls
`countChecklists(uid)` and returns `STORAGE_LIMIT_REACHED` when `existingCount >= 5` for non-premium
users.

But the **manual** checklist-creation UI does not go through the backend at all. The frontend
`checklistService.createChecklist` (`checklistService.ts:25-43`) writes the checklist **directly to
Firestore** (`setDoc(checklistDoc(userId, id), checklist)`) with **no tier check and no count check**.
The backend `checklistService.createChecklist` (`easebot-backend/src/services/checklistService.ts:37-53`)
also does not enforce a limit (the gate lives only in the planner-tool wrapper, and the manual UI never
calls it).

Result: a free-tier user who hits "Add checklist" in the planner UI can create an **unlimited** number
of checklists, completely bypassing the cap that the AI assistant enforces. The two creation paths
disagree on the same business rule — the assistant will refuse a 6th checklist ("Free plan is limited
to 5 checklists. Upgrade to Pro to add more.") while the manual button silently allows it.

Secondary issue (PRD-BugsFixes §2.2): even the enforced path keys on the boolean `isPremium`
(`plannerTools.ts:229`) rather than the actual tier, so pro/promax users whose `isPremium` flag is not
set would be wrongly limited. This ticket's primary finding is the manual-UI bypass; the isPremium
mismatch is noted for the fixer's awareness.

## Steps to reproduce (by reading)

1. Free user already has 5 checklists.
2. Ask the assistant to create another → backend tool path returns STORAGE_LIMIT_REACHED, user is
   blocked + shown upgrade copy (`plannerTools.ts:232-235`).
3. Instead click the manual "Add checklist" button in the planner UI → `checklistService.createChecklist`
   writes a 6th doc straight to `users/{uid}/checklists` with no check (`checklistService.ts:41`).
4. Checklist count is now 6 for a free user.

## Expected

The 5-checklist free-tier cap is enforced consistently regardless of creation path (manual UI and AI
tool), keyed on the resolved tier (free vs pro/promax), with the same upgrade messaging.

## Actual

Only the AI tool path enforces the cap. The manual UI writes directly to Firestore with no limit/tier
check, letting free users exceed 5 checklists.

## Evidence

- `checklistService.ts:25-43` (frontend) — direct `setDoc`, no count/tier check.
- `plannerTools.ts:229-235` (backend) — the only place the `>= 5` cap exists; uses `isPremium` boolean.
- `easebot-backend/src/services/checklistService.ts:37-53` — backend create has no cap either.
- STATIC — needs live re-verify (create 6 checklists via UI as a free user) when MCP+backend restored.
