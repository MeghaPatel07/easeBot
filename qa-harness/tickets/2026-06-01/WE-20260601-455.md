## Description

Every Azure chat completion in `azureAI.ts` sets `max_tokens: 4096` and none of the four functions inspect `choices[0].finish_reason`. When the model hits the token cap, Azure returns `finish_reason: 'length'` and the content is truncated mid-sentence. The pipeline does not detect this:

- Non-stream (`callAzureAI`): returns `message?.content ?? ''` with no truncation flag.
- Stream (`streamCallAzureAI` / `…WithToolResults`): accumulates `delta.content` and emits a `done` event with `toolCalls` + `usage` only — no `finish_reason`. The chatController `d` event (chatController.ts:1691) carries no truncation marker.

Assertion-eval angle: a stated property is "no response is longer than the configured max tokens" — that holds, but the *inverse* failure (a response that WANTED to be longer and got silently chopped) is unhandled. The user sees a reply that just stops mid-word with no "the response was cut off — continue?" affordance, and the frontend has no field to render one. This is most likely on knowledge mode (long cultural explanations, temperature 0.2) and planner timelines.

The summarizer (conversationSummarizer.ts:45) caps at `max_tokens: 300` with the same blind spot — a long thread's summary can be truncated, silently dropping "key decisions, dates, budgets" the summary prompt promised to preserve, which then degrades downstream trajectory memory.

## Steps to reproduce (by reading)

1. azureAI.ts:67/124/205/283 — `max_tokens: 4096`; no `finish_reason` read anywhere in the file.
2. Stream `done` event (azureAI.ts:162,243) carries `{ toolCalls, usage }` only.
3. chatController.ts:1691 `d` event has no truncation field; useChat replaces streamed text with `finalMeta.text`.

## Expected

Read `choices[0].finish_reason`; when it is `'length'`, surface a `truncated: true` flag in the `done`/`d` event (and the non-stream JSON) so the frontend can show a "response was cut off" notice and/or a continue button. Consider raising `max_tokens` for knowledge mode or appending a "[continued]" affordance.

## Actual

Truncation at 4096 tokens is invisible end-to-end; the user gets a mid-sentence cut-off with no explanation or recovery path. Summarizer 300-token truncation silently drops preserved facts.
