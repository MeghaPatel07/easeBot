## Description

`circuitBreaker.ts` exports four pre-configured breakers: `llmCircuitBreaker` (AzureOpenAI), `imageCircuitBreaker` (ImageGen), `speechCircuitBreaker` (AzureSpeech), and `translatorCircuitBreaker`. A repo-wide grep for `.execute(` / `CircuitBreakerError` shows the breakers are referenced ONLY in `services/translation.ts`. The Azure OpenAI chat calls (`callAzureAI`, `streamCallAzureAI`, `callAzureAIWithToolResults`, `streamCallAzureAIWithToolResults` — azureAI.ts) and the image-generation calls (imageGeneration.ts) issue `client.chat.completions.create(...)` directly with NO breaker wrapping. `speechCircuitBreaker` is likewise defined but unused.

Consequence (chaos eval): when Azure OpenAI degrades (sustained 500s / 429s / timeouts), every inbound chat turn makes a fresh upstream call that hangs or fails. There is no fast-fail: the breaker that exists to convert a flapping upstream into an immediate, cheap, friendly "we're slow right now" response is bypassed entirely. The user-facing result is a generic 500 (`res.status(500).json({ error: 'Internal server error' })`, chatController.ts:1142) per request, retried in full, amplifying load on an already-failing provider — the exact failure mode the breaker was built to prevent.

The translator path proves the intended pattern (translation.ts:49,93 wrap calls in `translatorCircuitBreaker.execute(...)` and map `CircuitBreakerError` to a graceful fallback). The LLM and image paths are missing this.

## Steps to reproduce (by reading)

1. circuitBreaker.ts:131 — `export const llmCircuitBreaker = new CircuitBreaker({ name: 'AzureOpenAI', ... })`.
2. Grep `llmCircuitBreaker` / `imageCircuitBreaker` / `speechCircuitBreaker` across `src/` → zero `.execute()` call sites outside circuitBreaker.ts; only `translatorCircuitBreaker` is used (translation.ts).
3. azureAI.ts:64/121/202/280 — `client.chat.completions.create(...)` called bare, no breaker.
4. imageGeneration.ts — no `import` of any circuit breaker.

## Expected

LLM chat calls wrapped in `llmCircuitBreaker.execute(...)`, image calls in `imageCircuitBreaker.execute(...)`, TTS/STT in `speechCircuitBreaker.execute(...)`, each mapping `CircuitBreakerError` to a user-friendly degraded message (e.g. chat → "I'm having trouble reaching the assistant right now, please try again in a moment"). Mirrors the translator pattern.

## Actual

Three of four breakers are dead code. Azure OpenAI / image / speech outages produce uncapped raw failures with generic 500s and no fast-fail.
