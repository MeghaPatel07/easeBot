## Description

`validateBody` does `req.body = result.data` (validateRequest.ts:15). Zod object schemas strip unknown keys by default, so after validation the controller only sees fields that `ChatRequestSchema` declares. The schema and the controller's destructure disagree:

Controller reads (chatController.ts:651):
`message, threadId, audioBase64, language, mode, history, userPersonalization, imageBase64, imageMimeType, lastGeneratedImageUrl, styleMemory, forceImageGeneration, preferredAspectRatio, vibeTitle, vibeDescriptors` + `attachments` (line 659) + `requestId` (stream).

Schema declares (chat.ts):
`message, threadId, mode, imageData, imageMimeType, toneSettings, language, history, forceImageGeneration, preferredAspectRatio, vibeTitle, vibeDescriptors`.

Mismatches on the validated `/chat` route:
- **`imageBase64`** (controller) vs **`imageData`** (schema) — NAME MISMATCH. The controller never reads `imageData`. So a user-attached image sent as `imageBase64` to `/chat` is stripped by validateBody → `visionData` is always `undefined` → vision/edit path silently never fires on the non-stream endpoint. (`imageData` that the schema does accept is read by nobody.)
- **`audioBase64`** — not in schema → stripped → a voice-only request (`message` empty) hits the `if (!message && !audioBase64 && !imageBase64)` guard at line 653 and 400s.
- **`userPersonalization`** — not in schema → stripped → tone/verbosity personalization suffix never applied on `/chat` (schema has `toneSettings` instead, which the controller doesn't read).
- **`lastGeneratedImageUrl`, `styleMemory`, `attachments`, `requestId`** — not in schema → stripped → "save that image to my note" cross-turn threading, style memory continuity, and attachment context all silently dropped on `/chat`.

The streaming `/chat/stream` route does NOT run validateBody at all (see WE-20260528-1402), so it reads all these fields fine — meaning the two endpoints accept different payloads for the same logical request. The non-stream path quietly degrades.

## Steps to reproduce (by reading)

1. chat.ts:11 — `/chat` mounts `validateBody(ChatRequestSchema)`.
2. validateRequest.ts:15 — `req.body = result.data` (unknown keys dropped).
3. chat.ts (schema):7 declares `imageData`; controller (chatController.ts:651, :774) reads `imageBase64` + `imageMimeType` and builds `visionData` from them.
4. Result: `imageBase64`/`audioBase64`/`userPersonalization`/`styleMemory`/`lastGeneratedImageUrl`/`attachments` are absent from `req.body` by the time the controller runs.

## Expected

The validated schema is the single source of truth for the request contract and includes every field the controller consumes, with matching names. Vision images, voice input, personalization, and style/attachment continuity work identically on `/chat` and `/chat/stream`.

## Actual

Schema omits/renames ~7 fields the controller depends on; validateBody strips them; non-stream chat silently loses vision, voice, personalization, style memory, and attachment context.
