## Description

In `handleChat` (non-streaming), the first LLM call uses `effectiveHistory` (line 825) — which, when `history.length > 10`, is the summarized history (older messages collapsed into one `[Previous conversation summary]` assistant turn, lines 718-733). But the tool-results follow-up pass calls `callAzureAIWithToolResults(history, …)` at **line 1029**, passing the raw, full, **un-summarized** `history` instead of `effectiveHistory`.

So within a SINGLE turn that involves a tool call (e.g. planner `create_checklist`, or `generate_image`), the model sees one conversation shape on pass 1 and a different (larger, un-summarized) shape on pass 2. This causes:
- Trajectory incoherence: the second pass can "remember" earlier-turn detail the first pass had summarized away, producing a final reply inconsistent with the streamed/first-pass framing.
- Token bloat / cost: the whole point of summarization (compress long history) is defeated on the tool path — the full history is re-sent, and on a 3-round tool chain it is re-sent up to 3 times.
- Potential context-length errors on very long threads that summarization was meant to prevent.

The streaming handler does this correctly: `streamCallAzureAIWithToolResults(effectiveHistory, …)` at line 1629. This is an asymmetry bug between the two handlers — the non-stream path is the one that's wrong.

## Steps to reproduce (by reading)

1. Read `chatController.ts` line 718-733: `effectiveHistory` is built (summarized when `history.length > 10`).
2. Line 825: first pass uses `effectiveHistory`. Correct.
3. Line 1028-1029: tool-results pass uses `history` (raw). **Bug.**
4. Compare streaming handler line 1628-1629: uses `effectiveHistory`. Confirms intended behavior.

## Expected

Both passes within a turn use the same `effectiveHistory` so the model has a consistent view of the conversation, and summarization savings are preserved on the tool path.

## Actual

Pass 1 = `effectiveHistory` (summarized); pass 2+ = `history` (raw full). Divergent context within one turn; summarization defeated for tool-using turns.

## Notes

One-line fix: change `history` to `effectiveHistory` at line 1029 to match the streaming handler.
