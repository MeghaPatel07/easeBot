WE-20260527-170 · Two sources of truth for user profile (AuthContext vs useAccount) P0

Bug summary

Two independent caches of the user profile: useAuth().profile (one-shot getDoc at sign-in, never refreshed) and useAccount().profile (TanStack Query, invalidated on settings mutations). Settings save refreshes only the useAccount cache; everything wired through useAuth (sidebar, chat header, NotesView, InvitePartner, useChat, useTokenPool, …) stays stale until F5.

Call-graph (pre-fix)

SettingsAccountTab.save
  └─ useAccount.updateProfile(patch)
      └─ profileMutation.mutateAsync(patch)
          └─ patchAccountProfile(patch)            [backend write → Firestore users/{uid}]
          └─ onSuccess: qc.invalidateQueries(['account','me'])
              └─ ProfileMenu re-renders with fresh useAccount cache  ✅
              └─ AuthContext.profile  ─── NOT TOUCHED ───            ❌ stale
                  └─ ChatSidebar:502   (name + initials)             ❌ stale
                  └─ ChatHeader:89     (ProfileIcon)                 ❌ stale
                  └─ Index:1349-1350   (InvitePartner / NotesView)   ❌ stale
                  └─ useChat:180,506   (voiceId, toneSettings, …)    ❌ stale
                  └─ useTokenPool:31, useActiveVibe:54, …            ❌ stale

Call-graph (post-fix)

SettingsAccountTab.save
  └─ useAccount.updateProfile(patch)
      └─ patchAccountProfile(patch)                [backend write → Firestore users/{uid}]
          └─ Firestore onSnapshot fires on users/{uid}
              ├─ AuthContext profile listener → setProfile(snap.data)   ✅
              │   └─ ALL useAuth() consumers re-render with new value   ✅
              └─ onSuccess: qc.invalidateQueries(['account','me'])      ✅
                  └─ useAccount cache refreshes (ProfileMenu)           ✅

Both caches now observe the same live Firestore doc — no possible drift.
