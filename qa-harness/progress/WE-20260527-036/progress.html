WE-20260527-036 · Feedback dialog missing required-field validation indicator P3

Repo: Wedding-Ease-Viva-Chat · Agent: fix-frontend · Branch: fix-WE-20260527-036 -> Bug-Resolve-claude · Worktree: worktrees/fix-WE-20260527-036

Bug summary

The Feedback dialog labels its textarea with "*" implying required, but the field does not expose aria-required="true", so assistive tech can't tell it apart from an optional field. Submitting an empty form previously triggered only a transient toast with no inline indicator, leaving keyboard / screen-reader users guessing which field failed. The Submit button also stayed enabled even when the form was clearly invalid.

Diagnosis: replace single-error submit-time validator with per-field validators + touched state.
Per-field validators (feedbackError, emailError) computed every render. Touched flags track whether the user has blurred each field. Errors only render inline when both touched AND error present, so the form doesn't yell on first paint. On submit-with-errors, both touched flags flip to true so all errors surface together. Submit button derives disabled from a canSubmit boolean (no submitting + no errors).
