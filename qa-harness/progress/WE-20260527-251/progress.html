Bug summary

Assistant chat replies stream in via TypewriterMarkdown but the message-list container has no role="log" and no aria-live region. VoiceOver / NVDA users get no signal that a reply arrived. WCAG 4.1.3 (Status Messages, AA) + 1.3.1 (Info and Relationships, A).

Audit trail

2026-05-27 — step 1
Read ticket, ChatMessages.tsx, useTypewriter.ts, useChat.ts.
Confirmed the visible container at line 246 has no a11y semantics. Streaming state is exposed via isTyping prop and the per-message streamingMsgId memo. The typewriter updates DOM character-by-character — so we cannot put aria-live="polite" directly on the visible content.
2026-05-27 — step 2
Chose sidecar-status-region strategy (per ticket suggestion).
Container becomes role="log" aria-label="Chat messages" aria-live="off" aria-relevant="additions". A sibling sr-only div with role="status" aria-live="polite" aria-atomic="true" announces the FINAL settled assistant text exactly once per message — fired by an effect that watches isTyping transitioning to false. Markdown stripped to plain prose. No assertive — won't interrupt.
