WE-20260527-220 — Chat image-attach has no client-side file size cap

Agent: fix-frontend  |  Branch: fix-WE-20260527-220  |  Severity: P1

Diagnosis

Two <input type="file" accept="image/*"> inputs in src/components/chat/ChatMessages.tsx at lines 289 and 315 feed FileReader.readAsDataURL(file) with no file.size guard. Codebase already uses 8MB cap in Vibe Composer and 10MB in Notes — chat-attach was the odd one out. Toast is via sonner (matches AttachmentPicker.tsx).

Fix

Added MAX_CHAT_IMAGE_BYTES = 10 * 1024 * 1024 module-level const. Both input onChange handlers now: (1) verify file.type.startsWith('image/'); (2) reject if file.size > MAX_CHAT_IMAGE_BYTES with toast.error('Image too large — please use under 10MB.'); (3) clear e.target.value on reject so re-picking the same file still fires onChange. Matches backend's post-WE-202 10MB cap (zero round-trips wasted).
