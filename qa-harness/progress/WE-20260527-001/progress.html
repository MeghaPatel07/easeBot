WE-20260527-001 · PostHog analytics proxy returns 404 on every page load P1

Repo: Wedding-Ease-Viva-Chat · Agent: fix-frontend · Branch: fix-WE-20260527-001 → Bug-Resolve-claude · Worktree: /Users/krish/Desktop/easebot/worktrees/fix-WE-20260527-001

Bug summary

Every page in dev fires two PostHog requests that 404 (or 500 in our case): the SDK calls /ingest/array/<key>/config.js and /ingest/array/<key>/config?ip=0, Vite proxies them at http://localhost:3001 (the backend), but the backend isn't running locally and its /ingest router exists only in prod. The SDK script load fails MIME validation (application/javascript expected, empty received), feature flags fall back to defaults, capture/replay never reach PostHog, and the console fills with noise.

2026-05-27 11:50
Wrote the fix — three small changes.
1) vite.config.ts: repoint /ingest proxy to https://us.i.posthog.com with changeOrigin + rewrite so dev works without the backend running.
2) src/lib/analytics.ts: tighten the init gate with a regex on KEY (^phc_[A-Za-z0-9]{20,}$) so placeholder/empty keys never boot the SDK. Added a one-line console.info breadcrumb in dev so devs see why analytics is off. __phDebug object now exposes keyValid.
3) .env.example: document the new dev proxy + the KEY regex gate. .env itself is NOT edited (blocked by harness rules).
