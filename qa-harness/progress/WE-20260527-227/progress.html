WE-20260527-227 · /api/generate-image returns 200 {"imageUrl":[]} on Azure failure P0

Repo: easebot-backend · Agent: fix-backend-api · Branch: fix-WE-20260527-227 → Bug-Resolve-claude · Worktree: /Users/krish/Desktop/easebot/worktrees/fix-WE-20260527-227

Bug summary

When generateImageGptImage1 (Azure GPT-Image) fails — missing credentials, content-policy refusal, both deployments errored — it returned []. The controller checked if (!imageUrl) to detect failure, but [] is truthy in JS, so the failure branch never fired. The controller then proceeded to chargeImage() and responded HTTP 200 with {"imageUrl": []} — silently charging users image-tier tokens for a no-result.

Root cause

Two coupled defects:

  1. imageGeneration.ts — generateImageGptImage1 and editImageGptImage1 used Promise<string[]> as their return type and returned [] for every failure mode (no creds, fallback deployment errored, empty result).
  2. imageController.ts:106 (and :51) used if (!imageUrl) to detect failure — truthy [] defeated this guard.
