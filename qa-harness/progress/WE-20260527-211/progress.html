WE-20260527-211 · SECURITY: Prompt injection via client-controlled history[].role='system' P0

Repo: easebot-backend · Agent: fix-backend-api · Branch: fix-WE-20260527-211 (off Bug-Resolve-claude) · Worktree: /Users/krish/Desktop/easebot/worktrees/fix-WE-20260527-211

Bug summary

ChatRequestSchema accepted history[].role: 'user' | 'assistant' | 'system'. When no threadId was supplied, getChatHistory returned client-supplied history verbatim and callAzureAI / streamCallAzureAI spread it into the LLM messages list AFTER the legitimate system prompt. Any unauthenticated guest could inject a fake role='system' message that the LLM treated as authoritative — CWE-1336 prompt injection.
