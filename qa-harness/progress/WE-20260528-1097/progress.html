Bug summary

BillingSettings.tsx documents that it provides "cancel/reactivate actions" (per PlanBillingTab.tsx comment) but in fact has no cancel UI. Per WCAG 3.3.4 (Error Prevention, Legal/Financial/Data, AA), a financial destructive action — cancelling a paid subscription — must be explicitly confirmable (or reversible / checked) before it fires. The matching DowngradeFlow.tsx already has a confirm step. Bring BillingSettings to parity by adding a Cancel subscription button gated behind a shadcn AlertDialog confirm.
