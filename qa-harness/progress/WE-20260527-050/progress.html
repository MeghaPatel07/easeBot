WE-20260527-050 · AnalyticsConsent banner overlays content + blocks pointer events P1

Repo: Wedding-Ease-Viva-Chat · Agent: fix-frontend · Branch: fix-WE-20260527-050 (off Bug-Resolve-claude) · Worktree: /Users/krish/Desktop/easebot/worktrees/fix-WE-20260527-050

Bug summary

The privacy-friendly analytics consent banner is position: fixed; bottom: 16px with a card up to 520px wide. It sits on every route as a sibling of <Routes>, has no layout-reservation, and visually overlays the bottom-most content row on Pricing, Help, Terms, Privacy, Checkout, Login, and the chat shell itself. On mobile the banner also covers the chat input area, which in WE-20260527-100 blocked 3 of 6 E2E journeys: chat input click, mode-switch, token-cap submit.

Fix approach

Two combined changes — keep the card visually pinned to the bottom of the viewport, but stop it from intercepting clicks or hiding content.

  1. Pointer-events pass-through. Wrap the visible card in a full-width fixed wrapper that is pointer-events: none; only the card itself stays pointer-events: auto. Clicks outside the card (e.g. on the chat input below) now go straight through.
  2. Layout reservation via CSS var. While the banner is visible, the component measures its own height with a ResizeObserver and exposes it as --analytics-consent-height on <html>. The chat input wrappers in Index.tsx add it to their padding-bottom calc, and the scrollable content pages (.gradient-bg.min-h-screen) gain a matching padding-bottom via global CSS. The variable is cleared on dismiss, so every rule is a no-op once the user has accepted or declined.
