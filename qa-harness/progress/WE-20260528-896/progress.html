Bug summary

Two empty-state surfaces use slightly different copy for the same situation: ShoppingListView.tsx:551 renders a static <p> reading "No items yet. Add your first item above." that points (incorrectly) to an "Add item" button rather than a visible input. ChecklistDetail.tsx:316 reads "No items yet." and follows it with a clickable "+ Add the first item" link that opens the add-item input. The CTA pattern is the more helpful of the two — this fix harmonises both surfaces on that pattern.

Root cause

The two views were authored independently and arrived at different empty-state conventions. ChecklistDetail's CTA button is the better UX because (a) the add-item input is hidden behind a toggle and (b) clicking the CTA opens it directly. ShoppingListView's static text falsely implies an input is visible "above" when only an "Add item" button is.

Fix

Convert ShoppingListView's static <p> empty state into a centered block that pairs the "No items yet." sentence with a clickable "+ Add the first item" link that calls setAddingItemToListId(list.id) — mirroring ChecklistDetail's pattern exactly. Drop the misleading "Add your first item above." sentence on Shopping. On ChecklistDetail leave the existing structure as-is (it already had the CTA). Both surfaces now expose the same "No items yet." + "+ Add the first item" CTA pattern.
