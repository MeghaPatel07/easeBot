WE-20260528-203 · inputSanitizer skips history[].content (control chars / NUL / ANSI) P0

Repo: easebot-backend · Agent: fix-backend · Branch: Bug-Resolve-claude · Worktree: worktrees/fix-WE-20260528-203

Bug summary

inputSanitizer only stripped control characters from string fields whose KEY was in SANITIZE_FIELDS = {message, prompt}. The middleware recursed into nested objects and arrays, but the filter was keyed on the field NAME — so history[].content, vibeTitle, vibeDescriptors[], imageMimeType, language, threadId all bypassed sanitization. NUL bytes can corrupt downstream Firestore writes; ANSI ESC sequences can hijack admin terminals tailing pm2 logs; control chars can bypass keyword-based promptGuard.

Fix shape

Inverted the model: SANITIZE_FIELDS (allowlist) was replaced with PRESERVE_VERBATIM_FIELDS (denylist of base64 fields: imageData, imageBase64, audioBase64). Every other string — at any depth, including elements of string arrays — is now sanitized. Sanitization strips C0 control bytes 0x00-0x1F (except \t \n \r) plus DEL 0x7F. The ANSI ESC byte 0x1B falls in that range and is therefore stripped at the source.
