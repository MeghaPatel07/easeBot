Bug summary

SidebarMenuSkeleton (sidebar.tsx:646-682) uses Math.random() inside useMemo(..., []) to set a CSS variable --skeleton-width. Even with empty deps, this is fragile:

  • Under React StrictMode (dev), components mount-unmount-remount, producing a different memoized random value the second time and a visible flicker.
  • Any parent change that forces a remount of the skeleton (key change, conditional render swap) re-rolls the random width.
  • The CSS variable is recomputed at every render via the inline style object literal, fighting browser style optimizations during repeated re-renders on slow networks.
The fix is to derive the width deterministically — accept an optional seed (or index) prop and rotate through a fixed pattern (60% / 75% / 90%), falling back to a stable per-mount value held in useRef (which, unlike useMemo, is not re-invoked by StrictMode).
