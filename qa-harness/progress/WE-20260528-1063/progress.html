Bug summary

WCAG 2.5.3 (Label in Name, Level A) + 4.1.2 (Name, Role, Value, Level A) violations. Multiple icon-only <button> elements in the chat surfaces have title= only (mouse-hover tooltip) but no aria-label. This means macOS Voice Control / Windows Voice Access users cannot say "Click Download" or "Click Close" — they must say "Show numbers" and pick the numbered overlay, then memorize the assignment. ~3× friction multiplier on every interaction.

Fix shape: pure attribute additions — add aria-label="<verb> <object>" to each affected icon-only button. No refactors. title= kept where present (for sighted mouse users) but is never sufficient on its own for AT users.

Out of scope (claimed by sibling agent WE-20260528-1056): src/components/chat/ChatMessages.tsx — do not touch.

Why title= isn't enough

  • title appears as a mouse-hover tooltip only. It is not exposed reliably to AT.
  • macOS Voice Control's "Click [label]" matching uses the accessible name — computed from aria-label, aria-labelledby, or visible text. title is a last-resort fallback that VoiceControl ignores for click-by-name.
  • Switch Control reads the accessible name when scanning. With only title, switch users hear no description and have to memorize position.
  • WCAG 2.5.3 (Label in Name) requires the accessible name contain the visible label. Where there is no visible label, an explicit aria-label is the canonical fix.
