Bug summary

src/pages/PaymentFailure.tsx rendered a raw gateway reason string to the user (Reason: <reason> in a monospace span) plus a bare "Try again" / "Back to app" pair, with no Help/Support link. This fails WCAG 3.3.3 (Error Suggestion), 3.2.6 (Consistent Help), and 3.3.4 (Error Prevention) — and at a high-cognitive-load moment (a failed payment) it exposes jargon that increases anxiety.

Ruling applied: generic graceful message + Help, NO PayU-error-code guessing. (This overrides the ticket's original "Expected" section, which had proposed a PayU-code → plain-English mapping table.)
