WE-20260528-002 - SSML injection via unsanitized voiceName in /api/tts P0

Repo: easebot-backend · Agent: fix-backend-api · Branch: fix-WE-20260528-002 -> Bug-Resolve-claude · Worktree: /Users/krish/Desktop/easebot/worktrees/fix-WE-20260528-002

Bug summary

The TTS controller read voiceName straight off req.body with zero validation, and resolveAzureVoice returned the user string verbatim as long as it ended in "Neural". That value was then interpolated unescaped into the SSML <voice name="${azureVoice}"> template, so an attacker could break out of the attribute and:

  • Substitute the synthesizer voice silently (HTTP 200 + WAV in attacker's chosen voice).
  • Inject arbitrary SSML elements (<prosody>) - Azure rejects with a 500 whose body leaked vendor internals ("websocket error code: 1007", "Node [speak] with type [RootSpeak]...").
